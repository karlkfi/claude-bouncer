# A trailing & stands Class A down for the whole command

`analyze_class_a` returns no findings whenever the command's last token is an
unquoted `&`
(`plugins/foreground-guard/scripts/bash-foreground-guard.py:730:if tokens and tokens[-1] == '&'`).
bash's `&` backgrounds only the and-or list it ends, so everything before the
last `;` or newline still runs in the foreground, and a blocking command
written there is never judged.

## Measured

2026-10-05, the hook on `origin/main` at `26962b0`, driven with a JSON payload:

| command | guard |
|---|---|
| `sleep 600` | deny -- control |
| `sleep 600; ls &` | **defer** |
| `while true; do sleep 5; done &` | defer -- correct, the loop is the list |

What the `&` covers was driven under
`env -i /opt/homebrew/bin/bash --norc --noprofile -c` (GNU bash 5.3.15), each
printing `$((SECONDS-s))` after `s=$SECONDS`:

| command | seconds |
|---|---|
| `sleep 2; true & echo …` | 2 |
| `sleep 2 && echo x & echo …` | 0 |
| `sleep 2 \| cat & echo …` | 0 |

Found while working Q267 and Q239, whose fixes leave this check as it is.

## Which way it gets built

Treat a trailing `&` as covering the and-or list it ends -- back to the last
`;`, newline or `&` outside any compound command -- rather than the whole
string. The per-segment check has the mirror defect: it marks only the last
segment of `sleep 300 && ls &` backgrounded, and today the whole-command check
is what stops that denying. Narrowing one without the other turns this false
negative into a false positive, so both move together.

## If it is never built

A foreground `sleep`, `watch` or poll written before a backgrounded command
on the same line runs without the guard seeing it, which is the hang the
guard exists to stop. It needs the `&` last on the line, so it is uncommon.
