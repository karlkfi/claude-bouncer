# Reads of bundled skills, sibling scratchpads and Go source all ask

Four read-only trees outside the project root prompt on every read, and the
maintainer approves every one. Measured from 2026-09-25 to 2026-10-25: about 51
asks, mostly in github-actions-gateway. Go stdlib and toolchain source 16,
sibling sessions' scratchpads 17, bundled skills 11, the app's side-session
notes under `~/Library` 7. Each tree re-driven 2026-10-25 against 1.13.0 asks
on a plain `cat`.

## Why each one asks

- **Sibling scratchpads: the exemption is keyed on the wrong directory.** It
  covers sessions sharing this session's `<tmp_root>/<project-slug>`
  (`plugins/workspace-guard/scripts/bash-workspace-guard.py:3553:if is_read and ctx.session_proj_dir \`),
  and Claude Code gives every worktree its own slug. A dispatcher reading a
  worker's scratchpad is in another slug, so the exemption meant for "a
  dispatcher plus its parallel workers" never reaches the case it was written
  for. Driven: a session id under this slug allows, the same path under a
  sibling worktree's slug asks, and so does one under the main checkout's
  slug.
- **Bundled skills** live at `<tmp_root>/bundled-skills/<cc-version>/<hash>/`.
  They are under the Claude temp root but carry no session id, so neither temp
  exemption applies, and they are not under `~/.claude/skills/`
  (`plugins/workspace-guard/scripts/bash-workspace-guard.py:341:for name in ('plugins', 'skills'):`).
  Claude Code itself writes them, on the same trust footing as
  `~/.claude/plugins/`.
- **Go source** is `$(go env GOROOT)/src` (`/usr/local/go/src` here) and the
  toolchain module cache, `~/go/pkg/mod/golang.org/toolchain@*/src`. Vendoring
  is the usual answer for dependency source, and it does not reach the
  standard library.
- **Side-session notes** are
  `~/Library/Application Support/Claude/side-session-notes/<family>/`. The
  desktop app adds this folder to the session as an additional working
  directory, and the guard does not know that. Whether the hook input carries
  the session's additional directories has not been checked.

## Which way it gets built

Read-only defaults in `allowed_read_prefixes`, one per tree, with writes
unchanged:

- Widen the sibling-read exemption from this slug to every slug of the same
  repository. Derive the repository from the slug's path prefix or from git's
  common dir, not from the undocumented slug encoding. Q23's maintainer quote
  is about a peer's *worktree*, not its scratchpad, and the existing exemption
  already reads same-slug scratchpads.
- Add `<tmp_root>/bundled-skills/` beside `claude_code_dirs()`.
- Add the Go toolchain roots only when `go` is on `PATH`, read from
  `go env GOROOT GOMODCACHE` at hook time. If that costs too much per call,
  leave it to `WORKSPACE_GUARD_READ_ALLOW_PREFIXES` and document the line.
- Side-session notes: first find out whether the hook input names additional
  working directories. If it does, honour them for reads. If not, add the
  app's notes root as a default.

This is several changes and splits cleanly: the sibling-slug fix is a bug and
can land alone.

**If never built:** about 51 approved prompts a month, concentrated in the
orchestrated runs this audit set out to quiet.
