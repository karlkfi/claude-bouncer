# Nothing reconciles `make check`'s gate list against what CI runs

`make check` names nine gates. `.github/workflows/tests.yml` re-lists them as
steps, and the two lists are kept in step by hand. Measured 2026-09-09 on the
Q92 branch, they agree — but only because eight are named in both and the ninth
is covered by accident.

`backlog-lint` is the ninth. No CI step runs it. What covers it is
`tests/test_backlog.py`, which re-declares the flags in a Python constant:

`tests/test_backlog.py:24:STRICT = ['--strict', 'blocked-opener',`

against the `Makefile` recipe:

`Makefile:101:--strict blocked-opener --strict deferred-trigger --strict empty-store`

So a fourth `--strict` class added to the `Makefile` leaves CI checking the old
three, and every signal reads green: `make check` runs the new class locally,
the suite passes because it asserts its own list, and the checks list shows a
`shared-parser` job that did run.

## Who it is for

Whoever adds or tightens a gate — which on this store is a recurring task, not a
one-off: Q104, Q107, Q112, Q132 and Q182 each add or move one.

## What happens if it is never built

A gate can be added to `make check` and never run in CI, or tightened locally
and left loose in CI, and nothing reports either. The failure is the one this
repo already spends `path-filter-check.py` and `install-ref-check.py` on — a
check that goes green by not running — arriving through the one door neither of
them watches. Both of those exist because that shape was met here before.

## Which way it gets built

A check that reads `check:`'s prerequisites out of the `Makefile` and asserts
each is reachable from `tests.yml`, in the shape of the two recurrence guards
already in `scripts/`. The `backlog-lint` case wants the narrower half too:
either the CI job runs `make backlog-lint` so there is one list, or the test
reads the flags out of the `Makefile` instead of restating them.

Keep the reason `STRICT` was duplicated in the first place — the comment above
it says the flags live there so a Windows runner can exercise the gate without
`make`. Reading them out of the `Makefile` preserves that; deleting the
constant does not.

**Sized against Q107, not instead of it.** That row moves the gate list into a
registry file to stop every gate-adding PR conflicting on one line. Both touch
the same list and neither fixes the other: a registry that still nothing
compares against CI has this defect unchanged, and a parity check over the
current list leaves the conflict. If Q107 lands first, this check reads the
registry.
