# Pin every action by SHA, and open a channel that keeps the pins current

Measured 2026-08-22 across `.github/workflows/`: 31 `uses:` references, 30 of
them on a mutable tag — `actions/checkout@v4` fifteen times and
`actions/setup-python@v5` fourteen. A tag is a pointer its owner can move, so
every one of those runs whatever the tag points at on the day, in a repository
whose whole subject is refusing to run things unchecked.

The one exception is the reference this row was filed alongside — the
`dorny/paths-filter` pin in `.github/workflows/tests.yml`, given a SHA because a
third-party action deserved one. Pinning one and leaving thirty is the worst of
both: it reads as a convention the repository does not actually have.

**Pinning alone makes the problem quieter, not smaller.** A SHA that nobody
bumps is a dependency frozen at whichever version happened to be current, and a
year later it is a known-CVE runner nobody has looked at. So this is two
changes that only work together:

1. Rewrite every `uses:` to a SHA with the version in a trailing comment, and
   add a gate that fails a mutable ref — one grep over the workflow directory,
   with a test that plants a tag and requires the gate to go red. It belongs
   beside `path-filter-check` and `version-check` in `make check`.
2. Add `.github/dependabot.yml` with the `github-actions` ecosystem, weekly,
   grouped into a single PR. That is the channel that turns a pin from a freeze
   into a reviewed bump, and it is the half that is easy to skip because the
   pinning is the visible work.

The `release-note` check reads a pull request body, so a Dependabot PR needs
either the `## Release note` block answered by template or an exemption; decide
which when the config lands rather than discovering it on the first bump.

**One mechanism deliberately not adopted yet.** A version pinned as a pair — a
tool version plus the checksum of the tarball it downloads — needs a reconciler
that bumps both in lockstep, which Dependabot cannot see. This repository has
no such pin today: every job installs Python through an action and nothing else
is fetched. Revisit if a job ever downloads a release asset.
