# `command -v kubectl` is read as a kubectl invocation

`plugins/prod-guard/scripts/bash-prod-guard.py:264:PLAIN_WRAPPERS = frozenset({'command', 'nohup', 'time', 'builtin', 'exec'})`
lists `command` as a wrapper, and
`plugins/prod-guard/scripts/bash-prod-guard.py:522:elif head in PLAIN_WRAPPERS:`
strips it to reach the real command. That is right for `command kubectl delete`,
which does run kubectl, and wrong for `command -v`, which only reports a path
and executes nothing.

The remaining operands then become the verb, so a probe for three binaries reads
as `kubectl` with verb `kubeconform` — absent from the read-only table, so
mutating, so denied against the ambient context.

## Measured

2026-08-31, prod-guard 2.5.2, repo tree, ambient context
`gke_actions-gateway-dogfood_us-east1-b_gag-dogfood`:

| command | verdict |
|---|---|
| `command -v kubectl` | allow |
| `command -v kubectl kubeconform` | **deny** |
| `command -v kubectl kubeconform yamllint` | **deny** |
| `command kubectl delete ns foo` | deny — correct |
| `which kubectl` | allow |
| `type kubectl` | allow |

Arity is the trigger, which is what makes it easy to miss: the one-argument form
that anyone would reach for while testing is the form that passes. The denial
observed in the wild was `command -v kubectl kubeconform yamllint 2>&1`, whose
reason named a command nobody wrote —
`` `kubectl kubeconform yamllint 2` ``, the redirect's digit included.

## Who it is for

A session checking which tools are installed before doing anything — the
read-only probe that precedes the risky work. It is denied, and the denial's
suggested fix (`kubectl --context <ctx>`) cannot be applied, because there is
no kubectl call to pin. The only exits are dropping to one binary per call or
`PROD_GUARD_OVERRIDE`, and an override reflexively reached for on a read-only
probe is the habit the override exists to stay out of.

## Which way it gets built

Treat `command` as a wrapper only when no `-v` / `-V` operand precedes the
command name; with one, the whole call is a lookup and prod-guard has no opinion
on it. `which` and `type` are already handled correctly and are the fixtures to
match against.

## If it is never built

A false deny on a read-only probe, with a fix line that cannot be followed —
the shape most likely to teach a session that this guard's denials are noise to
route around.
