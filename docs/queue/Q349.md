# A command ending in a lone backslash is judged by no guard

bash reads a backslash at the very end of its input as a literal character, so
`rm /etc/probe-target \` runs `rm` with a last argument of `\`. Python's `shlex`
raises `No escaped character` on the same text, and every guard treats a lex
error as "defer". The raise comes out of the shared lexer, from
`lib/bouncer_parse.py:1627:            token = super().read_token()`, inside
`QuoteTrackingLexer.read_token`, so all five guards defer on it.

A backtick body is the way this was found. `_unescape_backticks` turns a
trailing `\\` in the body into one `\`, as bash does, so the body handed to the
lexer ends in a lone backslash. That covers the first three shapes this row was
filed with, the five-backslash shape noted on #314, and the same body inside
double quotes:

| command, with `P` standing for each guard's trap | prod | ws | exit | branch | fg |
|---|---|---|---|---|---|
| `P` -- control | deny | ask | deny | ask | deny |
| `P \` | **defer** | **defer** | **defer** | **defer** | **defer** |
| `P # \` -- the backslash is inside a comment | deny | ask | deny | **defer** | deny |
| ``echo \\`P\\` `` | **defer** | **defer** | **defer** | defer | **defer** |
| ``echo `P\\` `` -- trailing pair only | **defer** | **defer** | **defer** | defer | **defer** |
| ``echo \\`P` `` -- leading pair only | deny | ask | deny | defer | deny |
| ``echo "`P\\`" `` | **defer** | **defer** | **defer** | defer | **defer** |
| ``bash -c "echo \\`P\\`"`` -- the parent runs the backtick | **defer** | **defer** | **defer** | defer | **defer** |
| the same with 6 backslashes | **defer** | **defer** | **defer** | defer | **defer** |
| the same with 5 -- the child runs it | **defer** | **defer** | defer | defer | **defer** |
| `echo $(P \\)` -- the pair survives in `$(…)` | deny | ask | deny | ask | deny |

Measured 2026-11-17 on `origin/main` at `a3a43e4d`. Each guard's hook script ran
as a subprocess with a hook payload and a fixture `$HOME` whose current kube
context was `kind-ci`; branch-guard ran in a fresh repository on `main`. The
traps were `kubectl --context gke_acme_prod-us delete ns x`, `rm
/etc/probe-target`, `make check | tail`, `git commit -m x` and `sleep 600`. A
`sys.settrace` wrapper logged every `ValueError` raised in `read_token` and every
string passed to a `shlex` lexer, and each bold defer logged `No escaped
character` on a string ending in a lone backslash. bash 5.3.15 (`env -i
/opt/homebrew/bin/bash --norc --noprofile -c`, with `echo RAN` as `P`) printed
`RAN` for every row.

The leading-pair and `$(…)` rows are the controls that pin the cause: the same
shapes without a lone trailing backslash in the lexed text are judged. The
5-backslash row's exit-status-guard defer is not this defect, since that guard
does not read a `bash -c` body at all (its README's limitations section says
so). branch-guard's defer on every backtick row is not this one either: it never
reads a backtick body, which is Q380. Its defer on the comment row is this
defect, reached through Q381's gap: branch-guard never calls `strip_comments`,
so the comment's text reaches the lexer, which the other four guards strip
first. Either fix closes that row. Found by the stream-A reviewer on #354.

## Which way it gets built

Treat a backslash at the end of the input as a literal, the way bash does,
rather than raising. One place does it for all five guards: in
`QuoteTrackingLexer`, before the lexer reads the input, or by catching the
`No escaped character` error and lexing again with the final `\` doubled. It must
not change what a backslash before a newline does. In four guards
`strip_comments` has already folded a continuation by the time the lexer runs.
branch-guard calls no `strip_comments` until Q381 lands, so there a
backslash-newline still reaches the lexer. Add the shapes in
the table as fixtures in each guard's suite. The unbalanced-quote defer stays
as it is: bash rejects that input too.

## If it is never built

Any guarded command runs unjudged if it ends in a lone backslash, written
directly or produced by a backtick body ending in `\\`. Agents do not write it
by accident: none of the 261,055 Bash commands in this machine's session
transcripts on 2026-11-17 ends in an odd run of backslashes (a direct check of
each command's last characters, in the first of two passes over those
transcripts; Q378's figure comes from the second pass, taken later as the
transcripts grew), so the exposure is
a command written or generated to slip past. No profile label: the cost is the
same whenever it is met. It keeps its rank: it reaches all five guards and is
the smallest of the rows split from it.

**The other shapes this row first carried belong elsewhere.**
``eval "$(echo \`P\`)"`` runs what the substitution prints, which is Q279's
command word the guard cannot resolve. The here-string shapes,
``bash <<< "echo \`P\`"`` and `bash <<< "\$X P"`, defer because no guard reads a
script fed to a shell on stdin, which is Q378. The single-quoted continuation,
`bash -c 'echo x; \` newline `P'`, is two defects: prod-guard and
foreground-guard rewrite the newline into a `;` the child reads as a literal
(Q379), and branch-guard never joins a continuation (Q381). workspace-guard
already asks on it.
