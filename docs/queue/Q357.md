# workspace-guard reads no bash 5.3 ${ list; } substitution

bash 5.3 added `${ list; }` and `${| list; }`, which run `list` in the
current shell and substitute its output (or `$REPLY`). The shared lexer has
no reading of either, so a reader in the body is never judged, and a `cd` in
the body moves every later command where the tracker cannot see it. Q356
covers the `eval`, `source` and trap half of that, which needed no lexer
change; this is the half that does.

Driven 2026-11-09 on c1e1f81 through workspace-guard, with `OUT` an outside
directory holding an `x` and the workspace holding its own `x`. bash is
`env -i /opt/homebrew/bin/bash --norc --noprofile -c`, 5.3.15(1)-release:

| Command | workspace-guard | bash reads |
|---|---|---|
| `echo ${ cd OUT; }; cat x` | allow | `OUT/x` |
| `echo "${ cd OUT; }"; cat x` | allow | `OUT/x` |
| `echo ${\| cd OUT; }; cat x` | allow | `OUT/x` |
| `x=${ cd OUT; }; cat x` | ask | `OUT/x` |
| `echo ${ cat OUT/x; }` | defer | `OUT/x` |

The `x=` row asks only by accident, the way spill-guard found for the same
shape: the split leaves `cd OUT` in command position after the `x=${`
prefix and the tracker follows it.

The fix has two halves. The scanner has to step over a funsub body as a
list of its own, the way `_scan_dollar_paren` does for `$( )`, so its
readers are judged. And the tracker has to treat the body's `cd` as moving
the caller, unlike a `$( )` body's. A funsub is recognised by an unescaped
`${` followed by a blank, a newline or `|`. That is how spill-guard's
`opensFunsub` matches it (karlkfi/claude-spill-guard#265, its Q228, with
the lexing half filed there as Q261).

Not measured: the other four guards. The lexer is shared, so whatever they
do with a substitution body they do not see one here either.
