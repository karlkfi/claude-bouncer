# prod-guard reads an empty --context as a name, not the current context

kubectl reads an empty `--context` as no context at all and uses the kubeconfig's current one, but prod-guard classifies `''` as a context name.
That name matches no pattern, so the command asks, where the same command without the flag denies.
When the current context is production, a user who approves the prompt mutates production.

Found by rev-prod-b on the Q385 pull request ([comment](https://github.com/karlkfi/claude-bouncer/pull/396#issuecomment-7227370296)), and re-measured 2026-11-27 on `main` at `9d77fa95`.
Pointed at a synthetic kubeconfig whose current context is `gke_acme_prod-us`, `kubectl config view --minify` (v1.36.3) chose `gke_acme_prod-us` for `--context=` and for `--context ''`, and `kind-ci` for `--context=kind-ci`.
That is the loader's choice, read offline; no mutating verb was run.
Through the end-to-end hook with the fixture `$HOME`, in every permission mode but `bypassPermissions`:

| command | current context `gke_acme_prod-us` | current context `kind-ci` |
|---|---|---|
| `kubectl delete pod x` (control) | deny | deny |
| `kubectl --context= delete pod x` | ask | ask |
| `kubectl --context '' delete pod x` | ask | ask |
| `kubectl --context="" delete pod x` | ask | ask |
| `Z=; kubectl --context=$Z delete pod x` | ask | ask |
| `export Z=; bash -c 'kubectl --context=$Z delete pod x'` | ask | ask |
| `env Z= bash -c 'kubectl --context=$Z delete pod x'` | ask | ask |
| `export Z=kind-ci; env -u Z bash -c 'kubectl --context=$Z delete pod x'` | ask | ask |

The control denies under `kind-ci` on the ambient-context rule, since a parallel session can repoint the current context.
The ask's reason advises adding a nonprod pattern that matches `''`, a name kubectl never looks up.

## Which way it gets built

Where the guard knows the value is empty, judge the command as if the flag were absent, so it gets the missing flag's decision and reason: a production current context denies on its name, and any other denies on the ambient-context rule.
A value the guard cannot resolve, such as an ambient `$Z`, keeps asking.
The context flags of the other covered tools were not measured.

## If it is never built

Each shape prompts where a missing flag refuses, and an approved prompt runs against whatever the current context is at the time.
