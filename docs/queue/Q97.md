# Deny a write into another session's scratchpad, and name the right one

A session that writes to `<tmp_root>/<slug>/<other-uuid>/scratchpad/x` gets an
`ask` carrying no correction. It is the last shape in this guard that still
reaches the operator as a prompt, and the reason it repeats is the verdict: an
approved `ask` never reaches the model, so the stale path stays in context and
the next write prompts again.

Measured 2026-08-22 over 30 days of local transcripts: 41 such prompts, every
one a write, and 40 of them naming a session uuid that is not the running
session's. One session in `claude-skills` took nine of them in ninety minutes,
all on the same path. The count is 0–5/day until 2026-08-16, then 15, then 40 on
2026-08-21 — it tracks parallel-dispatch days, where one worktree accumulates
several session dirs.

**The stale path is honestly come by.** A resume or a compaction mints a new
session id and a new scratchpad dir under the same project slug, while the path
already in the model's context still names the old one. The guard cannot tell
that apart from a genuine cross-session write, and should not try to.

Every other live shape here already denies. Probed against 1.10.0 with a real
session id: `${f%%:*}` into a scratchpad path, `$(basename …)` in a redirect
target, and `t=$(date +%s)` in a filename all deny; a glob loop, a
literal-assigned variable, and a sibling-session *read* all allow. Only the
cross-session write asks, which makes it the outlier rather than the rule.

So: return a category of its own from
`plugins/workspace-guard/scripts/bash-workspace-guard.py:2680:and path_at_or_under(rp, ctx.session_proj_dir)`
for the write case that exemption deliberately excludes, add it to the
`cross_hit` set at
`plugins/workspace-guard/scripts/bash-workspace-guard.py:2740:cross_hit = bool(cats & {'sibling', 'kill'})`
so it denies unless `WORKSPACE_GUARD_OVERRIDE` is set, and give it a hint
carrying this session's own scratchpad — `session_scratchpad` at
`plugins/workspace-guard/scripts/bash-workspace-guard.py:679:def session_scratchpad(session_id, session_proj_dir)`
already computes it, and the sibling-checkout deny at
`plugins/workspace-guard/scripts/bash-workspace-guard.py:2689:return ('sibling', {'root': root, 'branch': branch,`
is the precedent for handing back a corrected path.

Two things not to break. The read exemption stays: a dispatcher tailing a
worker's output is the case it was added for. And `session_scratchpad` returns
`None` when the dir is not there, so the hint has to fall back to the repo-local
scratch dir rather than steering at a path that does not exist.

`friction-report.py` categorises by reason text, so a new category needs its
pattern there too or it buckets as `other` — the same drift Q91 is about, one
guard over.
