# Re-vendor `queue.py`, and say what watches it

`scripts/queue.py` is vendored from the `session-backlog` skill, and the copy
here is one feature behind: the installed skill counts the citations an
`exhibit:` marker held back and adds `--show-exhibits` to name them, while this
copy prints
`scripts/queue.py:673:print(f"queue: {len(items)} item(s) OK")`
unconditionally. Measured 2026-08-22 by diffing the two — 34 lines, all of that
one change.

The consequence is the exact failure the upstream change closes. A waiver is
only self-policing if a run discloses it, so under this copy a store carrying a
silenced citation reads identically to one carrying none, and `make
backlog-lint` is the gate every backlog commit goes through.

**Naming what watches it is the other half.** `lib/bouncer_parse.py` has
`make sync-check`, which fails when a vendored copy drifts from the root, and
the obvious move is to want the same thing here. It is not available: the
source is `karlkfi/claude-skills` on the workstation, outside this repository
and absent from a CI checkout, so nothing here can compare against it. Say so
next to the vendoring note in
[maintaining-backlog.md](../development/maintaining-backlog.md) rather than
leaving a reader to infer a gate that cannot exist — the two vendored files
look alike and only one of them is guarded.
