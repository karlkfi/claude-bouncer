# Escalate suppression in modes that pre-approve

The hook has two ways of saying nothing. One is that it found nothing to catch.
The other is that it read a string it admits it cannot parse — an inline `-c`
body, a heredoc, an interpreter handed code — and declines to vouch. Both come
out as defer, and defer *runs* the command in `auto`, `acceptEdits` and
`bypassPermissions` ([the matrix](../../plugins/workspace-guard/docs/permission-modes.md)).
The source says so at the site:
`plugins/workspace-guard/scripts/bash-workspace-guard.py:3576:# block in EVERY permission mode, while a suppression only`.

**Who is worse off.** Anyone running those three modes, where the same page
states the plugin's job as downgrading an auto-approval the operator has already
opted into. The one class of string the guard has *declared* it cannot read is
the class it stays silent on, so the guard is quietest exactly where quiet means
yes.

**The number this row carried is real and is not what the row said it was.**
1,657 is `design.md`'s cost of the interpreter suppression — commands that lose a
blanket `allow`, 4.49% of a 52,251-command corpus
(`plugins/workspace-guard/docs/design.md:120:brings the cost to 1,657 commands (4.49%)`).
It counts withheld allows, not heredocs, and the suppressing shapes there are
inline `-c`/`-e`, a heredoc or stdin body, and a script resolving outside the
root. "Most routine heredocs" was unattributed; measure the split before ranking
on it.

**Which way it gets built.** The narrowing this row asks for is a *mode*
condition, not a narrower command signal, and the hook already reads the field —
`permission_mode` appears at four sites and every one tests `bypassPermissions`
alone. Escalate a suppression only where defer is a silent yes, and leave
`manual`, `dontAsk` and `plan` deferring, where defer already blocks and the
change buys nothing. foreground-guard is the precedent that a mode set is a
legitimate condition and that its membership follows the job rather than the
name: `plugins/foreground-guard/scripts/bash-foreground-guard.py:441:UNATTENDED_MODES = frozenset({'dontAsk', 'bypassPermissions'})`
answers a different question and excludes `auto` on purpose.

**Phase it, because the halves cost differently.** Under `bypassPermissions`
nobody is at a prompt, so `ask` and `deny` both block and an escalation charges
no one — that half is `S`. Under `auto` and `acceptEdits` an escalation reaches a
person, so it spends up to 4.49% of allows on whoever is watching, and needs the
volume measured on a live workstation rather than against the corpus. One
condition closes both, so this stays one item.

`M` holds — the code is small and the measurement is not — and so does rank
`a6`: it is the only security item above the middle of the queue, and the phasing
puts a no-friction half within reach first.
