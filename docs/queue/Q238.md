# Bash time -p leaves -p as the command head

bash's `time` keyword takes one option, `-p`, and `strip_sh_keywords` peels
the keyword and stops, so `-p` becomes the command head and the lookup behind
it misses. Driven on the Q219 branch, `cwd` set to a scratch workspace:

| command | decision |
|---|---|
| `time cat /q219-x` | ask |
| `time -p cat /q219-x` | **(silent)** |

On bash 5.3.15, `time -p cat f` reads `f` and prints POSIX-format timings.

The keyword loop is
`lib/bouncer_parse.py:1489:    while i < len(tokens) and is_reserved_word(tokens[i]):`,
so the fix lands in the shared parser and reaches every guard that peels
keywords. Only workspace-guard was driven here. Q234, filed on the Q222 branch
(#185), drove the other three and found exit-status-guard silent as well, with
prod-guard and foreground-guard already reading through it. It is this defect
seen from exit-status-guard, so whichever row reaches `main` second is merged
into the other rather than built twice. Q234 also measured that bash takes
`time --` the same way. Q219's wrapper peel cannot take it: the keyword is
gone before the peel runs, and a bare `-p` is not a wrapper.

## If it is never built

Anything behind `time -p` is unread by workspace-guard. How often sessions
write it is not measured. Flat cost of delay.
