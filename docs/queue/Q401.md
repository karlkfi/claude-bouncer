# Judge a known shell subset and deny the rest with a rewrite

Each guard reads bash with a Python lexer of its own over `lib/`, and most
recent fixes correct a spot where that lexer and bash read one string
differently: `case` after `!` (#322), `$((` (#348), bash 5.3 funsubs (#355), a
`=~` operand with a trailing comment (#360), quoting glued to `$(` (#361). The
grammar is large and changes between bash versions, so matching it construct by
construct does not converge, and recursion into `-c` bodies re-lexes the same
text under other quoting rules, which multiplies the surface.

The alternative is to define a subset the guards read with confidence — plain
commands, pipelines, `&&`/`||`/`;` lists, ordinary quoting, simple
substitutions, literal `-c` bodies — and to deny anything outside it with a
rewrite the model applies ("split this into separate calls", "write it as a
script file"). Each new construct then costs a line in a deny list rather than a
lexer change, and a misread construct can no longer reach an `allow`.

Two routes look closed: bash prints no parse tree (`bash -n` checks syntax
only), and the Python bash parsers are either incomplete (bashlex) or need a
native binary (tree-sitter), against the stdlib-only rule.

**Measure:** the share of real commands that fall outside a candidate subset,
which decides where its boundary goes. On 2026-11-17 a replay of 4,000 commands
sampled from this machine's last 30 days of transcripts through all five guards
found none of the shapes this release's notes list as new asks (26-deep `$(`
nesting, `time -- -p FOO[…]`, funsubs). That bounds the exotic tail and says
nothing about a subset's edge, where the ordinary idioms (heredocs, `for`
loops, `$(…)` in arguments, `trap`) sit. Run the corpus through `lib`'s `lex`,
classify each command against two or three candidate subsets, and report the
deny rate of each. The result settles whether this is a redesign or a row of
targeted denies.
