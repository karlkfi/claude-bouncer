# A comment inside a `$( )` substitution ends it at the wrong place

Bash reads a comment inside `$( )` as a comment, so a `)` or `'` in it is
text. `_scan_dollar_paren` has no comment handling: it closes the substitution
at a `)` in the comment, and an apostrophe there opens a quoted run that never
closes, so no substitution is returned at all. Either way the command on the
next line is outside what the guard judges.

Found by the independent review of the Q196 pull request. Re-driven 2026-10-01
through the hook (fixture `$HOME`, ambient context `gke_acme_prod-us`) at
`b27be8d` and at the Q196 head `1802d08`. That bash runs line 2 was driven
under `env -i /opt/homebrew/bin/bash --norc --noprofile -c` (5.3.15) with a
payload absent from `PATH`, which bash reports as `command not found`:

| command | bash 5.3 | main | Q196 head |
|---|---|---|---|
| `kubectl delete ns payments` | runs | deny -- control | deny -- control |
| `echo "$(# )` newline `kubectl delete ns payments)"` | runs line 2 | **defer** | **defer** |
| `echo "$(echo a # )` newline `kubectl delete ns payments)"` | runs line 2 | **defer** | **defer** |
| `echo "$(# don't` newline `kubectl delete ns payments)"` | runs line 2 | **defer** | **defer** |
| `x=$(# )` newline `kubectl delete ns payments)` | runs line 2 | **defer** | deny |
| `echo $(# )` newline `kubectl delete ns payments)` | runs line 2 | **defer** | deny |

The Q196 fix catches the two unquoted shapes, because tokenizing the rest of
the line still reaches the command. Inside double quotes everything after the
early close is one quoted word, so nothing reaches it. A comment with no `)`
or `'` in it, such as `"$(# c` newline `kubectl …)"`, is Q224's mechanism in
`tokenize` rather than this one, and Q224's fix does not reach the scanner.

## Which way it gets built

In `_scan_dollar_paren`, step over a comment to its newline (keeping the
newline, which sets command position), using the word-start rule
`strip_comments` already applies through `COMMENT_PRECEDERS`. Check that `$#`,
`${#x}` and a mid-word `a#)` still read as they do today, since none of those
starts a comment. On main prod-guard does not call this scanner; the Q196 fix
adds the call. exit-status-guard, branch-guard and workspace-guard already
call `command_substitutions`, so probe each on the shapes above before the
fixture list is final.

## If it is never built

A multi-line `$( )` with a comment above the command is ordinary agent output,
and a parenthesis or an apostrophe in that comment (`# (see below)`,
`# don't retry`) is enough to hide a mutating command written after it.
