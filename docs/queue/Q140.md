# Exempt inert reads under Claude's own home

**Event:** a re-run of the friction report still shows more than roughly 3 asks
per session against `~/.claude` and the Claude install dir. Below that, this row
stays closed — see the measurement.

`Q139` shipped 2026-09-03 in #85, so the first half of the trigger has fired and
the second is not yet measurable. The re-run waits on a week of post-ship
sessions — taken before roughly 2026-09-10 the report is still dominated by the
pre-`Q139` corpus the table below was read from, and would answer about the
state this row was deferred against rather than the one it is waiting on.

Deferred 2026-08-31, before implementation, because `Q139` covers most of what
it was filed for and the remainder is wanted rather than tolerated.

## Why it is not worth building

`plugins/workspace-guard/scripts/bash-workspace-guard.py:312:def claude_code_dirs():`
read-exempts `~/.claude/plugins/` and `~/.claude/skills/`. Reads of
`~/.claude/CLAUDE.md`, `scripts/`, `settings.json` and the installed binary
prompt on every call, 61 times in the week to 2026-08-31, all approved. This row
proposed extending the exemption.

`Q139` removes the repetition instead, and repetition is nearly all of the
count:

| | asks in the week | prompts once `Q139` ships |
|---|---|---|
| all guards | 244 | 102 |
| this row's subset | 61 | 24 |

The 24 fall across 21 sessions — 1.14 per session. So after `Q139` a session
that touches Claude's own config is asked about it approximately once, and this
row's remaining value is taking that one prompt to zero.

The maintainer's judgement, 2026-08-31, is that the one prompt is the point:
"if I can approve a session to edit its own config, that's probably good enough
to reduce the number of asks and still defend against a rogue session every now
and then. Usually when a session is editing claude settings it's because I told
it to or approved a retro action already." A standing exemption removes that
checkpoint for about 22 prompts a week.

## What this row established, which outlives it

`settings.json` was excluded from the proposed exemption and would stay excluded
if this is ever revived. Its `env` block is injected into every Bash tool
process — verified 2026-08-31 by reading the values back from inside a tool call
— so its contents reach the model and the on-disk transcript through any command
that prints the environment. The same process carried 58 variables including
`CLAUDE_CODE_MESSAGING_TOKEN`, set by the harness rather than by any config,
against 2 in settings.json itself.

That finding is the larger one and it is not this row's to fix: the process
environment is unguarded by `env`, `printenv`, `export -p` and the interpreter
equivalents, all of which return silent-allow against workspace-guard 1.11.0. It
was routed to `karlkfi/claude-spill-guard`, which owns egress, as a deny
carrying a redacted alternative.

## If the trigger never fires

Nothing is lost. The prompts this row would have removed are the ones the
maintainer wants to keep seeing, once per session.
