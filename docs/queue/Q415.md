# A single quote in a bare (( or $[ hides the substitution in it

`(( '$(echo RAN >&2; echo 1)' ))` runs the substitution, and so does `echo $[ '$(echo RAN >&2; echo 1)' ]`.
Under `env -i /opt/homebrew/bin/bash --norc --noprofile -c` (5.3.15) both print `RAN` and then an arithmetic error about `'1'`, so a `'` inside arithmetic is text and does not quote what follows it.

`command_substitutions` walks the body of a bare `((` and of a `$[` with its quote rules on, so it reads the `'` as opening a single-quoted run and returns no body for either command. Without the quotes it does find them: `(( $(echo RAN) ))` and `echo $[ $(echo RAN) ]` each return `['echo RAN']`.
Measured with Q362's change in place; `main` reads both the same way.

## Which way it gets built

`command_substitutions` reads a `$((…))` body with quoting off, the way bash expands one, by pushing an arithmetic region (Q362). A bare `((` and a `$[` are the same kind of body and likely take the same region.
`_comment_free_end` is where both spans are found today.
Before reusing it, measure whether its `((` test, which does not check command position, also fires on text bash reads as two parens: a `<((…) )` process substitution, for instance.
Pin both commands above with a parser test that fails on `main`.

## If it is never built

A command written inside quotes inside an arithmetic command runs past every guard that reads substitution bodies from `command_substitutions`.
Nobody writes the shape by accident.
