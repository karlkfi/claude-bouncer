# A parse-only `bash -n` run of a registered slow script is denied

Reported from github-actions-gateway 2026-08-29, where `bash -n
scripts/dogfood/validate-release.sh` — a syntax check that reads the file and
exits without executing a line of it — was denied as a foreground run of a
gate registered at 3600000 ms. Reproduced here the same day against this tree,
which is what makes it the guard's defect rather than that repo's regex: with
the README's own recommended registration, `{"scripts/gate\\.sh": 3600000}`,
the hook returns `deny` for `bash -n scripts/gate.sh`, `bash --norc -n`,
`bash -en`, `bash -n --`, `sh -n` and `zsh -n`, and for `bash -n -c
'scripts/gate.sh --all'`. `bash -x scripts/gate.sh` denies too and should —
that one runs.

The site is Class B's reducer, which peels the interpreter and then every
leading option without reading any of them
(`plugins/foreground-guard/scripts/bash-foreground-guard.py:677:the script is the command`),
so `-n` is discarded beside `-x` and the two invocations become the same argv.
Class A is untouched: its shell branch recurses into a `-c` body and otherwise
drops the segment, so no poll matcher ever sees the script.

**Who is worse off.** The agent that has just edited a slow gate script and
wants to know it parses. The command is instant, the guard says it needs an
hour, and the reason names a `timeout:` and a `run_in_background: true` that
would each be absurd — so the natural response is a
`FOREGROUND_GUARD_OVERRIDE=` prefix. That is the cost worth the row rather
than the wait: this guard's asks are rare by design, and an override written
on a command that could never block teaches the reflex on the one guard whose
value is that its findings are always real. Rate is low — it fires when
somebody syntax-checks a registered script, which is a habit some sessions
have and most do not.

**Which way it gets built.** In the reducer, not in the pattern: read the
interpreter's options while peeling them and drop the segment when they carry
`-n`, including inside a combined cluster (`-en`), and including the `-c`
form, since a body that is parsed and not run cannot be slow either. Leave
`-o noexec` alone unless it falls out for free — it is silent today by
accident, the `-o` peel leaving `noexec` as the command word, which is a
separate false negative and not this row's.

Assert both directions in `SlowCommandPositionTests`, where the neighbouring
case already stands
(`plugins/foreground-guard/tests/test_foreground_guard.py:645:assert_runs("bash -x scripts/gate.sh")`):
`bash -n scripts/gate.sh` must defer, a bare `bash scripts/gate.sh` must still
deny.

**If it is never built,** the guard keeps denying a class of command that
cannot run, and every repo registering a script gate inherits it — the
registration in the README is the one that reproduces, so there is no
configuration a repo could have written to avoid this.
