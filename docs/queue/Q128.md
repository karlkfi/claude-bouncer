# The friction report lists variable names as pattern-gap candidates

The "Unclassified targets" section is instructions to act on: both the section
header and the skill prompt above it say to vet each entry and add a `nonprod`
pattern for the ones that are not production. A variable name is never a valid
entry there. Measured 2026-08-24 over a 365-day window, `$CTX` was the
second-ranked unclassified target at 16 prompts, and a `nonprod` pattern
matching `$CTX` would classify every command holding its context in that
variable as non-production -- including one holding a production context.

The hook is right about these, so the defect is entirely in the report.
`targets_of` pulls the single-quoted target out of the hook's own reason, and
the hook does resolve a literal assignment made in the same command string:
probed 2026-08-24 against a temp HOME, `C=prod-us; kubectl --context $C delete
pod x` denies, as do the inline-prefix and `${C}` forms. A bare `$CTX` reaches
the reason only when the assignment happened in an earlier Bash call the hook
never saw, which is the case where unknown is the correct classification.

`targets_of` already drops `<...>` placeholders on the grounds that an
unresolved value has nothing to rank, and a `$`-prefixed target has nothing to
rank for the same reason -- so the fix is to exclude it from `unknown_targets`
there. Leaving it in the "Top targets" ranking is defensible, since that
section measures repeated friction rather than soliciting a config edit.
