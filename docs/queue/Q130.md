# Stop the README screenshot demo grepping the real `/etc/passwd`

`plugins/workspace-guard/scripts/capture-prompt-screenshot.sh:101:Run this bash command verbatim and then stop`
launches Claude Code with a prompt asking it to run `grep root /etc/passwd`, to
shoot `docs/img/ask-prompt.png` for the plugin README. That is the hand-exercise
`plugins/workspace-guard/CLAUDE.md:79:Never use real outside-workspace paths`
forbids, in the one place in the tree where the risk it names is live: the guard
is the thing under test, so an erroneous `allow` runs the command, and the frame
being captured is the one the README embeds.

Nothing has leaked. The shipped image shows the prompt with the command unrun,
which is what the script's own instructions ask for. The exposure is conditional
on the guard failing at the moment someone re-shoots.

**Why it is not part of Q82.** The 47 real paths there are fixture strings that
nothing executes and that rename mechanically. This one changes what the demo
does, so the image goes stale —
`docs/development/rendering-images.md:30:**Not generated:**` records that
`ask-prompt.png` has no SVG master and is re-shot by hand, on a Mac with Screen
Recording and Accessibility granted. That is a person at a keyboard, not a
worker.

**Which way it gets built.** Point the demo at a synthetic outside-workspace path
— `grep root /etc/q130-fake-target` keeps `/etc` and the same `outside` verdict —
and change the script now, so whoever runs it next gets the safe command. Do not
re-shoot for this alone: the image already shows Claude Code 2.1.159 and Opus
4.8, so fold the new command into the next reshoot the prompt UI forces, and say
in the PR that the asset is knowingly stale.

**If it is never built,** the plugin's own security rule has exactly one
counter-example in the tree, and it is the one that executes.
