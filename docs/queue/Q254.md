# strip_comments reads a # inside backticks or ${...} as a comment

`strip_comments` starts a comment at an unquoted `#` after whitespace or an
operator, and it tracks single and double quotes only. In bash, a `#` inside a
backtick substitution ends at the closing backtick, and a `#` inside `${...}`
is not a comment at all. `strip_comments` runs to the end of the line in both
cases, taking the rest of the command with it.

Found by the independent review of the Q224 pull request. Driven 2026-10-04 on
`origin/main` at `337decb`. That bash runs line 2 was driven under
`env -i "$(command -v bash)" --norc --noprofile -c` (5.3.15) with `echo RAN`:

| command | bash | exit-status-guard |
|---|---|---|
| `make check \| tail -5` | -- | deny -- control |
| ``echo `true # c` ; make check \| tail -5`` | runs it | **defer** |
| `echo ${x:- #} ; make check \| tail -5` | runs it | **defer** |

prod-guard defers on `` echo ${x:- #} ; kubectl --context gke_acme_prod-us delete ns payments ``, the same shape. The Q224 pull request avoids the backtick
case inside prod-guard by masking every substitution while comments are
stripped. That leaves `${...}` open and leaves the shared function unfixed.
workspace-guard calls `strip_comments` the same way and was not probed.

## Which way it gets built

Teach `strip_comments` that a `#` inside a backtick substitution ends at the
closing backtick, and that `${` opens a region where `#` is text up to the
matching `}`. Check that `$#`, `${#x}` and a mid-word `a#b` still read as they
do now. Q230 is the comment half of the `$( )` scanner, a different function.
Q225 is the `$'…'` quoting this function also lacks.

## If it is never built

One `${x:- #}`, or one comment inside backticks, hides the rest of the line
from every guard that strips comments this way.
