# workspace-guard reads a deno or bun subcommand as the script

`deno` and `bun` take a subcommand before the script, and `interp_code_source` reads that subcommand as the script, so the in-workspace word vouches and the real script, or the inline code, is never read.
Measured on `origin/main` at `c0bc0235`, with Q402's option walk applied, which leaves both unchanged because neither command has an option to walk:

| command | verdict |
|---|---|
| `cat in.txt; deno run /opt/q8-fake-target/t.ts` | allow |
| `cat in.txt; deno eval 'console.log(1)'` | allow |

Neither interpreter appeared in this machine's 30-day transcript corpus (43,989 commands with an interpreter and an option), so the bite rate is near zero here.
Next step: give the two rows in `INTERP_OPTIONS` their subcommands (`run`, `test`, `eval`, `x`, …) and read the script, or the code, from the word after one; a subcommand the row does not name should withhold the `allow`.
