# A quoted word is read as an assignment where bash runs a command

`'SP=/x'` is not an assignment. Bash strips the quotes after deciding what the
word is, so it looks for a program literally named `SP=/x`, fails, and leaves
`SP` at whatever the environment held. Every assignment reader in this
repository sees the post-shlex token, where the quotes are already gone, and
reads it as an assignment -- so the guards act on a variable bash never set,
and on a break-glass prefix bash never applied.

The test itself is quote-blind by construction
(`lib/bouncer_parse.py:42:ASSIGNMENT_RE = re.compile(`), and every consumer
feeds it tokens rather than raw text: workspace-guard's variable tracker
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:1402:if ASSIGNMENT_RE.match(t):`),
its break-glass reader
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:925:if not ASSIGNMENT_RE.match(tok):`),
branch-guard's
(`plugins/branch-guard/hooks/branch-guard.py:1861:if not ASSIGNMENT_RE.match(tok):`),
foreground-guard's
(`plugins/foreground-guard/scripts/bash-foreground-guard.py:353:elif ASSIGNMENT_RE.match(argv[0]):`),
and the shared command-head strip all five run
(`lib/bouncer_parse.py:775:while i < len(tokens) and ASSIGNMENT_RE.match(tokens[i]):`).

## Measured

2026-09-07, against the hooks at 46ede93, project root `/Users/karl/probe-proj`.
Bash's own reading confirmed with `bash -c "'SP=/x'; echo \"[\$SP]\""`, which
prints `bash: line 1: SP=/x: No such file or directory` then `[]`.

**The variable, and the sharp end.** With `SP` unset in the environment, bash
opens `/f`:

| command | verdict | path named |
|---|---|---|
| `SP=/Users/karl/outside; cat $SP/f` | ask | `/Users/karl/outside/f` |
| `'SP=/Users/karl/outside'; cat $SP/f` | ask | `/Users/karl/outside/f` |
| `'SP=/Users/karl/probe-proj'; cat $SP/f` | **allow** | -- |
| `"SP=/Users/karl/probe-proj"; cat $SP/f` | **allow** | -- |
| `cat /f` (what bash actually opens, in all four) | ask | `/f` |

Rows 3 and 4 are the ones worth the row. `allow` speaks for the whole string
and takes it past the user's own permission settings, and it is emitted here on
the strength of a value bash never assigned; the read bash performs is one this
same hook prompts on when written plainly. Row 2 is the same defect pointing
the safe way -- a prompt naming a path nothing opens.

**The break-glass.** `command_override` returns a reason from a quoted prefix:

```
WORKSPACE_GUARD_OVERRIDE=why cat x   -> 'why'
'WORKSPACE_GUARD_OVERRIDE=why' cat x -> 'why'
"WORKSPACE_GUARD_OVERRIDE=why" cat x -> 'why'
```

End to end in exit-status-guard, whose override is not gated on anything else,
so the downgrade is visible in the verdict:

| command | verdict |
|---|---|
| `make check \| tail -5` | deny |
| `EXIT_STATUS_GUARD_OVERRIDE=why make check \| tail -5` | defer |
| `'EXIT_STATUS_GUARD_OVERRIDE=why' make check \| tail -5` | defer |

Two guards measured end to end. The other three were read rather than run:
branch-guard, foreground-guard and prod-guard each keep the rule locally and
each match it against a post-shlex token, so the same input should disarm them
-- unverified, and worth a row of the fixture table rather than a claim.

Not every consumer is exposed the same way. `strip_env_prefix` dropping a
quoted `'LC_ALL=C'` makes the guard read `cat /outside` where bash runs a
program named `LC_ALL=C` and opens nothing, which over-finds and is safe.

## Which way it gets built

The information is in the raw string and nowhere else, so the fix is a
quote-aware assignment test rather than a change to `ASSIGNMENT_RE`, which is
handed tokens by every caller and cannot see what it is missing.

Two candidate shapes, and the choice is which layer holds the answer:

1. A `lib/` primitive that reads the raw string and reports which command-head
   words were written unquoted, additively, beside the existing tokenizer.
   Each guard then intersects its assignment run against that set. One
   implementation, five consumers, and it is the shape the repository already
   uses for anything the guards must agree on.
2. Have `lex` mark tokens that carried quotes, and let each reader skip a
   marked one in command position. Broader blast radius -- every caller of
   `lex` sees a changed token stream -- so only worth it if a second question
   needs the same fact.

Either way the *policy* stays per-guard: workspace-guard's variable tracker
should leave the name unset (its value is then unknown, which is the fail-safe
direction), and each break-glass reader should decline to arm. Fixture rows in
both directions, per consumer: single-quoted, double-quoted, and unquoted
forms of the same prefix, plus a quoted word that is not an assignment at all.

## Downstream

`karlkfi/claude-spill-guard` reported this from its own port -- its Q100, whose
whole content is "report this upstream", so this row is that report -- and its
Q92 is waiting alongside. There the unresolved form already proceeds with a
record, so the divergence trades a record for a scan of the wrong path and the
same bytes cross either way. Here it decides an allow.

## If it is never built

Rare in hand-written commands and rarer still by accident, which is why this
sits below the parser rows it neighbours rather than above them. The cost when
it does happen is the one the guard is least able to absorb: an `allow` that
vouches for a string on a variable bash never set, and a break-glass that
disarms on a word bash would have failed to execute.
