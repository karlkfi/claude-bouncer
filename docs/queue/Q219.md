# workspace-guard reads nothing behind a command wrapper

A guarded reader preceded by any of the usual command wrappers goes silent.
Driven 2026-10-01 against the branch that landed Q214, `cwd` set to the
worktree:

| command | decision |
|---|---|
| `cat /etc/hosts` -- control | ask |
| `env cat /etc/hosts` | **(silent)** |
| `env A=1 cat /etc/hosts` | **(silent)** |
| `nohup cat /etc/hosts` | **(silent)** |
| `nice cat /etc/hosts` | **(silent)** |
| `timeout 5 cat /etc/hosts` | **(silent)** |
| `command cat /etc/hosts` | **(silent)** |
| `stdbuf -o0 cat /etc/hosts` | **(silent)** |
| `xargs cat /etc/hosts` | **(silent)** |

Each of those runs `cat` on the operand in bash. The guard peels reserved
words and assignment prefixes before the `SPEC` lookup, and nothing else, so
the wrapper takes the command head and the lookup misses.

The guard already knows these words.
`plugins/workspace-guard/scripts/bash-workspace-guard.py:1983:    'env', 'find', 'ionice', 'nice', 'nohup', 'setsid', 'stdbuf', 'time',`
lists them as `LOCAL_SHELL_WRAPPERS`, but that set is consulted only to decide
whether an `sh -c` body underneath is analysed. A direct reader under the same
wrapper is not. The README's Limitations section does not mention it. In
`tests/test_workspace_guard.py`, a regex for a quoted wrapper followed by a
guarded reader (`env cat `, `timeout 5 grep `, ...) matches 0 lines, where the
same search for a bare quoted `cat ` or `grep ` matches 344.

## What a fix has to settle

Each wrapper has its own operand grammar: `timeout` takes a duration, `nice`
an optional `-n N`, `env` and `sudo` their own assignments and flags, and
`xargs` appends its stdin to the argv, so `xargs cat` reads files the
command string does not name. Three of the other guards each keep a wrapper
peel (prod-guard's `strip_wrappers`, exit-status-guard's `peel_wrappers`,
foreground-guard's `strip_head`), and none is shared; the
repo's rule for `lib/` is that a primitive moves there when a second guard
needs the same behaviour, which this would be the occasion to ask.

Q218 covers `env` operands the three peeling guards
misread; whatever this row builds for `env` has to take that rule from the
start.

## If it is never built

One word in front of any guarded command removes workspace-guard from the
call, with no verdict, no prompt and nothing a friction report can count. The
reach is everyone who installs workspace-guard.
