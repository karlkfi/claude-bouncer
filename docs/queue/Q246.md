# foreground-guard reads an env -S value as one word

`env -S STRING` splits STRING into words and runs them as the command.
foreground-guard's `env` branch in `strip_head`
(`plugins/foreground-guard/scripts/bash-foreground-guard.py:472:            value_flags = ENV_VALUE_OPTS`)
does not know `-S`. It drops the flag, and the whole string becomes a single
command word. What happens next depends on how that string happens to look:

| command | guard |
|---|---|
| `env -S 'gh run watch 456'` | deny -- the watch pattern matches the string |
| `env -S 'tail -f app.log'` | deny -- same |
| `env -S 'sleep 300'` | **defer** |
| `env -S 'nohup gh run watch 456'` | **defer** |
| `env -S 'FOO=1 gh run watch 456'` | **defer** -- read as an assignment |
| `env -S'gh run watch 456'` | **defer** -- attached value dropped with the flag |
| `env --split-string='gh run watch 456'` | **defer** |
| `env -S 'FOO=1 scripts/gate.sh'` | **defer** (Class B, gate registered) |

Measured 2026-10-04 by driving the hook with a JSON payload, after Q221.
`/usr/bin/env -S "echo RAN_S"`, `-S"echo RAN_SA"` and `-iS "/bin/echo RAN_IS"`
each ran their command under `env -i bash --norc --noprofile -c` (bash
5.3.15, BSD env).

## Which way it gets built

Split the value and peel again, the way prod-guard's `env_split_string`
does
(`plugins/prod-guard/scripts/bash-prod-guard.py:655:def env_split_string(argv):`).
That covers the separate, attached and `--split-string=` forms. It is not
shared code, so treat it as a model rather than a call site. A bundle ending
in `S` (`-iS 'cmd'`) needs the character-at-a-time walk the shared `wrapper_option` gives the
other value flags.

## If it is never built

A watch or long sleep written through `env -S` parks the main thread with no
deny. `-S` is mostly a shebang idiom and is rare in a typed command, so the
cost is occasional waiting.
