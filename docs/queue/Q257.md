# A quote in a substitution in double quotes hides the command after it

bash parses a `$( )` or backtick substitution inside double quotes as a
command of its own, so a `"` that is quoted inside the substitution does not
close the outer string. `QuoteTrackingLexer` is shlex and has no notion of a
substitution: it closes the outer string at that inner `"`, finds the real
closing `"` unbalanced, and `lex` raises `No closing quotation`.
`command_substitutions` reads the same commands correctly, so only the lexer
is wrong.

Found by the independent review of the Q225 pull request. Driven 2026-10-04
under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`, which prints
`5.3.15(1)-release`, and through the hooks on `origin/main` at `777c6ef`.
The fixture `$HOME` set the current context to `gke_acme_prod-us`. Payloads
were `kubectl delete ns payments` for prod-guard, `rm /etc/probe-target` for
workspace-guard, and `make check | tail` for exit-status-guard:

| command | bash runs P | prod / ws / exit |
|---|---|---|
| `echo "$(echo \")" ; P` -- control, escaped | yes | deny / ask / deny |
| `echo "$(echo '"')" ; P` | yes | deny / **defer** / **defer** |
| `echo "$(echo $'"')" ; P` | yes | deny / **defer** / **defer** |
| ``echo "`echo '"'`" ; P`` | yes | deny / **defer** / **defer** |

The `$'"'` row was the review's first report. The plain `'"'` row shows that
`$'…'` is incidental, and the backtick row shows the same mechanism outside
`$( )`.

## Which way it gets built

Have the lexer step over a substitution opened inside double quotes as one
unit, the way `command_substitutions` already finds its end, and keep reading
the outer string after it. Check that `"$(echo \")"` still reads as it does
now, and that a `"` the lexer should close on is still closed. Q230 is the
comment half of the `$( )` scanner and Q225 the `$'…'` quoting. Both are
different mechanisms that land in the same file.

## If it is never built

A quoted `"` inside a substitution in double quotes, as in
`"$(printf '%s"' x)"`, hides every command after it from workspace-guard and
exit-status-guard.
