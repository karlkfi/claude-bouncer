# worktree remove --force with a $VAR operand asks instead of denying

Since Q308, `git worktree remove --force` allows an absolute literal path into
the session's own scratchpad and asks for everything else
(`plugins/branch-guard/hooks/branch-guard.py:2213:                if target and is_literal_path(target) and os.path.isabs(target):`).
An operand the hook cannot expand, such as `"$S/pr1"`, falls through to that
ask. The person at the prompt sees the same unexpanded `$S` the hook did, so the
ask adds a wait and no information. A deny whose reason says "write the literal
absolute path" lets the model rewrite the command, and the rewrite then lands
on the Q308 allow when it is a scratchpad remove.

Measured while building Q308 by a Python walk over 31 days of this machine's
transcripts (`~/.claude/projects/**/*.jsonl`, to 2026-10-25): 157 forced
`worktree remove` calls, 67 with a `$VAR` operand and 57 with an absolute path
into a scratchpad. How many of the 67 resolved into a scratchpad is not
measured; the walk could not expand them either.

## Which way it gets built

In the `--force` arm, when the single operand is not a literal path, return a
deny whose reason names the rewrite: the same command with the absolute path
spelled out. Keep the ask for a literal path outside the scratchpad, where the
question is real: whether that worktree may go.

**If never built:** about two asks a day on this machine (67 in 31 days), each
answered by a human who can see no more than the hook.
