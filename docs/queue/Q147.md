# Nothing gitignores `settings.local.json`, so a run loses its effort pin

`session-orchestrator` opens every run by pinning its own reasoning effort, and
the write is guarded so it cannot litter a repo that would track the file:

```bash
git check-ignore -q .claude/settings.local.json \
  && printf '%s\n' '{"env": {"CLAUDE_CODE_EFFORT_LEVEL": "low"}}' \
     > .claude/settings.local.json
```

Here `git check-ignore` exits 1, so the `&&` short-circuits and nothing is
written. The guard is working exactly as designed — the repo has not opted in —
but the consequence is that every orchestrated run in this repository silently
runs its coordinating session at the launcher default instead of `low`.

`.gitignore` carries `tmp/`, `.claude/worktrees/`, `__pycache__/` and
`.DS_Store`, and no rule reaches `.claude/settings.local.json`. Claude Code
writes that path itself for per-clone settings, so it is a file this repo will
keep meeting whether or not an orchestrator asks for it.

## Who it is for

The coordinating session of any parallel run here, and the person paying for it.
The orchestrator's own context is the longest-lived in a run and its output is
re-read on every subsequent call, so the level it runs at is the front-loaded
cost — which is why that skill pins the level before it reads anything, and why
losing the pin is not cosmetic.

## What happens if it is never built

Nothing breaks. Every orchestrated run in this repository just pays full
reasoning cost for the one role whose job is routing and book-keeping, and no
signal reports it — the guard's refusal is a silent `&&` short-circuit, so the
run only notices if it checks the exit status, and the level is unfixable
mid-run because the file is what would fix it.

## Which way it gets built

One line in `.gitignore`. The path is per-clone by construction — it is what
Claude Code writes for settings that must not be shared — so ignoring it is the
same call the repo already made for `.claude/worktrees/`, one entry above.

Worth checking in the same edit whether `.claude/` should be ignored with an
un-ignore for the tracked `commands/` directory instead, since that is the
shape that survives Claude Code adding a sixth local-state file. Today
`.claude/` holds only `commands/`, so the narrow rule is enough and the broad
one is a guess about what lands next.
