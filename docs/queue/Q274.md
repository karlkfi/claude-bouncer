# A backtick substitution as a file operand is read as a literal name

workspace-guard treats an operand holding `$(…)` as runtime-expanded and
denies it, because bash decides that path when it runs. The same substitution
written with backticks is resolved as a literal filename. ``cat `cat list.txt` ``
reads whatever files `list.txt` names, and the hook allows it.

## Measured

2026-10-04. The hook was driven on `main` at 1efa1f0 with `cwd` set to a scratch
workspace whose `list.txt` holds `../q177-x`. bash 5.3.15 ran the same strings
under `env -i`, with a `q177-x` in the workspace's parent.

| command | hook | bash reads |
|---|---|---|
| `cat $(cat list.txt)` (control) | deny, runtime-expanded | `../q177-x` |
| `cat "$(cat list.txt)"` (control) | deny, runtime-expanded | `../q177-x` |
| ``cat `cat list.txt` `` | **allow** | `../q177-x`, outside |
| ``cat "`cat list.txt`" `` | **allow** | `../q177-x`, outside |
| ``grep x `cat list.txt` `` | **allow** | |
| ``cp `cat list.txt` out.txt `` | **allow** | |

There are two mechanisms, and both must be fixed:

- **`EXPANSION_RE` knows only `$`.** It decides whether
  `resolve_token` returns `expand`. A token holding a backtick falls through to
  `realpath` and is checked as the literal name ``"`cat list.txt`"``, which
  sits inside the workspace. Quoted, the whole substitution is one token, and
  that alone gets the `allow`.
- **Unquoted, the tokenizer splits the body into words.** ``cat `cat list.txt` ``
  reaches the group as `cat`, `` `cat ``, `` list.txt` ``, and each fragment is
  checked as a path. That is also where Q177's second spelling came from:
  ``cd .. && cat <<<`cat T` `` names a phantom ``T` `` that bash never forms.
  Q177's fix placed the body correctly, so that command now also names the real
  `T`, but the phantom stays until the fragments stop reaching the group.

## Which way it gets built

The first mechanism is the fail-open, and a local fix is enough: a token
holding an unescaped backtick is runtime-expanded. That denies the four `allow`
rows above. It also denies a single-quoted literal backtick such as
``cat 'a`b'``, which `'$HOME'` already gets today, so it fails closed the same
way.

The second needs the backtick span kept as one token before `split_groups`
sees it. The tokenizer's glue passes live in `lib/` (`glue_dollar_paren`), so
the clean fix reaches every guard and wants a `lib` label once it is scoped.
The body can contain `;` or `|`, and gluing across them changes how a command
splits into groups, so it needs its own corpus comparison.

## If it is never built

Any guarded command takes its file list from a backtick substitution with an
`allow`, so a file outside the workspace can be read or written through a list
the guard never sees. The `allow` short-circuits the user's own permission
settings.
