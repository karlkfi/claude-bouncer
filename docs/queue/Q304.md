# Two guards wrap strip_sh_keywords alike: skip a function name, keep time

The shared `strip_sh_keywords` strips leading reserved words and stops at the
first word that is not one. Two guards now need the same two corrections on
top of it, and each carries its own copy:

- after `function`, the name is not a reserved word, so the body's `{` and the
  command behind it stay hidden until the name is dropped and the strip runs
  again;
- `time` is a reserved word, but its `-p` and `--` belong to it, so a guard
  that walks wrappers hands `time` back rather than leaving `-p` as the
  program (Q241 is the `time` options defect itself).

prod-guard's is `strip_keywords` in `plugins/prod-guard/scripts/bash-prod-guard.py`
(Q300, #264), and branch-guard's is the `close()` inside `command_segments` in
`plugins/branch-guard/hooks/branch-guard.py` (Q302). Both read the same, and
nothing keeps them that way.

## Which way it gets built

Extend `strip_sh_keywords` additively, the way `strip_heredoc_bodies` grew
`unterminated`: an option that drops a `function` name, and one that returns
the stripped words alongside the body so a caller can hand `time` back and
read the group openers. The guards that call it today pass neither and are
unaffected. Then move both guards onto it and delete their copies.

## If it is never built

The next guard to need it writes a third copy, and a fix to one copy (a quoted
`function`, say) reaches only the guard it was made in.
