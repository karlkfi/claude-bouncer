# foreground-guard judges no substitution in a redirect's target word

bash expands a redirect's target word before the command runs, so `cat <<< "$(tail -f log.txt)"` follows the log in the foreground exactly as `echo "$(tail -f log.txt)"` does. foreground-guard denies the second and gives no decision on the first.
Driven 2026-11-26 through `scripts/bash-foreground-guard.py` on `origin/main` at `b49e7352`, under bash 5.3.15:

| command | decision |
|---|---|
| `echo "$(tail -f log.txt)"` | deny |
| `cat <<< "$(tail -f log.txt)"` | none |
| `cat <<< $(tail -f log.txt)` | none |
| ``cat <<< "x `tail -f log.txt`"`` | none |
| `cat <<< "$(gh run watch 1)"` | none |
| `cat <<< "$(sleep 600)"` | none |
| `echo x > "$(tail -f log.txt)"` | none |
| `cat < "$(tail -f log.txt)"` | none |
| `echo x 2> $(tail -f log.txt)` | none |
| `cat <<< ok; tail -f log.txt` | deny |

The other four guards judge the same shapes: with the body swapped for each guard's own trigger, workspace-guard and branch-guard ask and prod-guard and exit-status-guard deny on every here-string form, matching the bare command.

## Why it is missed

`mask_substitutions` replaces each substitution with a marker word, and `substitutions_in` finds a body by its marker in a segment's words.
`split_segments` drops a redirect operator and the word after it (`plugins/foreground-guard/scripts/bash-foreground-guard.py:458:                skip_next_word = True`), so the marker in a target word never reaches a segment and its body is never judged.
`REDIR` lists `'<<<'` beside the file redirects, which is why a here-string and a file target fail together.

## Which way it gets built

Keep the target word out of the segment's argv, since it is never a command, and still collect the markers it carries for that segment.
Not measured.

## If it is never built

A watch or long sleep written inside a here-string or a redirect target blocks the main thread with no deny.
How often sessions write one is not measured; Q378 lexed 261,089 commands on 2026-11-17 and found no shell fed a here-string, which says nothing about `cat <<<`.
