# exit-status-guard does not resolve an abbreviated long wrapper option

`getopt_long` accepts any unique prefix of a long option, so `--us` is
`--user`. Q222 gave `wrapper_operands` a table of value-taking flags that
lists only full spellings and matches a long option whole. An abbreviated
value-taking option therefore drops one word instead of two, its value is left
as the command word, and a gate piped into a filter goes through. That is the
missed-deny direction the table's comment documents.

Found by the independent review of the Q222 pull request. Driven 2026-10-04
through the hook at the Q222 head `c0de80b`:

| command | guard |
|---|---|
| `sudo --user root make check \| tail -5` | deny -- control |
| `sudo --us root make check \| tail -5` | **silent** |
| `env --unset FOO make check \| tail -5` | deny -- control |
| `env --un FOO make check \| tail -5` | **silent** |
| `stdbuf --output L make check \| tail -5` | deny -- control |
| `stdbuf --out L make check \| tail -5` | **silent** |

The review reports that sudo 1.9.17p2 accepts `--us`; I did not run sudo for
this row. `env --un` and `stdbuf --out` are GNU-only, since the BSD tools take
no long options.

## Which way it gets built

Resolve a long option by unique prefix against the wrapper's known long
options, the way Q228 does for prod-guard and branch-guard's walk already
does. Q233 proposes moving the wrapper tables and their arity walk into `lib/`.
If that lands first, this row closes there and should be deleted rather than
built twice.

## Who it is for, and what happens if it is never built

Anyone abbreviating a wrapper's long option in front of a gate. That is rare in
agent-written commands, which favour the short form. Left alone,
`sudo --us root make check | tail` loses its exit status with no deny.
