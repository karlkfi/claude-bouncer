# A deny discards the rest of the call, and no reason says so

A `PreToolUse` deny refuses the whole Bash invocation, so every other
statement in the command string never runs. Where one of them was a file
write, the write is silently lost: the reason names only the rule that fired,
so nothing in what reaches the model says an edit was discarded, and the next
command's output reads as success about a file that was never modified.

None of the five guards says it. Every reason ends on its own fix and its own
override, and the collateral is named nowhere:

- `plugins/exit-status-guard/scripts/bash-exit-status-guard.py:997:        emit('deny', REASON_PREFIX + reason)`
- `plugins/workspace-guard/scripts/bash-workspace-guard.py:2891:def emit(decision, reason):`
- `plugins/prod-guard/scripts/bash-prod-guard.py:2691:        'permissionDecisionReason': reason}}))`
- `plugins/branch-guard/hooks/branch-guard.py:2262:def emit(decision, reason):`
- `plugins/foreground-guard/scripts/bash-foreground-guard.py:930:    if decision == 'deny':`

## Measured

Reported 2026-09-10 from `actions-gateway/github-actions-gateway`, twice in one
session, both denied by exit-status-guard's pipe rule and both shaped
*heredoc writes a file, then a gate is piped into a filter*:

1. A heredoc wrote new test cases; the follow-up suite run reported
   `Ran 81 tests ... OK`, the untouched baseline. A mechanism-deletion probe
   then passed with the mechanism deleted, because the new tests did not
   exist. Caught only by noticing the count had not risen to 84.
2. A heredoc edited `main.go`; the follow-up `gofmt -l` came back empty and
   the build exited 0 — both true of the unmodified file, which is what made
   it convincing. This one produced a wrong root-cause diagnosis that reached
   the user.

Rate: once per deny that carries a bundled mutation, and bundling a write
with the gate that checks it is a common agent shape — two in one session.
Cost per occurrence is a silently discarded edit plus every reading taken
after it, which is worse than a wrong sentence because it steers the work
rather than only the report.

## The shape

A shared detector in `lib/`, over the tokens the parser already produces:
output redirection to a path that is not `/dev/null` (`REDIR` and `DUP` at
`lib/bouncer_parse.py:65:REDIR = {'>', '>>', '<', '<<', '<<<', '>|', '&>', '&>>'}`),
a heredoc feeding an interpreter (`lib/bouncer_parse.py:249:def strip_heredoc_bodies(cmd, expanded=None, unterminated=None,`),
and a small verb list — `tee`, `sed -i`, `cp`, `mv`. It returns a
description or nothing, and each guard appends a sentence to its reason on
`deny`. Every guard has a single `emit` chokepoint, so the wiring is one line
each.

A false negative costs nothing here: the note is additive, and its absence is
the state today. A false positive costs a sentence.

This is `lib/` work, so it reaches all five guards and releases none of them —
five version bumps follow separately, and the change needs `make sync` plus
all five suites.

## Why it does not conflict with the deny-carries-the-fix rule

`hook-verdict` says a deny's reason should carry the fix, and each of these
already does — for the rule that fired. The missing half is not a second fix
but a disclosure: the caller's *other* work in that call was destroyed, and
only the guard knows it. A sentence saying so is what lets the model re-issue
the write instead of reading a stale file as proof the edit landed.
