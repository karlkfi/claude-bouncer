# Two friction categories share a signature, so dict order decides

`deny_switch`'s reason carries both `Switching shared state is blocked` and `is
shared by every session`, so it matches the `deny-switch` and `ask-switch`
patterns alike and only `CATEGORY_PATTERNS` iteration order keeps it out of
`ask-switch`. Swapping the two entries sends every switch deny to `ask-switch`
-- measured 2026-08-24, where it flipped the live `kubectx bluefin` case.

foreground-guard holds the invariant prod-guard cannot: its
`test_signatures_mutually_exclusive` asserts no reason matches more than one
signature. Tightening `ask-switch` to its own tail -- `Prefer per-command
pinning` -- makes the five disjoint and lets that test come across.

`LiveCategoryTests` pins today's behaviour, so this is robustness rather than a
defect: the order is right, and nothing but the order makes it right.
