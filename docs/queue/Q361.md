# A quoted paren one $(( deeper still hides the rest of the command

`echo $(( $(( $(echo "(" | wc -c) )) + 1 )) ; make check | tail` gets no
decision from exit-status-guard. bash runs the pipeline:
`env -i /opt/homebrew/bin/bash --norc --noprofile -c` (5.3.15) prints the
arithmetic and then runs the command after `;`. prod-guard and foreground-guard
deny the same shape with their own stand-ins.

Q339 (#329) ended exit-status-guard's `$((…))` mask at the close that
`_scan_dollar_paren` reports, because the guard's own flat paren count read a
quoted `(` as an opener. `_scan_dollar_paren` has the same flat count for an
inner `$((`: it steps over the expansion with
`lib/bouncer_parse.py:980:i = _skip_balanced_parens(text, i)`.
The quoted `(` there leaves the scan with no close, it returns no body, and the
mask falls back to end-of-string. The #329 reviewer found it at `c8d9707`, and
Q339's worker reproduced it at the same head.

That branch is the one Q338 names, for a different defect: Q338 is about which
`$((` bash reads as arithmetic at all, and this row is about where real
arithmetic ends. One rewrite of the branch could close both, but either fix can
land alone.

## Which way it gets built

Make the arithmetic step at that line quote-aware, the way `_scan_dollar_paren`
already is for its own body, and pin the command above in exit-status-guard's
table so the test fails on `main`. A change in `lib/` reaches all five guards,
so re-run every suite. No remedy has been measured yet.

## If it is never built

exit-status-guard misses a gate piped into a filter whenever it follows two
levels of arithmetic with a quoted paren in a nested substitution. Nobody
writes that shape to run a gate.
