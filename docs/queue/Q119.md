# An apostrophe in an earlier heredoc body hides a substitution's heredoc

Q113 recovers a substitution body from the raw command string, because the
stripped one carries a `<<WORD` whose body and terminator are gone and a second
strip re-arms it. The recovery matches a raw body to a stripped one by stripping
it back down, so it only works where `command_substitutions` can find the
substitution in the raw string at all -- and its top-level scan is not
heredoc-aware. An apostrophe in an *earlier* top-level heredoc body opens a
quoted run that swallows the rest of the scan (the Q50 mechanism), the raw scan
returns nothing, and Q113's defect survives with no counterpart to swap in.

Measured 2026-08-23 on the Q113 branch, with `/etc/q-fake` outside the
workspace:

    cat <<EOF
    don't
    EOF
    echo "$(cat <<X
    b
    X
    cat /etc/q-fake)"

returns `allow`, where the same command with `plain` in place of `don't` asks.
`allow` rather than defer is what ranks this: the first `cat` is guarded and
reads stdin, so the hook vouches for the whole string on the strength of a
substitution whose outside read it never saw.

The scan the recovery needs is one that removes only the heredoc bodies of its
own level and leaves a nested one for the recursion to strip -- each level
stripping what belongs to it, which is idempotent by construction and closes
the general case rather than this shape. `strip_heredoc_bodies` already tracks
substitution contexts on a stack, so the condition is whether that stack is
empty when a body would be consumed. It is a `lib` change reaching five guards,
which is why Q113 took the guard-side route and left this behind rather than
widening its own blast radius; the label is left off until the route is decided.
