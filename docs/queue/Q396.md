# A production target nested past MAX_SUBST_DEPTH asks instead of denying

`MAX_SUBST_DEPTH` (25) and asks instead, which fixed the defer past ~500 levels
where the unbounded recursion raised `RecursionError`. It also turned every
production target between 26 and ~500 levels from deny into ask. Measured
2026-11-17 over `echo $( … $(kubectl --context=acme-production delete pod x) … )`
nested N deep, empty `$HOME`, default mode:

| N | `prod-guard/v2.8.0` | `main` at `82cfe6a6` |
|---|---|---|
| 1 | deny | deny |
| 25 | deny | deny |
| 26 | deny | ask |
| 100 | deny | ask |
| 400 | deny | ask |

A production target the guard can still read must keep denying. Blocks the
prod-guard 2.9.0 cut.
