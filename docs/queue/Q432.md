# A quote in an indexed array subscript hides the substitution in it

`a['$(echo RAN >&2; echo 1)']=1` runs the substitution, and so do `echo ${a['$(echo RAN >&2; echo 1)']}` and `a+=(['$(echo RAN >&2; echo 1)']=1)`.
Under `env -i /opt/homebrew/bin/bash --norc --noprofile -c` (5.3.15) each prints `RAN`, and the first two then an arithmetic error about `'1'`: an indexed array's subscript is arithmetic, and a `'` in it is text.
`command_substitutions` returns `[]` for all three, measured with Q415's change in place.

What decides it is the array's type, which the string may not carry.
After `declare -A a` the same assignment stores the key `$(echo RAN >&2)` and runs nothing, and so does the expansion.
An array nobody declared, or one declared `-a`, is indexed.

## Which way it gets built

The safe reading treats every subscript as arithmetic and returns the body, which over-reads only for a declared associative array.
That is the direction `command_substitutions` already takes inside arithmetic: `echo $(( x['$(echo RAN)'] ))` returns `['echo RAN']`, while bash quotes that subscript and runs nothing.
`_subscript_end` and `_comment_free_end` find the assignment's subscript today, and a `${a[…]}` is stepped over as a `${…}` word.

## If it is never built

A command written inside quotes inside an array subscript runs past every guard that reads substitution bodies from `command_substitutions`.
Nobody writes the shape by accident.
