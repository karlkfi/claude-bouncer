# The [[ position test misreads an escaped separator and a case pattern

Q346 made both comment scanners open `[[ … ]]` tracking only in command position, through `lib/bouncer_parse.py:509:def _command_position(text, i, closes=()):`.
That walk reads raw text backwards and stops at the first separator (`lib/bouncer_parse.py:521:        if not j or text[j-1] in ';&|\n(':`).
It does not see an escape before that character, and it does not track `case` syntax.
In the shapes below it opens a test bash never runs, so a `=~` after the `[[` starts an operand, the `;#it's` that follows reads as text, and its apostrophe hides every later line.

Measured 2026-11-17 on Q346's branch (#360) and on `main` at `328f612d`, which read each the same way.
`strip_comments` keeps the comment, and bash 5.3.15 runs `echo RAN` after each:

| command | why the walk opens a test |
|---|---|
| `echo \; [[ =~ x;#it's` ⏎ `echo RAN` | `\;` reads as a separator |
| `echo \) [[ =~ x;#it's` ⏎ `echo RAN` | `\)` reads as a case pattern's close |
| `echo \( [[ =~ x;#it's` ⏎ `echo RAN` | `\(` reads as an opening `(` |
| `echo \| [[ =~ x;#it's` ⏎ `echo RAN` | `\|` reads as a pipe |
| `case x in a) :;; [[ ) echo =~ x;#it's` ⏎ `;; esac; echo RAN` | a case pattern after `;;` |
| `case x in` ⏎ `[[ ) echo =~ x;#it's` ⏎ `;; esac; echo RAN` | a case pattern on its own line |

The unspaced `[[)` opens nothing, since a `[[` needs a blank after it.
Found by the stream-A reviewer on #360.

## Which way it gets built

Count the backslashes before a separator the walk stops at, and treat an odd count as a word.
A case pattern is the harder half: the walk would need to know it is inside `case … in` and not in a command list, and neither scanner tracks that.
Measure first whether ruling out a `[[` immediately followed by ` )` covers both case rows without losing a real test.

## If it is never built

A command on the line after one of these shapes goes unjudged by prod-guard, workspace-guard, exit-status-guard and foreground-guard.
Each shape needs a `[[` used as a word right after an escaped separator, or as a case pattern, and then a `=~` and a comment holding an apostrophe, so it is rarer than Q346's shapes.
