# A workspace-guard test deletes a temp root concurrent suites share

`test_bundled_skills_read_allowed_write_asks` plants a skill under the real Claude temp root, `<tmp_root>/bundled-skills/guardtest-<pid>/`, and removes the whole `bundled-skills` root afterwards whenever it was the one to create it, at `plugins/workspace-guard/tests/test_workspace_guard.py:10641:            shutil.rmtree(root if made_root else skill, ignore_errors=True)`.
The skill directory carries the process id and the root does not, so two suites running at once on one machine share the root, which is the case `plugins/workspace-guard/CLAUDE.md` warns about.
If the suite that created the root finishes first, it deletes the other's skill directory, and the other's hook then finds no `bundled-skills` tree to exempt.

Seen 2026-11-26 during a parallel dispatch with about ten sessions on the machine.
A `make check` over the Q362 branch (`c9c55864`) failed on this test alone:

```
AssertionError: 'ask' != 'allow'
 : expected 'allow' for 'cat /private/tmp/claude-501/bundled-skills/guardtest-96072/SKILL.md'; got 'ask'
```

Run alone right afterwards, the test passed six times in six, three against that branch's `lib/` and three against its parent's.
The concurrent run that removed the root is inferred, not observed: no other session's log was read.
One sighting, so no failure rate.

Q384 is the same mechanism in an exit-status-guard test.
It stays a separate row because the fix lands in a different plugin's suite, and Q384 was being edited on another branch when this was filed.

## Which way it gets built

Never remove the shared root: remove only the skill directory this run made, and leave an empty `bundled-skills` behind.
Not measured.

## If it is never built

Every parallel batch here can lose a `make check` run to a sibling's suite and have to re-run a gate of several minutes.
CI is unaffected, since each job runs one suite at a time.
