# An unresolved word that may expand to nothing hides the command after it

An unquoted `$X` in command position that the hook cannot resolve may expand
to nothing, and then bash runs the next word as the command. prod-guard takes
the literal `$X` as the command name, finds it in no table, and defers
(`plugins/prod-guard/scripts/bash-prod-guard.py:3068:tool = os.path.basename(argv[0])`).
`env -S` has the same shape inside its string, where env expands `${NAME}`
itself.

Found by the orchestrator's review of the Q287 pull request, for the `env -S`
spelling. Driven 2026-10-07 through the hook at `origin/main` `a17788e` and on
the Q158 branch, same verdicts, fixture `$HOME` with current context
`gke_acme_prod-us`; `<prod delete>` is
`kubectl --context=gke_acme_prod-us delete pod x`:

| command | guard |
|---|---|
| `env -S 'kubectl ${X} --context=gke_acme_prod-us delete pod x'` -- control | deny |
| `$X <prod delete>` | **defer** |
| `sudo $X <prod delete>` | **defer** |
| `env $X <prod delete>` | **defer** |
| `env -S '${X} <prod delete>'` | **defer** |
| `env -iS '${X} <prod delete>'` | **defer** |
| `env -S '${X} ${Y} <prod delete>'` | **defer** |
| `"$X" <prod delete>` | defer -- correct, bash runs an empty name |

What runs, with `/bin/echo` in place of the tool:

- bash 5.3.15 under `env -i`: `$X echo RAN` and `$X $Y echo RAN` print `RAN`;
  `"$X" echo RAN` fails with `: command not found`, rc 127.
- macOS `/usr/bin/env -S '${X} /bin/echo RAN'` prints `RAN` with `X` unset and
  with `X` empty.
- GNU coreutils 9.11 `genv -S '${X} /bin/echo RAN'` prints `RAN` with `X` unset
  and with `X=-i`; with `X` empty it fails on `''`, rc 127.

Q279 is the neighbour: a substitution that *names* the command. Here the word
names nothing and drops out. The other four guards were not driven.

## Which way it gets built

Judge both readings where the leading word is an unquoted expansion the hook
cannot resolve: the word as the command, and the words after it as the
command. Q287 built the two-reading path for an `env -S` string
(`strip_wrappers`' `alternates`), and the override scoping it carries applies
here too: an override in one reading reaches only that reading. A quoted
expansion keeps today's single reading.

## If it is never built

Any production command written behind an unset variable in command position
passes silently, at the top level, behind `sudo` or `env`, and inside an
`env -S` string.
