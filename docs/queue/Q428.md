# branch-guard defers on substitution text bash leaves literal

`has_shell_substitution` reads the tokens after shlex has removed the quotes, so a single-quoted `$( )`, backtick or funsub withholds an allow for a command bash never runs (`plugins/branch-guard/hooks/branch-guard.py:1089:FUNSUB_RE.search(t):`).
Driven 2026-11-26 through `hooks/branch-guard.py` with the payload's `cwd` in a feature worktree, on `origin/main` at `c0bc0235` and with Q383's fix at `67799f1`, where a bare `git commit -m x` allows:

| command | `c0bc0235` | `67799f1` |
|---|---|---|
| `git commit -m '$(x)'` | none | none |
| ``git commit -m 'a `x` b'`` | none | none |
| `git log --format='$(x)'` | none | none |
| `git commit -m '${ x; }'` | allow | none |
| `git log --format='${ x; }'` | allow | none |

The `$( )` and backtick rows predate Q383, which added the funsub spelling.
The cost is a missing auto-approve, never a missed prompt.

## Which way it gets built

The shared `command_substitutions` already skips single-quoted contexts and reports which bodies are funsubs, so the check can decide from it over the raw command instead of from regexes over the unquoted tokens.
Not measured.
Process substitution is the one spelling it does not return, so `<( )` and `>( )` need `process_substitutions` beside it, as Q420 does.

## If it is never built

A commit message or `--format` string quoting shell syntax keeps reaching the user's own permission rules on a feature branch.
How often sessions write one is not measured.
