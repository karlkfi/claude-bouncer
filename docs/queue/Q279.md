# A command name produced by a substitution is judged by no guard

bash runs whatever a substitution in command position prints:
`` `echo rm` /etc/x `` runs `rm`, and so does `$(echo rm) /etc/x`. Each
guard looks up the command word as written, finds `` `echo rm` `` or
`$(echo rm)` in none of its tables, and returns no decision. The guards
already judge the substitution's *body*, but the body here is a harmless
`echo`, and the command that matters is the one it names.

Found by the independent review of the Q274 pull request. Driven 2026-10-05
under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`, which prints
`5.3.15(1)-release`. A missing command name in each spelling was reported as
`command not found`, so bash runs it. Hooks ran on `origin/main` at `f440dbd`:

| command | prod | ws | exit | branch | fg |
|---|---|---|---|---|---|
| `rm /etc/probe-target` -- control | defer | ask | defer | defer | defer |
| `` `echo rm` /etc/probe-target `` | defer | **defer** | defer | defer | defer |
| `$(echo rm) /etc/probe-target` | defer | **defer** | defer | defer | defer |
| `C=rm; $C /etc/probe-target` | defer | ask | defer | defer | defer |
| `kubectl delete ns payments` -- control | deny | defer | defer | defer | defer |
| `$(echo kubectl) delete ns payments` | **defer** | defer | defer | defer | defer |
| `` `echo kubectl` delete ns payments `` | **defer** | defer | defer | defer | defer |
| `make check \| tail` -- control | defer | allow | deny | defer | defer |
| `$(echo make) check \| tail` | defer | allow | **defer** | defer | defer |
| `git commit -m x` on `main` -- control | defer | defer | defer | ask | defer |
| `$(echo git) commit -m x` | defer | defer | defer | **defer** | defer |
| `sleep 600` -- control | defer | defer | defer | defer | deny |
| `$(echo sleep) 600` | defer | defer | defer | defer | **defer** |

prod-guard's context came from a fixture `$HOME` set to `gke_acme_prod-us`,
and branch-guard ran in a fresh repository on `main`. workspace-guard already
follows a variable it can see assigned (`C=rm; $C …` asks). A substitution
has no assignment to follow.

## Which way it gets built

This is a policy choice before it is a parsing one. A command word holding a
substitution names a program the guard cannot know, so each guard needs a
verdict for it. A deny with the rewrite in its reason ("name the command
literally") matches how workspace-guard already treats an operand it cannot
read. It would also refuse legitimate shapes such as `$(command -v python3)
script.py`, so measure how often agents write those before choosing. A
substitution whose body is a literal `echo` or `printf` of one word can be
resolved outright, which covers the shapes above without that cost.

Recognising the unreadable command word is the same question in all five
guards, so the predicate belongs in `lib/` (and this row then takes the `lib`
label) once a guard's fix shows the shape.

## If it is never built

Any guarded command runs unjudged behind one `$(echo …)` or backtick wrapper
around its name. No guard asks, so the user's own permission settings decide
alone.
