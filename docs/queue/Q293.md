# `strip_comments` reads a `#` in an extglob group or `[[ ]]` as a comment

In an extglob group or inside `[[ … ]]`, a `(` or `|` starts no word, so a
`#` after one is text. bash parses extglob syntax in `[[ … ]]` always, and
elsewhere once `shopt -s extglob` has run. `strip_comments` counts both
characters as word breaks, so it starts a comment there
(`lib/bouncer_parse.py:437:        if not in_double and c == '#' and at_word:`),
and the rest of the line is dropped before any guard reads it:

```
strip_comments('[[ x == @(a|#b) ]]; P')   -> '[[ x == @(a|'
strip_comments('[[ a =~ (#x) ]] && P')    -> '[[ a =~ ('
```

Driven 2026-10-05 on `origin/main` at `ff2e52f`, with bash under
`env -i /opt/homebrew/bin/bash --norc --noprofile -c`, which prints
`5.3.15(1)-release`. Payloads were `kubectl delete ns payments` (fixture
context `gke_acme_prod-us`), `rm /etc/probe-target`, `make check | tail` and
`sleep 300`:

| command | bash runs P | prod / ws / exit / fg |
|---|---|---|
| `[[ x == @(a\|#b) ]]; P` | yes | **defer** ×4 |
| `[[ a =~ (#x) ]] \|\| P` | yes | **defer** ×4 |
| `shopt -s extglob` newline `echo @(a\|#b); P` | yes | **defer** ×4 |
| `[[ x == @(a\|b) ]]; P`, the control | yes | deny / ask / deny / deny |

Found while building Q258, which taught `command_substitutions` the same
word rule. Its review raised the shapes against that function, and Q258 holds
an extglob group and a `[[ … ]]` span with no comment in either.

## Which way it gets built

Hold the same spans in `strip_comments`: an extglob group, which is a `(`
glued to one of `?*+@!`, to its balanced close, and a `[[` in command
position to its `]]`. `_comment_free_end` in Q258's change already finds
both ends. A `#` glued after an extglob close is text too, as in `@(a)#b`.

## If it is never built

`[[ $x == @(a|#b) ]]; rm -rf x` passes every guard unjudged.
