# `stdbuf` and `unbuffer` are not wrappers prod-guard knows about

`PLAIN_WRAPPERS` holds `command`, `nohup`, `time`, `builtin` and `exec`.
`stdbuf` and `unbuffer` prefix a command the same way and are absent, so the
tool reads as `stdbuf` — uncovered — and the segment defers. Every form defers,
including the ones carrying no separate flag value at all.

This is the false-negative direction, which
[`plugins/prod-guard/CLAUDE.md`](../../plugins/prod-guard/CLAUDE.md) names as
the failure mode to fear.

## Measured

2026-09-04, prod-guard at `4a81387` with Q152's fix applied, fixture `$HOME`
with ambient context `gke_acme_prod-us`:

| command | verdict |
|---|---|
| `kubectl delete ns foo` | deny — control |
| `nohup kubectl delete ns foo` | deny — control, a listed wrapper |
| `stdbuf -oL kubectl delete ns foo` | **defers** |
| `stdbuf -o L kubectl delete ns foo` | **defers** |
| `unbuffer kubectl delete ns foo` | **defers** |
| `unbuffer -p kubectl delete ns foo` | **defers** |

Q152 could not reach any of it. That row's fix is about a flag's *arity* inside
a wrapper the guard already peels; here the guard never peels, so the attached
form `stdbuf -oL` — which carries no separate value and would survive any flag
table — defers too.

## Which way it gets built

Add both to `PLAIN_WRAPPERS`, and give `stdbuf` an entry in
`WRAPPER_VALUE_FLAGS`: it takes `-i`, `-o` and `-e`, each with a separate value
in the detached spelling. `unbuffer` takes only `-p`, which carries none.

The long forms are GNU's, and this machine's `stdbuf` rejects them —
`stdbuf --output=L echo RAN` answers `illegal option -- -`, measured 2026-09-04.
Carry `--input`/`--output`/`--error` anyway, the way `time`'s entry already
carries flags BSD refuses: the table is a union across platforms, since a
Linux runner has the GNU tool and the leak is live there. Say so where it
lands, or the next reader corrects it against whichever box they are on.

Check the `command`-style exception before landing it. Neither has a
run-nothing mode, so `is_command_lookup` has no analogue here — but confirm
that against their own usage rather than against this row.

## Not the sibling rows

[Q157](Q157.md) and [Q158](Q158.md) are about `sudo`'s flags, inside a wrapper
already peeled. `Q160`, filed on the branch behind
[#89](https://github.com/karlkfi/claude-bouncer/pull/89) and so not yet on
`main`, is Q152's defect in foreground-guard's `strip_head` — and foreground-guard
*does* carry `stdbuf` and `unbuffer` in its own `PLAIN_WRAPPERS`, which is how
this gap surfaced. The two guards keep separate wrapper sets by design, so one
fix closes neither.

`plugins/prod-guard/scripts/bash-prod-guard.py:265:PLAIN_WRAPPERS = frozenset({'command', 'nohup', 'time', 'builtin', 'exec'})`
