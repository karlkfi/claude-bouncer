# A cd inside a process substitution is ignored by the outer read of it

workspace-guard asks on `true <(cd sub; cat ../in.txt)`, naming `../in.txt`
as a path one level above the workspace. bash reads `sub/../in.txt`, which is
the workspace's own `in.txt`.

Measured 2026-10-05 on `origin/main` at `26962b0`, with the hook driven from a
`git archive` of that tree, its cwd and `CLAUDE_PROJECT_DIR` both a scratch
workspace holding `in.txt` and `sub/`:

| command | workspace-guard |
|---|---|
| `true <(cd sub; cat ../in.txt)` | ask |
| `cat <(cd sub; cat ../in.txt)` | ask |
| `true $(cd sub; cat ../in.txt)` (control) | allow |
| `true <(cd ..); cat in.txt`, cwd `sub/` (control) | allow |

The ask names `../in.txt` resolved from the workspace root. The last control
shows the `cd` does not leak past the `)` either, so the defect is only the
false ask.

The cause is the lexer. `tokenize_command('true <(cd sub; cat ../in.txt)')`
returns `['true', '<', '(', 'cd', 'sub', ';', 'cat', '../in.txt', ')']`, and
`split_groups` reads `<` as a redirect and takes `(` as its target
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:4185:                cur_redir.append(tokens[i+1]); i += 2; continue`).
So no subshell scope opens, `cd sub` lands in `true`'s group as two operands,
and `cat ../in.txt` becomes a group of its own at the starting cwd.
The Q259 worker reported the same merge in exit-status-guard, which prompted
this trace, and a fix there that masks each `<(…)` as `/dev/fd/63` before the
lexer runs, using lib's `process_substitutions` spans. That fix was not read
here.

Q276 made the body judged in its own right, at the right cwd, by recursing
into it. That recursion cannot withdraw the outer loop's offender, because
offenders from the two reads are merged.

## Which way it gets built

Mask each process substitution before tokenizing, as the Q259 worker reports
doing there, so the outer read sees one word where bash sees a file name. The body is
already judged by the substitution recursion, so the mask loses nothing. Keep
the last control as a fixture, and `cat <(cat ../x)`, which must still ask,
now through the body rather than through the outer `cat`.

## If it is never built

A `cd` followed by a relative read inside a process substitution asks when the
read is inside the workspace. It fails safe: the prompt is spurious, never
missing.
