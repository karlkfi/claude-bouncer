# A substitution in an unquoted heredoc delimiter is judged as run

foreground-guard denies `cat <<$(sleep 30)` with a body closed by the literal line `$(sleep 30)`, and bash runs no sleep at all.
The shell never expands a heredoc delimiter: the word is matched as text, and quote removal is the only thing done to it.
Which step judges it is not traced: on `main` a redirect's target word reaches no segment, so the deny comes from somewhere else.
The Q430 pull request, #411, starts judging substitutions in redirect target words, and a delimiter is one, so the fix has to exempt it there as well.

Found by the stream reviewer on the Q430 pull request, #411, at `8a7c7d3`, as a pre-existing behaviour it asked no action on.
Re-measured 2026-11-27 with `env -i /opt/homebrew/bin/bash --norc --noprofile -c` (GNU bash 5.3.15), a 1 s sleep, and the hook on `origin/main` at `d9ede7f` with a 30 s one:

| command | bash | foreground-guard |
|---|---|---|
| `cat <<$(sleep 1)` … `$(sleep 1)` | 0.04 s | deny |
| `cat <<"$(sleep 1)"` … `$(sleep 1)` | 0.03 s | none |

## Which way it gets built

Treat the word after `<<` or `<<-` as data whether or not it is quoted, and keep the body rule as it stands: an unquoted delimiter still makes bash expand the body's substitutions.
Not measured.

## If it is never built

A false deny costs one retry, on a delimiter shape the drive above had to construct.
How often sessions write one is not measured.
