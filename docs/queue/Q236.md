# workspace-guard peels no sudo, doas, caffeinate, chrt, taskset or flock

Q219 taught the guard to read through a command wrapper by the wrapper's own
option grammar, one row per wrapper in
`plugins/workspace-guard/scripts/bash-workspace-guard.py:1999:WRAPPER_GRAMMAR = {`.
The rows cover `env`, `nice`, `nohup`, `timeout`, `stdbuf`, `setsid`,
`ionice`, `time`, `xargs`, `exec`, `command` and `builtin`. Every other wrapper
still takes the command head, so the guarded command behind it is never judged.
Driven on the Q219 branch, `cwd` set to a scratch workspace:

| command | decision |
|---|---|
| `cat /q219-x` -- control | ask |
| `sudo cat /q219-x` | **(silent)** |
| `doas cat /q219-x` | **(silent)** |
| `caffeinate cat /q219-x` | **(silent)** |
| `chrt 1 cat /q219-x` | **(silent)** |
| `taskset 1 cat /q219-x` | **(silent)** |
| `flock l cat /q219-x` | **(silent)** |

## What a fix has to settle

Adding a row is the mechanism; the grammar is the work, and three of these
carry more than an arity table. `sudo` has run-nothing modes (`-l`, `-v`, `-K`,
`-e`, which edits its operands as files rather than running them), a `-D` that
moves the command's cwd, a `-R` that chroots it so no path means what it says,
and a `-h` that spells both `--help` and `--host` (Q158 is the same question
for prod-guard). `chrt` and `taskset` take a priority or a mask before the
command, and `-p` turns the rest into pids. `flock` takes a lock file first,
and its `-c` runs a shell string.

The peel already refuses to guess past a flag outside its row, so a row that
leaves a rare flag out costs a defer rather than a silent read. That is what
lets each wrapper land with only the flags it can settle.

## If it is never built

`sudo cat <outside>` defers, and in `auto`, `acceptEdits` and
`bypassPermissions` a defer runs. How often sessions reach for these wrappers is
not measured; on the machine this was filed from, `sudo -n true` answers that a
password is required, so `sudo` there runs nothing unattended. Flat cost of
delay.
