# A subscript the lexer splits still hides the command behind it

Q214 taught the shared parser to peel `NAME[sub]=v`, but only once the word
reaches it whole. bash keeps a subscript's contents in one word whatever they
hold, and `lex` splits on every space and every operator character first. So
each of these reads the file in bash and is still read as a command named
`FOO[a`, or similar, by every guard:

| prefix | bash 5.3.15 reads `f` | tokens `lex` hands the guards |
|---|---|---|
| `FOO[a b]=x` | yes | `FOO[a`, `b]=x` |
| `FOO[a;b]=x` | yes | `FOO[a`, `;`, `b]=x` |
| `FOO[a\|b]=x` | yes | `FOO[a`, `\|`, `b]=x` |
| `FOO[a<b]=x` | yes | `FOO[a`, `<`, `b]=x` |
| `FOO[$(echo 0)]=x` | yes | `FOO[$`, `(`, `echo`, `0`, `)`, `]=x` |
| `FOO[$((1+1))]=x` | yes | `FOO[$`, `((`, `1+1`, `))`, `]=x` |
| ``FOO[`echo 0`]=x`` | yes | ``FOO[`echo``, ``0`]=x`` |
| `FOO[""]=x` | yes | one token, `FOO[]=x`, with quoting recorded at the `]` |

Driven 2026-10-01 as `env -i bash --norc --noprofile -c '<prefix> cat f'`. The
`;` and `|` rows are the sharp ones: the guards cut the command there, so the
reader lands in a segment headed `b]=x`.

The last row is a different mechanism with the same symptom. The token is
whole, but `quoted_from` records only where quoting began, so an empty pair
at the `]` cannot be told from a quoted `]` -- and bash treats those
differently (`FOO["]"=x` is a syntax error). `is_assignment` refuses it.

`SubscriptAssignmentTests.test_the_lexer_splits_what_bash_keeps_whole` in
`tests/test_bouncer_parse.py` holds every row above as an assertion that
fails when its gap closes.

## What Q214 got wrong about this class

Q214 listed `FOO["a]b"]=x` and `FOO[a\]b]=x` as spellings that peel in bash.
They do not: on bash 5.3.15 both print `FOO[a]b]=x: command not found` and
leave FOO unset. The parser already refuses them, which is correct, so they
are not part of this row.

## The over-peel half

`is_assignment` now accepts quoting that starts inside a subscript, because
bash peels `FOO["0"]=x` and `FOO['a']=x`. It cannot tell whether that quoting
ran on past the `]`, so `FOO["0]"=x` peels too, where bash reports a syntax
error and runs nothing. That direction costs precision, not security: the
guard judges a command that never runs.

## Which way it gets built

A fix lives in the lexer: bracket depth has to be tracked while words are
split, which is what bash does. That is the shared tokenizer every guard
uses, so it reaches all five and needs `make sync` and every suite.

## If it is never built

Each spelling is a one-token bypass for any guard, the same reach Q214 had,
behind a slightly stranger word.
