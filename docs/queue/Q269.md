# `env` operands never reach a nested `sh -c` body

`env C=<context> bash -c 'kubectl --context "$C" …'` hands the child `C`, and
prod-guard evaluates the body without it. A body pinned to production asks
where the bare prefix denies, and a body pinned to a non-production context
asks where the bare prefix defers.

## Measured

2026-10-04 on the Q176 branch, cut from `origin/main` at `587fbd6`. `main`
gives the same verdicts. The guard ran as a subprocess with the test suite's
fixture `$HOME`:

```
C=gke_acme_prod-us     bash -c 'kubectl --context "$C" delete ns x'  -> deny
env C=gke_acme_prod-us bash -c 'kubectl --context "$C" delete ns x'  -> ask
C=kind-ci              bash -c 'kubectl --context "$C" delete ns x'  -> defer
env C=kind-ci          bash -c 'kubectl --context "$C" delete ns x'  -> ask
```

bash 5.3.15 under `env -i`, with `echo` in place of the tool:

```
env C=from-env bash -c 'echo "body=[$C]"'   -> body=[from-env]
env C=from-env echo "arg=[$C]"              -> arg=[]
```

The second line is why only the nested body is affected. The parent expands
an argument before `env` runs, so `env C=x kubectl --context "$C"` really does
read the parent's `C`, and the guard is right to ignore the operand there.

## Mechanism

`child_env` is built from the segment's inline assignments before the wrapper
walk merges `env`'s operands into them, so the body is evaluated without them:

`plugins/prod-guard/scripts/bash-prod-guard.py:2694:child_env = {**exported, **seg_inline}`

Q176 moved the override check below the walk for the same reason. It left
`child_env` where it was, because the override is a flag on the whole command
and never reaches the body's environment.

## Which way it gets built

Build `child_env` after the walk, or merge the walk's additions into it.
`same_shell`, which expands the segment's own arguments, must stay built
before the walk. Merging there would make `env C=x kubectl --context "$C"`
read `x`, which bash does not do. `env -i` and `env -u NAME` also change what
the child inherits, and the walk drops both today, so decide whether this row
covers them or files them separately.

## If it is never built

The `env` spelling of a `bash -c` call costs one needless prompt for a
non-production context, and turns a production deny into an ask. Neither
direction lets a command through unseen.
