# Two more guards read words after a substitution as a command

Both guards segment on their own and split at the `(` of `$(`, so words after
the close are judged as a new command. Neither of these runs the command it is
judged as. Driven 2026-11-06 at `87361d7`:

| command | guard | verdict |
|---|---|---|
| `echo $(date) git push origin main` | branch-guard | ask |
| `echo $(date) make check \| tail` | exit-status-guard | deny |

workspace-guard had the same split, and Q355 fixed it there. How often these two
fire is not measured. In workspace-guard the fix moved no `ask` to a defer over
32,382 real commands, so expect this to be rare: read it as correctness, and run
the same before/after comparison before spending much on it.

## Which way it gets built

Do not port the fix blindly. `$(echo) git push origin main` and
`env $(echo) git push origin main` run the push under bash, and they are judged
today only because of the split, so a resume has to skip a substitution at the
head and behind a wrapper. `resumes_after_substitution` in workspace-guard is
that test, and a third guard needing it is the point to weigh moving it to `lib/`.
