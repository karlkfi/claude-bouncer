# A guard wired through a non-Python entry point reads as 100% deny

`--plugin all` reads two streams and joins them on a plugin label. The deny
stream reads the label off the reason opener; the attachment stream reads it off
the hook command, and it looks for a `*.py` basename to do it
(`plugins/foreground-guard/scripts/friction-report.py:221:m = re.search(r'([A-Za-z0-9_-]+)\.py', command or '')`).
A guard whose hook command names no `.py` returns `None`, and the walk drops the
record before anything else happens
(`plugins/foreground-guard/scripts/friction-report.py:347:if name is None:`).
Its denies are unaffected, because `DENY_TEXT` matches any `[a-z0-9-]+-guard`
opener (`plugins/foreground-guard/scripts/friction-report.py:129:+ '|'.join([r'[a-z0-9-]+-guard']`).

**The two streams therefore disagree in opposite directions, and the result is
not a visible zero.** It is a plausible deny rate that is wrong, which is the
reading a maintainer acts on.

## Measured

2026-09-11, against `origin/main` at cadc8c1, over 2,069 local transcripts and
137,520 `PreToolUse:Bash` attachments. spill-guard is wired
`"${CLAUDE_PLUGIN_ROOT}/hooks/run-spill-guard.cmd" hook`:

    python3 plugins/foreground-guard/scripts/friction-report.py --plugin spill-guard --since 90d

    spill-guard decisions recorded: 659
      outcomes: deny 659

100% deny. The attachment stream it never reached holds 1,767 records for the
same window and the same guard:

    1650  defer (silent)
      87  ask
      20  hook error/cancelled
       9  defer
       1  unparseable stdout

So the true prompt count is 659 denies plus 87 asks, and the deny share is 88%,
not 100%. The 20 hook-failure records are the sharper loss:
`plugins/foreground-guard/scripts/friction-report.py:134:# this type carries a verdict. The others mean the hook never spoke, so reading`
says the cross-guard view is where you would notice a sibling has stopped
running at all, and for a non-`.py` sibling that is exactly the class the drop
removes.

**Every `.py`-wired sibling resolves, which is the control.** In the same run
`guard_name()` returned a label for all 109,070 workspace-guard records, 16,786
branch-guard, 3,834 pr-sentinel and 262 foreground-guard, and `None` for all
1,767 spill-guard. The probe could and did go both ways.

**spill-guard is not the defect.** It ships the opener the convention asks for —
every one of its denies carries the opener `DENY_TEXT` reads, 659 of them in the
window above — and its launcher is named correctly. The reader is what cannot
see it. Do not file this against `karlkfi/claude-spill-guard`.

## Why it is in scope

`plugins/foreground-guard/scripts/friction-report.py:120:# needs no edit here, but a name outside that shape has to be listed or its`
states that a new sibling guard needs no edit, and the module points at
`plugins/foreground-guard/docs/development/cross-guard-deny-convention.md` as
the cross-repo contract. So siblings from other repos are meant to appear under
`--plugin all`. The deny side already reasons carefully about under-counting —
that is what `NON_GUARD_PLUGINS` and the issue #25 comment are for — and the
attachment side has no equivalent protection and no caveat in the output, where
the deny side prints one
(`plugins/foreground-guard/scripts/friction-report.py:522:"plugin name under-reports")`).

The convention doc's checklist asks a sibling for the opener and says nothing
about the shape of its hook command
(`plugins/foreground-guard/docs/development/cross-guard-deny-convention.md:123:3. Use the same opener on **every** deny path, including the ones added later.`),
so a guard can conform to every published rule and still be half-invisible.

## Which way it gets built

**Not in `lib/`.** `friction-report.py` is not vendored — `scripts/sync-lib.py`
syncs `bouncer_parse.py` and `bouncer_grants.py` only — and the four copies have
already diverged. foreground-guard's is the only one carrying the cross-guard
view, so this is its fix alone.

Fall back, when no `*.py` is found, to the launcher's own basename with a `run-`
prefix stripped, and accept it on the same shape `DENY_TEXT` uses: a `-guard`
suffix, or membership in `NON_GUARD_PLUGINS`. That keeps the two streams
agreeing by construction, which is the property the current docstring is built
on.

Three things that rule has to get right, all measured in the same run:

- **Keep the `.py` search first.** workspace-guard, exit-status-guard and
  branch-guard also wire through a `.cmd`, but pass the script as an argument —
  `"${CLAUDE_PLUGIN_ROOT}/scripts/run-python-hook.cmd" bash-workspace-guard.py`.
  A rule preferring the launcher basename would relabel all three
  `python-hook`, breaking the 125,856 workspace-guard and branch-guard records
  that resolve correctly today.
- **The `-guard` shape is what rejects that launcher anyway.** `python-hook`
  has no `-guard` suffix, so it falls through to `None` correctly.
- **It also keeps project-local hooks unlabelled**, which is required rather
  than incidental. The `None` bucket holds 216 records for
  `claude-piped-gate-hook.sh` and `claude-go-throttle-hook.sh`, which are not
  plugins and must not be credited as any.

Then say so in the convention doc, beside the opener rules: a sibling's hook
command must name its `.py`, or its launcher must carry the plugin name.

**Who is worse off:** whoever runs `--plugin all` to decide where friction is.
**If it is never built:** the blind spot tracks siblings adopting a launcher, so
it widens as the convention succeeds.
