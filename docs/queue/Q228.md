# An abbreviated long wrapper option hides the command from prod-guard

GNU `getopt_long` accepts any unique prefix of a long option, so `--kill` is
`--kill-after` and `--us` is `--user`. `WRAPPER_VALUE_FLAGS` lists only full
spellings, and `flag_arity` (from the Q200 fix) matches a long option whole.
An abbreviated value-taking option therefore drops one word instead of two,
and its value is left standing as the command.

Found by the independent review of the Q200 pull request. Re-driven 2026-10-01
through the hook (fixture `$HOME`, ambient context `gke_acme_prod-us`) at the
Q200 head:

| command | guard |
|---|---|
| `timeout --kill-after 5 10 kubectl delete ns payments` | deny -- control |
| `timeout --kill 5 10 kubectl delete ns payments` | **defer** |
| `timeout --sig KILL 5 kubectl delete ns payments` | **defer** |
| `sudo --user root kubectl delete ns payments` | deny -- control |
| `sudo --us root kubectl delete ns payments` | **defer** |

GNU `timeout` 9.11 runs the command after both abbreviations. That was driven
under `env -i bash --norc --noprofile -c` with a payload absent from `PATH`,
which `timeout` reported as `failed to run command`. The review checked sudo
with `echo RAN`. BSD `env` on this host takes no long options, so GNU env's
`--uns` was not measured.

## Which way it gets built

Match a long option against each value-flag spelling as a prefix, and take the
value when exactly one spelling starts with what was written. An ambiguous or
unknown prefix stays one word. That is a missed deny, the direction this guard
already accepts on parse uncertainty.

## If it is never built

A mutating command behind an abbreviated wrapper option, which GNU tools
document as ordinary usage, reaches production with the guard silent.
