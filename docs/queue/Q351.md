# A captured status that exits on failure still reads as ignored

Rule 3 denies a gate sequenced with `;` before a state change. It also denies
the form where the status is captured, tested, and the script exits on failure
before the state change runs. Re-driven 2026-11-02 against the hook on `main`
at `0608cb6b`:

| Command | Verdict |
|---|---|
| `make check > l 2>&1; rc=$?; [ "$rc" -eq 0 ] && git commit -m x` | no decision |
| `make check > l 2>&1 \|\| exit 1; git commit -m x` | no decision |
| `make check > l 2>&1; rc=$?; [ "$rc" -eq 0 ] \|\| exit 1; git commit -m x` | deny |
| `make check > l 2>&1; rc=$?; [ "$rc" -ne 0 ] && exit 1; git commit -m x` | deny |
| `make check > l 2>&1; rc=$?; if [ "$rc" -ne 0 ]; then exit 1; fi; git commit -m x` | deny |

The last three are false positives. In each, the commit runs only when the
check passed, exactly as in the first two. The rule credits a capture only
when the mutator hangs off the test by an unbroken `&&` chain
(`plugins/exit-status-guard/scripts/bash-exit-status-guard.py:1020:def tested_form(segs, gate_at, mutator_at):`).
A test that exits on failure, and then a `;` before the mutator, is not one of
the shapes it walks.

**Who is worse off.** A session that captures a gate's status to print a log
tail before deciding. That is the shape the guard's own deny text recommends
(`cmd > log 2>&1; rc=$?`), so the guard pushes sessions toward the capture, then
refuses the natural next line. Met once in the 2026-11-01 batch retro, on
`make backlog-lint` before `git commit`. The workaround is a separate call. The
denial costs one rewrite, and the reason it gives ("the status is read
correctly and then ignored") is wrong for this command, which teaches the
session nothing. Flat urgency.

**Next step.** Credit a mutator in `tested_form` when every path from the
capture to the mutator passes a test of the captured variable whose failure
branch is `exit` or `return`: `[ test ] || exit`, `[ !test ] && exit`, and the
`if …; then exit; fi` spelling. Pin all five rows above. Also pin that
`[ "$rc" -eq 0 ] || echo bad; git commit` still denies, because an `echo` is
not an exit.
