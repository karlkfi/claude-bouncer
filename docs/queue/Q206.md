# The launcher stderr reports name neither the plugin nor the script

Every guard prefixes its own verdicts with its plugin name. The shared launcher
does not -- it opens `run-python-hook.cmd: `, which is the same seven reports
from three different plugins, so a user seeing one cannot tell which guard has
stopped enforcing. `karlkfi/claude-ground-truth` PR #16 closed the same gap on
its copy by passing the script name in as the first argument. Re-applying the
mechanism here needs a decision that repo did not have to make.

## Measured

Seven emit sites, not the six the upstream change touched: the cmd.exe half has
four at
`plugins/workspace-guard/scripts/run-python-hook.cmd:47:no working Python 3 interpreter found`
(plus line 48, and the missing-script-name and script-not-found reports above
them), and the POSIX tail has three at
`plugins/workspace-guard/scripts/run-python-hook.cmd:88:no working Python 3 interpreter found`
(plus 89 and its script-not-found). The POSIX half has no missing-script-name
guard where the cmd.exe half does, which is one of several ways the two
families have already diverged -- so this is a re-application, not a file copy.

The three copies are byte-identical, one digest across
`plugins/branch-guard/hooks/`, `plugins/exit-status-guard/scripts/` and
`plugins/workspace-guard/scripts/` (2026-09-10), and must stay that way.

**The script name is not the plugin name here**, which is what ground-truth did
not have to deal with: its hook scripts are `chronos.py` and `kenos.py`, so
naming the script named the plugin for free. The three `hooks.json` entries here
pass `branch-guard.py`, `bash-exit-status-guard.py` and
`bash-workspace-guard.py`. A naive port emits
`run-python-hook.cmd: bash-workspace-guard.py: this guard is NOT enforcing`.

**The reader's mapping already exists, in the reader.** Every friction report
folds the script name back onto the plugin's own at
`plugins/foreground-guard/scripts/friction-report.py:224:name = re.sub(r'^bash-', '', m.group(1))`,
with `guard_name` at line 210 carrying the reasoning. Putting that mapping in
the emitter duplicates it into a batch file and a shell script, in three
vendored copies, with nothing keeping the two in step.

**Neither form satisfies the attribution convention the guards already keep.**
branch-guard's `GUARD_PREFIX` puts the plugin name at position 0, and its
`CLAUDE.md` records that position is the whole assertion. It also records that
foreground-guard 0.5.1 keys its cross-plugin friction report on an anchored
`^(?:Error:\s*)?([a-z0-9-]+-guard):\s` -- which `run-python-hook.cmd: ` fails
today and would still fail with the script name inserted after it.

## Inferred

**Who is worse off**: a user on a machine with no working Python 3, reading a
report that says a guard is not enforcing without saying which. Also any later
sweep of transcripts trying to attribute one.

**Exposure is near zero and the row is ranked on that.** These strings print
only when no Python 3 resolves. An upstream re-measurement over 2,050 local
transcripts on 2026-09-10, taking hook stderr rather than raw string matches,
found zero firings for either wording. Not re-measured here.

**What has to be decided before this is buildable.** Four things, which is why
it is filed rather than shipped:

- What name the launcher emits -- the raw script name, a name derived by
  stripping `bash-`, or the plugin label supplied as its own argument from
  `hooks.json`. The third avoids duplicating the reader's regex and is the only
  one that yields the plugin's actual name, at the cost of a second argument.
- Where it goes in the string. ground-truth keeps `run-python-hook.cmd: `
  first. This repo's own convention, and its friction-report regex, want the
  plugin name at position 0.
- Whether anything gates it. Q134 records that no test drives these lines on
  either half of the polyglot, so a change here ships unasserted unless that
  row lands with or before it.
- Whether the two plugins that bypass the launcher entirely (Q205) are fixed
  first. Shipping this alone attributes three guards of five.

**Ask:** whether the launcher should read as the launcher speaking
(`run-python-hook.cmd: ` first, matching ground-truth) or as the guard speaking
(the plugin name at position 0, matching every other string these plugins
emit). Both are defensible and the choice is about how the two repositories
should relate, which is not settleable from this tree.

`S` once the four questions above are answered.
