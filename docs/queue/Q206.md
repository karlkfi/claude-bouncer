# The launcher stderr reports name neither the plugin nor the script

Every guard prefixes its own verdicts with its plugin name. The shared launcher
does not: it opens `run-python-hook.cmd: `, the same seven reports for five
different plugins, so a user seeing one cannot tell which guard has stopped
enforcing. `karlkfi/claude-ground-truth` PR #16 closed the same gap on its copy
by passing the script name in as the first argument. Re-applying it here needed
a decision that repo did not have to make, and that decision is now made below.

## Measured

Seven emit sites, re-read 2026-10-04 at `442c86e`. The cmd.exe half has four:
missing script name, script not found, and the two lines at
`plugins/workspace-guard/scripts/run-python-hook.cmd:47:no working Python 3 interpreter found`
and 48. The POSIX tail has three: script not found and the two lines at
`plugins/workspace-guard/scripts/run-python-hook.cmd:88:no working Python 3 interpreter found`
and 89. The POSIX half has no missing-script-name guard where the cmd.exe half
does, so this is a re-application, not a file copy.

The five copies are still one blob: `git hash-object` on all five gives
`d23e339` five times. They must stay that way, and Q215 owns keeping them in
step.

**The script name is not the plugin name here.** ground-truth's hook scripts
are `chronos.py` and `kenos.py`, so naming the script named the plugin for
free. The five `hooks.json` files here pass `branch-guard.py`,
`bash-exit-status-guard.py`, `bash-workspace-guard.py`, `bash-prod-guard.py`
and `bash-foreground-guard.py`.

**The reader keys on the plugin name at position 0.** foreground-guard's
friction report recovers a deny with an anchored
`^(?:Error:\s*)?([a-z0-9-]+-guard):\s`
(`plugins/foreground-guard/scripts/friction-report.py:127:DENY_TEXT = re.compile(`).
Today's `run-python-hook.cmd: ` fails that, and so would the script name
inserted after it.

## Which way it gets built

**Ask (answered):** the row asked whether the launcher should read as the
launcher speaking (`run-python-hook.cmd: ` first, matching ground-truth) or as
the guard speaking. That turned out not to be a preference. The
`hook-attribution` skill is the convention these plugins already follow, and
it settles it. Every string a hook hands to the human or the model opens with
"the plugin's own name, spelled exactly as `.claude-plugin/plugin.json` spells
it", at position 0, with a colon and one space. It is "not the script's name",
and a name placed after other text counts as missing. So the guard speaks
first. ground-truth's order is the deviation, not a precedent to match. That
is a finding for that repository, not for this row.

The four sub-questions, answered:

- **Which name.** The plugin label, passed from `hooks.json` as a second
  argument. It is the only one of the three candidates that produces the
  plugin's own spelling, and it keeps the five launcher copies identical,
  because the label lives in each plugin's `hooks.json`, not in the launcher.
  Deriving it by stripping `bash-` would copy the reader's mapping
  (`plugins/foreground-guard/scripts/friction-report.py:229:name = re.sub(r'^bash-', '', m.group(1))`)
  into a batch file and a shell script, with nothing keeping the two in step.
- **Where.** Position 0, as `<plugin>: ` followed by today's text, which keeps
  `run-python-hook.cmd` in the message as the thing that failed.
- **What gates it.** Q134 records that nothing drives these lines on either
  half. The pull request that changes them asserts the new opener on the POSIX
  half at least, in the same change. Where Q134 has landed first, that means
  extending its fixture.
- **Which plugins.** All five. Q205 (#155) routed prod-guard and
  foreground-guard through the launcher, which is why the labels above now
  name every guard.

**Who is worse off:** a user on a machine with no working Python 3, reading a
report that a guard is not enforcing without saying which one. Also any later
sweep of transcripts trying to attribute it.

**If it is never built**, exposure stays near zero. These strings print only
when no Python 3 resolves. An upstream re-measurement over 2,050 transcripts
on 2026-09-10, carried from the earlier version of this row and not re-taken
here, found zero firings. Flat urgency. That rarity is the reason it ranks
low, not that the change is hard.

Rank: it keeps its place, after Q134. `S`: five `hooks.json` edits, one
launcher edit synced to all five copies, and a test.
