# The push-target ask fires on every sibling branch a dispatch pushes

`plugins/branch-guard/hooks/branch-guard.py:1060:return ('ask', f"Push targets '{dst_b}', not the worktree branch '{current}'")`
prompts whenever an explicit refspec names a branch other than the session's
`HEAD`. Under `strict` that is answered before any overlap probe runs, so it is
the cheapest verdict in `push_decision` and the one a parallel run meets most.

The rule reads a push to another branch as a mistake. In a dispatch run it is
the arrangement: one session holds several items, and the branches it pushes are
siblings minted from the same run.

## Measured

Seven days to 2026-08-31. branch-guard raised 62 asks; 29 were this rule, and
every one was approved. The pairs name themselves:

| target | worktree branch |
|---|---|
| `claude/hungry-mahavira-d19a81-q1026` | `claude/hungry-mahavira-d19a81-q1020` |
| `claude/hungry-mahavira-d19a81` | `claude/hungry-mahavira-d19a81-q1020` |
| `claude/cranky-snyder-3651c7-q55` | `claude/cranky-snyder-3651c7-q56` |

Two of the three share a session prefix and differ only in the item suffix. The
guard has the evidence in hand at decision time and does not read it.

## Who it is for

A session in a parallel batch, which meets this once per push and cannot avoid
it — the refspec is explicit precisely because the session is being careful
about which branch it sends. The prompt therefore lands hardest on the sessions
doing the right thing.

## Which way it gets built

Narrow the ask rather than removing it. A push whose destination shares the
session branch's dispatch prefix is the case with no operator judgement in it;
a push to an unrelated branch name still deserves the prompt. Read the prefix
from the branch the worktree holds instead of pattern-matching `claude/`, so
the rule does not encode one naming scheme.

`v1.6.0-rc.2` appears once in the measured set as a push target, which is a tag
cut from a release branch and is not a sibling — that one should keep prompting,
and is a useful negative fixture.

This overlaps `Q135` in file and function and not in subject: that row is about
`push_overlap` measuring the wrong tree and minting `deny-rebase`, this one is
about the `ask` that `push_decision` returns before any probe runs. `Q135` owns
the measurement of the four push verdicts; this row cites it rather than
restating it.

## If it is never built

29 approved prompts a week that scale with batch width — the one prompt class
here that gets worse as parallel dispatch is used more.
