# A wrapper's own `--help` or `--version` denies the command behind it

`--help` and `--version` print usage and run nothing, whichever wrapper they
are given to. `strip_wrappers` drops each as an ordinary flag, so the operands
behind read as a command and a production target in them is denied for
something that was never going to run.

The guard already knows the shape one level down: a help flag on the *covered
tool* defers, and `HelpFlagTests` is that fixture (issue #28). It is the
wrapper's own help that is not read.

Same class as Q157, which shipped `sudo`'s run-nothing modes — five of them,
not the three that row named, since its own criterion yielded more. Those
flags are distinctive to one wrapper; these two are shared by every wrapper in
the table, which is why they need their own row rather than a line in that
one. Q157 deliberately left `-V`/`--version` here rather than taking it.

## Measured

2026-09-09, prod-guard at `6cc585b` with Q161's fix applied, fixture `$HOME`
with ambient context `gke_acme_prod-us`. Every wrapper the guard peels denies:

| command | verdict |
|---|---|
| `kubectl delete --help` | defers — the covered tool's own help, correct |
| `sudo --help kubectl delete ns foo` | **deny** |
| `env --help kubectl delete ns foo` | **deny** |
| `timeout --help 5 kubectl delete ns foo` | **deny** |
| `nohup --help kubectl delete ns foo` | **deny** |
| `command --help kubectl delete ns foo` | **deny** |
| `exec --help kubectl delete ns foo` | **deny** |
| `stdbuf --help kubectl delete ns foo` | **deny** |

`--version` behaves the same on every one of them.

That none of these runs the command was measured separately, against the real
tools with `env -i PATH="$PATH" bash --norc --noprofile -c`, using `echo RAN`
as the operand. Two behaviours, one outcome:

```
timeout --help 5 echo RAN    rc=0    Usage: timeout [OPTION]... DURATION ...
gstdbuf --help echo RAN      rc=0    Usage: gstdbuf OPTION... COMMAND
env --help echo RAN          rc=1    env: illegal option -- h
nohup --help echo RAN        rc=127  nohup: illegal option -- -
sudo --help echo RAN         rc=1    usage: sudo -h | -K | -k | -V
```

The GNU tools print usage and exit 0; the BSD ones reject the flag and exit
non-zero. Neither ran `echo RAN`, and the same five ran it without the flag.
This machine is macOS, so `env`, `nohup` and `sudo` are the BSD spellings —
a Linux runner has the GNU ones, which print help rather than erroring. The
property the guard needs is the same either way.

## Which way it gets built

A shared run-nothing check in the wrapper loop, breaking out of it the way
`command -v` already does (Q142) so the segment stays uncovered and defers.
Both flags are long-form only, which is what keeps this separable from
[Q158](Q158.md): that row is about `sudo -h` meaning two things, and nothing
here reads a short `-h` at all.

`ssh` is the counter-example to check against, not to include — it has no long
options, so `--help` there is a command run on the remote and `HelpFlagTests`
already pins that. The wrapper set is the bound; a wrapper the guard does not
peel is not reached by this.

## If it is never built

A deny where nothing was at stake, which runs the whole Bash call not at all —
so an edit bundled into the same call is silently skipped, the cost Q154
measures for the same class in a sibling guard. Rarer than Q157's, since a
`--help` is usually typed on its own rather than ahead of a full command.
