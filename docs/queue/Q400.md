# exit-status-guard never reads a bash -c body

`bash -c 'make check | tail -5'` exits with `tail`'s status, which is the failure rule 1 denies at top level.
The README states the gap as a limitation (`plugins/exit-status-guard/README.md:572:body is not analyzed.** The quoted string is one word to the`), and the other four guards all read a `-c` body, so this guard is the only one where the wrapper hides the command.

Measured 2026-11-17 on `main` at `b17c7054`, through the hook's launcher:

| command | verdict |
|---|---|
| `make check \| tail -5` (control) | deny |
| `bash -c 'make check \| tail -5'` | **defer** |
| `bash -c "make check \| tail -5"` | **defer** |
| `bash -c 'bash -c "make check \| tail -5"'` | **defer** |

Next step: recurse into a literal `-c` body with the bound the other guards use, judging all three rules inside it, and reconcile the README limitation in the same change.
A `-c` call in the background or behind `;` raises the question of which rule owns the outer status, so settle that before coding.

How often it bites is not measured precisely: a regex over this machine's 30-day commands finds about a hundred `sh -c` bodies holding a `|`, an upper bound that includes pipes no gate is in.
