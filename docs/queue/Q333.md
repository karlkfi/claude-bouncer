# Override hint promises a prompt bypassPermissions cannot give

Under `bypassPermissions`, `decide()` denies every offender
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:4053:    deny_now = bypass or (host_temp_hit and ctx.tmp_action == 'deny') \`),
because an `ask` there has nobody to answer it. Its reason is built without
knowing that, so the cross-workspace denies (sibling-checkout write,
cross-session scratch write, unanchored kill) say two things that are false in
that mode:

- With no override set, the reason ends with `override_hint`'s sentence that
  `WORKSPACE_GUARD_OVERRIDE` "downgrades it to a prompt". It does not: setting
  it still denies.
- With the override set, the reason opens "prompting because
  WORKSPACE_GUARD_OVERRIDE is set"
  (`plugins/workspace-guard/scripts/bash-workspace-guard.py:3390:        lead = ("Unanchored process kill(s) — prompting because "`)
  on a decision that is `deny`.

Measured 2026-11-01 at `5c9f6490` through the hook (the suite's `run_hook`),
`pkill -f node` on the Bash tool and `Stop-Process -Name node` on the
PowerShell tool:

| Mode | Override | Decision | Reason says |
|---|---|---|---|
| `auto` | unset | deny | the override downgrades it to a prompt |
| `auto` | set | ask | prompting because the override is set |
| `bypassPermissions` | unset | deny | the override downgrades it to a prompt |
| `bypassPermissions` | set | **deny** | **prompting** because the override is set |

Both frontends give the same four rows. Found by the independent review of
#298 (https://github.com/karlkfi/claude-bouncer/pull/298#issuecomment-6566994947),
and it predates that PR.

The escalation deny already gets this right. Q210 (#281) made
`escalate_suppression` name only routes its reader can take, and it skips the
hint under `bypassPermissions`
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:3999:        if mode != 'bypassPermissions':`).
`decide()` passes `override` and `prefixable` to `build_reason` but not
`bypass`, so the hint builders cannot do the same.

**The fix:** pass `bypass` through `build_reason` to the three hint builders.
Under it, drop the `override_hint` sentence, and do not open with "prompting"
when the override is set; say the override changes nothing in this mode.
Tests: each cross-workspace category on both frontends, in `bypassPermissions`
with and without the override, asserting no "prompt" promise in the reason.

**If never built:** an agent in `bypassPermissions` reads a route out of the
deny, the operator sets the override, and the next call denies again while
saying it is prompting. That costs a round trip and some trust in the
reasons, and nothing gets through: every verdict here is already `deny`.
