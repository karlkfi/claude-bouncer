# An unquoted brace expansion with a slash escapes the root unjudged

bash turns `docs/{a,../../x}` into `docs/a` and `docs/../../x`.
The hook resolves the unexpanded word, where `{a,..` is one path component that the next `..` cancels, so the outside path is never judged and the call is allowed.

Measured 2026-11-24 on `main` at `de050f70`, with the hook run against this checkout; `bash -c 'echo docs/{a,../../x}'` printed `docs/a docs/../../x`:

| command | verdict |
|---|---|
| `cp README.md ../x` (control) | deny, as a write into a sibling checkout |
| `cp README.md docs/{a,../../x}` | **allow** |
| `cat docs/{a,../../x}` | **allow** |
| `rm {,../}x` | **allow** |

The `for`-list path already refuses a brace item (`literal_for_item`), so a loop over the same word denies.
The side-session notes exemption refuses a resolved path that still holds a brace, and has the same gap where a later `..` cancels it: `<run>/{a,../../x}/../y` is allowed.

Next step: expand an unquoted brace list to its words before any operand is judged, or give such an operand the `expand` deny.
A quoted brace must stay literal, which needs the per-character quoting that `QuotedStr` does not carry for a partly quoted word.
Count how many recorded commands use a brace operand before choosing between the two.

## If it is never built

A call whose brace list holds `..` or an absolute path reads or writes outside the project with no prompt.
