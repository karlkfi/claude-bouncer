# A value-taking wrapper flag hides the command from Class B

`strip_head` peels a `PLAIN_WRAPPERS` head and then drops leading flags one
token at a time
(`plugins/foreground-guard/scripts/bash-foreground-guard.py:385:while argv and argv[0].startswith('-')`).
A flag that takes a *separate* value leaves that value standing as the command
word, so a registered script one token to its right matches nothing and the
segment defers.

This is Q152 in a second tree. That row is prod-guard's
`strip_wrappers`, where the cost is a mutating command against production
running unprompted; here it is a registered slow gate running in the foreground
with no warning. The two share a mechanism and nothing else — different plugin,
different function, different flag sets — so neither fix closes the other, and
the shared half is a habit rather than a line of code.

Q149 fixed the same shape one function down, in the interpreter option peel,
and could not reach this one: its arity table is the shell's own options, not
the wrappers'.

## Measured

2026-09-04, against this tree with the README's own registration
`{"scripts/gate\\.sh": 3600000}`:

| command | verdict |
|---|---|
| `nohup scripts/gate.sh` | deny — correct |
| `builtin scripts/gate.sh` | deny — correct |
| `command scripts/gate.sh` | deny — correct |
| `exec scripts/gate.sh` | deny — correct |
| `stdbuf -oL scripts/gate.sh` | deny — correct |
| `unbuffer -p scripts/gate.sh` | deny — correct |
| `exec -a gate scripts/gate.sh` | **defers** |
| `stdbuf -o L scripts/gate.sh` | **defers** |
| `stdbuf -o L -e 0 scripts/gate.sh` | **defers** |
| `/usr/bin/time -o out.txt scripts/gate.sh` | **defers** |
| `/usr/bin/time -f %e scripts/gate.sh` | **defers** (see the platform note) |

The attached form `-oL` is unaffected, which is what makes the separate value
the whole of the defect.

All three wrappers really do run the command after the flag, verified rather
than assumed: `stdbuf -o L echo RAN`, `exec -a x echo RAN` and
`/usr/bin/time -o /dev/null echo RAN` each print `RAN`. `nohup`, `builtin`,
`command` and `unbuffer` carry no value-taking flag in that position.

**The flag sets are platform-split, so read the usage rather than a GNU list.**
Measured on this machine (macOS, BSD userland) by running each tool:

    /usr/bin/time: usage: time [-al] [-h | -p] [-o file] utility [argument ...]
    stdbuf:        usage: stdbuf [-e 0|L|B|<sz>] [-i 0|L|B|<sz>] [-o 0|L|B|<sz>] <cmd> [args ...]

So here `time` takes `-o` and nothing else — `-f`, `--format` and `--output` are
all rejected (`illegal option`) — and `stdbuf` has no long forms at all. GNU
coreutils has all of them, which is why a table written from a GNU list would
carry flags this platform never sees, and a table written from this one would
miss the leaks a Linux runner really has. `time -f %e` is therefore a real leak
on GNU and a parse artifact here: the guard drops `-f` and reads `%e` as the
command word, but `/usr/bin/time` exits on the flag and the gate never runs.
Cover both sets, and let the union be deliberate rather than accidental.

## Which way it gets built

Give each wrapper its own value-taking flag set and skip flag *and* value, the
way `sudo`, `env` and `timeout` already are a few lines above in the same
function — `exec` takes `-a`; `time` takes `-o` on BSD and additionally
`--output`, `-f` and `--format` on GNU; `stdbuf` takes `-i`/`-o`/`-e`, plus
their `--input`/`--output`/`--error` long forms on GNU only. Those three are
the fixtures to match against. Q152 prescribes the same shape for prod-guard, so
whoever takes one should read the other before writing a second table by hand.

## If it is never built

A registered gate invoked through `stdbuf -o L` or `time -o` runs unguarded,
and the reducer keeps the shape Q149 was filed against: being wrong about the
command word produces no signal in either direction, so nothing reports the
miss and no friction report can count it.
