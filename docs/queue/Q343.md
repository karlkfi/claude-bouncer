# exit-status-guard denies an array assignment holding a quoted `)`

`arr=(")" $(make check))` is denied as a gate's status lost behind another
command, though bash keeps that status: under
`env -i /opt/homebrew/bin/bash --norc --noprofile -c` (5.3.15),
`arr=(")" $(false))` exits 1. The guard denies it on `origin/main` at
76d5c891.

The Q291 rule folds each `NAME=(` … `)` into one assignment word before it
segments the command, and the fold stops at the first token equal to `)`
(`plugins/exit-status-guard/scripts/bash-exit-status-guard.py:1256:            while j < len(tokens) and tokens[j] != ')':`).
A quoted `")"` is the same string after quote removal, so the fold closes on
it, and the substitution after it reads as a command word. The stream E
reviewer found it on #306 (comment 6567895522).

## Which way it gets built

Close the fold only on an unquoted `)`: one the lexer emitted as an
operator, not one that came from a quoted word. Add `arr=(")" $(make check))`
as a silent case beside the other array cases.

## If it is never built

A false deny, whose rewrite (`out=$(cmd)`, then build the array from `$out`)
still works. The Q291 transcript replay — 51,416 distinct Bash commands
holding a substitution — found no array assignment among the 44 commands that
rule newly denies, so the shape is rare. The cost of delay is flat.
