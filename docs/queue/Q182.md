# One regex drops two classes of citation, and reports neither

`CITATION_RE` in `scripts/queue.py` is two lines, and each drops a class of
citation on the floor. Neither is a note the window suppresses and neither is a
class `--strict` can promote: nothing is emitted, at any window, under any flag.

`scripts/queue.py:86:CITATION_RE = re.compile(`

**The path half** — line 87 — requires the cited path to end in one of a fixed
list of extensions (`go|py|sh|md|ya?ml|json|ts|js|rs|java`). A path with no
extension matches nothing, so the citation is never recognised as a citation.

**The fragment half** — line 88 — opens the fragment group with `\S`. A fragment
whose first character is whitespace fails it, the optional group does not match,
and the citation silently degrades to bare `path:line`. That is worse than a
miss: it still resolves, so it reads as checked.

Measured 2026-09-09 on `origin/main` at `80d19b3`, by driving the regex on two
strings differing only in leading spaces:

```
'`exhibit:a/b.py:12:def foo():`'      -> fragment='def foo():'
'`exhibit:a/b.py:12:    def foo():`'  -> fragment=None
```

(The `exhibit:` prefix on those two is not part of the input being demonstrated —
it is there because a synthetic citation inside this row is still a citation to
the checker, which is the same class of self-reference the row is about.)

**`grep -n` on an indented line produces the second form**, so the whitespace
case is what a *careful* copy looks like rather than a careless one. The trigger
is the fragment opening with whitespace, not the line being indented — a copier
who trims the indent is safe and does not know why.

## What the store actually holds

Sixteen citations in other rows the checker cannot see, against **one** it
reports as drifted at `--citation-window 0 --strict stale-citation` on the same
tree.

| class | count | where |
|---|---|---|
| extensionless path | 7 | Q115 ×2, Q132, Q134 ×3, Q183 |
| whitespace fragment | 9 | Q179 ×7, Q180 ×2 |

One of Q115's two is a bare mention of a line it had wrong once; the
load-bearing remainder is Q115's `Makefile:85`, Q132's `Makefile:81`, Q134's
three, and Q183's `Makefile:101`. Q134 is the one that retires the guess this
row used to make: it cites `plugins/branch-guard/.gitattributes:4` and
`run-python-hook.cmd:40` and `:46`, all invisible, while the `run.sh` citation
beside them is checked. So the class is `.cmd` and `.gitattributes` as well as
`Makefile` — measured, where the earlier version of this row speculated about
`.githooks/pre-commit` and `LICENSE` and had no instance beyond its own.

Q115 and Q132 are stale on `main` right now and always have been silently:
`Makefile:85` is a blank line and `Makefile:81` is `done`, with the fragments
they name at 101 and 97.

**This row adds eight more, which is the count demonstrating itself.** Quoting
the paths above re-cites them — seven occurrences of five paths — and the
second exhibit's fragment opens with whitespace. That is 24 invisible on the
tree carrying this amendment, still against the same one reported. The ratio is
a reading of a tree rather than a constant; what does not move is that neither
number is reachable from anything the linter prints.

## Who it is for

Anyone who writes a citation the regex does not recognise — and every later
reader who takes a clean `--citation-window 0` run to mean the store's citations
were checked. That reader is the one this costs, because the run is clean and
the belief is wrong.

## What happens if it is never built

The convention keeps its gate for source files cited without indentation and has
none for anything else, at a ratio measured here of 24 unchecked to 1
reported. The
cost falls on the reader who follows a number to the wrong line and believes it,
which is the failure the fragment field was added to prevent.

## Which way it gets built

**One regex, both halves, or the fix manufactures a false close.** This is the
part to get right: an implementer who fixes only the path half goes green, closes
this row, and ships a checker that still degrades every whitespace-opening
fragment silently — and
the completed row then reads as the defect being gone. The two halves are one
line apart in one expression, so whoever edits either is already holding the
other.

The path half has two candidates and the choice is the item. Widening the
extension list is smaller and keeps the anchor that stops the pattern matching
ordinary prose like `Q92:1`; it fixes today's instances and leaves the next
extensionless file out. Matching a path with no extension needs a different
anchor to stay safe — most plausibly requiring the path to resolve in the tree
before treating the match as a citation, which is a check the linter already
performs one step later.

The fragment half is narrower: `\S` exists to stop a fragment opening with a
space, which `grep -n` never emits *for the line's own text*. It does emit one
when the line is indented. Relaxing it wants a rule that still refuses an empty
fragment, and the fragments already in the store are the fixtures.

**Fix it upstream first.** `scripts/queue.py` is vendored from
`karlkfi/claude-skills`, so a repair made only here is reverted by the next
vendor drop — the hazard `docs/development/maintaining-backlog.md` already
names. The `lib` label is for that reach rather than for `lib/`: the fix lands
in a file five guards' repos share by copy.

## Notes

The path half was found 2026-09-09 while working Q92, whose diff edits the
`Makefile` and so moves both cited lines; they were already wrong before that
edit, which is why this is a row rather than part of that change.

**The fragment half is the workspace-guard stream's reading** (worktree
`objective-gould-7ac26c`), arrived at independently and merged into this row
because it is the same expression. Their contribution is not the count but the
trigger: they relocated it from "the cited line is indented" to "the fragment
opens with whitespace", which is what makes it a property of how the citation
was copied rather than of the code being cited — and therefore why a careful
`grep -n` copy is the one that fails.
