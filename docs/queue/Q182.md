# Citation checking is blind to a path with no file extension

`CITATION_RE` in `scripts/queue.py` requires the cited path to end in one of a
fixed list of extensions:

`scripts/queue.py:87:r"\b([\w./-]+\.(?:go|py|sh|md|ya?ml|json|ts|js|rs|java)):(\d+)"`

`Makefile` matches none of them, so a citation into it is never recognised as a
citation at all. It is not a note the window suppresses and not a class
`--strict` can promote — nothing is emitted, at any window, under any flag. That
is a third way a citation can go unchecked, beside the two Q115 already
separates.

Two rows in this store are stale on `main` right now because of it:

| row | cites | what that line actually holds |
|---|---|---|
| Q115 | `Makefile:85` `--strict blocked-opener …` | blank; the fragment is at 93 |
| Q132 | `Makefile:81` `` `dangling-link` stays advisory … `` | `$(PYTHON) scripts/render-images.py`; the fragment is at 89 |

Measured 2026-09-09 against `origin/main` at `fe7ad9a`, by running
`CITATION_RE` over both citation lines directly: no match, where the same probe
on a `.py` citation from Q135 matches. `queue.py lint --citation-window 0
--strict stale-citation` reports 40 drifted citations over this store and
neither of these, which is what makes the hole quiet — the gate looks like it
swept the store.

## Who it is for

Anyone who writes a citation into a file the list does not name, and every
later reader who trusts a clean `--citation-window 0` run to mean the store's
citations were checked. `Makefile` is the case in the tree today;
`.githooks/pre-commit` and `LICENSE` are the same shape.

## What happens if it is never built

The citation convention keeps its gate for source files and quietly has none
for the rest, so drift into them accumulates at whatever rate rows cite them —
two rows so far. The cost is paid by the reader who follows a number to the
wrong line and believes it, which is the failure the fragment was added to
prevent.

## Which way it gets built

Two candidates, and the choice is the item.

Widening the extension list is the smaller change and keeps the anchor that
stops the pattern matching ordinary prose like `Q92:1`. It fixes `Makefile` and
leaves the next extensionless file out.

Matching a path with no extension needs a different anchor to stay safe — most
plausibly requiring the path to resolve in the tree before treating the match
as a citation, which is a check the linter already performs one step later.

**Fix it upstream first.** `scripts/queue.py` is vendored from
`karlkfi/claude-skills`, so a repair made only here is reverted by the next
vendor drop — the hazard `docs/development/maintaining-backlog.md` already
names. The `lib` label is for that reach rather than for `lib/`: the fix lands
in a file five guards' repos share by copy.
