# exit-status-guard never reads a substitution inside arithmetic

`echo $(( $(make check | tail -1 | wc -c) ))` gets no decision from exit-status-guard, on `main` and on Q339's head (#329, `c8d9707`). bash runs the substitution: under `env -i /opt/homebrew/bin/bash --norc --noprofile -c` (5.3.15), a stand-in body that writes to stderr does write. prod-guard and foreground-guard deny the same shape with their own stand-ins.

Two things hide it.
Before shlex reads the command, `mask_arithmetic` replaces the whole expansion with one word, so the segment loop never sees the pipe.
The recursion into substitution bodies then gets nothing either: `command_substitutions("echo $(( $(make check | tail -1 | wc -c) ))")` from `lib/` returns `[]`, because it steps over `$((…))` whole.
The #329 reviewer found it, and Q339's worker reproduced both readings.

## Which way it gets built

Find the `$( )` bodies inside each arithmetic span and decide them like any other substitution body.
Either exit-status-guard collects them itself while masking, or `command_substitutions` learns to descend into arithmetic.
The second reaches all five guards, and how prod-guard and foreground-guard already reach these bodies has not been traced.
Read that first: it may be the primitive to reuse.
Pin the command above with a test that fails on `main`.

## If it is never built

A gate piped inside a substitution inside arithmetic loses its status unnoticed.
Counting a gate's output with `$(( $(…| wc -c) ))` is a plausible shape, but it is rare.
