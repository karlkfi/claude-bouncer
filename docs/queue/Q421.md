# Each unclosed brace level still costs a scan to the end of the text

`echo ${x:-$(${x:-$(`…`echo ; rm /etc/probe-target`, with the `${x:-$(` pair repeated d times and nothing closed, still costs `command_substitutions` time quadratic in d.
Measured with the Q370 fix in place, calling the parser directly:

| d | 24 | 200 | 2000 |
|---|---|---|---|
| seconds, unquoted | 0.0016 | 0.10 | 9.95 |
| seconds, in double quotes | 0.0008 | 0.05 | 4.99 |

Before Q370 the cost doubled per level and d=24 took past 90 seconds, so this is what is left rather than a regression. bash runs nothing for the shape, and a 2,000-level command is about 14,000 characters, so it is reached only by a command built to stall the guards.

## Why it is quadratic

Each `${x:-$(` brace scans its `$(` body through `_scan_dollar_paren_steps`, which reads a nested `$(` inline on its own frame stack rather than yielding a keyed nested scan.
So the keyed memo `_trampoline` keeps cannot answer for it, and every level's body scan walks on to the end of the text.
A cProfile at d=600 counted 360,600 resumes of `_scan_dollar_paren_steps`, about 600 × 601.

## Which way it gets built

Making the inline `$(` a keyed nested scan would let the memo answer it, but each inline frame saves the scan's own state (`cmd_pos, clauses, pending, parens, brk, dollar, braces`), so that is a restructuring of the scan rather than a new key.
A cheaper bound may do, not yet measured: a brace whose body scan failed once at a start fails at every later start inside it.
Pin d=2000 with a call count in the parser suite, the way `test_unclosed_brace_levels_are_scanned_once` pins d=24.
