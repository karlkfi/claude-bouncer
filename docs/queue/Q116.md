# A row should not assert an ordinal, a count, or a live ID as an example

Nothing reads prose, so a durable claim about a mutable set rots silently in a
store that deletes rows on completion. Two instances, from the 2026-08-22/23
batch, and they are the same defect:

**An ordinal counts a set that changes underneath it.** Q103 closed with
"Third in the set of Bash-side behaviours the PowerShell frontend has not
taken, beside Q73 and Q76." By rank it was second, not third — the sentence was
already wrong before anyone touched it. A session correcting it for a different
reason nearly replaced the stale ordinal with a fresh one, which would have
been true that morning and wrong by lunchtime, since two of the three items
merged that day. The fix that held writes set membership in the **past tense**:
"The set also held the interpreter suppression (Q73) and the entry-operand
roles (Q76)" stays true whatever becomes of Q73, Q76 or the ranks, because it
claims they were in the set rather than that they still are.

**A real ID used as an example dangles as soon as that item ships.**
`docs/queue/README.md` uses Q76 for its "what an item looks like" block. Q76
completed on 2026-08-23, so the store's own front-door doc now illustrates the
format with an item the store no longer holds. That file has one commit in its
whole history, written at store creation, so nothing about the current process
would ever have refreshed it — which is the point: an example is exactly the
kind of text nobody revisits. A placeholder that can never be allocated retires
the problem permanently.

**What to decide.** The README fix is concrete and one edit. The convention is
the part worth arguing: whether it belongs in `maintaining-backlog.md` as a
rule, in the `session-backlog` skill as guidance for every repo using this
layout, or nowhere because a reader can be trusted to notice. Note the skill
already reaches this class from one side — it flags a link at an item the store
no longer holds — and reaches neither an ordinal nor a bare-ID example, both of
which are prose a linter cannot decide.

Worth checking in the same pass whether anything else in the store carries an
ordinal or a count over a set of rows. This came from two sightings in one
batch rather than from a sweep.
