# Archive the five retired repos, once the first tags publish from here

An install predating the consolidation is pinned to `<plugin>@<plugin>` on a
retired marketplace, and nothing there will ever move again. Measured
2026-08-24 with `gh api`: all five of `claude-workspace-guard`,
`claude-branch-guard`, `claude-prod-guard`, `claude-exit-status-guard` and
`claude-foreground-guard` are public and unarchived, none names claude-bouncer
in its description, and each still serves the exact version this repo does —
1.10.0, 1.9.0, 2.5.1, 2.0.0, 0.5.1.

Parity is what made holding them open right. An archive notice pointing at a
marketplace with no tags behind it sends a reader to the version they already
have. The five bumps in this release end the parity: from the merge onward an
old-marketplace install is behind and has no way to learn it.

`claude-exit-status-guard` answers to `claude-pipe-guard` as well, because 2.0.0
renamed it and GitHub still redirects the old path — including through `gh api`,
which returns the renamed repo without saying it followed a redirect.
`scripts/verify-release-notes.sh` composes its fallback venue as
`karlkfi/claude-<plugin>`, so it lands on the current name by luck rather than by
knowing; a plugin renamed the other way would send it somewhere that does not exist.

The work lands in the five retired repos rather than this one. Each needs a
README banner and a description naming `karlkfi/claude-bouncer`, the two
`/plugin` lines that replace the old pair, and then the archive flag. Archiving
makes a repo read-only and is reversible, and the 279 issue, pull-request and
tag-pinned links still pointing into these repos keep resolving either way —
that is why the plan is to archive them rather than delete them.
