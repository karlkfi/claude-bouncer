# A quoted assignment in command position arms the override

Every guard reads its tokens from a lexer that has already stripped the quotes,
then classifies them with
`lib/bouncer_parse.py:42:ASSIGNMENT_RE = re.compile(r'^[A-Za-z_][A-Za-z0-9_]*=')`.
So a word bash reads as a **command name** — because something in it up to and
including the `=` was quoted or escaped — is read here as an inline assignment.
Nine spellings put `PROD_GUARD_OVERRIDE` into the env dict that arms the escape
hatch. Bash runs none of them as an assignment; it looks for a program with that
name and fails to find one.

The two consumers are
`plugins/prod-guard/scripts/bash-prod-guard.py:491:while i < len(argv) and ASSIGNMENT_RE.match(argv[i]):`,
which peels the prefix that carries the override, and
`lib/bouncer_parse.py:775:while i < len(tokens) and ASSIGNMENT_RE.match(tokens[i]):`,
which peels it so the guards can find the real command word. Both take
post-`lex` tokens, so neither can see that a quote was ever there.

## Measured

Driven 2026-08-31 against prod-guard 2.5.2 and re-driven 2026-09-07 against

C4 is in the table because eleven ARMEDs in a row is the shape of a probe that
cannot return anything else. It is the case that proves the drive can print a
dash.

bash 5.3.15 on the same forms, reading whether the variable was set or the word
was executed:

```
SG_OVR=x env             set    -- an assignment
SG_OVR='x y' env         set    -- an assignment
SG_OVR=x"y" env          set    -- an assignment
'SG_OVR=x' env           --     command not found
"SG_OVR=x" env           --     command not found
'SG'_OVR=x env           --     command not found
"SG"_OVR=x env           --     command not found
SG_OVR''=x env           --     command not found
\SG_OVR=x env            --     command not found
S\G_OVR=x env            --     command not found
SG_OVR\=x env            --     command not found
```

**The rule the drive establishes**: quoting *or escaping* any character up to
and including the `=` makes the word a command; quoting inside the value leaves
it an assignment. Nine spellings are in the class, both guards arm on all nine,
and neither guard's tests name more than two.

**Write the list into a fix as a floor, not a census.** `SG_OVR\=x` is the
spelling to keep in view: the escaped character is the `=` itself, which is
neither name nor value, so a spec written as *quoting the name* does not
classify it — and backslash is a third quoting mechanism a pass over `'` and `"`
alone never reaches. A fix written against the narrower spec ships, turns its
flipped pins green, and leaves that spelling arming in all five guards.

## Who it is for, and what it is worth

The person reading a permission prompt or a denial before approving it. The
exposure is bounded in both places this was driven: `PROD_GUARD_OVERRIDE` skips
a prompt, and spill-guard's equivalent downgrades a block to a confirmation.
Neither is an allow, so nothing is sent or run without a human seeing it.

What it costs is the stated defence of command-position-only, which is
**legibility** — the override sits in the command a human is being asked to
approve, so a reader can see it. `'PROD_GUARD_OVERRIDE=x'` is not a spelling any
reader would call an override, and it is a plausible thing to type by accident
when quoting a value.

## What happens if it is never built

The guards keep honouring nine break-glass spellings that bash does not, and the
argument for putting the override in command position keeps being made about a
position the parser does not actually enforce. Nothing reports it: the arming is
silent by construction, and the command it was attached to fails with `command
not found` for reasons unrelated to the guard.

## Which way it gets built

**Unknown, and the row deliberately does not guess.** One constraint is
established and it rules out the obvious approach: a probe that keeps the quotes
in the token — the natural way to carry provenance — breaks six `TestLex` cases
upstream in spill-guard: a quoted operator character, a quoted newline, two
backslash-in-quotes cases, a backslash before a closing quote, and an empty
quoted word. So the lexer's contract is that callers receive quote-stripped
tokens, and both `internal/readers` there and `extract_env_prefix` here consume
them on that basis. **Provenance has to travel beside the token, not inside
it**, and nobody has measured what shape that should take.

**Measure:** what a per-token provenance channel costs — a parallel list of
was-any-of-this-word-quoted flags out of `lex`, versus a second classifier that
re-scans the raw string for the command word's extent. Read it against the
`TestLex` contract above and against every `ASSIGNMENT_RE` call site in this
tree, then write the chosen shape into this row and drop the label.
