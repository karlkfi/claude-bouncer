# One companion-plugin roster across all five READMEs

Each guard's README names a different subset of its siblings and then states
the count in prose, so all five disagree with each other and four are stale.
Measured 2026-08-22:

- `plugins/exit-status-guard/README.md` — four siblings plus pr-sentinel, and
  the only current one.
- `plugins/foreground-guard/README.md` — three siblings, then "All four
  compose".
- `plugins/prod-guard/README.md` — two siblings, then "All three run side by
  side".
- `plugins/branch-guard/README.md` — "## Companion plugin", workspace-guard
  alone.
- `plugins/workspace-guard/README.md` — "## Companion plugin: branch-guard",
  branch-guard alone.

The prose count is what makes each one rot separately: adding a guard means
editing five sections that each phrase the roster differently, and nothing
fails when one is missed. Settle a single shape and apply it to all five. The
six plugins are already enumerated in
[cross-guard-deny-convention.md](../../plugins/foreground-guard/docs/development/cross-guard-deny-convention.md),
so the roster has a source; what it does not have is one form.
