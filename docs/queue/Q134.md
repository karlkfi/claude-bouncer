# Nothing drives the launcher path that warns the guard is not enforcing

The launcher is LF-only and carries a construction that broke an identically
built launcher in a sibling project. It is also driven through cmd.exe on every
Windows run and green, which the sibling's never was. So the line-ending
question is answered and the coverage gap the check turned up is not.

## Measured

branch-guard 1.10.0, the version installed on this machine, ships
`hooks/run-python-hook.cmd` at 3481 bytes with 0 CRLF and 90 bare LF. The tree
copy is byte-identical (`cmp`, 2026-08-25).
`plugins/branch-guard/.gitattributes:4:* text=auto eol=lf` is why, and that is
the same line that made the sibling's copy LF-only.

The label lookups sit at
`plugins/branch-guard/hooks/run-python-hook.cmd:40:for %%I in ("py -3" "python" "python3") do (`.
Lines 40-43 are a parenthesized block issuing `call :try_interp` and
`goto :found` from inside it; `:found` is at 51 and `:try_interp` at 55. Lines
45-49 are the fall-through: two stderr lines saying the guard is NOT enforcing,
then `exit /b 1`.

**cmd.exe runs this file on every Windows CI run.**
The `branch-guard-windows` job in `.github/workflows/tests.yml` runs
`bash test/run.sh` on `windows-latest`, Git Bash hands a `.cmd` to the Windows command processor,
and `plugins/branch-guard/test/run.sh:225:launcher answers from its cmd.exe half`
pins that rather than assuming it. Every fixture but the missing-script one
passes a real script name, so the block at 40-43 and its `goto :found` run
under cmd.exe in every one of them, and a label lookup that missed would take
every decision to empty. Green on `main` at d51a5b5: run 32797942729, job
97652997285, 494 passed and 0 failed.

**Nothing drives lines 45-49.** No case anywhere runs the launcher with Python
off `PATH`, so the two stderr lines and the exit code are unasserted on either
half of the polyglot. `plugins/exit-status-guard/scripts/run-python-hook.cmd`
and `plugins/workspace-guard/scripts/run-python-hook.cmd` have the same hole.
The work here is branch-guard's copy.

## Inferred

**The sibling result is a reason to look, not a defect proven here.** In
`karlkfi/claude-spill-guard`, `hooks/run-spill-guard.cmd` shipped LF-only from
the same `.gitattributes` line, and on `windows-latest` cmd.exe answered
`The system cannot find the batch label specified - deny_missing`. Four arms,
three cases each: `block x LF` was the only failing one, and every CRLF arm
died on POSIX with `set: Illegal option -`. GitHub Actions runs 32810504524 and
32810620064 in that repo are the durable evidence, since the branch is deleted;
the write-up is `docs/queue/Q54.md` on that repo's `main` at d65c0b1. The
geometry is not the same. There the fall-through ran *past* a block to reach a
later `goto`; here the `goto` is issued from inside the block and the
fall-through ends in `exit /b 1`, so the measured shape does not occur in this
file. What the two share is a label lookup resolving past a parenthesized block
in an LF-only batch file. Given the driven green above, that is closed for this
file. Do not reopen it on resemblance, and note that a `.gitattributes` flip
would not have been the fix anyway: CRLF is what breaks the POSIX tail this
file carries in the same bytes.

**`exit /b 1` on a missing interpreter is the design, not the defect.** Claude
Code treats a failed PreToolUse hook as non-blocking, which the file's own
header says, so the exit code is not what protects anyone. The two stderr lines
are, and
`plugins/branch-guard/hooks/run-python-hook.cmd:46:instead of silently degrading into an unenforced guard`
says as much. That is the sharp end. If a label lookup ever does die first, on
this file or on the next edit to it, the user gets neither the guard nor the
warning: the designed failure path is loud, and that one would be silent.

**Who is worse off**: a Windows user whose `py -3`, `python` and `python3` all
fail, which is the Microsoft Store stub case the launcher exists for. **If it
is never built**, the one path that tells them they are unprotected stays the
one path no run has ever taken.

**Which way it gets built.** One case in `test/run.sh`, guarded on
`NATIVE_PATHS` the way the polyglot-half check already is, invoking the
launcher with every Python removed from `PATH` and asserting exit 1 plus both
stderr lines. Settling the remaining question costs that one driven case. The
shape ports to the other two launchers; file those separately if they are
wanted.

`S` holds. Rank `aar` puts it beside the other coverage gaps, below Q108 and
above Q82.
