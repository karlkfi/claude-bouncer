# nawk is not guarded as an alias of awk

`ALIASES` maps `gawk` and `mawk` to the `awk` row, but not `nawk`, the name
the one-true-awk lineage still installs on some systems. So `nawk` is no
guarded command at all, and neither its operands nor its program are read:

| Command | Verdict |
|---|---|
| `nawk '{print}' /q334-fake/x` | defer |
| `nawk '{print > "/q334-fake/x"}' f` | defer |
| `awk '{print}' /q334-fake/x` | ask |

Measured 2026-11-17 by running the hook on the Q334 branch against a scratch
workspace; reviewer C raised it in the Q334 review. A defer runs unexamined in
`auto` and `bypassPermissions`. macOS has no `/usr/bin/nawk` (checked), so
whether nawk's flag set matches the `awk` row's, the question an alias has to
answer (see Q3 on `rg`), was not measured.

## Where it lands

`ALIASES` in `bash-workspace-guard.py`, and the guarded-command list in the
README.
