# A git variable that runs a program rides a read-only allow

`GIT_EXTERNAL_DIFF='echo ran-external-diff' git diff` is auto-approved, and git
runs the program: measured 2026-11-01 on git 2.55 in a scratch repository,
where the hook answered `allow` and the diff printed `ran-external-diff`. The
same shape holds for any variable git executes, such as `GIT_SSH_COMMAND` on a
fetch and `GIT_PAGER` or `PAGER` when stdout is a terminal (both unmeasured),
and for a loader variable like `LD_PRELOAD` that any program honours.

Q305 treats a `GIT_CONFIG*` variable as the `-c` escape hatch it spells, so
config can no longer reach an allow. A variable that names a program directly
is the same reach without config, and the prefix is read as harmless
(`FOO=1 git log` allows, rightly).

Bites only when a session sets such a variable, which is rare and is exactly
the shape that gets code past an auto-approve. Next step: decide whether to
name the git variables that execute (from git(1) ENVIRONMENT) and downgrade
an allow beside them as `env_configures` does, or to withhold an allow from any
prefix assignment outside a short safe list, and measure what each costs on
the transcripts first.
