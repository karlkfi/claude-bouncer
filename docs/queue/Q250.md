# GNU env -a hides the git command from branch-guard

GNU `env` takes `-a NAME` (long form `--argv0`) to set the command's
`argv[0]`, then runs the command after it. branch-guard's `env` entry in
`WRAPPER_VALUE_OPTS` does not list it
(`plugins/branch-guard/hooks/branch-guard.py:'env': frozenset({'-u', '--unset', '-C', '--chdir', '-P',`),
so `-a` consumes one word instead of two. Its value is then read as the
command, and the guard has no opinion.

Measured 2026-10-04 from a feature-branch worktree, at #173's head `bf31961`
(Q223, which added the wrapper peeling) and at `origin/main` `a3c9052`:

| command | #173 | main |
|---|---|---|
| `git push --force origin main` (control) | ask | ask |
| `env -a x git push --force origin main` | none | none |
| `env --argv0 x git push --force origin main` | none | none |
| `env -ia x git push --force origin main` | none | none |
| `env --argv0=x git push --force origin main` | ask | none |

The `=` spelling asks only because its value is inside the same word, so
skipping one word happens to be right. "none" falls through to Claude Code's own permission flow
rather than to an allow, so this is a missed ask, not an auto-approve. The
independent review of #173 found it, and `genv --help` on coreutils 9.11 lists
`-a, --argv0=ARG`. GNU env 9.11 ran the command after `-a zz` here. BSD `env`
has no `-a`, so this reaches hosts where `env` is GNU's.

The same gap was filed for prod-guard as Q245 and fixed for foreground-guard
in Q221, both in flight when this row was filed. exit-status-guard's new
`env` entry in #185 (Q222) also lacks `-a`. Q233 is the row that moves these
tables into `lib/` so that one entry covers all five guards.

## Which way it gets built

Add `-a` and `--argv0` to the `env` entry, and add `env -a x`,
`env --argv0 x` and `env -ia x` to section 29a's wrapper loop in
`test/run.sh`. Check that each of them fails with the entry removed.

**Who is worse off:** a session on a GNU host whose `env -a` push to `main`
reaches the normal permission prompt without the guard's reason, or runs
unprompted where `git push` is allowlisted.
