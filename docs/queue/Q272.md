# A cd in a piped or backgrounded compound command moves the tracked cwd

Q173 stopped a `cd` in a pipeline stage or a backgrounded command from moving
the tracked cwd, but only when the `cd` itself is the stage. The `own` flag
`split_groups` reports looks at the separators on either side of each simple
command. A `{ … }` group, a loop or an `if` piped or backgrounded as a whole
runs in a subshell, but the `cd` inside it sits between `;`s, so it still moves
the cwd for everything after.

## Measured

2026-10-04, from the review of the Q173 pull request, reproduced on that
branch. The hook was driven with `cwd` set to a scratch workspace with a
`sub/`. bash 5.3.15 ran the same strings under `env -i`, with a `q173-x` in
the workspace and another in its parent.

| command | hook, `main` and branch | bash reads |
|---|---|---|
| `{ cd sub; } \| cat; cat ../q173-x` | **allow** | the parent's |
| `{ cd sub; } & wait; cat ../q173-x` | **allow** | the parent's |
| `for i in 1; do cd sub; done \| cat; cat ../q173-x` | **allow** | the parent's |
| `if true; then cd sub; fi \| cat; cat ../q173-x` | **allow** | the parent's |
| `if true; then cd sub; fi & wait; cat ../q173-x` | **allow** | the parent's |

The review counted seven shapes across `{ }`, `for`, `while` and `if`, each
piped and backgrounded.

## Which way it gets built

`own` needs to belong to the compound command, not the simple command. The
fix tracks compound openers (`{`, `do`, `then`) and their closers (`}`, `done`,
`fi`), and judges `own` from the separator after the closer, applying it to
every group inside. The scope stack Q173 added in `enter_shell` already
restores a cwd on leaving a scope, so treating a piped compound as a scope of
its own reuses that.

The review sketched remedies but didn't measure them. Drive the table above
and Q173's `SubshellCdTests` against whatever is built.

## If it is never built

A `cd` in a compound command that is piped or backgrounded, followed by a
relative read, gets an `allow` for a file outside the workspace.
