# gawk options that name a file are not judged

The `awk` row in `SPEC`, which `gawk` aliases, knows `-v`, `-F` and `-f`. gawk
has more options that name a file, and the hook reads none of them:

| Command | Verdict | What gawk 5.2.1 does |
|---|---|---|
| `gawk -d/q334-fake/x 'BEGIN{x=1}' f` | allow | writes the file |
| `gawk --dump-variables=/q334-fake/x 'BEGIN{x=1}' f` | allow | writes the file |
| `gawk -o/q334-fake/x 'BEGIN{x=1}' f` | allow | writes the file |
| `gawk -p/q334-fake/x 'BEGIN{x=1}' f` | allow | writes the file |
| `gawk -i /q334-fake/x 'BEGIN{x=1}' f` | allow | reads it as source |
| `gawk -E /q334-fake/x f` | allow | reads it as source |
| `gawk --source='BEGIN{x=1}' /q334-fake/x` | allow | reads it as input |

Verdicts measured 2026-11-17 by running the hook against a scratch workspace.
gawk's behaviour was measured in a `debian:stable-slim` container with relative
names (`-dD1`, `--dump-variables=D2`, `-oO1`, `-pP1` each created its file; `-i
./incf` and `-E incf` ran the file's `BEGIN`; `--source=PROG f` printed
`FILENAME` as `f`). `-l`/`--load`, which loads a shared library, was not run.

The last row is a different failure from the others: `--source` (and `-e`)
supplies the program, so the first positional is an input file, but the `awk`
row's `prog: 1` still skips it as the program. `gawk -e 'BEGIN{x=1}'
/q334-fake/x` asks, and from the row it reads as luck rather than design: `-e`
is not consumed, so the program word is skipped in the file's place. `-d`,
`-o` and `-p` take their file attached or not at all, which the `consume` table
cannot say.

## Where it lands

The `awk` row and `WRITE_MODE_FLAGS` in `bash-workspace-guard.py`. These are
gawk's options, and what macOS awk and mawk do with the same letters was not
checked, so the question to settle first is whether `gawk` keeps aliasing `awk`
or gets its own row. Q334 reads the program; this row is the options around
it.
