# A push of a branch the session created, or a queue-id claim, asks

Under the `strict` policy a push asks unless it sends the worktree's own
branch. Two kinds of push that sessions make routinely fall outside that, and
neither carries the risk the ask exists for.

Measured from 2026-09-25 to 2026-10-25: 37 asks where the push target differed
from the worktree branch. They were new branches the session itself created and
pushed with `-u`, `refs/queue-ids/*` claims, and release-candidate tags. Driven
2026-10-25 against branch-guard 1.12.0 from a worktree on `claude/wt`:

| command | verdict |
|---|---|
| `git push -u origin feat/q123-new` | ask |
| `git push -u origin HEAD:feat/q123-new` | ask |
| `git push origin abc123:refs/queue-ids/Q42` | ask |
| `git push --force-with-lease=refs/queue-ids/Q42: origin abc123:refs/queue-ids/Q42` | ask |
| `git push origin v1.2.0-rc.1` | ask |

The cross-name ask is
`plugins/branch-guard/hooks/branch-guard.py:1427:return ('ask', f"Push targets '{dst_b}', not the worktree branch '{current}'")`
and the non-branch one is
`plugins/branch-guard/hooks/branch-guard.py:1404:return ('ask', f"Push targets '{other}', a tag or other non-branch ref "`.

## Which way it gets built

Two halves, and the second can land first.

- **A branch this session created.** Record the name when `git checkout -b`,
  `git switch -c`, `git branch <new>` or `git worktree add -b` runs, as a
  session grant through `lib/bouncer_grants.py`, the way the worktree grant
  records a path. A push whose destination is a granted, unprotected branch
  then allows like the worktree branch does. Creation is the only moment that
  shows ownership. A branch that already existed on the remote is a peer's
  until shown otherwise, so record only when the remote has no such branch,
  or only for a branch with no upstream.
- **A queue-id claim.** Allow a push to `refs/queue-ids/QN` only in its
  create-only form: a `--force-with-lease=refs/queue-ids/QN:` lease with an
  empty expectation, naming the same ref. That form cannot overwrite anything,
  because the remote refuses it when the ref exists. Every other spelling into
  the namespace keeps the ask. The vendored allocator runs its push inside a
  script the hook never sees, so these asks come from sessions writing the
  claim by hand.

Tags stay asks: a release tag publishes.

**Who it is for:** the maintainer, approving pushes of work the session itself
started. **If never built:** about 37 prompts a month, nearly all approved.
