# A literal env -C directory is not followed the way git -C is

`git -C ../repo commit` is judged against the branch checked out in `../repo`.
`env -C ../repo git commit` runs the same commit in the same place, but the
guard does not follow the directory. Q223 taught `parse_invocation` to peel
wrappers. It marks a chdir option (`env -C`/`--chdir`, `sudo -D`/`--chdir`,
`sudo -R`/`--chroot`) and then gives up on the tree outright
(`plugins/branch-guard/hooks/branch-guard.py:inv_cwd = None if inv['chdir'] else git_cwd(seg_cwd, inv['globals'])`).
So a commit that lands on `main` is checked against the session's feature
branch and gets no decision.

Measured 2026-10-04 from a feature-branch worktree whose primary checkout
`../repo` is on `main`, at #173's head `bf31961` and at `origin/main`
`a3c9052` (same answers):

| command | decision |
|---|---|
| `git -C ../repo commit -m x` (control) | ask |
| `cd ../repo && git commit -m x` (control) | ask |
| `env -C ../repo git commit -m x` | none |
| `env --chdir=../repo git commit -m x` | none |
| `sudo -D ../repo git commit -m x` | none |

"none" means Claude Code's own permission flow applies, so nothing here is
auto-approved. A wrapped allow is already downgraded to defer, and the
independent review of #173 found no path from a chdir wrapper to an allow. It
also found this gap.

## Which way it gets built

Carry the chdir value out of `peel_wrappers`. When it is a literal path, walk
`seg_cwd` through it with `resolve_path`, then hand the result to `git_cwd`,
which is the order the shell and git apply them in. Keep giving up on a
non-literal value, and on `sudo -R`, whose path names a new root rather than a
directory under the current one. Cross the fixtures over literal ×
non-literal × the three spellings, with the `git -C` control beside them.

**Who is worse off:** a session that reaches for `env -C` rather than
`git -C` to commit in a sibling checkout. Where commits are allowlisted, the
commit lands on `main` with no prompt at all. Elsewhere a prompt still
appears, but it doesn't carry the guard's reason.
