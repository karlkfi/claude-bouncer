# A funsub whose own walk ends blind falls back to the session's branch

Since Q427 the cwd walk follows a literal `cd` out of a funsub, but `list_exit` reads a body whose own walk ends blind as unknown, and unknown falls back to the session's branch.
Q303's rule is the opposite for the same shape outside a funsub: a `cd` bash may skip leaves the cwd blind, which has no fallback, because bash may be in either of two trees.
Driven 2026-11-27 through `hooks/branch-guard.py` with the payload's `cwd` in a feature worktree and `../main` a checkout of `main`: `echo ${ true && cd ../main; }; git commit -m x` gets no decision, while `true && cd ../main; git commit -m x` asks, and bash 5.3.15 runs the first one's commit on `main`.

Next step: have `list_exit` report a blind end as blind, and have `segment_cwds` carry that out of the funsub segment as `behind` carries a skipped `cd` out of `||`; the `[funsub]` fixtures in `test/run.sh` are where its pair goes.
How often sessions write a conditional `cd` inside a funsub is not measured.
