# prod-guard tracks exported values, not the export attribute

bash exports a name, not a value: once `C` carries the export attribute, every
later assignment to `C` reaches a child, and so does a name exported after it
was assigned. prod-guard keeps a separate `exported` scope that only
`export NAME=value` (and its `declare`/`typeset` forms) writes, so three
shapes leave the child's view wrong. A later `C=…` updates `shell_env` and
leaves the old exported value in place. A bare `export C` exports nothing.
`set -a` / `set -o allexport` is not modelled at all. Mechanism read from the
source, not traced.

Found by review-b-prod on the Q365 pull request (comment 6954721838), and
re-measured 2026-11-17 on `main` at `4ea1d077` with the fixture `$HOME`, whose
current context is `gke_acme_prod-us`. bash 5.3.15 under `env -i
/opt/homebrew/bin/bash --norc --noprofile`, with `echo` in place of kubectl,
printed the production value `p` in the child for each of the last four
shapes:

| command | prod-guard |
|---|---|
| `export C=gke_acme_prod-us; bash -c 'kubectl --context=$C delete pod x'` (control) | deny |
| `export C=kind-ci; C=gke_acme_prod-us; bash -c 'kubectl --context=$C delete pod x'` | **defer** |
| `C=gke_acme_prod-us; export C; bash -c 'kubectl --context=$C delete pod x'` | ask |
| `set -a; C=gke_acme_prod-us; bash -c 'kubectl --context=$C delete pod x'` | ask |
| `set -o allexport; C=gke_acme_prod-us; bash -c 'kubectl --context=$C delete pod x'` | ask |

The second row is the sharp one: the child runs against production and the
guard passes it on the earlier nonprod value. The other three fail closed.
The review also showed `export C=kind-ci; B='$C'; C=gke_acme_prod-us; bash -c
"kubectl --context=$B delete pod x"` deferring, which is the same reassignment
reached through Q365's single-quoted value.

## Which way it gets built

Track the attribute rather than the value: hold the set of exported names,
add to it on `export NAME` with or without a value and on every assignment
while `set -a` is on, and on each assignment to a name in the set write the
new value to the exported scope too. `unset` and `export -n` take a name out.
A `set -a` inside a body that may not run makes the attribute itself unknown,
which the Q301 union can carry. Not measured.

## If it is never built

Reassigning an already-exported name to production and then starting a child
shell runs the mutation with no prompt, as long as the first exported value
was nonprod.
