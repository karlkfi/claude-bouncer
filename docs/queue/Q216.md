# branch -D and the force overwrites skip the republished-rebase check

Q145 gave `classify_reset` a third question for a tip nothing else reaches:
`orphans_republished`, which allows when every commit the move would orphan
has a verbatim patch-id match among the newest 200 commits on the recovery refs.
The `-D` path in `classify_branch` and `overwrite_verdict` (`-f`/`-M`/`-C`)
take the second question, `orphans_only_reproducible_merges`, and not the
third. So one branch in one state — rebased, the result pushed under another
name — now answers `allow` to `git reset --hard` and `ask` to
`git branch -D`.

That split is the shape `orphans_only_reproducible_merges`' own docstring
calls the whole defect when it was the other way round: what the proof
establishes is about a ref move, and both callers already take it over what
deleting the ref would orphan, so the same proof covers them.

Who it is for: a session cleaning up a branch it rebased and republished,
which is told to confirm a delete that loses nothing. If nothing is done the
cost is one prompt per such delete, against a deny on the reset side that
Q145 measured as the second-most-fired branch-guard denial; the `-D` side is
an ask, so it is cheaper and in an unattended mode it becomes a deny.

The fix is one more `or` at each of the two call sites, plus the fixtures:
`test/run.sh` section 28 builds the republish repos with `make_republish_repo`
and asserts the reset verdicts only. Cross the new cells as the
reproducible-merge tier does — a positive, the inside-context and partial
negatives, a configured-protected name, and `dontAsk`.

Filed from the Q145 work. Not re-measured beyond reading the two call sites at
`plugins/branch-guard/hooks/branch-guard.py`: neither calls
`orphans_republished`.
