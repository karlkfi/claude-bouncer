# A sed script w or r filename is never judged

A sed script can name files of its own: `w FILE` and `W FILE` write the pattern
space there, `s///w FILE` writes each substituted line, `r FILE` and `R FILE`
read it in, and GNU's `e` runs a command. workspace-guard treats the script as
an opaque program operand, so none of those filenames is checked, and a sed
call that writes or reads outside the workspace is allowed silently.

Measured 2026-11-01 on the branch of #296, with the hook run directly against a
temporary workspace holding `f`; reported by #296's reviewer against `main`:

| Command | Verdict |
|---|---|
| `sed '/x/w /q-fake/leak' f` | allow |
| `sed -e '/x/w /q-fake/leak' f` | allow |
| `sed -i '' 's/x/y/w /q-fake/leak' f` | allow |
| `sed -i '' -e '/x/r /q-fake/secret' f` | allow |

The reviewer confirmed on macOS `/usr/bin/sed` that `sed -i '' -e '/x/w leak.txt' in.txt`
creates `leak.txt` holding the matched line, so the write is real.

## Where it lands

The script reaches the hook as the `sed` row's program positional or an `-e`
value, and `files_in_command` drops both. A fix reads the script's commands:
split on `;` and newlines, step over `/…/` and `\cREGEXc` addresses and the
`s` command's pattern and replacement, and take the rest of the line after a
`w`/`W`/`r`/`R` command or an `s` flag list ending in `w` as a file operand in
write or read context. GNU's `e` command and `s///e` run a command, which this
guard does not judge as a file; they belong with whatever the repo does for
interpreter code (`INTERPRETER_SIGNAL`).

Q232 waits on this parser. #296 tried handing `sed -i '' SCRIPT FILE` the
`-e` rewrite and withdrew it, because every regex test it tried for a script
naming a file either steered one onto this allow or left almost nothing
eligible. Its tests pin today's ask for those shapes.

`-f SCRIPTFILE` is out of scope: the script file is itself already judged as a
read, and its contents are not the hook's to read.

A test per row of the table above, each asking with the filename named, and a
plain `sed 's/a/b/' f` and `sed -n '/w/p' f` (a `w` inside an address) still
allowing.
