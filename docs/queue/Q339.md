# exit-status-guard defers on a $(( holding a nested $( ) in double quotes

`echo "$(echo "$(( $(echo "(" | wc -c) ))" ; make check | tail)"` runs the
gated pipeline under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`
(5.3.15), and exit-status-guard defers on it. On Q325's head (#301) the shared
parser returns the outer body whole, and prod-guard, workspace-guard and
foreground-guard deny or ask; `echo "$(echo "$(( 1 ))" ; make check | tail)"`
denies in exit-status-guard too. So the miss is in exit-status-guard's own
walk, reached only when the arithmetic carries a nested substitution. Nobody
has traced which part.

The stream-A reviewer found it reviewing Q325. Driven 2026-11-01 by Q325's
worker, with `P` the stand-ins Q325 used (prod-guard's
`kubectl --context gke_acme_prod-us delete ns payments`, workspace-guard's
`rm /etc/probe-target`, exit-status-guard's `make check | tail`,
foreground-guard's `tail -f log.txt`):

| command | `main` at `f4f9857c` | #301 |
|---|---|---|
| `echo "$(echo "$(( $(echo "(" \| wc -c) ))" ; P)"` | defer / allow / defer / defer | deny / ask / **defer** / deny |

It may share a cause with Q338, which is about a `$((` bash re-reads as a
subshell. That one defers in exit-status-guard even unquoted; this one is real
arithmetic, so it was filed apart.

## Which way it gets built

Trace exit-status-guard's handling of a substitution body that holds `$((`,
find where the nested `$(` inside it stops the walk, and pin the command
above with a test that fails on `main`.

## If it is never built

A gate piped into a filter, written after an arithmetic expansion that holds
a nested substitution inside a double-quoted `$( )`, is not caught by
exit-status-guard. Nobody writes that shape to run a gate, so it is rare.
