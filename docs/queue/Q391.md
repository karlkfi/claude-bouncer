# An escaped dollar in a double-quoted sed script is read as an expansion

The hook substitutes a command's own literals into a sed script word and, since
Q335, denies a `$1`, `$_` or bound name it cannot substitute. Both rules act on
the token's text, and the token cannot tell `\$b` from `$b`: `tokenize_command`
gives `s/a/$b/` with the same `quotes` and `quoted_chars` for
`sed "s/a/\$b/" f` and `sed "s/a/$b/" f`. Bash keeps an escaped `\$b` as the
literal `$b`, so the hook substitutes text that is not there.

| Command | `main` (`f54f605`) | before Q335 (`328f612`) |
|---|---|---|
| `b='x/'; sed "s/a/\$b/;w /q334-fake/x" f` | allow | allow |
| `sed "s/a/\$b/;w /q334-fake/x" f` | ask | ask |
| `sed "s/a/\$1/" f` | deny | allow |

Measured 2026-11-17 by running both hooks against a scratch workspace. The
first row is a wrong-allow older than Q335: the substituted `x/` turns the
script into `s/a/x//`, an `s` followed by an unterminated address, so the sed
reader stops there and never reads the `w` after it. macOS sed runs the same
shape (`b='x/'; sed "s/a/\$b/;w esc-out" f`, with a relative target) and
creates `esc-out`. The third row is a false deny Q335 added, of a literal `$1`.

## Where it lands

The quoting record is `QuotedStr` in `lib/bouncer_parse.py`, which keeps which
quotes a word used but not which of its `$` characters bash left literal. A fix
that records escaped `$` offsets there reaches every guard's tokens, which is
why the row carries `lib`; the consumers are `substitute_vars` and
`sed_script_hides` in `bash-workspace-guard.py`. A fix confined to the guard
would have to re-read the raw source for the word, the way `output_assigned`
does for `NAME=$(…)`.

Found while scoping Q334, whose awk program reading would inherit the same
blind spot if it reuses Q335's substitution.
