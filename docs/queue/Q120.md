# `overwrite_verdict` skips the reproducible-merge second chance

Q110 gave `classify_reset` the second chance `classify_branch`'s `-D` path
already had, on the argument that `orphans_only_reproducible_merges` proves
something about a ref *move* rather than about a verb. That argument reaches one
more caller, which Q110 left alone: `overwrite_verdict`, the shared classifier
for `git branch -f`, `-M` and `-C` onto an existing ref. It asks
`plugins/branch-guard/hooks/branch-guard.py:1294:rec = tip_is_recoverable(cwd, name)`
and stops on `False`, exactly as the reset path did.

Measured 2026-08-23 on a throwaway repo — `main` and `other` on remote-tracking
refs, `tmp-basecheck` branched off `main` carrying one `--no-ff` merge of
`other`, so its tip is unreachable *because* it merged:

| command | verdict |
|---|---|
| `git branch -D tmp-basecheck` | allow |
| `git reset --hard HEAD~1` on that branch | allow *(since Q110)* |
| `git branch -f tmp-basecheck main` | **ask** |

Same branch, same state, same loss — the ref moves off a merge git can re-run —
and the third spelling still prompts. `git branch -M tmp-basecheck renamed`
allows, but that is a rename onto a free name rather than an overwrite, so it
never reaches the probe.

This is deliberately not folded into Q110. That row's urgency was the `deny`,
which is a dead end costing a break-glass; this one returns `ask`, which a human
answers, so the friction is a prompt rather than a wall. Q110 was sized S around
two named bullets and widening it would have roughly doubled the diff.

The fix is the same shape as Q110's — a second question on the `rec is False`
arm, returning `allow` where the probe proves it — and it costs nothing on the
auto-approved path, because a surviving tip returns above it. Q110 measured the
probe at 18ms on the merge case and 6ms on a non-merge orphan (git 2.55, macOS,
four-commit repo).

Two things to settle beyond the call itself:

- **The `ask` wording.** Unlike the reset path there is no `DENY_ROUTES` entry
  here, so the surviving `ask` keeps whatever `overwrite_verdict` already says.
  Check it still reads right once the merge case stops reaching it.
- **The fixtures.** The `-D` and `reset --hard` mirrors both sit on the
  `testmerge` block in
  `plugins/branch-guard/test/run.sh:1321:git -C "$WORK" checkout -q -b testmerge pushed`,
  and the `-f` mirror belongs on the same fixtures. Note `overwrite_verdict`
  serves three spellings from one body, so one fixture per spelling is not what
  this needs — cover the shared arm and cross the protected check.
