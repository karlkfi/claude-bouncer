# The README names 6 of the 11 wrappers the guard peels

`README.md`'s parsing paragraph lists wrappers as `sudo`, `env`, `timeout`,
`xargs`, `nohup` and `time`. The guard peels eleven names. The five it does not
name — `builtin`, `command`, `exec`, `stdbuf`, `unbuffer` — are peeled exactly
as the six listed ones are.

The sentence is a sample by construction: its subject is that compound commands
are split and each segment evaluated, with wrappers as one illustrative
category. So nothing in it is false, and this is an undercount rather than a
wrong claim — the reconciliation runs clean in the other direction, with no
name listed that the guard does not peel.

What makes it worth a row is that the gap widens on its own. Three of the five
absentees (`command`, `builtin`, `exec`) predate this repository's backlog, and
two (`stdbuf`, `unbuffer`) arrived with Q161 — a change that had no reason to
touch the sentence, since it falsified nothing in it. Every future wrapper
lands the same way.

`command` appears in both code columns because it is in `PLAIN_WRAPPERS` and
carries the `is_command_lookup` exception (Q142).

## Which way it gets built

Two halves, and the second is the one that lasts.

- Complete the list, or reword it so it does not read as an enumeration at all
  — "wrappers such as" costs one word and retires the drift permanently. Prefer
  that unless the full set is genuinely useful to a reader at that point in the
  page, which is the call whoever takes this should make rather than inherit.
- Reconcile it in a test, in both directions, so the next wrapper cannot land
  without either the name or a deliberate exemption. The reconciliation above
  is four lines of regex over the two files and needs no fixture. Where the
  wording is changed to a non-enumeration, this half is what should *not* be
  built — a test asserting a sample is complete is the defect it was meant to
  prevent, inverted.

[Q88](Q88.md) is the sibling in foreground-guard: same class — a user-facing
claim about the hook that nothing reconciles — against its decision table
rather than a wrapper list, and preventive there because that table was
measured to agree. This one has a measured gap, so it is corrective.

## If it is never built

A reader checks whether their `stdbuf -oL kubectl …` is guarded, finds `stdbuf`
absent from the list, and concludes it is not — when Q161 made it guarded. The
undercount reads as a limitation rather than as an omission, which is the
direction that costs the reader something.

## Notes

Where the store's uncheckable citations are, recorded here because a groom
reading the newest row will find it and [Q122](Q122.md) — which owns the defect
— is a live row this change does not touch.

`CITATION_RE` requires a non-space first character for the fragment group, so a
citation whose fragment *opens* with whitespace parses as path-and-line with no
fragment at all. Nothing is then compared, at any window and under any
`--strict`. It is a property of how the citation was copied, not of the cited
line: `grep -n` on an indented line hands you exactly that shape.

Nine such citations exist in the store, measured 2026-09-09 — seven in
[Q179](Q179.md), two in [Q180](Q180.md), all pointing into prod-guard and
foreground-guard. All nine are correct today. None of them can be checked by
any gate in this repository, so the next edit to either script breaks them
silently.

never recognised either — filed separately as Q182, with the fix routed to the
