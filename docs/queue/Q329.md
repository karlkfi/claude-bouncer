# git checkout -f -b discards edits while branch-guard allows it

`git checkout -f -b newb` throws away uncommitted edits to tracked files on
git 2.55 and creates the branch, and branch-guard allows it, as it allows
`-fb` and `--forc -b`. The same loss spelled `git switch -f -c newb` asks.
Found by the independent review of PR #295 and passed on for a row; the
reviewer drove it on git 2.55, and this row has not re-driven it.

The checkout rule returns `allow` on any `b` letter before it looks for a force
(`plugins/branch-guard/hooks/branch-guard.py:2196:        if 'b' in short:`),
where the switch rule asks on `f` or `--force` first. checkout is not in
`GIT_LONG_OPTS`, so `--forc` is never read as `--force` there either.

Bites whenever a session forces a checkout onto a new branch, which a session
recovering from a dirty tree reaches for. Next step: give the checkout rule the
switch rule's force check ahead of the `-b` allow (`f`, `--force`, and
`--discard-changes` is not a checkout option), add checkout's options to
`GIT_LONG_OPTS` from `git checkout --git-completion-helper-all` so an
abbreviated `--force` is read, and cross `-f -b`, `-fb`, `--force -b` and
`--forc -b` against plain `-b`.
