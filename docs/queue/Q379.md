# Two guards misread a continuation in a single-quoted bash -c body

Inside single quotes the parent shell keeps a backslash-newline as two
characters, and the child shell started by `bash -c` joins them as a line
continuation. So `bash -c 'echo x; \` newline `P'` runs `echo x; P`.
prod-guard and foreground-guard both rewrite every newline in the raw command to `;` before lexing, quoted or not, at
`plugins/prod-guard/scripts/bash-prod-guard.py:476:    masked = _LIVE_BACKTICK.sub(r'\1;', masked).replace('\n', ';')`
and
`plugins/foreground-guard/scripts/bash-foreground-guard.py:309:    raw = LIVE_BACKTICK.sub(r'\1;', strip_comments(raw)).replace('\n', ';')`.
The child body then reads `echo x; \;P`, where `\;` is an escaped literal `;`
glued to the next word, so the command word is `;kubectl` or `;sleep` and
neither guard knows it.

Measured 2026-11-17 on `origin/main` at `a3a43e4d`, with the harness and traps
described in Q349, and bash 5.3.15 printing `RAN` for `echo RAN` in every row:

| command | prod | fg | body each guard lexed |
|---|---|---|---|
| `bash -c 'echo x; P'` -- control | deny | deny | `echo x; P` |
| `bash -c 'echo x` newline `P'` -- plain newline | deny | deny | |
| `bash -c "echo x; \` newline `P"` -- double quotes | deny | deny | |
| `bash -c 'echo x; \` newline `P'` | **defer** | **defer** | `echo x; \;P` |

In double quotes the parent itself removes the continuation, which is why that
row is judged. workspace-guard asks on the single-quoted row: it lexes the body
as `echo x; rm /etc/probe-target`. exit-status-guard does not read a `bash -c`
body at all, and branch-guard misses it for a different reason (Q381).

Found by the stream-A reviewer on #314 and filed in Q349's first draft as
unmeasured.

## Which way it gets built

Leave a backslash-newline inside quotes alone when rewriting newlines, so the
child body keeps its continuation, and fold it when the body is lexed as a
script, the way `strip_comments` already does at top level. Check that a plain
quoted newline still splits the child body.

## If it is never built

A guarded command runs unjudged behind a continuation inside a single-quoted
`bash -c` body. A continuation there is an ordinary way to wrap a long child
script, so the shape needs no intent to occur. Rate unmeasured: a regex count
over this machine's transcripts could not tell a quoted `-c` argument from text
that only looked like one.
