# An interpreter option argument is read as the script

`interp_code_source` takes the first token after an interpreter that does not
start with `-` as the script, so an option that takes an argument hands it the
argument instead. The real script is then never read-checked, and the
in-workspace argument vouches for the string. Measured by the PR 368 reviewer at
`192866a`, identical on `origin/main`:

| command | verdict |
|---|---|
| `cat in.txt; bash /opt/q8-fake-target/t.sh` | ask |
| `cat in.txt; bash -o errexit /opt/q8-fake-target/t.sh` | allow |
| `cat in.txt; bash -O extglob /opt/q8-fake-target/t.sh` | allow |
| `cat in.txt; python3 -W ignore /opt/q8-fake-target/t.py` | allow |
| `cat in.txt; perl -I lib /opt/q8-fake-target/t.pl` | allow |
| `cat in.txt; node -r ./in.txt /opt/q8-fake-target/t.js` | allow |

PR 368 stops the write-then-run variant (`bash -o errexit t.sh` after a write to
`t.sh`) by counting every later operand as a possible script once an option
precedes the chosen one. The read check still picks the wrong token.

Next step: give each interpreter in `INTERP_CMDS` and `SHELL_C_CMDS` a table of
the options that take a separate argument, read off its own man page, and skip
those arguments in the operand scan; an option outside the table should make
every later operand a checked read rather than guess.
