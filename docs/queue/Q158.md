# `sudo -h` is both `--help` and `--host`, so neither arity is safe

Q152 gave each wrapper a set of flags that take a separate value, so the value
is skipped with the flag instead of becoming the tool. `sudo -h` was held out
of that set because sudo spells two different options `-h`, and the two want
opposite arities — whichever is chosen, one shape walks past the tool.

**Ask:** whether this is worth closing at all. Both shapes are near-unreachable
in practice, and the answer turns on how far the guard should go for a form
sudoers cannot execute.

## Measured

2026-09-04, prod-guard at `4a81387` with Q152's fix applied, fixture `$HOME`
with ambient context `gke_acme_prod-us`:

| command | verdict | if `-h` took a value |
|---|---|---|
| `sudo -h kubectl delete ns foo` | deny — correct | would skip `kubectl`, defer |
| `sudo -h myhost kubectl delete ns foo` | **defers** | would deny — correct |

Read off `sudo -h` on sudo 1.9.17p2, whose options list carries both
`-h, --help` and `-h, --host=host`, and whose command-running synopsis carries
`[-h host]`.

## Which way it gets built

Undecided, and that is the row. Three candidates, none endorsed:

- **Leave it.** The false negative needs `-h <host>` before a command, and
  sudoers does not support remote commands at all — so on a stock install that
  command fails rather than running, and the guard's silence costs nothing.
- **Value-taking, with a lookahead**: treat `-h` as taking a value only when
  what follows it is not a covered tool. That is `xargs`'s scan applied to one
  flag, so the mechanism is already in the file.
- **Break out of the loop**, as [Q157](Q157.md) proposes for the run-nothing
  modes, and let the segment defer either way. Safe against the false deny and
  gives up the false negative.

The lookahead is the only one that gets both shapes right, and it is also the
only one that puts tool-name knowledge inside the flag walk.

## If it is never built

`sudo -h <host> kubectl delete …` is unclassified — silence where a deny is
owed, but for a command a stock sudoers refuses to run.
