# workspace-guard asks on xargs and kill where a deny could ship the fix

In `auto` and `acceptEdits`, a command whose operands the hook cannot see asks
the maintainer. For two of the signals the deny reason could carry a rewrite
the model applies itself, so the question never needs a person.

Measured from 2026-09-25 to 2026-10-25: 58 workspace-guard asks on shell bodies
it could not parse, sorted by regex into loops, `xargs`, wrappers and redirect
targets. Re-driven 2026-10-25 against 1.13.0, most of those shapes no longer
ask. A `for f in $(…)` loop, a `while read f` loop, `cat $(git ls-files …)` and
`echo hi > "$OUT"` all deny with the literal-path rewrite already. What still
asks is the suppression escalation in
`plugins/workspace-guard/scripts/bash-workspace-guard.py:3677:def escalate_suppression(signal, mode):`,
for example `ls docs | xargs -I{} cat docs/{}`. The audit scripts are gone, so
the 58 cannot be split by guard version or by signal now.

The escalation already writes a fix for each signal. For `xargs` it is "name
the files on the command itself"; for a kill it is "signal the literal pid".
Both are rewrites the model can make. The `sh -c` signal is different: a
container or remote body has no plain-command rewrite.

## The open question

**Ask:** the function's docstring records the opposite decision on purpose.
"Denying in them would remove the human rather than protect them"
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:3692:Denying in them would remove the human rather than protect them.`).
Under `hook-verdict`, a verdict whose fix fits in the reason should deny, and
the human is only needed where it does not. What turns on the maintainer is
whether to reverse Q74's recorded call for the `wrapper` and kill signals.

If yes: deny those two in every mode that escalates, keep `ask` for `sh -c`.
The Q210 route then becomes a precondition for the deny, because a model
denied a command it really needs has to have a way through. That route is
`WORKSPACE_GUARD_OVERRIDE` downgrading the deny to an ask. Q210 settled that
override's tier and destination, and this change is the flip it was waiting
for. If no: the docstring's argument stands and this row is deleted.

**If never built:** the maintainer keeps answering an `xargs` or `pkill` prompt
whose fix is already written in its own reason.
