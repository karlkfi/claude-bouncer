# prod-guard keeps a word whole when it mixes quoted and unquoted parts

prod-guard splits an unquoted expansion only in a word written with no quoting at all, so a word with a quoted run beside an unquoted `$B` stays one word, where bash splits the unquoted run.
Measured 2026-11-26 through the hook, on Q382's branch at `dcdfcdf` (the `eval` row at `084fd37`):

| command | prod-guard |
|---|---|
| `A=--context; B="gke_acme_prod-us delete ns x"; kubectl "$A"=$B` | **defer** |
| `X="echo hi; kubectl --context gke_acme_prod-us delete pod x"; eval "$X"''` | **defer** |
| `kubectl --context=gke_acme_prod-us delete ns x` (control) | deny |

bash split the first: `A=RAN; B="x a b"; /bin/echo "$A"=$B` printed `RAN=x a b` as four words. bash ran both commands of the second: `X="/bin/echo hi; /bin/echo RAN"; eval "$X"''` printed `hi`, then `RAN`. `eval "$X"''` with `X` holding the delete alone denies, so the `eval` miss shows only once the delete follows another command.
The gate is `plugins/prod-guard/scripts/bash-prod-guard.py:1314:            if getattr(tok, 'quoted_from', None) is None and word != tok:`.
The lexer records which quote characters a word used (`quotes`) but not where each run sits, so the guard cannot tell which characters came from an unquoted expansion.

## Which way it gets built

Have the lexer record each run's span and quoting on the token, additively, then split only the characters an unquoted expansion produced.
That change is in `lib/bouncer_parse.py`, so it carries `lib` once scoped, and the other guards keep their current reading unless they opt in.

## If it is never built

A production mutation written as one mixed-quoting word runs with no prompt.
It needs a quoted run directly beside an unquoted expansion that holds the verb, so it is rarer than a plain `$X`.
