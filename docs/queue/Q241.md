# time's `-p` and `--` options hide the command after them

bash 5.3.15 reads `time -p cmd` and `time -- cmd` as the reserved word with its
own option, then runs `cmd`. Under
`env -i /opt/homebrew/bin/bash --norc --noprofile -c`, `time -p FOO[a;b]=x cat f`,
`time -- FOO[a;b]=x cat f` and `time -p -- FOO[a;b]=x cat f` each print f.

`strip_sh_keywords` drops `time` and stops, so `-p` or `--` becomes the command
word and the lookup misses. It is called by workspace-guard and
exit-status-guard. prod-guard peels `time` as a wrapper with options of its own
(`PLAIN_WRAPPERS`, `WRAPPER_VALUE_FLAGS`). It does not then peel an assignment
prefix behind the wrapper, which bash accepts there.

Driven 2026-10-04 through the hooks on `origin/main` at `442c86e`. The fixture
`$HOME` set the current context to `gke_acme_prod-us`. Payloads were `kubectl
delete ns payments` for prod-guard, `rm /etc/probe-target` for
workspace-guard, and `make check | tail` for exit-status-guard:

| command | prod / ws / exit |
|---|---|
| `time P` -- control | deny / ask / deny |
| `time -p P` | deny / **defer** / **defer** |
| `time -- P` | deny / **defer** / **defer** |
| `time -p FOO[a;b]=x P` | **defer** / **defer** / **defer** |

The Q217 pull request reads the subscript in the last row as one word after
`time -p` or `time --`, so the tokens are right. The guards still defer,
because of the peel described above.

This was found while working the independent review of the Q217 pull request,
which named `time -p FOO[a;b]=x cmd` as a pre-existing residual.

## Which way it gets built

In `strip_sh_keywords`, after a `time` in command position, also drop a `-p`
and a `--` that follow it. Then check whether prod-guard's wrapper peel should
hand its remainder to `strip_env_prefix`, as the keyword path does. Q219
(workspace-guard and external wrappers such as `env` and `nohup`) and Q228
(abbreviated long wrapper options in prod-guard) are neighbouring rows with
different mechanisms.

## If it is never built

`time -p` is how `time` gets POSIX output. Any guarded command behind it goes
unjudged by workspace-guard and exit-status-guard, and an assignment prefix
behind it is enough to hide the command from prod-guard as well.
