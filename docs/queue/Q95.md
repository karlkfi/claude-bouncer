# Deny the push-overlap ask, and give it an override of its own

The overlap check names work for the model — `git fetch && git rebase
origin/main` — and then spends the human's attention asking whether to do it.
`hook-verdict`'s routing test says a cause whose fix fits in the reason should
deny: the model applies it and nobody is interrupted.

Measured 2026-08-22, twice in one session: both pushes hit the overlap ask, both
times the operator denied the prompt and pasted the reason into the session by
hand, and both times the rebase was the right move. The guard was correct on
both; the prompt was the cost. Whether `additionalContext` reached the model is
unmeasured — the reason arrived as a pasted message either way, so the paste
does not settle it. Measure that first: if the context does land, this is purely
a verdict change, and if it does not, the deny is also the fix for a context
that never arrives.

**A deny alone would be a dead end, which is the half to get right.** Denying
without adding an override reproduces #78 — a refusal with no answer reroutes
the work instead of stopping it. The verdict is tagged `ask-rebase` and nothing
can lift it, at three places in `plugins/branch-guard/hooks/branch-guard.py`:

- `plugins/branch-guard/hooks/branch-guard.py:1469:return ('ask-rebase'` — where
  the verdict is minted.
- `plugins/branch-guard/hooks/branch-guard.py:488:OVERRIDABLE_GIT = frozenset({`
  — holds no `push`.
- `plugins/branch-guard/hooks/branch-guard.py:2067:An 'ask-rebase' is never overridable`
  — the combine site refuses it on both clauses of `liftable`.

So this is two changes, not one: route `ask-rebase` to `deny`, and add an
override scoped to that tag alone. It must not widen to `ask-shared`, and it
must not put `push` into `OVERRIDABLE_GIT` — a push can lose state this machine
does not hold, which is why every push form is outside that set today. A
separate variable, or a tag-keyed exception ahead of `is_overridable`, keeps the
existing locks intact.

The fixture surface is what makes this M rather than S. `test/run.sh` already
crosses the overlap matrix against both push policies, `dontAsk`, the
protected-target ask that beats it, the chained `push && rm`, and the
break-glass refusing to lift it — and that last case asserts today's behaviour,
so it inverts rather than survives.
