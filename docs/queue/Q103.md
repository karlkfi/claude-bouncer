# Guard PowerShell link creation, the counterpart of the Bash `ln` check

Measured 2026-08-22, while closing Q80 on the Bash side: `New-Item -ItemType SymbolicLink -Path link -Target /q80-fake-target` defers, and so do the `HardLink` and `ni` spellings, while `Get-Content` and `Remove-Item` on the same path already ask. `New-Item` has no `PS_SPEC` row, so nothing sees either operand.

The Bash fix is the shape to port: `ln_operands` splits sources from the destination and `_analyze_command` checks both in write context, leaving `classify_ln`'s staging to the forms whose link path is a token. PowerShell needs the same two halves, and `-Target` names the path the link points at rather than a file the cmdlet opens — a row alone will not do it, because `New-Item` also creates ordinary files and directories, where there is no target operand at all.

A Bash-side behaviour the PowerShell frontend has not taken. The set also held the interpreter suppression (Q73) and the entry-operand roles (Q76).
