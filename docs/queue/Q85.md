# Count the friction report's native-tool decisions

The 5 holds and undersells the gap by counting denies only. Re-measured
2026-08-24 over 1,160 local transcripts, workspace-guard's hook emitted 311 asks
the report never sees — 164 `PreToolUse:Read`, 92 `PreToolUse:Edit`, 55
`PreToolUse:Write` — beside the 5 native-tool denies. Against the 1,675 Bash asks
and 141 recovered Bash denies it does see, that is 316 of 2,132: **14.8% of
workspace-guard's measured friction is invisible to workspace-guard's own
friction report.**

Both passes drop it, for different reasons, in one line each. The attachment pass
tests `hookName != 'PreToolUse:Bash'`; the deny pass drops any result with no
Bash `tool_use` behind it
(`plugins/workspace-guard/scripts/friction-report.py:361:# tool (Edit, Write, Read) — out of scope for a Bash report,`).

**Who is worse off.** Whoever runs the report to decide what to fix. It is the
instrument behind every "which prompts can we remove without weakening security"
call in this plugin, so a ranking of Bash friction is being read as a ranking of
the guard's friction. `measuring-friction.md` already names the gap
(`plugins/workspace-guard/docs/development/measuring-friction.md:60:A block of a native tool`),
which makes the total an honest floor and does not make it a usable one.

**A ninth of the matcher set, not a third.** `hooks/hooks.json` registers the
hook on nine tools — `Bash|PowerShell`, `Edit|Write|MultiEdit|NotebookEdit`,
`Read|Grep|Glob` — and the report reads one. `PreToolUse:PowerShell` produced
zero attachments in this corpus because it was taken on a Mac, so the Windows
half is unmeasured here rather than absent; PowerShell guarding shipped at
v1.11.0, the newest release.

**Which way it gets built.** Widen both filters to any `PreToolUse:` hook name,
key the join on the tool the attachment names instead of assuming Bash, and add a
tool column to the ranking. A native-tool decision carries a path and no command,
so "top triggering commands" takes a null there while the reason categories work
unchanged. Fix workspace-guard's copy only: prod-guard, foreground-guard and
exit-status-guard carry the same line but register on `Bash` alone, so widening
theirs is a no-op. branch-guard registers on `Edit|Write|MultiEdit|NotebookEdit`
(46 asks in the same corpus) and ships no report at all — say so in the doc, do
not build one here.

**If it is never built,** the blind spot tracks the newest surface the plugin has
grown, so it widens with the plugin.

`S` holds. Rank `af` does not — it sits 20th and it is the instrument the friction
items above it are ranked with. It belongs just below Q107 and above Q117.
