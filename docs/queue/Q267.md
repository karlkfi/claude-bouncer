# foreground-guard reads a comment as running past its newline

foreground-guard lexes with `QuoteTrackingLexer` and keeps shlex's default
`#` comment handling. shlex swallows a comment *and* the newline that ends it,
so the next line merges into the commented line's segment, and the command
written there is never judged. bash ends the comment at the newline and runs
the next line. `strip_comments` exists in `lib/` for exactly this. The other
guards strip comments with it before lexing, and prod-guard does the same
since its Q224 fix.

Found 2026-10-04 while driving the Q264 shapes through every hook. bash runs
are under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`, which prints
`5.3.15(1)-release`. The hook ran on `origin/main` at `8c4d8f4`, with `P` set
to `sleep 600`, which foreground-guard denies on its own:

| command | bash runs P | foreground-guard |
|---|---|---|
| `echo a` newline `P` -- control | yes | deny |
| `echo a # c` newline `P` | yes | **defer** |
| `# c` newline `P` | yes | **defer** |
| `echo $(true)#b; P` | yes | **defer** |

The last row is a mid-word `#` after a substitution's close, which bash reads
as text. Once the comment handling uses `strip_comments`, the Q264 change
covers it as well.

## Which way it gets built

Pass the command through `strip_comments` before lexing and turn off shlex's
`commenters`, as workspace-guard and exit-status-guard do. Check what a
heredoc body does to that ordering first: the other guards strip heredoc
bodies before comments, so an apostrophe in a body can't throw off the quote
tracking.

## If it is never built

A foreground `sleep`, `watch` or test run written on the line after any
comment runs without foreground-guard seeing it, which is the hang the guard
exists to stop.
