# foreground-guard's dontAsk premise is measured false

`UNATTENDED_MODES` converts a configured `ask` into a `deny` in two modes
(`plugins/foreground-guard/scripts/bash-foreground-guard.py:458:UNATTENDED_MODES = frozenset({'dontAsk', 'bypassPermissions'})`),
and the comment above it gives the mechanism for the first one: in `dontAsk`,
Claude Code
`plugins/foreground-guard/scripts/bash-foreground-guard.py:909:own generic deny and the reason is lost`.

That half is false. Measured 2026-09-09 at CLI 2.1.261, six cells, calibrated
against the four the published matrix already fixes
(`plugins/workspace-guard/docs/permission-modes.md:97:The first four reproduce the matrix, which is what makes the last two worth`):
in `dontAsk` an unanswered `ask` blocks and hands the hook's
`permissionDecisionReason` to the agent verbatim, exactly as a `deny` does. The
generic *don't ask mode* message that does lose the reason is what **defer**
produces, not `ask`. The `bypassPermissions` half of the comment is untouched by
this and stands.

**Who it is for.** The next guard author reading that comment as settled
precedent. It reads as one, because it cites branch-guard and workspace-guard by
name — and it nearly propagated: Q84 was filed asking workspace-guard to add a
`dontAsk` case on this reasoning, and the case was dropped only because the cell
was re-run.

**What happens if it is never built.** The comment goes on arguing for a
conversion its own stated mechanism does not support, and the next guard that
needs a mode set inherits it. That is the third time around a loop this repo has
already been through twice — branch-guard dropped `auto` from
`NON_INTERACTIVE_MODES` in v1.7.0 after the same shape of premise, and the
comment being corrected here is the one that records that lesson.

**Which way it gets built** is settled for the comment and open for the code.
Rewrite the comment either way: it is wrong about `dontAsk` whatever happens to
the set. Whether `dontAsk` should stay in `UNATTENDED_MODES` turns on one thing
nobody has measured — whether an interactive `dontAsk` session renders a prompt
a person can answer. If it does, converting the `ask` removes the human that a
repo setting `"action": "ask"` asked for, and the entry goes. If it does not,
the entry is harmless and keeps its second, accurate half of the argument.

**Measure:** run a `dontAsk` session with a PreToolUse hook returning `ask` on a
TTY, not headless `-p`, and record whether a prompt renders. The six cells
behind this row were all headless, which is why they settle the reason and not
the prompt.

`S` either way: one comment, and at most one entry in a frozenset with the
tests that name it.
