# foreground-guard's dontAsk premise is measured false

`UNATTENDED_MODES` turns a configured `ask` into a `deny` in two modes
(`plugins/foreground-guard/scripts/bash-foreground-guard.py:571:UNATTENDED_MODES = frozenset({'dontAsk', 'bypassPermissions'})`).
The comment above it explains the `dontAsk` half: there, it says, Claude Code
turns the `ask` into its
`plugins/foreground-guard/scripts/bash-foreground-guard.py:1061:own generic deny and the reason is lost`.

That is false twice over. The headless cells already showed the reason
survives: in `dontAsk` an unanswered `ask` hands the hook's reason back
verbatim, and it is **defer** that produces the generic message (CLI 2.1.261,
`plugins/workspace-guard/docs/permission-modes.md:116:They establish that the reason survives — not whether an interactive`).
The measurement this row asked for now shows an interactive `dontAsk` session
waits on a person.

## Measured

2026-10-04, CLI 2.1.282. Three interactive sessions (a real TTY in the Terminal
panel, not `-p`), each run as
`claude --model haiku --permission-mode <mode> --settings <file>`, with a
`PreToolUse` hook on `Bash` that returns a fixed verdict, asked to run one
`echo`. Each session's transcript was read for the gap between the tool call
and its result:

| mode | hook returns | `tool_use` | `tool_result` |
|---|---|---|---|
| `default` (control) | `ask` | 21:37:18.728Z | none before the session was closed |
| `dontAsk` | `deny` (control) | 21:39:58.274Z | 21:39:58.743Z, the hook's reason verbatim |
| `dontAsk` | `ask` | 21:38:08.350Z | none 69 s later, when the session was closed |

The `deny` control is what makes the third row readable. The same interactive
`dontAsk` session settles a hook's verdict in under half a second. So an `ask`
still waiting at 69 s is waiting on the one party who has not answered, which
is the person at the prompt. That matches the `default` control, which waits
the same way. **The prompt itself was not seen:** the Terminal panel's reader
cannot capture the full-screen interface, so "a prompt rendered" is inferred
from the pending call, not observed here. One trial per cell.

The review of this row observed it. CLI 2.1.289, driven in a pseudo-terminal
with `--permission-mode dontAsk` and a hook returning `ask`: the screen showed
the hook's reason under "Do you want to proceed?", and answering yes ran the
command. One trial, on a later CLI than the cells above.

## Which way it gets built

**Measure (answered):** an interactive `dontAsk` session does reach a person,
so by the row's own rule the `dontAsk` entry goes. Converting the `ask` removes
the human that a repo setting `"action": "ask"` asked for. That is the same
lesson branch-guard learned when it dropped `auto` from
`NON_INTERACTIVE_MODES` (#33, fixed in #88).

- Drop `dontAsk` from `UNATTENDED_MODES`, and rewrite the comment: only
  `bypassPermissions` has nobody at the prompt. Update the tests that name the
  mode, and the README's mode table, whose `dontAsk` row says it "converts it
  to its own generic deny, dropping the guard's reason".
- **branch-guard carries the same entry**
  (`plugins/branch-guard/hooks/branch-guard.py:485:NON_INTERACTIVE_MODES = frozenset({'dontAsk', 'bypassPermissions'})`),
  and reads it at two sites: the ask emitter, which denies "because
  permission mode 'dontAsk' has no way to prompt for confirmation", and the
  worktree-grant ask. The mechanism and the fix are the same, so it belongs in
  this row rather than a second one: drop it there too, with its tests and the
  six README lines that name `dontAsk` as promptless. This widens the row from
  one guard to two, on purpose.
- Add the interactive cells to `plugins/workspace-guard/docs/permission-modes.md`
  beside the headless ones, so the next guard author finds them. That doc's
  closing caveat ("not whether an interactive `dontAsk` session renders a
  prompt at all") is now answered.

**Who it is for:** an operator running `dontAsk` who configured a guard to
`ask`. Today they get a deny they never chose. Also the next guard author, who
would otherwise copy a set that two guards share.

**If it is never built:** every configured `ask` in a `dontAsk` session becomes
a deny. The operator's choice is overridden on every such call, and the reason
reaches the agent but never a person. Flat urgency.

Rank: it keeps its place. `S`, at the top of that size: one frozenset entry
and its comment in each of two guards, their tests, two READMEs, and a doc
table.
