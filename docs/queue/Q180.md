# A chained append concatenates raw values, before expansion

`extract_env_prefix` resolves `NAME+=v` by concatenating the prior value with
the new one while both are still unexpanded, and `resolve_assignments` expands
the result afterwards. When the prior value is a bare `$VAR` and the appended
text starts with a name character, the two glue into a different variable name.

## Measured

2026-09-07, on the Q174 branch:

```python
extract_env_prefix(['AWS_PROFILE=$P', 'AWS_PROFILE+=x', 'aws', 's3', 'ls'],
                   {'P': 'prod'})
  raw      -> {'AWS_PROFILE': '$Px'}
  resolved -> {'AWS_PROFILE': '$Px'}      # `Px` is unset
```

bash 5.3.15 disagrees:

```
P=prod; AWS_PROFILE=$P AWS_PROFILE+=x printenv AWS_PROFILE   ->  prodx
```

`plugins/prod-guard/scripts/bash-prod-guard.py:459:        name, append, value = split_assignment(argv[i])`
is where the concatenation happens; expansion is a later pass.

## Who it is for, and what it is worth

The direction is fail-safe: `$Px` resolves to nothing, so the target reads
UNKNOWN and the command prompts rather than being pinned to a profile that
does not match a production pattern. It is a missed *tightening*, not a
bypass -- the guard fails toward asking.

It needs both halves to reach: a prior assignment in the same run whose value
is an unexpanded `$VAR`, and an append whose text begins with a name
character. `AWS_PROFILE+=-ro` is unaffected, because `-` ends a variable name.

## What happens if it is never built

A narrow class of chained appends resolves to an unset variable instead of the
value bash produces, and the command prompts where it could have been
classified.

## Which way it gets built

Expand the prior value before concatenating, or brace it (`${P}x`) so the
appended text cannot extend the name. The second is smaller and covers the
measured case; the first is correct for any prior value and costs an ordering
change, since `extract_env_prefix` currently returns raw values by contract.

A fixture with a bare-word suffix is what catches it --
`plugins/prod-guard/tests/test_prod_guard.py:1083:    def test_append_chains_within_one_run(self):`
uses `-ro`, which cannot.

## Notes

Found in review of the Q174 pull request, in the append-resolution code that
row added. Not a regression: before Q174 the whole command deferred, because
`AWS_PROFILE+=x` was not read as an assignment at all.
