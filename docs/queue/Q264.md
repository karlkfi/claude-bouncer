# strip_comments reads a # after a substitution's close as a comment

bash reads `$(a)#b`, `<(a)#b` and `$((1))#b` as single words, because the
close of a substitution doesn't end the word. `strip_comments` starts a comment
at a `#` after any character in `COMMENT_PRECEDERS`, and `)` is one of them.
So it strips everything from that `#` to the newline, including the commands
after it. On `origin/main` at `67ee2a6`:

```
strip_comments('cat <(true)#b; P')    -> 'cat <(true)'
strip_comments('echo $(true)#b; P')   -> 'echo $(true)'
strip_comments('echo $((1))#b; P')    -> 'echo $((1))'
strip_comments('(true)#b; P')         -> '(true)'     # right: a subshell's close
```

Driven 2026-10-04 under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`,
which prints `5.3.15(1)-release`, and through the hooks on `origin/main` at
`67ee2a6`. The fixture `$HOME` set the current context to `gke_acme_prod-us`.
Payloads were `kubectl delete ns payments` for prod-guard,
`rm /etc/probe-target` for workspace-guard, and `make check | tail` for
exit-status-guard:

| command | bash runs P | prod / ws / exit |
|---|---|---|
| `cat <(true)#b; P` | yes | defer / **allow** / defer |
| `x=$(cat <(echo a)#b); P` | yes | deny / **allow** / defer |
| `echo $(true)#b; P` | yes | deny / defer / defer |
| `echo $((1))#b; P` | yes | defer / defer / defer |

workspace-guard *allows* an `rm` outside the project in the first two rows.
The independent review of the Q230 pull request found the second row. That
pull request fixes the same distinction in `_scan_dollar_paren`, a different
function, and doesn't change this one.

## Which way it gets built

In `strip_comments`, treat the `)` that closes a `$(`, `<(`, `>(` or `$((` as
part of the word, as the Q230 change does in `_scan_dollar_paren`, and keep a
subshell's `)` a word break. `strip_comments` doesn't track parens today, so
this needs it to know which `(` each `)` closes. Q254 is the neighbouring row
in this function, about a `#` *inside* backticks or `${…}`. The allocator
flagged it as a near-duplicate by title. The mechanism is different, and a fix
for either leaves the other open, but both can share one walk over
substitutions.

## If it is never built

A `#` written straight after a substitution's close hides every command after
it on that line. workspace-guard allows a write it would otherwise ask about.
