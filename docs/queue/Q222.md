# exit-status-guard stops peeling a wrapper at its first option

`peel_wrappers` drops a word in `WRAPPERS` (and the `NAME=v` operands of `env`
and `sudo`), then loops. It never drops an option. A wrapper followed by any
flag therefore leaves that flag as the command word, the registry pattern does
not match, and a gate piped into a filter goes through. This holds for a flag
that takes no value too, which separates it from the arity rows in prod-guard
(Q152, and Q200 for bundles) and foreground-guard (Q160, Q221).

Measured 2026-10-01 at `b27be8d` by driving the hook with a JSON payload:

| command | guard |
|---|---|
| `make check \| tail -5` | deny -- control |
| `sudo make check \| tail -5` | deny -- control |
| `nohup make check \| tail -5` | deny -- control |
| `stdbuf make check \| tail -5` | deny -- control |
| `sudo -n make check \| tail -5` | **defer** |
| `sudo -u root make check \| tail -5` | **defer** |
| `exec -a g make check \| tail -5` | **defer** |
| `env -u FOO make check \| tail -5` | **defer** |
| `stdbuf -oL make check \| tail -5` | **defer** |
| `setsid -w make check \| tail -5` | **defer** |
| `command -p make check \| tail -5` | **defer** |

That `env -u`/`env -iu` and `exec -a` run the command after them was driven
for Q200, with a payload absent from `PATH` under
`env -i bash --norc --noprofile -c`.

The README says gate patterns match "after leading `VAR=val` assignments and
`bash`/`sudo`/`time`-style wrappers are peeled". It says nothing about
options.

## Which way it gets built

Give `peel_wrappers` an option loop per wrapper, with each wrapper's
value-taking flags and arity decided per character (the shape Q200's fix uses
in prod-guard). Unknown options come off one word at a time. Wrong arity there
costs a missed deny, which is the direction this guard already accepts on
parse uncertainty.

`bash` and `sh` are in `WRAPPERS` too, and their options (`-e`, `-o pipefail`,
`-c`) mean something else. Leave them out of the loop.

## If it is never built

A registered gate run as `sudo -n make check | tail` or `stdbuf -oL ... | tail`
loses its exit status, with no deny.
