# An attached short-option value is not judged

A file-valued short option written with its value attached, `-t/x` rather than `-t /x`, is read as a flag with no value, so the file it names is never resolved.

Measured 2026-11-27 with the hook run against this checkout at `716a47fd`, in `default` mode; `/usr/bin/grep -f<file>` with the value attached read `<file>` as its pattern file:

| command | verdict |
|---|---|
| `cp -t /tmp/q8-fake-target README.md` (control) | deny |
| `cp -t/tmp/q8-fake-target README.md` | **allow** |
| `cp --target-directory=/tmp/q8-fake-target README.md` | deny |
| `cp -t ../q8-fake README.md` (control) | deny |
| `cp -t../q8-fake README.md` | **allow** |
| `grep -f /etc/q8-fake x README.md` (control) | ask |
| `grep -f/etc/q8-fake x README.md` | **allow** |
| `grep --file=/etc/q8-fake x README.md` | ask |
| `sed -f/etc/q8-fake README.md` | **allow** |

So the spaced and `--opt=val` spellings are judged and only the attached short one is lost.
`cp -t` is a write target, so this reaches outside writes as well as reads.
Q392 covers gawk's `-d`, `-o` and `-p`, which are file options gawk takes only attached; this row is the general case for every `SPEC` row whose short flag takes a file.

Found in review of the Q404 change by the reviewer session, and re-measured here.

Next step: in `_split_args`, a short flag in `file_flags` with characters after it takes those characters as its value, as `getopt` does, and so does a flag clustered after value-less ones (`-it/x`), which was not measured.

## If it is never built

Any guarded command whose short option names a file reads or writes outside the project with no prompt when the value is written attached to the flag.
