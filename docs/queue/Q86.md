# Drop `auto` from `UNATTENDED_MODES`

`plugins/foreground-guard/scripts/bash-foreground-guard.py:433:UNATTENDED_MODES = frozenset`
converts a would-be `ask` into a `deny`. Both classes deny by default, so the
set only fires on a config-de-escalated `ask` — where a repo wrote
`"action": "ask"` and asked to be prompted. Honour that in `auto`, and keep
`dontAsk` and `bypassPermissions`, where the prompt genuinely reaches no one.

Decided 2026-08-22 on the cross-guard convention rather than a new measurement.
branch-guard dropped `auto` from `NON_INTERACTIVE_MODES` in v1.7.0, for #33 and
#78: an `ask` in `auto` reaches Claude Code's standard permission prompt and
somebody answers it, so converting it removed the human rather than protecting
them. workspace-guard treats `bypassPermissions` alone as human-free.
foreground-guard was the last of the three still holding `auto`, and its own
README already concedes the prompt is delivered — the `auto` row reads "prompts
you *anyway*", so what the deny bought was silence, not an answer. A repo's
explicit `ask` is the more specific signal and outranks the session mode.

Four surfaces, and two fixtures invert rather than survive:

- `plugins/foreground-guard/tests/test_foreground_guard.py:852:for mode in ("auto", "dontAsk", "bypassPermissions"):`
  loses `auto`, which moves up to `test_supervised_ask_survives_an_attended_mode`.
- `plugins/foreground-guard/tests/test_foreground_guard.py:857:def test_supervised_slow_ask_becomes_a_deny_unattended(self):`
  runs its one case in `auto`; re-point it at an unattended mode.
- The mode table's `auto` row,
  `plugins/foreground-guard/README.md:430:interrupting the run you chose not to babysit`,
  joins the attended group, and the "three modes cannot deliver the prompt"
  sentence above the table becomes two.
- The comment at the emit site explains the deny per mode and loses its `auto`
  clause.

`test_override_defers_in_every_permission_mode` and
`test_default_denies_in_every_mode` both loop over `auto` and are unaffected —
an override defers everywhere and the defaults deny everywhere, neither of
which routes through the set.
