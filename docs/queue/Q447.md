# A cd late in a loop body is not applied to the next pass

The hook tracks the working directory through a loop body once, top to bottom, so a `cd` after a read in the body never reaches that read, though bash runs it again from the new directory.

Measured 2026-11-27 with the hook run against this checkout at `c851c3d7`, in `default` mode.
Under bash 5.3.15, `for i in 1 2; do cat f; cd sub; done` printed `f` and then `sub/f`:

| command | verdict |
|---|---|
| `cd /tmp/q8-fake-target && cat x` (control) | deny |
| `for i in 1 2; do cd ..; cat x; done` (control) | ask |
| `for i in 1 2; do cat x; cd /tmp/q8-fake-target; done` | **allow** |
| `for i in 1 2; do cat x; cd ..; done` | **allow** |
| `while true; do cat x; cd ..; done` | **allow** |
| `for i in 1 2; { cat x; cd ..; }` | **allow** |
| `for i in 1 2; do cat x; pushd ..; done` | **allow** |

Found in review of the Q406 change by the reviewer session, and re-measured here.
It is Q406's defect for the working directory instead of a variable, which is why it is a row of its own: Q406 drops names, and this needs the cwd to go unknown.

Next step: at a loop's first group, if any group in the body moves the cwd, treat the cwd as unknown for the whole body, as an untracked `cd` already does, using the loop spans `split_groups` records.
