# branch-guard judges no process substitution's body

bash runs the command inside a `<( )` or `>( )`, so `cat <(git commit -m x)` commits.
The guard reads a process substitution only to withhold an `allow`, in `has_shell_substitution`, so on `main`, where the bare commit asks, these get no decision.
Driven 2026-11-26 through `hooks/branch-guard.py` with the payload's `cwd` in a checkout of `main`, on `origin/main` at `c0bc0235` and on the branch that judges command substitution bodies, with the same verdicts:

| command | verdict |
|---|---|
| `git commit -m x` | ask |
| `cat <(git commit -m x)` | defer |
| `diff <(git push --force origin main) x` | defer |

## Which way it gets built

`substitution_verdicts` judges each body `command_substitutions` returns, placed in the directory in force where it sits.
`lib`'s `process_substitutions` returns these bodies with their spans, and workspace-guard's `all_substitutions` already merges the two lists, dropping a `$( )` nested inside a `<( )` so no two spans overlap.
A process substitution runs in a subshell, so a `cd` in its body moves nothing outside it, the same as in an ordinary command substitution.

## If it is never built

A protected-branch git command written inside a process substitution reaches the user's own permission rules instead of branch-guard's prompt.
How often sessions write that shape is not measured.
