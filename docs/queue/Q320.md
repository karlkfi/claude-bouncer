# command_substitutions reads a comment inside [[ ]] as text

`_comment_free_end` holds a whole `[[ … ]]` span comment-free for
`command_substitutions`
(`lib/bouncer_parse.py:1170:            quiet = max(quiet, _comment_free_end(text, i, brk))`),
on the reading that a `(` or `|` starts no word there. bash disagrees after a
blank. Under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`, which
prints `5.3.15(1)-release`, `[[ -n x #it's` newline `]] && echo P` prints P:
the `#it's` is a comment. `[[ (#c` newline `-n x) ]] && echo P` and
`[[ x =~ ( #c` newline `) ]] || echo P` print P too. Inside `[[`, a `#` is
text only in a `=~` operand and only when not after a blank, as in
`[[ a =~ (#x) ]]`.

Read as text, the `'` in that comment opens a quote that runs over the rest of
the string, so the `$( )` on the next line is never returned. Driven
2026-11-01 on the Q293 branch, with `P` standing in for prod-guard's
`kubectl --context gke_acme_prod-us delete ns payments`, workspace-guard's
`rm /etc/probe-target`, exit-status-guard's `make check | tail` and
foreground-guard's `tail -f log.txt`:

| command | prod / ws / exit / fg |
|---|---|
| `[[ -n x #it's` newline `]] && echo "$(P)"` | deny / **defer** / deny / **defer** |
| `[[ -n x #c` newline `]] && echo "$(P)"`, the control | deny / ask / deny / deny |

`command_substitutions` on the first returns `[]`, and on the control `['P']`.

Q293 met this while fixing the same misreading in `strip_comments`, where it
took bash's rule instead of `_comment_free_end`'s span: an extglob group held
whole, and inside `[[` only a `=~` operand's glued `#` held as text.

## Which way it gets built

Give `command_substitutions` the rule `strip_comments` now carries: drop the
`[[` branch from `_comment_free_end`, and track the `=~` operand in the scan so
a `#` not after a blank there opens no comment. Keep Q258's cases passing, and
correct `_comment_free_end`'s docstring, which states the span reading.

## If it is never built

A `$( )` written on the line after a `[[ … ]]` that carries a comment with an
apostrophe goes unjudged by workspace-guard and foreground-guard. The shape
needs both a comment inside `[[` and a quote character in it, so it is likely
rare.
