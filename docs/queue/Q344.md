# A sed token after -i '' that sed would reject gets the -e rewrite

Q232 turns the outside ask on the token after `sed -i ''` into a deny that
tells the agent to write `sed -i '' -e SCRIPT FILE`, where Q328's parser reads
that token as a script naming no file and running nothing. The parser stops at
the first command sed would reject and does not say so, so a token it stopped
on counts as clean. That covers scripts sed rejects, whose rewrite hands the
agent a command sed will not run, and most real file paths under GNU's reading,
which lose the outside ask a person could answer.

| Command | Today | With the remedy below |
|---|---|---|
| `sed -i '' /q-fake/hosts` | deny, sed script | ask, outside |
| `sed -i '' /q-fake/data/notes.txt` | deny, sed script | ask, outside |
| `sed -i '' '/x/{' f` | deny, sed script | ask, outside |
| `sed -i '' '/x/}' f` | deny, sed script | ask, outside |
| `sed -i '' '/x/Z;w /q-fake/a' f` | deny, sed script | ask, outside |
| `sed -i '' '/^#/d' f` | deny, sed script | deny, sed script |
| `sed -i '' '/x/{p;}' f` | deny, sed script | deny, sed script |
| `sed -i '' /q232-fake/target` | deny, sed script | deny, sed script |

Measured 2026-11-01 with the hook run directly against a scratch workspace, at
Q232's merged head (the "Today" column) and with the remedy applied (the other
column). Every verdict is a deny or an ask, so nothing runs unjudged either way.
Found by the stream D reviewer on Q232's pull request.

## The remedy, and why it was not taken with Q232

`sed_script_reads` returns a third value, whether it read to the end with its
braces closed, and `sed_script_slot` relabels only when both bracket readings
did. The check it would extend is
`plugins/workspace-guard/scripts/bash-workspace-guard.py:3268:        if named or runs:`.
Written and measured for Q232 but not pushed: a test of the five "ask" rows above
failed exactly those five at Q232's head, and removing the brace tracking failed
exactly the two brace rows.

It was held back because it does not make GNU paths consistent. `/q-fake/hosts`
asks again, since `o` is not a sed command, but `/q232-fake/target` reads to the
end (an address, then `t` with the label `arget`) and still denies. Whether a
GNU file asks or denies would turn on whether its name happens to be valid sed.
Q232 accepted the GNU deny as a trade, since GNU runs an empty script over the
file and changes nothing.

**Settles:** whoever takes this decides whether a rewrite that is wrong for a
rejected script, and a deny on a real GNU path, are worth the arbitrary split
the remedy introduces. Taking the remedy is the smaller change; the alternative
is to keep today's behaviour and say so in the README's Limitations entry.
