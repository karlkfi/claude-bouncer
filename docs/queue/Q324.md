# strip_comments reads a # after an escaped blank as a comment

`strip_comments` starts a comment at a `#` that follows a blank, including a
blank escaped with `\`
(`lib/bouncer_parse.py:451:        at_word = (not out or out[-1] in COMMENT_PRECEDERS) and len(out) != glued`).
bash reads `\ ` as a literal space inside the word, so the `#` after it is
text. Under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`, which prints
`5.3.15(1)-release`, `echo a\ #b ; echo P` prints `a #b` and then `P`, and
`[[ x =~ a\ #b ]] || echo P` prints `P`.

`strip_comments` cuts both at the `#`: `echo a\ #b ; id` comes back as
`echo a\ `, so every guard sees no command after it. Driven 2026-11-01 on the
Q293 branch, with `P` standing in for prod-guard's
`kubectl --context gke_acme_prod-us delete ns payments`, workspace-guard's
`rm /etc/probe-target`, exit-status-guard's `make check | tail` and
foreground-guard's `tail -f log.txt`:

| command | bash runs P | prod / ws / exit / fg |
|---|---|---|
| `echo a\ #b ; P` | yes | **defer** ×4 |
| `[[ x =~ a\ #b ]] \|\| P` | yes | **defer** ×4 |

`origin/main` at 4e50dc4 defers on both as well; r-lib found it reviewing Q293.

## Which way it gets built

Treat a blank preceded by an unescaped `\` as part of the word, so it starts
no word and opens no comment. Check the other readers of `COMMENT_PRECEDERS`
and `_comment_free_end` for the same shape, and test `\\ #b`, where the
backslash is itself escaped and the `#` does start a comment.

## If it is never built

Any command written after `\ #` on the same line goes unjudged by all four
guards. An escaped blank before a `#` is an unusual way to write an argument,
so the shape is likely rare outside a deliberate attempt.
