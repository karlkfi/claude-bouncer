# `mkdir` and `md` are functions over `New-Item`, so its row misses them

Q103 gave `New-Item` a `PS_SPEC` row, which closed the link forms it was filed
for and, with them, ordinary creation: `New-Item -ItemType File -Path <outside>`
now asks. `mkdir` and `md` still defer. They are PowerShell **functions** that
call `New-Item -ItemType Directory`, not aliases of the cmdlet, so `PS_ALIASES`
never sees them and neither does the row.

Measured 2026-08-23 on the Q103 branch, with the project root elsewhere:

    mkdir /q103-fake-target
    md /q103-fake-target

both defer, while `New-Item -ItemType Directory -Path /q103-fake-target` asks.
An outside-workspace directory creation through the spelling a session is most
likely to reach for.

Two `PS_ALIASES` entries would route them, and the reason it was left out of
Q103 is Q3's: an alias whose parameter set diverges from the row it points at is
the mistake that item recorded. `mkdir`'s signature looks like a subset of
`New-Item`'s, and it forces `-ItemType Directory`, so `-Value` would correctly
read as content -- but that is a reading of the documentation rather than a
measurement, and the host that filed this has no PowerShell on it
(`command -v pwsh powershell` exits 1). Confirm the binding on a Windows venue
before adding the entries, or the row buys a silent misbinding instead of a
check.
