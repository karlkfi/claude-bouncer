# A wrapped write gets no note that it never ran

When a guard refuses a whole Bash call, `note_discarded_writes` appends a sentence naming the writes in it that did not happen, so the model does not believe an edit landed.
`_segment_writes` finds the command name after `strip_env_prefix` and `strip_sh_keywords`, which take off a leading `FOO=1` and a keyword such as `time`, but no wrapper.
So a write behind `env`, `nice` or `sudo` is left out of that sentence, whatever kind of write it is.
Measured 2026-11-16 on `origin/main` at `36d05ed8`, calling `discarded_writes` directly:

| command | writes named |
|---|---|
| `sed -i p f` | `` `sed -i` `` |
| `env sed -i p f` | none |
| `tee g` | `` `tee g` `` |
| `env tee g` · `sudo tee g` | none |
| `cp a b` | `` `cp` to `b` `` |
| `nice cp a b` | none |
| `FOO=1 tee g` | `` `tee g` `` |

Found by review-r1 on #347, for `env sed -i p f`.
All five guards call `note_discarded_writes`, so each one's refusals lack the note.
The refusal itself still lands and nothing runs.

Q372 is the same note missing `gsed -i`, for a different reason: the `sed` case matches the bare name.
One change to `_segment_writes` may close both, but that is unmeasured.
Whether peeling here should go through the shared wrapper walk (`lib/bouncer_wrappers.py`) or a narrower skip is not settled either.

## Which way it gets built

Peel the wrappers off `argv` in `_segment_writes` before reading the name, and pin a wrapped row of each write kind in the shared parser's tests.
Then `make sync` to carry it into all five vendored copies.

## If it is never built

A refused call whose write sits behind a wrapper says nothing about that write.
A model that wrote the edit and its check in one call may then read the edit as done, which is the mistake the note exists to stop.
