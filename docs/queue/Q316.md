# An owned branch pushed from another branch skips the overlap check

Since Q309, branch-guard allows a push of a branch this session created, under
the default `strict` policy. When that push sends `HEAD`, the overlap check
still runs and still denies a branch whose base moved under its edited lines.
When it sends some other owned branch — `git push origin feat/other` from the
worktree branch — no overlap check runs at all, so a branch whose base moved
under it is pushed without the `deny-rebase` a worktree-branch push would get.

The cause is that `push_overlap` measures `HEAD`, not the branch being pushed
(`plugins/branch-guard/hooks/branch-guard.py:1721:def push_overlap(cwd, branch):`).
Measuring `HEAD` for a push that does not send it would deny or pass on the
wrong branch's diff, so `push_decision` reports such a push through its
`off_branch` out-parameter and the caller stands the check down
(`plugins/branch-guard/hooks/branch-guard.py:2132:        if decision == 'allow' and probe and not off_branch \`).
That was the safe half of the choice; this row is the other half.

Found while building Q309, by reading the two call sites; no fixture drives an
owned non-`HEAD` push against a moved base, and the bite rate is unmeasured.
Before Q309 the same push asked, so a human saw it; after, nothing does.

## Which way it gets built

Teach `push_overlap` to measure a named ref instead of `HEAD`, and pass the
pushed branch when `off_branch` names an owned branch. Queue-id claims, the
other `off_branch` case, carry no tree and stay exempt.

**If never built:** an owned side branch whose base moved can be pushed stale
without a prompt or a deny, where the same push from its own worktree is denied.
