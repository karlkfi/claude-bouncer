# A sed script variable reassigned after IFS keeps its stale text

Assigning `IFS` stops variable tracking for the rest of the string and clears `varmap` and `loopmap`, but not `textmap`, which holds the values a double-quoted sed script splices in.
A later reassignment is then not seen, and the script is read with the old text.

Measured 2026-11-24 on `main` at `de050f70`, with the hook run against this checkout:

| command | verdict |
|---|---|
| `S="1p; 2p"; S="w /etc/q8-fake"; sed -n "$S" README.md` (control) | ask |
| `S="1p; 2p"; IFS=x; S="w /etc/q8-fake"; sed -n "$S" README.md` | **allow** |

`bash` expands the second `$S` to the `w` command.
The branch is `plugins/workspace-guard/scripts/bash-workspace-guard.py:6258:if 'IFS' in assigned:`.

Next step: clear `textmap` there, as the `clobbers_ifs` branch below it does, and check `funsub_poison`, which is called on `varmap` and `loopmap` only.

## If it is never built

A sed script that writes a file outside the project is allowed when its variable is set before and after an `IFS` assignment.
