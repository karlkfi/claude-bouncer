# prod-guard does not peel nice, so the command behind it defers

`strip_wrappers` peels `sudo`, `env`, `timeout`, `xargs` and the
`PLAIN_WRAPPERS` set. `nice` is in none of them, so `nice` takes the command
head and the covered tool behind it is never classified.

Found by the independent review of the Q200 pull request. Re-driven 2026-10-01
through the hook (fixture `$HOME`, ambient context `gke_acme_prod-us`) at the
Q200 head:

| command | guard |
|---|---|
| `nice kubectl delete ns payments` | **defer** |
| `nice -n 5 kubectl delete ns payments` | **defer** |
| `ionice -c 3 kubectl delete ns payments` | **defer** |
| `setsid kubectl delete ns payments` | **defer** |
| `chrt -f 1 kubectl delete ns payments` | **defer** |
| `taskset -c 0 kubectl delete ns payments` | **defer** |

BSD `nice` runs the command after both spellings. That was driven under
`env -i bash --norc --noprofile -c` with a payload absent from `PATH`. The
other four are Linux tools that are absent here, so whether they run the
command is from their documentation, not a drive. workspace-guard's
`LOCAL_SHELL_WRAPPERS` already names `nice`, `ionice` and `setsid`.

## Which way it gets built

Add the wrappers with their value-taking flags, and put each new set through
`flag_arity` so bundles and attached values come out right from the start:
`nice -n` is measured here. `chrt` and `taskset` take a positional operand
before the command, like `timeout`'s duration, according to their usage text.
Measure every Linux-only wrapper on a Linux runner before relying on that. Q194 counts the README's wrapper list, so update the
README in the same change.

## If it is never built

`nice kubectl delete …` is a natural way to run a heavy command politely, and
it reaches production with the guard silent.
