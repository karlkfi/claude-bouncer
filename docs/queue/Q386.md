# An unquoted expansion in a program slot splits into skipped operands

`sed`, `grep` and `awk` take their first positional as the program, and the
hook skips that slot. Unquoted, a `$p` there is word-split by bash, so its value
can carry operands, and even options, that the hook never judges. The same
`$p` as a file operand denies as runtime-expanded. Measured by the Q335 design
review on `origin/main` at `6908336`, with the hook run against a scratch
workspace:

| command | workspace-guard | real |
|---|---|---|
| `p='p in.txt /etc/qf'; sed $p` | allow | `p='p in.txt ../x'; /usr/bin/sed $p` printed `../x` |
| `p='-n -ew/etc/qf'; sed $p in.txt` | allow | `-n -ew../leakU` created `../leakU` |
| `p='x /etc/qf'; grep $p` | allow | not run |
| `p='{print} /etc/qf'; awk $p` | allow | not run |
| `p='in.txt /etc/qf'; cat $p` (control) | deny | |

Q335 left this alone. It reads a sed script's expansions, and this is a
different mechanism that reaches grep as well. Q334, awk's own program, is a
neighbour too and does not cover it.

## Where it lands

A program slot holding an unquoted expansion would get the existing `expand`
deny, which `cat $p` already gives. Two traps from building it once for sed in
Q335:

- **Quoting is lost on sliced values.** A value cut from its option, such as
  `--expr='$r f'` or `-e'$p'`, comes back from `split_eq` or a slice as a
  plain `str` with no `QuotedStr` record. So a single-quoted script reads as
  unquoted, and `sed --expr='$r /x' f` turned from its ask into the `expand`
  deny.
- **An unquoted `$(…)` and `$((…))` both reach the group as a bare `$(`**, the
  tokenizer's placeholder, so arithmetic (`sed -n $((n+1))p f`) cannot be told
  from a command substitution there. Q335 lets the bare `$(` through.

## If it is never built

An agent's `sed $p`, `grep $p` or `awk $p`, with `p` holding a space, reads or
writes the files in the value with no prompt.
