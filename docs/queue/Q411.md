# Move the four other friction reports onto lib/bouncer_friction.py

Blocked on karlkfi/claude-bouncer#374, which is changing the four scripts this row replaces parts of.

`lib/bouncer_friction.py` reads hook decisions out of session transcripts, and branch-guard's report is the only one built on it.
The other four still carry their own copy of that reader, so one change in what Claude Code records is four edits.
The denial prefix was: #374 fixes it four times, and found two of the four had never read a denial.

Moving a report onto the module also fixes what its copy gets wrong today:

- **A call copied into a second transcript counts twice.** #374 measured 49 of 7,918 denials, and its rule is per file.
  The module keys on the tool-use id across files.
- **A launcher-wired guard reads as all denies** (Q249), in the three copies whose `guard_name` requires a `.py`.
- **An untimestamped record or a `command hook N` label** is handled once instead of four times.

## Which way it gets built

One report per pull request, each keeping its own categories and printing, and its own denominator.
The module yields a call or a decision and filters nothing, so `--since`, `--repo` and `--plugin` stay in the script. exit-status-guard and workspace-guard also recover denials recorded before the opener shipped, by their own wording.
The module does not read those, so it needs a hook for it: the `own_label` argument is the same shape, over an error result.

Run each report over the real corpus before and after, and account for every count that moves.

**Who is worse off:** whoever next changes how a transcript is read, and anyone comparing two guards' reports, which read the same records by different rules.
