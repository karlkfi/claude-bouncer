# A `#` in `${…}` or backticks inside a `$( )` hides the rest of its body

bash reads a `#` inside `${…}` as text, and ends a comment inside backticks at
the closing backtick. The scanner that finds a `$(…)` body starts a comment at
any word-start `#`
(`lib/bouncer_parse.py:812:        if c == '#' and brk:`), so it reads both
as comments running to the newline. The commands after one fall into the
comment, and when the substitution's `)` falls in too, no body comes back.

Unquoted, the guards still judge P, because the flat lexer spills the body's
words into the outer command. In double quotes nothing spills. Driven
2026-10-05 on `origin/main` at `eed9305`, with bash under
`env -i /opt/homebrew/bin/bash --norc --noprofile -c`, which prints
`5.3.15(1)-release`. Payloads were `kubectl delete ns payments` (fixture
context `gke_acme_prod-us`), `rm /etc/probe-target`, `make check | tail` and
`sleep 300`:

| command | bash runs P | prod / ws / exit / fg |
|---|---|---|
| `echo "$(echo ${y:- #}; P)"` | yes | **defer** ×4 |
| ``echo "$(echo `true # c`; P)"`` | yes | **defer** ×4 |
| `echo "$(echo ${y:-x}; P)"`, the control | yes | deny / ask / deny / deny |
| `x=$(echo ${y:- #}; P)` | yes | deny / ask / deny / deny |

This is Q254's mechanism, which that fix closed in `strip_comments`, met in
the body scanner Q230 taught about comments. It was found while building Q258,
which added the same word rule to `command_substitutions`.

## Which way it gets built

Hold a `${…}` span and a backtick span whole in `_scan_dollar_paren`, the way
`strip_comments` does. `_brace_end` and `_scan_backticks` already find their
ends. Keep Q230's cases passing: a comment in the body still runs to its
newline.

## If it is never built

`"$(echo ${y:- #}; rm -rf x)"` passes every guard unjudged.
