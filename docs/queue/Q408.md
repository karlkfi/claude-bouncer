# foreground-guard's report counts no Monitor denial

foreground-guard's hook runs on `Bash|Monitor`, and its friction report reads `Bash` alone.
A denied Monitor call is dropped three times over: the attachment filter takes `PreToolUse:Bash` only, the index that joins a result to its call holds Bash calls only, and the denominator counts Bash calls only.

Measured 2026-11-24 over every local transcript, counting error results that open with this guard's name by the tool that was called: 561 Bash and 20 Monitor, one of the 20 in the last seven days. pr-sentinel had 8 Monitor denials in those seven days beside 18 on Bash, so `--plugin all` misses more of another plugin's denials than of this guard's. workspace-guard's copy joins on any tool and already counts them.

## Which way it gets built

Read both tools in all three places.
The rate needs a wording change with it: the text report, the README and the `bash_calls` JSON key all say Bash calls, and a Monitor call is not one.
Keep the key and its meaning, and add `monitor_calls` beside it, so a reader of the JSON sees no number change meaning under the same name.

**Who is worse off:** anyone tuning the guard from its report.
Monitor is where a denied poll goes next, so a report that cannot see it reads a moved habit as a fixed one.
