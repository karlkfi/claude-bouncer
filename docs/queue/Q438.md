# A job backgrounded in a process substitution is read as detached

foreground-guard defers on `cat <(sleep 30 &) >/dev/null`, which holds the main thread for the full sleep.
`cat` reads the FIFO until every writer has closed it, and the backgrounded `sleep` inherits the FIFO as its stdout, so the reader waits.
This is the `$( )` case Q363 fixed, one operator over: a process-substitution body is judged as foreground already (`cat <(sleep 30)` denies) but never with the `piped` flag, so its backgrounded segments stay exempt.

Found by the stream reviewer on the Q363 pull request, #406, at `908a285`, in its review comment there.
Re-measured 2026-11-27 with `env -i /opt/homebrew/bin/bash --norc --noprofile -c` (GNU bash 5.3.15) and the hook on the Q430 branch at `5c3f160`:

| command | bash, 1 s sleep | foreground-guard, 30 s sleep |
|---|---|---|
| `cat <(sleep 1 &) >/dev/null` | 1.05 s | none |
| `cat <(sleep 1 >/dev/null &)` | returns at once (reviewer: 0.05 s) | none |

## Which way it gets built

Analyse a `<( )` body with `piped` set, the way a `$( )` body is.
The reader decides whether the wait happens: `cat` reads to EOF, a consumer that stops early would not wait.
So this leans toward a deny on a reader the guard cannot see, which the fix should say rather than discover.
Not measured.

## If it is never built

A wait written as `cmd <(sleep N &)` blocks the main thread while the guard reads it as detached.
How often sessions write one is not measured.
