# A substitution in a redirect target is judged from the session's tree

`substitution_cwds` places each substitution at the segment that holds it, and a redirect target's substitution gets no place, so its body is judged from the session's cwd (`plugins/branch-guard/hooks/branch-guard.py:3799:def substitution_cwds(text, spans, funsubs, seg_cwd):`).
Driven 2026-11-27 through the hook on `main` 6f66f79, with the payload's `cwd` a feature worktree and `../main` a checkout of `main`, the first two get no decision while the last two ask, and bash commits on `main` in all four:

```
cd ../main && echo x > >(git commit -m x)
cd ../main && echo x > "$(git commit -m x)"
cd ../main && cat <(git commit -m x)
cd ../main && echo "$(git commit -m x)"
```

The command-substitution form predates Q420, which inherited it for process substitutions; Q430 is foreground-guard's version of a redirect target the walk does not read.

Next step: have `substitution_cwds` give a redirect target's substitutions the place of the segment the redirect belongs to; the `[procsub]` fixtures in `test/run.sh` are where its pair goes.
How often sessions write a substitution as a redirect target is not measured.
