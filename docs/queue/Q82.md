# Reconcile the "no real sensitive paths in fixtures" rule with the tree

The counts hold. Re-measured 2026-08-24 over
`plugins/workspace-guard/tests/test_workspace_guard.py`: `/etc/passwd` 35 times,
`id_rsa` and `.aws/credentials` 6 each, across 44 lines of a 10,289-line file.
Eight are comments quoting the fixture beside them, so they rename with it.

**The rule is not losing, which changes what this is.** `git log -S` over this
repository's history of that file returns no commit that moved the `/etc/passwd`
count, against seven that added a `qN-fake-target` placeholder — 192 of those now
stand against 47 real-path tokens, and the newest carry IDs q113, q119, q121.
Every real path predates the import. So it is residue rather than drift, and
nothing in the suite is at risk: `_decision` hands the command to the hook as a
JSON string and no test executes one.

**One site is not residue, and this row did not name it.**
`plugins/workspace-guard/scripts/capture-prompt-screenshot.sh:101:Run this bash command verbatim and then stop`
launches Claude Code and asks it to run `grep root /etc/passwd` for real. That is
the hand-exercise the rule forbids, in the one place where the risk it names is
live. It is out of scope here because the fix restages a screenshot with no SVG
master, on a Mac with Screen Recording granted — filed as Q130.

**Which way it gets built: rename, do not narrow.** All three risks the rule
states are about execution, so narrowing it to the executing surface is
defensible — and it would leave standing the single instance that executes, which
is the split that produced Q130 rather than an argument for looser prose. Rename
the 47 to `qN-fake-target`, rename the 13 in `tests/test_bouncer_parse.py` beside
them, and add a grep gate to `make check` so the rule stops being prose the tree
contradicts. `/etc` itself is load-bearing in three Git-for-Windows path-mapping
cases and stays. Decide in the same pass where the rule lives: it sits in
`plugins/workspace-guard/CLAUDE.md:79:Never use real outside-workspace paths`,
which has no reach over the shared parser's test at the repo root — hence the
`repo` label.

**Out of scope, deliberately.** `plugins/workspace-guard/README.md` carries 23,
and the rule scopes itself to fixtures and hand-exercises. `grep secret
/etc/passwd` is the clearest line a reader gets for what `ask` means, and a gate
over the README would need an exception for it anyway.

**If it is never built,** the rule keeps reading as unenforced to the next
session that opens the suite after loading that `CLAUDE.md` line — which is how a
convention that is currently winning starts losing.

`S` holds. Rank `ab` holds: it is a tidy-up, and the instance with teeth left
with Q130.
