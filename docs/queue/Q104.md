# Nothing checks that the five companion rosters still agree

Q89 gave all five plugin READMEs one companion-plugin roster: the same six
entries, in the same order, with byte-identical bullet text, and no count
stated in prose. Uniformity is what makes drift greppable, and nothing enforces
it — adding a sixth guard still means editing five sections by hand, and
missing one fails no gate.

`make check` cannot see this today. It runs sync-check, version-check,
path-filter-check, backlog-lint, lib-test and plugin-tests; none reads a
README. The check itself is small: extract the bullet block between
`## Companion plugins` and `They run side by side` from each of the five, assert
every plugin lists exactly the other five in the canonical order, and assert
each sibling's bullet text is identical across the files that carry it. A
session wrote that check ad hoc while completing Q89 and it found the roster
clean; it was not kept, because a gate belongs in the tree rather than in a
transcript.

Rank is tail on purpose: the rosters agree right now, so this prevents a
recurrence rather than fixing a live defect. It comes due the next time a guard
is added or removed.
