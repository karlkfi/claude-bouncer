# A probe word used as an argument exempts a real gate

`Registry._matches` exempts a gate when any word after the command name is in `PROBE_FLAGS` (`plugins/exit-status-guard/scripts/bash-exit-status-guard.py:621:        if any(w in PROBE_FLAGS for w in words[1:]):`).
That reads the word's spelling and not its role, so a probe word that is an option's argument or a positional operand exempts a run whose status is real.
Driven 2026-11-16 against the hook at `c3e1f736`, which is Q350's branch, with `git commit -m x | tail` denied beside them as the control:

- `git commit -m --help | tail` is silent.
- `git commit -m --version; git push` is silent.
- `git commit -m version; git push` is silent.
- `git checkout version | tail` is silent.

git runs every one of them.
In a scratch repository on git 2.55.0, `git commit --allow-empty -m <word>` for each of `--help`, `-h`, `--version` and `-V` made a commit and took the count from 1 to 5, and `git checkout version` with a branch of that name exited 0 and switched to it.

**Who is worse off.** A session whose commit message or branch name happens to be a probe word, which loses the exit status the guard exists to keep.
That is rare: a message that is exactly `--help`, or a branch called `version`.
Flat urgency, but a missed deny, so it fails silent where Q350 failed loud.

**Next step.** Stop exempting a probe word that is an option's argument or an operand.
Which position counts as a flag differs by tool (`go test --help` and `make --version` both probe), so measure the table's existing probe cases before narrowing.
Pin the four commands above as denies, and keep every `--version`/`--help` case already in the table silent.
