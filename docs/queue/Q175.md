# `glue_dollar_paren` drops token provenance, so a quoted override arms

exit-status-guard drops its deny when the command string carries an override
whose name bash never assigns, provided a `$(` follows the quoted part. The
same quoted word without the `$(` keeps the deny.

## Measured

2026-10-07, driven through the hook on `origin/main` at `b76477a`, worktree
root as `cwd`:

| command | verdict |
|---|---|
| `make check \| tail` -- control | deny |
| `EXIT_STATUS_GUARD_OVERRIDE=$(echo x) true; make check \| tail` -- real override | defer |
| `'EXIT_STATUS_GUARD_OVERRIDE=x' true; make check \| tail` | deny |
| `'EXIT_STATUS_GUARD_OVERRIDE='$(echo x) true; make check \| tail` | **defer** |
| `'EXIT_STATUS_GUARD_OVERRIDE'=$(echo x) true; make check \| tail` | **defer** |

Bash does not assign either of the last two. Under
`env -i /opt/homebrew/bin/bash --norc --noprofile -c` on 5.3.15,
`'FOO='$(echo x) true` and `'FOO'=$(echo x) true` each print
`FOO=x: command not found`, exit 127, and leave `FOO` empty.

The cause is the one rebuild on exit-status-guard's path.
`lib/bouncer_parse.py:1768:out[-1] += '('` glues the `(` onto the
word before it, and `str + str` is a plain `str`, so the glued word loses the
`quoted_from` record the lexer attached. `is_assignment` then reads it as
written plain. The tokens reach the override reader through
`plugins/exit-status-guard/scripts/bash-exit-status-guard.py:208:return glue_dollar_paren(split_operator_runs(tokens)), cleaned, expanded`
and are read at
`plugins/exit-status-guard/scripts/bash-exit-status-guard.py:798:for tok in strip_sh_keywords(seg.tokens):`.

## Which way it gets built

**Decide what a word is on the token the lexer produced. Carry the record
through a rebuild only where the rebuild leaves the word's prefix intact.**
This row was filed offering three shapes and choosing none; the repo had
already chosen, and two of the three are now measured out.

1. **In `glue_dollar_paren`, return a `QuotedStr` that keeps the glued word's
   `quotes` and `quoted_from`.** Appending `(` leaves every offset into the
   word unchanged, so the copied record stays exact. Prototyped 2026-10-07 on
   a scratch copy of exit-status-guard at `b76477a`, with the edit asserted
   present in the file first: the two bold rows above return `deny`, and the
   other three rows are unchanged. One change in `lib/` covers
   workspace-guard's glue as well, at
   `plugins/workspace-guard/scripts/bash-workspace-guard.py:3864:return glue_dollar_paren(split_operator_runs(list(lex)))`.
2. **Rewrite the provenance paragraph of `is_assignment`'s docstring**, at
   `lib/bouncer_parse.py:1618:pre-Q170 behaviour, and fail-open in this direction: it arms an override on`.
   It should state the rule above, drop `glue_dollar_paren` from its list of
   rebuilds, and say that the cost of the plain-`str` fallback depends on the
   reader (see *What the fallback costs* below). Its sentence *Every
   command-position caller in that file runs above its boundary* does not say
   which file it means.
3. **Fixtures**: the five rows above as exit-status-guard end-to-end cases,
   and a parser test that a glued word keeps `quoted_from`.

**The rule is already the repo's pattern at every rewrite that is not
append-only.** workspace-guard decides its peel on the raw tokens and applies
it by index in two places:
`plugins/workspace-guard/scripts/bash-workspace-guard.py:4037:# Decide the peel on`
and
`plugins/workspace-guard/scripts/bash-workspace-guard.py:4806:# Count the peel on the raw group, apply it to the substituted one by`.
prod-guard keeps its only command-position reader,
`plugins/prod-guard/scripts/bash-prod-guard.py:773:while i < len(argv) and is_assignment(argv[i]):`,
on the lexed group at
`plugins/prod-guard/scripts/bash-prod-guard.py:3023:seg_env, argv_raw = extract_env_prefix(group, shell_env)`,
above the rebuild at
`plugins/prod-guard/scripts/bash-prod-guard.py:3037:argv = strip_wrappers(expand_argv(argv_raw, same_shell), seg_inline,`.

**Carrying the record through every rebuild is out.** A word can become
assignment-shaped only after substitution, and then there is no record to
carry: `n=foo; $n=x true` prints `foo=x: command not found` on bash 5.3.15,
exits 127, and leaves `foo` unset (re-run 2026-10-07).
Carried through `substitute_vars`, the record would say "written plain",
which is true of `$n=x` and wrong about `foo=x`. A rewrite that changes the
text also leaves `quoted_from` pointing into a different string.

**A fallback that refuses a plain `str` is out, because at runtime it is the
fail-open shape.** prod-guard turns any exception into a silent exit unless
`PROD_GUARD_DEBUG=1`. Measured 2026-10-05 on a scratch copy at `189510f`: with
`is_assignment` raising on a plain `str` and a call added below
`expand_argv`, `kubectl --context gke_acme_prod-us delete ns y` went from
`deny` to no output, exit 0. The same patch with no added call left the
verdict at `deny`, so the existing reader never receives a plain `str` on that
payload.

**A general gate is not built here.** workspace-guard reads post-substitution
tokens on purpose in `poison_vars` and `clobbers_ifs` -- its docstring says
*Called on the post-substitution tokens so an expanded builtin name is still
recognised* -- so a mechanical "no plain `str` at command position" check
needs an opt-out at each such site, and nobody has counted them. Q294 holds it
as deferred, with the trigger that would make the cost worth paying.

**Measure (answered):** the census below.

## What the fallback costs

This row's title used to call the fallback fail-open, and that is true of
some readers and not others. The cost depends on what the reader does with a
word it wrongly takes for an assignment.

- **A break-glass override is bounded by what writing it plainly gets.** The
  deny reasons tell the model to add the prefix, so arming one off a quoted
  word gives nothing the model could not get by writing it plainly. In
  prod-guard that is a confirmation prompt instead of a deny
  (`plugins/prod-guard/docs/design.md:40:The override keeps intentional prod work possible in exactly one deliberate, auditable step`).
  In exit-status-guard it is the deny dropped. Measured on a scratch
  prod-guard copy whose prefix reader was handed plain strings:
  `'PROD_GUARD_OVERRIDE=x' true; kubectl delete ns y` moved from `deny` to
  `ask` and no further.
- **A shell variable that later expansion reads is the real fail-open
  route.** On the same copy, `'C=kind-ci'; kubectl --context $C delete ns y`
  moved from `ask` to no output against an ambient prod context: the guard
  resolved `$C` to a variable bash never set. This is the hazard a reader
  placed below `expand_argv` would bring back. On `main` that payload asks.
- **A peel that finds a command bash never runs** is the workspace-guard
  case: the `cd` a quoted `'d=sub'` hid was applied, and a read above the root
  resolved inside it. That one is repaired.

## Who it is for, and what it is worth

Two readers. A model whose command string happens to carry a quoted
`EXIT_STATUS_GUARD_OVERRIDE` name before a `$(` loses a deny it did nothing
to disarm; that is rare, and the cost of each occurrence is a gate status
read through a pipe that the break-glass could have waived anyway. The larger
reader is whoever adds the next command-position reader in `lib/` or a
guard, starting with Q241: the docstring is where they will look, and it
currently says the wrong thing about which rebuilds lose the record and what
losing it costs.

The rate is low and flat, so this ranks where it sits rather than higher. It
should land before Q241's prod-guard half, or that change should cite the
rule itself.

## If it is never built

exit-status-guard keeps arming on a word bash runs as a command, and nothing
tests it. The next reader added below a rebuild is placed from a docstring
that names `glue_dollar_paren` as a boundary to avoid rather than one that
can carry the record, and that calls the cost fail-open without saying which
route actually is.
