# Token provenance ends at `expand_argv`, and the fallback is fail-open

`is_assignment` reads how a word was written from an attribute the lexer
attaches to the token, and falls back to matching `ASSIGNMENT_RE` against a
plain `str` that carries no such record. The fallback is deliberate and is
documented: a caller holding hand-built tokens gets the pre-fix behaviour.

What is not documented is that a token loses the record part-way through
prod-guard's own pipeline. `expand_argv` builds new strings for `$VAR`
expansion, and a new `str` is a plain `str`, so every token downstream of it
reaches `is_assignment` stripped of its provenance and is read as written
plain.

**For a command-position consumer that is the fail-open direction**, because
"written plain" is exactly what makes a quoted `'PROD_GUARD_OVERRIDE=x'` arm
the escape hatch again. Anything placed below `expand_argv` silently gets the
behaviour the quoting fix removed.

## Measured

2026-09-07, tracing one token through prod-guard on the head that fixes the
quoting defect:

```
raw: export 'AWS_PROFILE=prod'

  out of tokenize()                'AWS_PROFILE=prod'  QuotedStr  quoted_from=0
  after extract_env_prefix         'AWS_PROFILE=prod'  QuotedStr  quoted_from=0
  after expand_argv + strip_wrappers 'AWS_PROFILE=prod'  str      (attribute absent)
```

**No prod-guard site is exposed.** `extract_env_prefix`, the one
command-position reader in that file, runs on the pre-expansion group -- which
is why `argv_raw` above still carries the record. The `ASSIGN_BUILTINS` loop
that runs after expansion is an `export` operand reader, and an operand is
supposed to be read as written plain, so it wants the fallback it is getting.

**workspace-guard has a reader that IS downstream of a rebuild.**
`plugins/workspace-guard/scripts/bash-workspace-guard.py:3772:mk = classify_mktemp(g, inline_tmpdir(kw_g))`
passes `kw_g`, built at
`plugins/workspace-guard/scripts/bash-workspace-guard.py:3617:kw_g = strip_sh_keywords(sub_g)`
from `sub_g`, which is
`plugins/workspace-guard/scripts/bash-workspace-guard.py:3601:sub_g = [substitute_vars(t, varmap) for t in g]`.
`substitute_vars` returns
the same object unless the token carries a `$`, and rebuilds it when it does --
so a token containing `$` reaches `inline_tmpdir`'s classifier as a plain
`str`, with no record, and is read as written plain.

The neighbouring reader is not exposed and shows the intended shape:
`plugins/workspace-guard/scripts/bash-workspace-guard.py:3619:assigned = apply_assignment_group(g, varmap, persists)`
passes the pre-substitution `g`, and that function's docstring already states
the rule -- *must be called on the PRE-substitution tokens*. Two readers, two
lines apart, one on each side of the boundary.

All line numbers here are `origin/main`. The fixing branch moves them, which is
the reason each carries the text of its own line.

**It is getting the right answer for the wrong reason, and nothing can catch a
change to that.** Converting that operand site to `is_assignment` on a copy of
the tree -- asserting the edit was present in the file first -- changed no
output at all across seven probe rows, including two controls that move in
opposite directions on every other site. A swap there is undetectable, so no
fixture can pin the site and no test can fail if a later change makes it wrong.

That is the finding rather than the token trace: a silent degradation with no
instrument over it.

**At the exposed site the verdict does not move, and that is luck rather than
design.** Driven end to end against the fixing head, project root as `cwd`:

```
  mktemp -d                             deny    no TMPDIR at all
  TMPDIR=<proj>/t mktemp -d             allow   bound, correctly
  'TMPDIR=<proj>/t' mktemp -d           allow   no `$`, record intact, NOT read as an
                                                assignment -- argv[0] is the word itself,
                                                an unrecognised command
  H=<proj>; 'TMPDIR=$H/t' mktemp -d     allow   `$` present, record lost, READ as an
                                                assignment -- argv[0] is mktemp and
                                                TMPDIR binds to a path bash never set
```

Rows 3 and 4 are the same shape either side of the boundary and both `allow`,
by opposite routes. A quoted word in command position makes the command
unrecognisable when it is classified correctly, and binds a variable when it is
not, and at this site both land on `allow`. So there is no verdict to point at
today -- which is exactly what makes it worth a row rather than a fix: the
site's semantics happen to absorb the wrong answer, and nothing guarantees the
next one will.

## Who it is for, and what it is worth

The next person to add an assignment reader to prod-guard. The cost is paid
once, by whoever places one below `expand_argv` and gets pre-fix behaviour with
a green suite -- the guard arms an override on a word bash would have run as a
command, and every test still passes.

Frequency is low and the blast radius is not: this is the same defect the
quoting fix closed, reachable again through a door nobody is watching. It ranks
here rather than higher because no site is exposed today, and above the general
hygiene rows because the failure is silent in both directions -- the wrong
behaviour and the absent test.

## What happens if it is never built

The fix holds while the pipeline does not change, and stops holding the first
time somebody moves or adds a reader without knowing that expansion strips the
record. Nothing in the code says so, and no gate reports it.

## Which way it gets built

Unknown, and this row does not guess -- there are three shapes and they have
different costs, none of them measured.

Carrying the record through `expand_argv` is the direct fix and the widest: the
function rebuilds strings from several inputs, so what a merged token's
provenance even *means* is a question rather than a detail. Making the fallback
loud instead -- refusing to answer for a plain `str` where the caller says it
is asking about command position -- is narrower, and turns a silent wrong
answer into a caller that must say which it wants; the cost is every existing
hand-built-token call site, including the tests. Documenting the boundary and
gating it, so a reader below the expansion line fails a check rather than a
runtime, is the cheapest and leaves the degradation in place.

**Measure:** which readers exist below a rebuild today, in all five guards. Two
are known -- prod-guard's `ASSIGN_BUILTINS` loop, which wants the fallback, and
workspace-guard's `inline_tmpdir`, which does not and survives on its own
semantics. `substitute_vars` and `expand_argv` are two rebuild boundaries;
`expand_tilde`, `ps_expand_tilde` and `expand_loop_candidates` are named in
workspace-guard and unread. Then say what each reader would need if the
fallback started refusing. Then write the chosen shape into this row and drop the label.
