# `classify_reset` skips the reproducible-merge second chance

`classify_branch`'s `-D` path asks `tip_is_recoverable` first and, on `False`,
gets a second question: does the delete orphan anything that is not already
derivable from the refs outliving it?
`plugins/branch-guard/hooks/branch-guard.py:1384:if orphans_only_reproducible_merges(cwd, b):`
answers it by recomputing the merge tree, so a scratch branch whose only
unshared commit is a clean test-merge auto-approves. `classify_reset` asks the
first question and stops, at
`plugins/branch-guard/hooks/branch-guard.py:1447:rec = tip_is_recoverable(cwd, branch)`.
The same branch, in the same state, therefore gets two answers depending on the
verb.

Measured 2026-08-22 on a throwaway repo — `main` and `other` both on
remote-tracking refs, `tmp-basecheck` branched off `main` carrying one `--no-ff`
merge of `other`, so its tip is unreachable *because* it merged:

| command | before Q99 | after Q99 |
|---|---|---|
| `git branch -D tmp-basecheck` | allow | allow |
| `git reset --hard HEAD~1` on that branch | ask | **deny** |

Deleting the whole ref is auto-approved; moving its pointer back one commit is
refused. The gap predates Q99 — allow-versus-ask before it — but Q99 promoted
the reset side to a deny, so it now costs a break-glass rather than a keystroke,
and the reason it prints is aimed at the wrong case: `gh pr view <n>` settles
nothing about a scratch branch that never had a pull request.

Two things to settle, and the row is S because the first is a few lines:

- **Give `classify_reset` the same second chance.** What
  `orphans_only_reproducible_merges` proves is about what a ref move would
  orphan, which is the question a reset asks too — it is scoped to the `-D` path
  by where it is called rather than by what it establishes. Price it first: it
  shells out to `git rev-list` and `git merge-tree`, and a reset pays neither
  today.
- **Then re-read the deny's routes.** With the second chance in place the
  surviving denies really are branches that lost content, so `gh pr view` fits.
  Without it, the reason has to name the merge case as well.

The `-D` side's fixture is
`plugins/branch-guard/test/run.sh:1362:git branch -D a scratch test-merge -> allow`,
built on the `testmerge` branch the block above it sets up. The reset side needs
its mirror, on the same fixtures.
