# An env operand read by a double-quoted bash -c body asks, not denies

`env C=<prod> bash -c "…"` hands the child `C`, and a `$C` the parent leaves as text in a double-quoted body reaches the child and expands to it. Q269 deliberately keeps `env`/`sudo` operand names out of a body that is not wholly single-quoted, because a `$C` left over there could be the parent's, so the command asks.
That fails closed.
Where the operand's value is production it is weaker than it needs to be: the child runs against production and the user gets a prompt rather than a refusal.

Found by review-b-prod on the Q365 pull request (comment 6954721838), and re-measured 2026-11-17 on `main` at `4ea1d077` with the fixture `$HOME`, whose current context is `gke_acme_prod-us`. bash 5.3.15 under `env -i /opt/homebrew/bin/bash --norc --noprofile`, with `echo` in place of kubectl, printed `p` in the child for `B='$F'; env F=p bash -c "echo [$B]"` and for `env F=p bash -c "echo [\$F]"`:

| command | prod-guard |
|---|---|
| `env C=gke_acme_prod-us bash -c 'kubectl --context=$C delete pod x'` (control) | deny |
| `env C=gke_acme_prod-us bash -c "kubectl --context=\$C delete pod x"` | ask |
| `B='$C'; env C=gke_acme_prod-us bash -c "kubectl --context=$B delete pod x"` | ask |

## Which way it gets built

Give an operand-supplied name its value as one reading beside unknown, the union Q301 introduced, in place of leaving it out.
A production operand then denies, and a nonprod one still asks, which is the case Q269 exists for.
Not measured.

## If it is never built

These shapes prompt where they could refuse, so a user who approves the prompt runs a production mutation.
It takes an `env` operand and a double-quoted body together, so it is likely rare.
