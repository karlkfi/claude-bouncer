# Two wrapper spellings bash never runs as written in PeelWrappersTests

`PeelWrappersTests` says each spelling "was driven on bash 5.3.15 against GNU
coreutils 9.11 and the macOS `env`". `test_each_wrapper_and_its_value_spellings`
asserts every one peels to `cat f`. Two do not run `cat f` under bash at all.
Driven 2026-10-04 as `env -i /opt/homebrew/bin/bash --norc --noprofile -c`
(5.3.15), with `/bin/bash` 3.2.57 agreeing:

- **`time -o log cat f`** runs a command named `-o`
  (`-o: command not found`, then the timing, rc 127). A bare `time` is bash's
  reserved word, and the word only takes `-p`. GNU time's `-o FILE` applies
  when the binary runs, as `/usr/bin/time` or `command time`. GNU time is also
  not part of coreutils.
- **`builtin cat f`** runs nothing: `builtin: cat: not a shell builtin`, rc 1.

Both err toward more checking. The guard reads `f` where bash reads no file,
so no decision moves in the unsafe direction.

## Which way it gets built

Decide per spelling whether the guard should keep peeling. For `time -o`, the
binary is reached by a path or `command time`. Under the same bash,
`command time -o tlog cat f` printed f and wrote `tlog` through macOS's BSD
`/usr/bin/time`, which takes `-o` too. GNU time was not installed, so it was
not driven. That spelling could replace the bare one. `builtin cat f`
could move to a case that pins it as opaque or as not running `cat`. Then make
the docstring say which spellings were driven, and against what.

**Who is worse off:** the reader of the test, who takes "driven on bash" to
mean bash runs each line as written.
