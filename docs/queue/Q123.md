# `make check` is red between a PR's code commit and its backlog commit

`tests/test_doc_links.py` takes its file list from the index and its contents
from the working tree. `tracked_markdown()` shells out to `git ls-files -z
'*.md'`; `read_in_repo()` opens each result with no existence check, and
`broken()` calls it unconditionally on every path. A tracked markdown file that
is gone from the working tree and not yet committed therefore raises
`FileNotFoundError` out of the test body -- an unhandled ERROR with a traceback
and no diagnosis, rather than a failure naming what is wrong.

Every row-completing pull request passes through exactly that state. The store
rule is that a completed row is deleted in its own isolated commit, separate
from code, so between the code commit and the backlog commit the deleted row is
absent from the working tree and still in the index. `make check` run in that
window is guaranteed red:

    ERROR: test_every_relative_link_resolves (test_doc_links.DocLinkTests...)
    FileNotFoundError: [Errno 2] No such file or directory:
      '.../docs/queue/Q103.md'
    make: *** [lib-test] Error 1

Measured 2026-08-23 while completing Q103, on a tree whose own change was
green before and after.

The cost is a session debugging its own diff for a failure the diff did not
cause -- and the traceback points at the row it is completing, which is the most
convincing wrong lead available. Nothing in `docs/development/` warns about it.

`broken()` is the only unguarded reader; `reachable_pages()` takes the same
`exists` callable and already skips a missing page, so the shape to match is
there.

Skip it, rather than reporting a vanished tracked file as its own finding. Every
other check in `make check` grades the working tree, so a link checker that
alone grades the index is the inconsistency; and the case reporting would catch
-- a doc genuinely lost rather than mid-commit -- is one `git status` names
first, at the moment it happens, without a traceback. Settled in the groom on
the row's own argument, so this needs no decision before it is picked.
