# The `[[` comment rule misreads a quoted `=~` operand and a plain `[[`

`strip_comments` and `command_substitutions` both track `[[ … ]]` so that a `#` glued into a
`=~` operand stays text (Q293, Q320). Two shapes defeat that tracking, and in both the scanner
reads a real comment as text. An apostrophe in the comment then opens a quote that hides every
later line from all four guards that read commands.

The first is an operand that starts with a quote, an ANSI-C `$'…'`, an escape, a backtick,
`$(` or `${…}`. `strip_comments` updates the operand state only for characters that reach its
own branch (`lib/bouncer_parse.py:469:            elif regex == 'op':`), and those forms are
consumed earlier. So the state stays at `'next'` and the first `]` sets it to 0. The `]]` then never
closes the `[[`, and in `[[ x =~ "a" ]];#it's` + newline + `P` the `;#` reads as text.
Q320 moved `command_substitutions`' copy of the update ahead of those branches, and
`strip_comments` still needs the same move.

The second is a `[[` outside command position, which opens the tracking anyway
(`lib/bouncer_parse.py:476:            if at_word and cmd[i+2:i+3] in ('', ' ', '\t', '\n'):`
and `lib/bouncer_parse.py:1221:                if brk and text[i+2:i+3] in ('', ' ', '\t', '\n'):`).
Examples are `echo [[ =~ x;#it's` + newline + `P` and `case [[ in [[)`. bash runs `P` in both.

Measured 2026-11-01 by the stream-A reviewer on #312 at `631d2bc`, through each guard's hook
script with `P` standing in for that guard's trap command:

| command | bash runs `P` | prod / ws / exit / fg, `main` and #312 |
|---|---|---|
| `[[ x =~ "a" ]];#it's` newline `P` | yes | defer ×4 |
| `echo [[ =~ x;#it's` newline `P` | yes | defer ×4 |
| `[[ -n $( [[ x =~ "a" ]];#it's` newline `echo y) ]] && echo $(P)` | yes | ws and exit defer |
| `[[ x =~ $'a' ]];#it's` newline `P` | yes | defer ×4 |
| `[[ x =~ ${y:-a} ]];#it's` newline `P` | yes | defer ×4 |

The third row reaches `strip_comments` through the `$( )` body: `command_substitutions`
returns `P` for it on `main` and on #312, so the defer comes from the body's own scan. Make
the last three rows test cases.

## Which way it gets built

In `strip_comments`, update the operand state before the quote, ANSI-C, escape and
substitution branches, as `command_substitutions` now does. In both functions, open `[[` only
in command position; `_at_command_start` already answers that for `strip_comments`. Neither
change is measured yet. Pin `[[ a =~ (#$(P)) ]]` and `[[ x =~ (a|#b) ]] || P` beside each new
deny, since both must keep reading the glued `#` as text.

## If it is never built

A command on the line after one of these shapes goes unjudged by every guard. Each shape needs
a comment holding an apostrophe right after a quoted `=~` operand, or a `[[` used as a plain
word, so it is likely rare.
