# A comment line hides every command after it from prod-guard

`tokenize` rewrites each newline to `;` before lexing, and shlex's default
comment handling then reads from `#` to the next newline. No newline is left,
so a comment swallows the rest of the command, including every line after it.

Found by the independent review of the Q196 pull request. Re-driven 2026-10-01
through the hook (fixture `$HOME`, ambient context `gke_acme_prod-us`) at
`b27be8d` and at the Q196 head, with identical results. That bash runs the
second line was driven under `env -i bash --norc --noprofile -c` with a
payload absent from `PATH`:

| command | guard | bash runs line 2 |
|---|---|---|
| `kubectl delete ns payments` | deny -- control | yes |
| `# note` newline `kubectl delete ns payments` | **defer** | yes |
| `echo hi # c` newline `kubectl delete ns payments` | **defer** | yes |

## Which way it gets built

`lib/bouncer_parse.py` already has `strip_comments`, which applies bash's own
rule (an unquoted `#` at the start of a word) and keeps the newline that ends
the comment. Run it before the newline rewrite and turn shlex's own comment
handling off, as its docstring describes. Check that a `#` inside a heredoc
body and inside quotes stays text.

## If it is never built

A leading comment line is ordinary agent output, so any mutating command
written below one reaches production with the guard silent.
