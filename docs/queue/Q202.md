# A quoted operator word splits a simple command, hiding its argv

`split_simple_commands` decides what ends a simple command by reading the
token's text alone --
`plugins/prod-guard/scripts/bash-prod-guard.py:435:if t and all(c in PUNCT_CHARS for c in t)`.
A word made entirely of punctuation chars has the text of an operator and is
not one, so `kubectl ';' --context=prod delete pod x` is cut after `kubectl`
and the flags that name the target land in a segment headed by
`--context=prod`, which matches no covered tool.

The docstring's fail-safe argument does not survive it. It says crude
splitting "only ever creates extra segments to inspect ... never hides one",
which is true of a real operator and false of a quoted one: the covered tool
keeps its own segment and loses the argv the classification reads.

## Measured

2026-09-10, driving `PreToolUse` payloads at the hook with `cwd` set to a
scratch git root:

| command | verdict |
|---|---|
| `kubectl --context=prod delete pod x` | **deny**, targets kube-context 'prod' |
| `kubectl --context prod delete pod x` | **deny**, same |
| `kubectl ';' --context=prod delete pod x` | **no decision** (defer) |

Two controls, because a permissive arm on its own reads the same as a hook
that was never pointed at anything.

## Why this is ranked below its workspace-guard sibling

The same defect in the shared parser was a positive `allow` in
workspace-guard, and it shipped there because `cat` reads its remaining
operands after reporting the missing one. Here the mis-parse does not reach a
dangerous command: bash hands `kubectl` a subcommand of `;`, which errors
before anything is deleted. So this is a guard that cannot see a command,
rather than a guard that clears one.

## The fix

`is_operator` in `lib/bouncer_parse.py` is the shared predicate — vocab
membership plus `quoted_from is None` — and answers exactly this. prod-guard
keeps its own `PUNCT_CHARS` and its own segmenter deliberately (segmentation
is per-guard, see `CLAUDE.md`), so the change is the `quoted_from` test in
this loop rather than adopting the lib vocab, and the docstring's fail-safe
paragraph is rewritten with it.
