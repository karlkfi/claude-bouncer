# A shell body behind -lc, -c -- or find -exec is never read

prod-guard reads a shell's script from the word after a `-c` token, so three
ordinary ways of writing the same command hand it no body at all, and a
production mutation in that body passes at top level with no prompt.

Found by review-b-prod on the Q340 pull request (comment 6956141632), and
re-measured 2026-11-17 on `main` at `f54f6053` through the hook, with the
fixture `$HOME`, whose current context is `gke_acme_prod-us`. bash 5.3.15
under `env -i /opt/homebrew/bin/bash --norc --noprofile`, with `/bin/echo` in
place of kubectl, ran the body of every deferring shape below, the two `find`
rows included.

| command | prod-guard |
|---|---|
| `bash -c '<delete>'` (control) | deny |
| `bash -e -c '<delete>'` (control) | deny |
| `bash -lc '<delete>'` | **defer** |
| `bash -ec '<delete>'`, `bash -xc '<delete>'`, `sh -ec '<delete>'` | **defer** |
| `bash -c -- '<delete>'` | **defer** |
| `find . -exec bash -c '<delete>' \;`, and with `{} +` | **defer** |
| `find . -exec <delete> \;` | **defer** |

`<delete>` is `kubectl --context gke_acme_prod-us delete pod x`.

Three causes, each read from the source and checked by calling
`first_flag_value` on the argv:

- **A clustered short flag.** The lookup at
  `plugins/prod-guard/scripts/bash-prod-guard.py:3578:            body = first_flag_value(argv_raw, ('-c',))`
  matches the exact token `-c`, so `-lc` and `-ec` return no body.
- **`--` after `-c`.** The same lookup returns `--` as the body, and bash takes
  the next word instead.
- **`find -exec`.** The guard peels no `find` action, so whatever `-exec` runs is
  never judged, a bare `kubectl` as much as a shell.

Stdin forms (`bash <<<`, `echo … | bash`) are Q378's. The other four guards
were not measured for these shapes.

## Which way it gets built

Read `-c` out of any single-dash cluster in a SHELL_NAMES argv, take the body
from the next word that is not `--`, and peel `find`'s `-exec`, `-execdir`,
`-ok` and `-okdir` up to their `;` or `+` the way `xargs` is peeled, so the
command it runs is evaluated like any other. A cluster also holding `o` takes
the following word as the option's argument, so the body moves one word on.
Not measured.

## If it is never built

`bash -lc` is a common way to run a command under a login shell, so a
production mutation written that way, or run through `find -exec`, passes with
no prompt whenever the guard would otherwise deny it.
