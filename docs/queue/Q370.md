# Each unclosed ${x:-$( level doubles the time the guards take

`echo "${x:-$(${x:-$(`…`echo ; rm /etc/probe-target`, with the `${x:-$(` pair
repeated d times and nothing closed, takes `command_substitutions` twice as
long for every level added. Measured on `main` at `cdbcbea7`, calling the
parser directly:

| d | 12 | 14 | 16 | 18 | 19 | 20 |
|---|---|---|---|---|---|---|
| seconds | 0.014 | 0.056 | 0.223 | 0.889 | 1.763 | 3.549 |

The same command without the opening `"` costs about twice as much again,
0.44s at d=16. Through workspace-guard's hook the d=16 command took 3.63s and
the d=18 one 14.11s, so a forty-character extension of the command adds hours.
Every hook in `plugins/workspace-guard/hooks/hooks.json` has `"timeout": 10000`,
which Claude Code reads as seconds, so the session waits that long before the
hook is abandoned. The #336 reviewer found it, at d=24 past 90s on `main`
(comment 6939822925 on that PR).

The hook returned no decision at d=2 and at d=18, with exit 0 and empty
stdout. bash runs nothing either: under `env -i /opt/homebrew/bin/bash --norc
--noprofile -c` (5.3.15) the d=3 command, with `echo RAN` in place of the `rm`,
exits 2 with `unexpected EOF while looking for matching` `)`, quoted and
unquoted alike. So no decision is correct, and the cost is the wait alone.

## Why it doubles

`_brace_end_steps` at a `${` yields `_scan_dollar_paren_steps` for the `$(`
inside it, which yields `_brace_end_steps` for the next `${`, and so on to the
end of the input. Nothing closes, so the innermost scan fails and each brace
returns -1. The `$(` scan that yielded it then reads the same `${` as plain
text and walks on, which reaches the next `${` and starts its whole subtree
again. Each level scans its subtree twice: once inside the brace that failed,
and once after the failure. A cProfile at d=16 counts 131,069 generator sends,
about 2 × 2^16.

## Which way it gets built

Both scans are functions of `(text, start)` alone, so a failure found once
is the answer every time. Remembering failed starts for the length of one
`_trampoline` run should make the cost linear in the depth. Not measured yet.
Pin d=24 under a time bound in the parser suite, and the hook's d=24 verdict in
workspace-guard's, so that each fails on `main`.

## If it is never built

A session that writes the shape waits hours for workspace-guard, and the
other guards are slow too: at d=16, exit-status-guard took 2.04s, prod-guard
2.26s, foreground-guard 2.05s and branch-guard 0.95s, each with exit 0 and no
output. Nobody writes the shape by accident, so it is reached only by a command
built to stall the guards.
