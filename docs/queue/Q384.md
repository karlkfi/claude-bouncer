# An exit-status-guard test deletes a directory concurrent suites share

`test_scratchpad_is_read_from_the_payload` makes its session directory under
one fixed project directory and removes that whole directory when it is done,
at
`plugins/exit-status-guard/tests/test_exit_status_guard.py:2042:        project = os.path.join(root, 'exit-status-guard-suite-project')`
and
`plugins/exit-status-guard/tests/test_exit_status_guard.py:2050:            shutil.rmtree(root if made_root else project)`.
The session name carries the process id, but the project directory does not,
so two suites running at once on one machine share it. Whichever finishes
first deletes the other's directory, and the other's `rmtree` then fails.

Seen 2026-11-17 during a parallel dispatch, with several sessions running
`make check` in their own worktrees at once. A `make check` over a branch that
does not touch exit-status-guard (`fdea1f09`, the Q377 branch) failed with one
error and passed on the run before it over nearly the same tree:

```
ERROR: test_scratchpad_is_read_from_the_payload (test_exit_status_guard.TestHookEndToEnd.test_scratchpad_is_read_from_the_payload)
FileNotFoundError: [Errno 2] No such file or directory: '/tmp/claude-501/exit-status-guard-suite-project'
```

The concurrent run that removed the directory is inferred, not observed: no
other session's log was read. One sighting, so no failure rate.

## Which way it gets built

Give the project directory the process id too, or make it with `tempfile.mkdtemp`
under the scratch root, so each suite removes only what it made. Not measured.

## If it is never built

Every parallel batch here can lose a `make check` run to a sibling's suite and
have to re-run a ten-minute gate. CI is unaffected, since each job runs one
suite at a time.
