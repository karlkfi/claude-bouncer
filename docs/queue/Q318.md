# exit-status-guard does not peel timeout, nice, or a path-spelled time

exit-status-guard peels only the wrappers in its own `WRAPPERS` set
(`plugins/exit-status-guard/scripts/bash-exit-status-guard.py:65:WRAPPERS = frozenset({'sudo', 'nohup', 'command', 'exec', 'bash', 'sh', 'zsh',`),
which names neither `timeout` nor `nice`, and peels `time` only as bash's
reserved word. Each of these programs exits with its child's status, so a gate
behind one and piped into a filter loses that status with no deny.

Driven 2026-11-01 on the Q241 branch, payload `make check | tail` in the P
position, prod-guard / workspace-guard / exit-status-guard / foreground-guard
with their own payloads beside it for comparison:

| command | prod / ws / exit / fg |
|---|---|
| `timeout 60 P` | deny / ask / **defer** / defer |
| `nice -n 5 P` | deny / ask / **defer** / defer |
| `/usr/bin/time -p P` | deny / ask / **defer** / deny |
| `command time -p P`, the control | deny / ask / deny / deny |

Under `env -i /opt/homebrew/bin/bash --norc --noprofile -c` (5.3.15),
`timeout 60 false`, `nice -n 5 false` and `/usr/bin/time -p false` each exit 1.

The shared `lib/bouncer_wrappers.py` already carries an option grammar for
`timeout`, `nice`, `time`, `ionice`, `chrt`, `taskset` and the rest, which the
other guards peel by. foreground-guard's defers on `timeout` and `nice` are
not examined here: a `timeout` bounds a foreground command, so its reading
may be deliberate.

## Which way it gets built

Widen `WRAPPERS` to the programs in the shared grammar that run their operand
and pass its status through, and match a path-spelled name by its basename the
way the `command time` control already reaches `time`. Keep `xargs` and
`flock FD` out: neither runs the gate as its own child in the shape a pipe
would hide.

## If it is never built

`timeout 600 make check | tail` is a likely spelling for a session bounding a
slow gate, and it reads green on a failure. How often sessions write it is not
measured.
