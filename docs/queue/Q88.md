# Nothing checks the README decision table against the hook

Driven by hand 2026-08-24: all 27 rows of the decision table in
`plugins/foreground-guard/README.md` agree with the hook, across 29 probes — one
row lists three commands, and four carry a payload qualifier. A control inverting
one expectation reported the disagreement, so the zero is a reading rather than a
harness that could not fail. This is therefore preventive.
There is no drift to fix, and this repository's history is too short to give a
drift rate: three commits have touched the guard here, and the one that moved a
decision (#23) moved the README in the same commit.

**Who is worse off.** A reader who pastes a row and gets a different verdict, and
the session told to check the table by hand before committing
(`plugins/foreground-guard/CLAUDE.md:19:update the README decision table`). That
step leaves no trace, so nobody downstream can tell a checked table from an
unchecked one — including the reviewer of the commit that skipped it.

**Which way it gets built,** and the shape is measured rather than guessed. 21 of
the 27 rows are a backticked command and a decision, and parse with two lines of
regex. The other six need context the cell cannot carry: `with
run_in_background: true`, `with timeout: 600000`, `(configured min 600000 ms,
default timeout)`, and one row whose cell is `cat <<EOF` … `tail -f x` … `EOF`
with real ellipses. Do not teach a parser to read those — carry the payload in an
HTML comment beside the row, so the table renders unchanged and the test reads a
literal kwargs dict for `run_hook`. Fail the test on a row with neither a parse
nor a comment, which is what stops the next row being added outside the check.

**If it is never built,** nothing changes today, and the cost lands on the commit
that moves a decision without moving the table — whose author is the one least
likely to reread it.

`S` holds: `run_hook` already takes every knob the six qualified rows need. Rank
`aa` does not — on present evidence this is the weakest ready foreground-guard
item, with no defect and no drift rate behind it, so it belongs below Q87 and
Q82 rather than above them.
