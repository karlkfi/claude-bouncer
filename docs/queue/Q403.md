# A quoted variable whose value holds a space is denied as unexpanded

`literal_assignment_value` refuses a value holding whitespace, because an unquoted use word-splits.
A quoted use does not, and it is denied anyway.

Measured 2026-11-24 on `main` at `de050f70`, with the hook run against this checkout:

| command | verdict |
|---|---|
| `D="./ab"; cat "$D/x.txt"` (control) | allow |
| `D="./a b"; cat "$D/x.txt"`, or `"${D}/x.txt"` | **deny** |
| `D="./a b"; cat "$D"/x.txt` | **deny** |
| `D="./a b"; echo hi > "$D/x.txt"` | **deny** |
| `D="./a b"; cd "$D" && cat x.txt` | **deny** |
| `D="./a b"; echo "$(cat "$D/x.txt")"` | **deny** |
| `for f in "./a b"; do cat "$f/x.txt"; done` | **deny** |
| `D="./a b"; cat $D/x.txt` (must stay) | deny |

The side-session notes folder has a space in its path, `Application Support`, and 4 denies over 2026-11-18 to 2026-11-24 (UTC) on one machine named it through a variable.
Whether a fix clears all 4 is not verified.

`textmap` already keeps such values, for a double-quoted sed script, and a wholly double-quoted word is recognisable (`QuotedStr.quoted_chars` equals its length).
Splicing one into the other is a few lines, and it was left out of the notes-write change for three reasons:

- It covers `"$D/x"` and not `"$D"/x`, whose quoting is per character and not recorded.
- It changes the words every classifier below it reads: a command name, a `-c` body, a `kill` pattern, an awk program.
- `textmap` goes stale after an `IFS` assignment, which is a separate bug filed beside this row.
  As path input it would turn that into a wrong `allow` for any command.

Next step: fix the stale `textmap` first, then splice only into file operands and redirect targets.

## If it is never built

A command that puts a path with a space in a variable gets a deny and is rewritten with the literal path.
