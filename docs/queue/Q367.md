# A titled reference definition is not read by the doc link checker

`REFDEF` in `tests/test_doc_links.py` wants the line to end right after the
URL, so `[r]: Q3.md "Q3"` (and the `'…'` and `(…)` title forms) is invisible to
`links()` and a missing target passes. Reproduced by the filer on `d62d652`:
`links('[r]: Q3.md "Q3"\n')` returns `[]` where `links('[r]: Q3.md\n')` returns
the target. Found by the independent review of #341 (review-r3,
https://github.com/karlkfi/claude-bouncer/pull/341#issuecomment-6939608718),
which scanned the real store and found no definition in 72 items, so this is
latent. The pattern predates Q271 and the miss is repo-wide, every Markdown
file rather than the store alone.

## Which way it gets built

Add an optional title group to `REFDEF`, then drive each of the three title forms red against a missing target.
Run the checker over the real tree first, because widening what `links()` reads can surface links that were hidden.

## Who is worse off

A doc author who writes a titled reference link, and the reader who clicks a dead one.
Flat cost, met only when someone writes that form.
