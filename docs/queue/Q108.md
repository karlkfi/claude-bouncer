# No test reaches the Dependabot release-note exemption

`.github/workflows/release-note.yml` exempts Dependabot from the
`## Release note` block, because Dependabot writes its own pull request body
and has no option to template one. The exemption is a shell condition inside a
`run:` block, and no target in the tree executes it: `make check` runs no
workflow step, and `tests/test_release_note.py` covers `scripts/release-note.py`
rather than the YAML that calls it.

So the branch that gets checked is the one nobody has watched fail. An
exemption that matched too broadly -- a substring test rather than an equality
test, say -- would let any author skip the block, and every gate in the repo
would stay green while it did.

Verified by hand when it landed 2026-08-22, by extracting the `run:` block from
the YAML and driving it under `bash -e`: a Dependabot author with an empty body
exits 0, a human with an unanswered body exits 1, a human with an answered body
exits 0, and an author merely *containing* `dependabot[bot]` exits 1. That is
the check to mechanize, and it needs a harness the repo does not have -- nothing
here extracts a workflow step into a test. `tests/test_verify_release_notes.py`
is the nearest precedent and it tests a committed shell script, which is a
different thing.

Decide whether the harness is worth building for one step, or whether the
condition should move into `scripts/release-note.py` behind an author argument,
where the existing suite already reaches it. The second is probably cheaper and
puts the logic where a test can see it.
