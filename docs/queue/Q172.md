# The PowerShell subexpression recursion starts from the string cwd

Q169 fixed this for bash and left the PowerShell frontend as it was, which the
row explicitly allowed. The two defects are the same one: a subexpression body
is recursed into against the cwd the string *started* in
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:5556:sub_off, _, sub_sig = _ps_analyze_command(body, ctx, base_cwd,`),
while the segment walk right above it threads a cwd that a `Set-Location`
earlier in the string has already moved
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:5529:off, g, sig, cwd, cwd_unknown = ps_analyze_segment(`).
So a relative path written inside a `$(…)` after a location change is judged
against a directory the command has left -- silent when the change went out of
the workspace, and a prompt naming a path nothing reads when it went in.

## What it costs

The same two failures Q169 measured for bash, on the shell tool the Windows
frontend guards. The out-of-workspace direction is the one that decides the
row's severity: a read or write inside a subexpression, after a location
change out of the root, is the boundary the guard exists to hold.

Unmeasured on Windows -- this row is filed from reading the two lines above,
not from driving the hook, and the drive is the first thing the work does. Say
in the pull request what the pre-fix table looked like, the way Q169 did.

## Which way it gets built

Q169's shape transfers, and the frontend is already most of the way there.
`ps_subexpressions` masks each body out of the outer text
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:4780:out.append('$')`)
-- which is the mask Q169's bash fix was modelled on -- but the mask is
anonymous, so nothing downstream can say which body it stood for. Number it
the way `mark_substitutions` numbers its own
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:3472:def substitution_bodies(cmd, base_cwd, base_cwd_unknown, stable_vars=None,`),
have the segment walk record the cwd in force where each numbered mask lands,
and pass that to the recursion in place of `base_cwd`.

One thing to settle first, because it is where the two frontends differ. The
masked text and the bodies come from two separate scans over two differently
stripped strings -- `ps_subexpressions(stripped)[0]` for the text and
`ps_subexpressions(expandable_text)[1]` for the bodies
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:5519:bodies = ps_subexpressions(expandable_text)[1]`)
-- so a numbering that indexes one is not automatically an index into the
other. Reconcile that, or scan once and derive both.

## If it is never built

The Windows frontend keeps a hole the POSIX one no longer has, on a construct
both shells write the same way, and the two guards disagree about the boundary
they are supposed to enforce identically.
