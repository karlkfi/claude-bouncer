# The `sh -c` suppression escalates on bodies the hook demonstrably read

In `auto` the escalation prompt fires on commands whose `-c` body the hook did
reach and did check, so its own reason — "a shell `-c` body it could not reach
(a container or remote wrapper, or an untracked cwd)" — is false for the shape
that dominates the firing.

`plugins/workspace-guard/scripts/bash-workspace-guard.py:4032:elif shell_c_group(g)`
sets the signal on `shell_c_group`'s deliberately loose scan — some token is a
shell, a later short-option cluster carries `c` — and never consults
`shell_c_bodies`, the strict extractor that actually pulls the body when the
group runs a local shell or a `LOCAL_SHELL_WRAPPERS` head. Where that extractor
succeeds the caller re-analyzes the body as its own command string a few lines
below, so its paths are checked.

Measured 2026-09-17 at 4db1270, module imported directly, cwd a claude-bouncer
worktree, `permission_mode` `auto`:

```
timeout 240 bash -c 'until grep -q DONE tmp/w.log; do sleep 5; done'; cat tmp/a
    -> outside=0 guarded=False suppressed=['sh -c'] -> ask
timeout 240 bash -c 'cat /Users/karl/secrets.txt'
    -> outside=[('/Users/karl/secrets.txt','outside',None)]
```

The second line is the proof: the extractor whose success case the first line
ignores is the one that produced the offender in the second.

## Frequency

Replaying 13,527 Bash commands from the 120 most recent local transcripts
through `analyze_command`: 9 `sh -c` suppressions (0.07%), 2 kill, 742
interpreter (5.5%, which does not escalate under the default `scoped`).
Transcript `queue-operation` records show 14 real prompts of this text — 12 on
2026-09-16, 2 on 2026-09-17 — clustered in parallel-dispatch sessions, where
the watcher idiom `timeout N bash -c 'until <test>; do sleep N; done'` sharing a
string with a `tail` or `grep` of a log is the dominant shape. So the
over-report is most of what fires.

## The fix

Set the signal only where the body could not be extracted: `shell_c_group(g)`
true and `shell_c_bodies(g)` empty, or the cwd untracked — the same condition
the extraction below already runs under. The genuinely opaque cases keep
asking; the readable local-wrapper shape stops.

Q60's guarantee is untouched, which is what keeps this small. The `allow` is
still withheld for a readable body, because `interp_code_source` fires on the
same shell word and suppresses as `interpreter`. Only the label changes, and
the label is what the escalation reads: `interpreter` sits outside the default
`scoped` scope. Tests pin both directions.
