# A --git-dir or GIT_DIR write is judged against the session's branch

`git --git-dir=../other/.git --work-tree=../other commit` and its
`GIT_DIR=../other/.git GIT_WORK_TREE=../other git commit` spelling are allowed
when the session sits on a feature branch, though the commit lands on whatever
`../other` has checked out. Measured 2026-11-01 on this branch's head in a
scratch repository, session on `claude/s`, `../other` on `main`: both spellings
allow, while `git -C ../other commit` asks, because `-C` is followed and the
branch is read there.

`invocation_cwd` returns None for a redirect it cannot follow
(`plugins/branch-guard/hooks/branch-guard.py:2671:def invocation_cwd(cwd, inv):`),
and the caller then falls back to the session's own directory for the branch
while only the probes stand down. So every branch-sensitive verb, `commit`,
`merge`, `rebase` and `pull` among them, is judged as if it ran here.

Bites once per command that names another repository by option or variable,
which is rare and lands on someone else's protected branch when it happens.
Next step: when the tree cannot be named, have the branch-sensitive verbs ask
rather than read the session's branch, and cross the option and variable
spellings against `-C` on a protected and a feature branch.
