# Nothing pins the order of the repairs a deny message hands back

The suite asserts which tokens a reason *contains* and, for three of the four
cross-workspace categories, nothing about how they are arranged. On an `ask` that
gap costs little: a human reads the whole prompt. On a `deny` the reason is
everything the guard produces — the command did not run, nobody is prompted, and
what the agent does next is decided entirely by which repair it reaches first.
Arrangement is the product, and it is untested.

## Measured

2026-09-04 against `origin/main` at `4a81387`, over the whole of
`plugins/workspace-guard/tests/test_workspace_guard.py` (10,289 lines):

| Assertion kind | Count | What it pins |
|---|---|---|
| `assertIn` / `assertNotIn` / `assertRegex` | 245 | a token is present or absent |
| `assertLess(r.index(…), r.index(…))` | 4 | arrangement |
| `assertGreater` | 0 | — |

Three of those four sit in `BuildReasonTests` and pin *which category bucket*
comes first (`outside`, then `expand`, then `untracked`) and token sort inside
one bucket. The fourth is in the host-temp hint —
`assertLess(hint.index("tmp"), hint.index(pad))`, with a comment saying so:
"Still steers to the repo-local dir first, knobs still last." Both `assertRegex`
uses read `tests.yml`, not a reason.

So exactly one hint builder has its advice pinned in order, and it is
`build_scratch_hint`. `build_sibling_hint`, `build_kill_hint` and
`build_crosssession_hint` have none.

**What that permitted.** Q155 rewrote the sibling deny end to end — the corrected
path went from an instruction to a statement, and the trailing override sentence
became a two-route pair with the lead rewritten around it. **All 1458 tests
passed against the new wording before a single new test existed.** Every
assertion on that message is `assertIn` of a branch name, a path, or the string
`WORKSPACE_GUARD_OVERRIDE`, and all of them survive an arbitrary reordering.

## Who is worse off

The agent holding a denial, which is the reader this guard's whole case for
denying over asking rests on: the deny self-heals in one round trip *because the
reason carries the repair*. A repair that has moved, or that is now second to one
the caller cannot apply, heals nothing — and the suite goes green either way. It
is the same shape as [Q156](https://github.com/karlkfi/claude-bouncer/pull/90),
one level up: there a whole suite exercised an override route nobody meant to
test, here a whole suite pins decisions and not the product of a decision.

## Which way it gets built

The four cases Q155 adds for `sibling` are the pattern — assert the pairing is
present and that each route says which case it is for, and assert the route that
must *not* be promoted is not. `kill` and `crosssession` want the same, and are
the residue this row is for. `build_scratch_hint` already has its one assertion
and needs nothing.

Scope note, because it decides the size: this is an arrangement assertion per
hint builder, not a golden-file test of the whole reason. A golden file would
redden on every wording improvement and be updated without being read, which is
the failure that produced this gap rather than a fix for it.

Second note, on why this row carries no `path:N:fragment` citations. Its subject
is code that two open branches move — the Q156 fix by about 96 lines and the
Q155 one by about 10 — so a pointer written here would have been stale before
anyone picked the row up. Function and test-class names survive both merges and
a rename shows up as a failed search rather than as a plausible wrong line. Worth
reaching for whenever a row is filed against code that another open branch is
already moving, which in a parallel batch is most of them.

## If it is never built

Every future edit to a deny message is unreviewed by anything but a human
reading the diff, on the one surface where a green suite is least informative —
and the message is what an agent acts on, not the decision it accompanies.
