# Two guards miss a sudo option written after an assignment operand

sudo's argument loop goes back to `getopt_long` after each assignment
operand, so options and `NAME=value` operands can come in any order. The
source comment says it is there to "allow environment variables to be
interspersed with command line options" (`src/parse_args.c:282` in sudo
1.9.17p2). exit-status-guard and foreground-guard peel sudo's options and
then its operands, once each. An option after an operand stops the peel,
the option becomes the command head, and the command sudo actually runs
goes unread.

Found by the independent review of the Q218 pull request (#221), in
https://github.com/karlkfi/claude-bouncer/pull/221#issuecomment-5989886743.
Driven 2026-10-05 through each hook at `main` a34ca7e. `main` before Q218
(5da5818) gives the same verdicts:

| command | exit-status-guard | foreground-guard |
|---|---|---|
| `sudo -u root A=1 <cmd>`, the control | deny | deny |
| `sudo A=1 -u root <cmd>` | **silent** | **silent** |
| `sudo A=1 -n <cmd>` | **silent** | **silent** |
| `sudo 1=x -E <cmd>` | **silent** | **silent** |
| `sudo -- A=1 <cmd>` | deny | deny |

Each `<cmd>` was the guard's own control: `make check | tail -5` for
exit-status-guard, and `tail -f log.txt` for foreground-guard. sudo itself
was not driven past its password prompt, so the claim that it runs the
command is read from its source.

The last row fails in the other direction, closed. After `--` sudo assigns
nothing (`got_end_of_args`, `parse_args.c:272`), so `sudo -- A=1 cmd` runs
a program called `A=1`, while both guards peel `A=1` and judge `cmd`.

The sites:

- `plugins/exit-status-guard/scripts/bash-exit-status-guard.py:341:                while tokens and assigns_operand(wrapper, tokens[0]):`
- `plugins/foreground-guard/scripts/bash-foreground-guard.py:494:            while argv and '=' in argv[0] and argv[0][0] not in '/=':`

## Which way it gets built

For sudo, alternate between peeling options and peeling operands until
neither matches, and stop taking operands once `--` has been seen. `env` is
not affected: both GNU env 9.11 and macOS env run `-i` as the command in
`env A=1 -i cmd`, so their options end at the first operand. Q240 gives prod-guard a sudo operand peel, and should
take this shape from the start rather than copy the two-pass one.

## If it is never built

A sudo option written after an assignment hides any piped gate or
foreground watch behind it, and both guards stay silent.
