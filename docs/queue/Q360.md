# Behind a wrapper, a substitution still hides the file after it

`env grep -v <(echo x) /outside/f` reads the file, and workspace-guard answers
`allow`. The same read without the wrapper asks. Driven 2026-11-16 at `61695c2`, and the guard column re-taken at `e51e681` after Q354 merged,
with bash 5.3.15 run as `env -i "$(command -v bash)" --norc --noprofile -c` on a
planted file, and the hook run on `/etc/q360-f`:

| command | bash | guard |
|---|---|---|
| `env grep -v <(echo x) f` | prints the file | allow |
| `command grep -v <(echo x) f` | prints the file | allow |
| `nice grep -v <(echo x) f` | prints the file | allow |
| `env cat <(echo a) f` | prints the file | allow |
| `env grep -v $(echo x) f` | prints the file | allow |
| `nice cat $(echo a) f` | prints the file | deny |
| `env $(echo) cat f` | prints the file | ask |
| `cat <(echo a) f`, `env cat f` | print the file | ask |

The reviewer on the Q354 pull request, number 328, reported this first. Its comment
also lists `sudo grep -v <(…)`, and about thirty shapes where the guard and bash
agree. Q354's fix, merged in pull request 328, does not change any row above.

## Where the split is kept

`resumes_after_substitution` decides whether the words after a substitution's
`)` belong to the command before it, and it returns False whenever the first
word is a wrapper, at
`plugins/workspace-guard/scripts/bash-workspace-guard.py:4550:return name != 'eval' and name not in WRAPPER_GRAMMAR`.
The split is then kept, so the file becomes the command name of a group of its
own, and nothing resolves it. That answer is right where the substitution comes
straight after the wrapper: `env $(echo) cat f` runs the `cat`, and the split is
what judges it (Q355). It is wrong where the wrapper already names its command
before the substitution, as `env grep` does. This cause comes from reading the
function and was not checked by trying a fix. The deny row works through a
different rule: `cat $(…) f` is denied as an operand the guard cannot expand.

## Which way it gets built

Peel the wrapper's own words with its grammar, then apply the existing
plain-name test to what is left, so that `env grep` resumes and `env $(echo)`
keeps the split. Q355's own rows `env FOO=1 $(echo) cat f`, `timeout 5
$(echo) cat f` and `nice -n $((5)) cat f` must keep asking. Q353 wants
the same wrapper skip in two more guards, so it is a reason to weigh moving the
function to `lib/`.
