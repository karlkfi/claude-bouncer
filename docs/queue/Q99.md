# Deny the unreachable-tip ask on a clean `git reset --hard`

`plugins/branch-guard/hooks/branch-guard.py:1430:moves branch '{branch}', whose tip`
asks the human whether a branch tip nothing else reaches is worth keeping. The
missing input is not intent, authority, or a blast radius the model cannot see
— it is a fact about the world the model can establish for itself, which is the
case `hook-verdict`'s routing test sends to deny with the fix written into the
reason. Two commands settle it: `gh pr view <n> --json state,mergeCommit`, and
a content check against what landed on `main`.

**The trigger is squash merges, so it fires on the safest instance of its
class.** A squash-merged branch's tip is unreachable by construction — the
content is on `main` under a different object name — so `tip_is_recoverable`
cannot see it, and the ask lands on the most routine end-of-work cleanup there
is. Measured 2026-08-22 on `karlkfi/claude-spill-guard`: of the nine pull
requests merged that day, eight produced a single-parent merge commit and only
#6 produced two. GitHub's compare API agrees on the consequence — the eight
squashed heads read `diverged` against `main`, meaning not an ancestor, while
#6's head reads `behind`.

**Cheaper than [Q95](Q95.md), which makes the same argument for the
push-overlap verdict.** That one is M because it needs a whole new override
mechanism: `push` is outside
`plugins/branch-guard/hooks/branch-guard.py:488:OVERRIDABLE_GIT = frozenset({`
and an `ask-rebase` is never liftable. Here the override half already works.
`reset` is in that set, and the combine site at
`plugins/branch-guard/hooks/branch-guard.py:2076:{OVERRIDE_VAR} is set` already
lifts a plain `ask` to `allow` when the break-glass is set. One site changes,
not two.

**Scope it to that one return.** `classify_reset` has four `ask` returns and
three of them stay:

- `branch is None`, and the `not probe` foreign-repo case — the guard cannot
  determine the fact, so there is nothing to write into a reason.
- `is_protected` returns `ask-shared`, a different tag over a genuinely shared
  ref.
- The dirty worktree, at
  `plugins/branch-guard/hooks/branch-guard.py:1426:if worktree_is_clean(cwd) is not True:`,
  is the honest `ask` and the row's own evidence that this is a verdict split
  rather than a blanket relaxation. Uncommitted work is reachable from no ref,
  so nothing can prove it recoverable, and whether those changes matter is
  knowledge the human holds and the guard does not.

**What the deny carries**, in `hook-verdict`'s order — the runnable rewrite
first, the break-glass last: establish whether the tip's content is already on
`main` with `gh pr view`; a branch spent by a squash merge costs nothing to
leave alone, so no reset is needed; `BRANCH_GUARD_OVERRIDE=<reason>` where the
loss is deliberate.

Two fixtures, which is what keeps this S. One inverts —
`plugins/branch-guard/test/run.sh:721:git reset --hard on an irrecoverable tip -> ask`
— and one is new, asserting the break-glass still lifts the new deny. The
existing override crossing at
`plugins/branch-guard/test/run.sh:1556:override on reset --hard on main -> ask`
does not cover it: that cell is the `ask-shared` site, where the lift is
supposed to fail.

One caveat against overclaiming. The trace asymmetry says an approved `ask`
teaches the session nothing, which is half of why denying is right — but this
particular ask did reach the model, because the harness surfaced the refusal
text, and that is how the argument above got written. The reason lands
sometimes; it just lands without the model being able to act on it.
