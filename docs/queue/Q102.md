# Name the release-note pre-check where a session will look for it

`make check` is the gate `CLAUDE.md` names, and it cannot see a pull request
body. `.github/workflows/release-note.yml` can, and fails a body with no
answered `## Release note` block. So a session runs the full local gate green,
opens a pull request, and takes a red check on a surface no local target
reaches.

`.github/pull_request_template.md` is the mechanism that should prevent this,
and it only fires when GitHub supplies the body. `gh pr create --body-file`
does not, which is how an agent writes a body of any length — so the trap fires
on essentially every agent-authored pull request rather than occasionally.
Measured 2026-08-22 on PR #23: `release-note` red at `!! NO SECTION`, four
seconds, one edit-and-rerun cycle to clear.

The pre-check already exists and takes a second:

```
python3 scripts/release-note.py < body.md
```

It exits 1 on `!! NO SECTION` and `!! UNANSWERED`, which is the whole check.
Nothing names it outside `docs/development/release-process.md`, where it is
documented for the release runbook harvesting notes across a tag range rather
than for an author about to open one pull request.

The fix is a line in the `## Checks` section of the root `CLAUDE.md`, beside
`make check` — that section reads as the complete local gate list, which is
exactly why a green run there gets taken as ready-to-open. Say that the body is
gated separately and give the command.

**Not a `make` target.** The input is a file that exists only while a body is
being drafted, so a target would need a path argument and would still not run
under `make check`. The command is short enough to name directly.

**The same line is already wrong in the other direction.**
`CLAUDE.md:67:backlog lint, parser tests, doc links, all five suites` lists the
gate set, and no doc-link gate exists. `check` runs sync-check, version-check, path-filter-check,
backlog-lint, lib-test and plugin-tests; no target and no script checks links
in docs, and `queue.py`'s `dangling-link` is scoped to links between queue
items and is advisory at exit 0. So the one line a session reads as the
complete local gate list both omits a gate that runs and names one that does
not. Measured 2026-08-22 while completing Q89, whose README heading renames
moved three anchors that nothing would have caught. Fix both in the one edit.
