# gsed is not guarded, where sed is

`gsed` is how GNU sed is usually installed on macOS (Homebrew's `gnu-sed`), and
workspace-guard does not recognise the name, so every check `sed` gets is
skipped: the file operands, the in-place write, and the `w`/`r` filenames Q328
reads out of a script.

| Command | Verdict |
|---|---|
| `gsed -i 's/a/b/' /q-fake/y` | defer |
| `gsed -n '/x/w /q-fake/x' f` | defer |
| `sed -i 's/a/b/' /q-fake/y` | ask |

Measured 2026-11-01 with the hook run directly against a temporary workspace,
at #303's head; found by stream D's reviewer on #303. A defer hands the command
to the operator's own permission rules, so where those allow `gsed` it runs
unchecked.

## Where it lands

`ALIASES` in `plugins/workspace-guard/scripts/bash-workspace-guard.py` already
maps `gawk` and `mawk` to `awk`. A `'gsed': 'sed'` entry is the obvious fix,
but the plugin's CLAUDE.md forbids aliasing a tool whose flag set diverges from
the row it joins (Q3 on `rg`). So the work is to check the `sed` `SPEC` row,
`WRITE_MODE_FLAGS` and `_sed_scripts` against GNU sed's options first. They
were written to read GNU's argv as well as BSD's, which suggests the alias
holds; that was not checked. Also check every site that names `'sed'`
directly instead of going through `ALIASES`.
