# prod-guard splits a held command on whitespace whatever IFS holds

prod-guard splits an unquoted expansion on space, tab and newline, and never reads an `IFS` assignment, so a value split on any other character stays one word.
Measured 2026-11-26 through the hook, on Q382's branch at `dcdfcdf`:

| command | prod-guard |
|---|---|
| `IFS=,; X="kubectl,--context,gke_acme_prod-us,delete,ns,x"; $X` | **defer** |
| `IFS=,; A="--context,gke_acme_prod-us,delete,ns,x"; kubectl $A` | **defer** |
| `X="kubectl --context gke_acme_prod-us delete ns x"; $X` (control) | deny |

bash ran both: `env -i /opt/homebrew/bin/bash --norc --noprofile -c 'IFS=,; X="/bin/echo,RAN,a"; $X'` printed `RAN a`, and so did the same split in argument position.
The split is `plugins/prod-guard/scripts/bash-prod-guard.py:1299:                fields = _IFS_RE.split(word.strip(' \t\n'))`, against the fixed `plugins/prod-guard/scripts/bash-prod-guard.py:1279:_IFS_RE = re.compile('[ \t\n]+')`.

The `-c` body is the one place a split narrows what is judged, and Q382 already reads it from both the split word and the word as written, so `IFS=; B="<delete>"; bash -c $B` denies.

## Which way it gets built

Track `IFS` as the walk tracks any other shell variable, and split on its characters, with bash's distinction between whitespace and non-whitespace separators.
Where the value is unknown (an `IFS` read from a file, a substitution, or a branch that may not run), judge the default split and the unsplit word both, as the `-c` body already does.

## If it is never built

A production mutation runs with no prompt when a session sets `IFS` and runs a command held in a variable.
Setting `IFS` to a comma is an ordinary idiom for splitting a list, so the shape is not only adversarial.
