# branch-guard judges no funsub body and no double-quoted $( ) body

A protected push branch-guard asks about bare goes unjudged when a substitution hides it, unless the substitution is a bare `$( )`.
Driven 2026-11-17 through `hooks/branch-guard.py` with the payload's `cwd` in a worktree on a `claude/` branch.
`main` at `a3a43e4d` and Q357's branch gave the same verdicts:

| command | verdict |
|---|---|
| `git push --force origin main` | ask |
| `echo $( git push --force origin main )` | ask |
| `echo "$( git push --force origin main )"` | defer |
| ``echo "`git push --force origin main`"`` | defer |
| `echo ${ git push --force origin main; }` | defer |
| `echo "${ git push --force origin main; }"` | defer |

bash runs the push in every row.
The `${ …; }` form is bash 5.3's funsub.

The bare `$( )` asks only because its body's tokens stay in the stream and the segmenter splits at the `(`. branch-guard's own `extract_command_substitutions` reads a substitution only to decide whether it is one of the `PURE_SUBSTITUTIONS`, which can downgrade an `allow` to a defer and never produces an `ask`.
The shared `command_substitutions`, which Q357 taught the funsub, is not called.
The CLAUDE.md note that body extraction "stays out of `lib/` until a second guard needs this guard's answer" is about shell `-c` bodies, so it does not settle this either way.

## Which way it gets built

Judge each body `command_substitutions` returns with `judge_segments`, the way `body_verdicts` judges a `-c` string, keeping only its `ask`/`ask-shared`/`DENY_ROUTES` verdicts.
The open question is the cwd a body runs in: a funsub's `cd` moves the caller and a `$( )` body's does not, and `group_cwd` reads neither.

## If it is never built

A protected push or a destructive git command that a session wraps in a quoted substitution or a funsub reaches the user's own permission rules instead of branch-guard's prompt.
In `auto` those rules may pre-approve it.
How often sessions write that shape is not measured.
