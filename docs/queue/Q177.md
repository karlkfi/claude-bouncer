# Two of the three here-string spellings get the wrong answer

`split_groups` steps over a here-string's operand without collecting it. The
`<<<` case shares the `<<` branch, which advances past the operator and its
operand and continues without appending either to the group's command tokens
or to its redirect targets
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:3441:if t in ('<<', '<<<'):`).
What happens next depends on how the substitution was spelled, and only one of
the three spellings comes out right.

## Measured

2026-09-07, against `main` at c368aca -- the commit that closed Q169, so this
is the state after that fix rather than before it. Project root is a fresh
directory outside host temp; `/etc` stands in for the outside directory, and
`T` is the relative operand `T` resolving to `/etc/T`. Nothing executed -- the
hook resolves lexically.

**The path column is the point.** A verdict-only table records rows 2 and 3 as
identical, and they are not: one of them names a file that does not exist.

| # | command | verdict | path named | bash opens |
|---|---|---|---|---|
| 1 | `cd /etc && cat <<<"$(cat T)"` | **allow** | -- | `/etc/T` |
| 2 | ``cd /etc && cat <<<`cat T` `` | ask | **``/etc/T` ``** | `/etc/T` |
| 3 | `cd /etc && cat <<<$(cat T)` | ask | `/etc/T` | `/etc/T` |
| 4 | `cd /etc && echo "$(cat T)"` | ask | `/etc/T` | `/etc/T` |
| 5 | `cd /etc && cat <<EOF`⏎`$(cat T)`⏎`EOF` | ask | `/etc/T` | `/etc/T` |

Rows 4 and 5 are the same read in two spellings Q169 closed, and they are what
makes rows 1 and 2 defects rather than a decision.

**Row 1 is an affirmative allow, not a miss.** The reason is
`Guarded commands target workspace/pipe only`
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:4121:decision, reason = "allow", "Guarded commands target workspace/pipe only"`).
That is stronger than the failure Q169 fixed, where the body fell out of the
recursion and the string deferred. Q169 drops `guarded` for a recursed body
precisely so a clean body can never earn an allow on the enclosing string's
behalf; here the body never reaches the recursion at all, so the outer `cat`
allows on its own account. A defer leaves the decision to the user's own
permission settings. An allow spends the guard's word on it.

**Row 2 is a false positive wearing a correct-looking verdict.** The path it
names carries the trailing backtick inside the filename, and no such file
exists; the file bash opens is `/etc/T`, which does. The mechanism is
tokenization rather than substitution handling:

```
lex('cat <<<`cat T`')     -> ['cat', '<<<', '`cat', 'T`']
lex('cat <<<"$(cat T)"')  -> ['cat', '<<<', '$(cat T)']
lex('cat <<<$(cat T)')    -> ['cat', '<<<', '$', '(', 'cat', 'T', ')']
```

``T` `` survives the backtick spelling as a bare word after the `<<<` operator
and is checked as an ordinary file operand. So the prompt is the Q169
false-positive shape -- a path the command never touches -- arriving on the one
here-string spelling a verdict-only reading records as working.
`command_substitutions` finds `cat T` in all three strings, so the scanner is
not what differs.

Row 3 is genuinely covered, and for the reason Q169 catalogued: `(` is
punctuation the tokenizer keeps, so the bare spelling splits into ordinary
tokens and the operand reaches the group with the tracked cwd. That accident
covers exactly one of the three.

## Which way it gets built

Q169 added a marker pass to answer *where did this body sit*, and a marker
standing in a here-string operand is never seen by it, so the body falls back
to the string's entry cwd. Collecting the operand into `cur_redir` rather than
`cur` is the cheaper shape: the marker scan already reads `g + g_redir`, so the
position is picked up with no change to how the group is classified. That wants
checking against the redirect-target handling, which treats what it finds there
as a path to guard -- and against row 2, where the operand is a shredded
backtick token rather than a path at all.

Q169 left `split_groups` byte-for-byte equivalent to the block it was extracted
from, verified over 4,036 token lists. Collecting the operand forfeits that
property, so this wants its own differential run rather than a fixture or two.

## If it is never built

An out-of-root read that the guard affirmatively vouches for, on one spelling;
and on another, a prompt naming a file that does not exist while the real
target goes unmentioned. The second is the more corrosive of the two -- a human
approving a path they cannot check is the failure Q169 called its more visible
half, and here the named path is not merely wrong but unopenable, so nothing
about the prompt invites the reader to doubt it.
