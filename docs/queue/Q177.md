# A quoted here-string body never reaches the substitution position scan

`split_groups` steps over a here-string's operand without collecting it. The
`<<<` case shares the `<<` branch, which advances past the operator and its
operand and continues without appending either to the group's command tokens
or to its redirect targets
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:3429:if t in ('<<', '<<<'):`).
A marker standing in that operand is therefore never seen by the scan that
pairs each substitution with the directory it runs in, so the body falls back
to the string's entry cwd -- the defect Q169 closed everywhere else.

## Measured

2026-09-07, against the tree of the pull request that closed Q169. Project root
is a fresh directory outside host temp; `/etc` stands in for the outside
directory. Nothing executed -- the hook resolves lexically.

| command | main | Q169 head | bash would open |
|---|---|---|---|
| `cd /etc && cat <<<"$(cat T)"` | allow | **allow** | `/etc/T` |
| ``cd /etc && cat <<<`cat T` `` | ask | ask | `/etc/T` |
| `cd /etc && echo "$(cat T)"` | defer | ask | `/etc/T` |
| `cd /etc && cat <<EOF`⏎`$(cat T)`⏎`EOF` | allow | ask | `/etc/T` |

Row 1 is the gap: an out-of-root read after a `cd` out of the project root,
silent before Q169 and silent after it. Rows 3 and 4 are the same read in the
two spellings Q169 did close, and they are what makes row 1 an omission rather
than a decision.

**Only the quoted spelling is missed**, which is the axis Q169 turned out to
be about. Written with backticks the substitution is shredded into ordinary
tokens that never enter the `<<<` branch, so the operand's contents reach the
group and the accident that covered a bare `$( )` covers this too. Quoted, the
whole thing is one token sitting where nothing reads it.

## Why it was not fixed in Q169

That pull request left `split_groups` byte-for-byte equivalent to the block it
was extracted from, and a reviewer verified the equivalence over 4,036 token
lists. Collecting the here-string operand changes what the function returns,
so it forfeits that property and wants its own differential run.

The cheaper shape is likely to be collecting the operand into `cur_redir`
rather than `cur`: the marker scan already reads `g + g_redir`, so the position
would be picked up with no change to how the group is classified. That wants
checking against the redirect-target handling, which treats what it finds there
as a path to guard.

## If it is never built

One spelling of one construct stays silent where its four neighbours prompt.
The cost is the same as Q169's security half -- an out-of-root read or write
that draws no prompt at all -- narrowed to commands that pipe a substitution
into a here-string after leaving the project root.
