# A PowerShell deny's override route runs the command unprompted

Every workspace-guard deny on the PowerShell tool that names the override tells
the agent to re-issue the command through the Bash tool, prefixed with
`WORKSPACE_GUARD_OVERRIDE=<reason>`, "which downgrades it to a prompt"
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:3083:    return (" For %s, re-issue this through the Bash tool prefixed with "`).
It does not. Driven 2026-10-25 against the #280 branch head in `auto`, both
`WORKSPACE_GUARD_OVERRIDE=x Stop-Process -Id 1234` and
`WORKSPACE_GUARD_OVERRIDE=x pwsh -c "Get-Content ./in.txt; Stop-Process -Id 1234"`
sent through the Bash handler emit nothing. That is a defer, and in `auto`,
`acceptEdits` and `bypassPermissions` a defer runs. The Bash handler does not
judge a cmdlet, and does not read into a `pwsh -c` body, so the override has
nothing to downgrade.

So the route the deny names either fails (a bare cmdlet is not a Bash command)
or runs the command with no prompt at all, which is looser than the prompt it
promised. It reaches the PowerShell tool's denies built through
`override_hint` with `prefixable=False`: the unanchored-kill, sibling-checkout
and cross-session denies from `decide()`, and since #280 the
`Stop-Process`/`taskkill` escalation deny. `Edit` and `Write` denies share the
sentence, but a Bash re-issue of a file write is a command the Bash handler
judges, so the downgrade there plausibly works as promised; that case was not
driven. Found by the #280 review
(https://github.com/karlkfi/claude-bouncer/pull/280#issuecomment-6405089634)
and predates that PR.

The route that does reach the hook from a PowerShell session is
`WORKSPACE_GUARD_OVERRIDE` in the hook's own environment, which the operator
sets before the session starts
(`plugins/workspace-guard/scripts/bash-workspace-guard.py:3504:override=command_override(cmd) or env_override(),`).
The fix is the `prefixable=False` sentence naming that route as the operator's,
rather than a Bash re-issue the agent can take and should not. Pin it with a
test that drives the Bash re-issue and asserts it does not prompt, so the
sentence cannot drift back.

**If never built:** an agent that follows the reason in `auto` runs the kill or
write unexamined. Frequency is low (PowerShell-tool sessions only, and only on
these denies), and the bite is a looser outcome than the deny it routed around.
