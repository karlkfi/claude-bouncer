# `.claude/settings.local.json` is unignored, so a worker loses effort

A dispatched session writes its reasoning effort to `.claude/settings.local.json`
as its first act, behind a guard that refuses when no ignore rule covers the
path — the point of the guard being that an unignored settings file rides into
the PR at the next `git add -A`. This repo has no such rule: `.gitignore` covers
`__pycache__/`, `tmp/` and `.claude/worktrees/`, and `git check-ignore -v
.claude/settings.local.json` exits 1. Measured 2026-09-01 in a worker session,
where the guard declined, no `.claude/settings.local.json` was written, and the
session ran at the launcher default.

It cost that session nothing, because the launcher default already was the level
the brief named — `CLAUDE_EFFORT` read `high` either way. That is the argument
for fixing it rather than against: the skip is silent in both directions, so a
brief asking for a level the default does not supply is discarded with nothing
to show for it, and the only reason this instance is legible at all is that the
worker read `CLAUDE_EFFORT` back and found the two agreed by coincidence.

Every item in this store is worked that way, so the fix is one line — add
`.claude/settings.local.json` to `.gitignore` — and it takes effect for every
future dispatch. Add `.claude/settings.json` alongside it only if the repo means
to keep per-machine settings out of the tree; today it tracks neither.
