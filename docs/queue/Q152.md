# A value-taking wrapper flag swallows the guarded command

`strip_wrappers` peels a `PLAIN_WRAPPERS` head and then drops leading flags one
token at a time. A flag that takes a *separate* value leaves that value behind,
and the value becomes the tool — so the real command after it is never
classified and the segment defers as an uncovered tool.

This is the false-negative direction, which
[`plugins/prod-guard/CLAUDE.md`](../../plugins/prod-guard/CLAUDE.md) names as
the failure mode to fear: a mutating command against a production target runs
with no prompt at all.

## Measured

2026-09-01, prod-guard 2.5.2, fixture `$HOME` with ambient context
`gke_acme_prod-us`:

| command | verdict |
|---|---|
| `exec kubectl delete ns foo` | deny — correct |
| `exec -a x kubectl delete ns foo` | **defers** |
| `/usr/bin/time -o out.txt kubectl delete ns foo` | **defers** |
| `/usr/bin/time -f %e kubectl delete ns foo` | **defers** |
| `command time -o out.txt kubectl delete ns foo` | **defers** |
| `nohup kubectl delete ns foo` | deny — correct |
| `builtin kubectl delete ns foo` | deny — correct |

`strip_wrappers(['exec', '-a', 'myname', 'kubectl', 'delete'])` returns
`['myname', 'kubectl', 'delete']`, so the tool reads as `myname`.

Both wrappers really do run the command, verified against bash 5.3.15 rather
than assumed: `exec -a myname echo …` prints its argument, and `/usr/bin/time -o
<file> echo …` prints its argument. Bash's `time` *keyword* does not take `-o`
— it reports `-o: command not found` — so the leak needs the binary, which
`strip_wrappers` reaches anyway because it matches on `os.path.basename`.

`nohup` and `builtin` take no value-carrying flags and are unaffected.

## Which way it gets built

Give each wrapper its own value-taking flag set and skip flag *and* value, the
way `sudo`, `env` and `timeout` are already handled a few lines above in the
same function — `exec` takes `-a`, `time` takes `-o`/`--output` and
`-f`/`--format`. Those three are the fixtures to match against.

Deferring when the tool cannot be identified is right in general; the defect is
that the tool *is* identifiable and the flag loop walked past it.

## If it is never built

A `kubectl delete` against production that the guard never sees. Unlike Q131 and
Q142, whose costs were a prompt that should have been a deny and a deny that
should have been silence, this one is silence where there should have been a
deny.

`plugins/prod-guard/scripts/bash-prod-guard.py:264:PLAIN_WRAPPERS = frozenset({'command', 'nohup', 'time', 'builtin', 'exec'})`
