# branch-guard reads git long options whole, so an abbreviation slips past

git's option parser expands any unambiguous prefix of a long option:
`--forc` is `--force` to `git branch`, and `--discard` is `--discard-changes`
to `git switch`. `classify_git` and `classify_branch` match long options by
their full spelling, so each abbreviation reads as no option at all and the
command lands on the verb's default verdict, which is usually allow.

Measured 2026-10-05 on git 2.55.0 against this repo's `main` at `26962b0`, in a
scratch repository on a feature branch, permission mode `default`:

| command | branch-guard | what git did |
|---|---|---|
| `git branch --force main feat` (control) | ask | — |
| `git branch --forc main feat` | **allow** | moved `main` to `feat`, exit 0 |
| `git switch --discard-changes main` (control) | ask | — |
| `git switch --discard main` | **allow** | dropped an uncommitted edit, exit 0 |
| `git restore --staged --worktree f` (control) | ask | — |
| `git restore --staged --work f` | **allow** | not run |

The `git branch` row moves a protected branch, so under `dontAsk` it is the
same hole Q252 closed for `switch -C`: one spelling denies and another allows.

Q252 handles prefixes for `--force-create` alone, in `force_create_name`, and
leaves every other long option alone. An ambiguous prefix is refused by git
(`--forc` to `git switch` exits 129, `ambiguous option: forc`), so only a
prefix that resolves to exactly one option needs reading.

## Which way it gets built

Expand an abbreviated long option against the subcommand's own long-option
list before the flag sets are built, so every arm reads `--force` whether the
command wrote `--forc` or `--force`. The list has to be per subcommand, since
uniqueness is: `--forc` is unique to `git branch` and ambiguous to
`git switch`. A prefix the list cannot resolve to one name should keep today's
reading rather than guess. Cross fixtures over every flag an arm tests by long
name (`--force`, `--delete`, `--move`, `--copy`, `--discard-changes`,
`--worktree`, `--staged`, the push flags), each with a control at the full
spelling.

Q253 is the same parsing gap for wrapper options in exit-status-guard, and
Q233 moves the wrapper tables into `lib`; neither reaches git's own options.

## If it is never built

`git branch --forc main <rev>` moves `main` with no prompt, and
`git switch --discard <branch>` throws away uncommitted work with none.
