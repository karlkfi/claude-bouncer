# A $(( that bash re-reads as a subshell substitution hides its commands

bash tries a `$((` as arithmetic, and where the text is not an arithmetic
expression it re-reads it as `$( (`, a command substitution opening on a
subshell. Under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`
(5.3.15), `echo $((echo x) ; echo P)` prints `x P`, and so does
`echo "$(echo "$((echo x) ; echo P)")"`. The parser steps over every `$((`
as arithmetic, as `_scan_dollar_paren` does at
`lib/bouncer_parse.py:960:        if c == '(' and i + 1 < n and text[i+1] == '(':`,
so the commands inside are never returned as a substitution body.

The stream-A reviewer found it reviewing Q325 (#301). Driven 2026-11-01 by
Q325's worker, with `P` standing in for prod-guard's
`kubectl --context gke_acme_prod-us delete ns payments`, workspace-guard's
`rm /etc/probe-target`, exit-status-guard's `make check | tail` and
foreground-guard's `tail -f log.txt`; the same verdicts on `main` at
`f4f9857c` and on #301's head:

| command | prod / ws / exit / fg |
|---|---|
| `echo $((echo x) ; P)` | deny / ask / **defer** / deny |
| `x=$((echo x) ; P)` | deny / ask / **defer** / deny |
| `echo "$(echo "$((echo x) ; P)")"` | **defer** / ask / **defer** / **defer** |

Where three guards still decide on the unquoted form, it is presumably
because the flat token stream carries `P`; no one traced it.

## Which way it gets built

Decide whether a `$((` is arithmetic the way bash does before skipping it,
and where it is not, scan it as a `$(` whose body opens with `(`. bash's own
test is whether the text up to the matching `))` parses as arithmetic, which
is more than this parser should carry; a cheaper proxy is to treat a `$((`
whose matching close is a single `)` followed by more text as a
substitution. Measure the proxy against bash before picking it. Every site
that steps over `$((` needs the same answer, including `_brace_end` and
`strip_comments`.

## If it is never built

A command written inside `$((…) ; …)` is not judged by exit-status-guard,
and in double quotes by prod-guard and foreground-guard either. bash accepts
the shape, but nobody writes it by accident, so it is likely rare outside a
deliberate attempt.
