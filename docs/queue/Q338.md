# A $(( that bash re-reads as a subshell substitution hides its commands

bash tries a `$((` as arithmetic, and where the text is not an arithmetic
expression it re-reads it as `$( (`, a command substitution opening on a
subshell. Under `env -i /opt/homebrew/bin/bash --norc --noprofile -c`
(5.3.15), `echo $((echo x) ; echo P)` prints `x P`, and so does
`echo "$(echo "$((echo x) ; echo P)")"`. The parser steps over every `$((`
as arithmetic, as `_scan_dollar_paren` does at
`lib/bouncer_parse.py:978:        if c == '(' and i + 1 < n and text[i+1] == '(':`,
so the commands inside are never returned as a substitution body.

The stream-A reviewer found it reviewing Q325 (#301). Driven 2026-11-01 by
Q325's worker, with `P` standing in for prod-guard's
`kubectl --context gke_acme_prod-us delete ns payments`, workspace-guard's
`rm /etc/probe-target`, exit-status-guard's `make check | tail` and
foreground-guard's `tail -f log.txt`; the same verdicts on `main` at
`f4f9857c` and on #301's head:

| command | prod / ws / exit / fg |
|---|---|
| `echo $((echo x) ; P)` | deny / ask / **defer** / deny |
| `x=$((echo x) ; P)` | deny / ask / **defer** / deny |
| `echo "$(echo "$((echo x) ; P)")"` | **defer** / ask / **defer** / **defer** |

Where three guards still decide on the unquoted form, it is presumably
because the flat token stream carries `P`; no one traced it.

Re-driven 2026-11-16 on `main` at `979c919e`, after #329 changed
exit-status-guard's own `$((` mask to end at `_scan_dollar_paren`'s close:
all three rows give the verdicts above, cell for cell. Q361 and Q362 sit on
the same `lib/` branch and are separate defects; either can land alone.

## Which way it gets built

bash decides by the delimiter, not by whether the text parses as
arithmetic. A `$((` whose matching close is `))` is arithmetic, even when
the text is not valid arithmetic. One that closes on a single `)` is a `$(`
whose body opens with `(`. Measured 2026-11-16 under
`env -i /opt/homebrew/bin/bash --norc --noprofile -c` (5.3.15):

| command | bash |
|---|---|
| `echo $((echo x))` | arithmetic syntax error, error token `x` |
| `echo $(( 1 ) )` | substitution: `1: command not found` |
| `echo $((echo x) ; echo P)` | substitution: prints `x P` |
| `echo $(( $(echo ")" \| wc -c) ))` | arithmetic: prints `2` |
| `echo $(( $(echo "(" \| wc -c) ))` | arithmetic: prints `2` |

So read a `$((` by finding its matching close the way bash does, and where
that close is a single `)`, scan it as a `$(`. The close has to be found
quote-aware. Today's flat `_skip_balanced_parens` reads the last two rows as
substitutions, because it counts the quoted paren. That is the stream
reviewer's simulation on #334, not re-run here. Q361 needs the same
quote-aware close, so the two can share a matcher. Every site that steps
over `$((` needs the same answer, including `_brace_end` and
`strip_comments`.

Pin it with the five rows above as parser tests, the last two as the cases
a flat matcher gets wrong, and the three commands in the first table as
guard verdicts.

## If it is never built

A command written inside `$((…) ; …)` is not judged by exit-status-guard,
and in double quotes by prod-guard and foreground-guard either. bash accepts
the shape, but nobody writes it by accident, so it is likely rare outside a
deliberate attempt.
