# prod-guard keeps an assignment-shaped argument whole after expansion

`expand_argv` never splits a word shaped like `NAME=value`, which is right for an inline prefix and for an operand of `export` or `declare`, and wrong for an argument to any other command, where bash splits it.
Measured 2026-11-26 through the hook, on Q382's branch at `dcdfcdf`:

| command | prod-guard |
|---|---|
| `X="1 kubectl --context gke_acme_prod-us delete ns x"; env A=$X` | **defer** |
| `env A=1 kubectl --context gke_acme_prod-us delete ns x` (control) | deny |

bash split it: `X="1 /bin/echo RAN"; /usr/bin/env A=$X` printed `RAN`.
The branch is `plugins/prod-guard/scripts/bash-prod-guard.py:1408:        if ASSIGNMENT_RE.match(tok):`, which takes every assignment-shaped word, wherever it sits in the command.

## Which way it gets built

Split an assignment-shaped word unless it is an inline prefix (already removed by `extract_env_prefix` before `expand_argv` sees the words) or an operand of a declaration builtin (`export`, `declare`, `typeset`, `local`, `readonly`).
Keep the `env` operand reading for the word's first field, since `env` treats it as an assignment, and judge the rest as the command it runs.

## If it is never built

A production mutation runs with no prompt when an `env` operand's value holds the command.
It needs the command packed into an assignment value, so it is an adversarial shape rather than one a session writes by accident.
