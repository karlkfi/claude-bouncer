# Wrapper option reader takes sudo --login as --login-class

`wrapper_option` matches a long option by unique prefix against the
value-taking spellings only. sudo's `--login` takes no value, but it is a
prefix of `--login-class`, which does, so the reader returns `--login-class`
and consumes the next word as its value. getopt_long takes an exact match
first, so sudo itself reads `--login` as `-i` and runs the command.

Measured 2026-10-08 on `main` at `54fe0f2`:
`wrapper_option(['--login', 'git', 'push'], WRAPPER_VALUE_OPTS['sudo'])`
returns `(2, '--login-class', 'git')`, and branch-guard answers
`sudo --login git push --force origin main` with no decision where
`sudo -i git push --force origin main` asks. Every guard peeling sudo through
the shared reader inherits it; any other no-value long option that prefixes a
value-taking one has the same shape.

Next step: let `wrapper_option` see the whole long-option table, so an exact
match on a `none` option wins before prefix matching, add the lib test, and
re-run each guard's sudo fixtures.
