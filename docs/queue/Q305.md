# A GIT_DIR or GIT_WORK_TREE assignment escapes the break-glass scope

The break-glass promises to lift only a loss in the checkout the session owns,
so `is_overridable` refuses a `git -C`, `--git-dir` or `--work-tree` through
`targets_other_repo`. The same redirect spelled as an environment variable is
not read: `GIT_DIR`, `GIT_WORK_TREE` (and `GIT_INDEX_FILE`, `GIT_CONFIG_*`,
which reach config the way `-c` does) set as a command prefix, or as an `env`
or `sudo` operand, aim git elsewhere while the ref probes still measure the
session's own tree.

Measured 2026-10-08 on `main` at `54fe0f2`, in a scratch repository on a
session branch whose unpushed commit makes `git reset --hard origin/main` a
deny, permission mode `default`:

| command | branch-guard |
|---|---|
| `BRANCH_GUARD_OVERRIDE=why git --git-dir=/elsewhere/.git reset --hard origin/main` | ask |
| `GIT_DIR=/elsewhere/.git BRANCH_GUARD_OVERRIDE=why git reset --hard origin/main` | **allow** |

The wrapped-override fix lets `env` and `sudo` operands arm the override, so
`env GIT_DIR=… BRANCH_GUARD_OVERRIDE=why git reset --hard` is lifted the same
way after it. Next step: have `parse_invocation` hand back the assignments it
peels — leading ones and wrapper operands — and treat a git repository or
config variable among them as `targets_other_repo` and `GIT_ESCAPE_HATCHES`
treat their option forms, which also stands the ref probes down for it.
