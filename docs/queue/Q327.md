# prod-guard's long_option repeats the shared wrapper walk's prefix rule

`long_option` in prod-guard matches a wrapper's long option word the way
getopt_long does: exact spelling first, then a unique prefix, against every
long option of the `WRAPPER_GRAMMAR` row
(`plugins/prod-guard/scripts/bash-prod-guard.py:1083:def long_option(head, tok):`).
Since Q306, `wrapper_option` in `lib/bouncer_wrappers.py` applies the same rule
to the same rows, so the two copies can drift: a change to how one resolves a
prefix, such as how it treats `--` or a `--no-` form, is a change to one guard
only. Found by the independent review of PR #287, as a note rather than a hold.

Costs nothing while the two agree, and bites once, whenever the rule next
changes and only one copy is edited. Next step: export one long-option
resolver from `lib/bouncer_wrappers.py`, have `wrapper_option` and prod-guard's
`long_option` both call it, run `make sync`, and re-run prod-guard's
help/version and `env -i` fixtures, which are what read `long_option`.
