# Skip heredoc bodies when scanning a `$(…)`

Measured 2026-08-22 while fixing Q81: `_scan_dollar_paren` tracks quotes but
not heredocs, so an apostrophe in a heredoc body written inside a substitution
opens a single-quoted run that never closes. The scan reaches end-of-input,
returns `(None, start)`, and `command_substitutions` yields nothing -- the
whole substitution is silent. `echo "$(case $x in a) cat <<EOF` / `it's fine` /
`EOF` / `cat /etc/target;; esac)"` defers rather than asking about
`/etc/target`.

`strip_heredoc_bodies` cannot pre-empt it. It runs over the raw command, where
this heredoc sits inside the outer double quotes, so it treats `<<EOF` as
quoted text and collects nothing -- verified by calling it directly on that
string, which returns the input unchanged with an empty `expanded`.

This is a different mechanism from Q81's `case` tracking, which is why Q81 did
not close it: one fix does not close both. Q81 narrowed the shape, though --
before it, a truncated substitution left the tail of the clause to be rescanned
as top-level text, and a `$(…)` sitting there was sometimes picked up by
accident. That accident is gone, so a string of this shape now defers where it
occasionally asked.
`plugins/workspace-guard/tests/test_workspace_guard.py` pins the current
behaviour in `CaseClauseSubstEndToEndTests`; the fix flips that assertion.

The fix lands in `lib/bouncer_parse.py` and reaches all five guards, so it
needs `make sync` and every suite re-run.
