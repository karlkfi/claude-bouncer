# Skip heredoc bodies when scanning a `$(…)`

Measured 2026-08-22 while fixing Q81: `_scan_dollar_paren` tracks quotes but
not heredocs, so an apostrophe in a heredoc body written inside a substitution
opens a single-quoted run that never closes. The scan reaches end-of-input,
returns `(None, start)`, and `command_substitutions` yields nothing -- the
whole substitution is silent. `echo "$(case $x in a) cat <<EOF` / `it's fine` /
`EOF` / `cat /etc/target;; esac)"` defers rather than asking about
`/etc/target`.

`strip_heredoc_bodies` cannot pre-empt it. It runs over the raw command, where
this heredoc sits inside the outer double quotes, so it treats `<<EOF` as
quoted text and collects nothing -- verified by calling it directly on that
string, which returns the input unchanged with an empty `expanded`.

This is a different mechanism from Q81's `case` tracking, which is why Q81 did
not close it: one fix does not close both.

Q81 also cost one shape a prompt, and it is narrower than a first reading
suggested. Before Q81 a truncated substitution left the clause tail to be
rescanned as top-level text, so a `$(…)` sitting there was picked up by
accident; the accurate parse ends that. Measured 2026-08-23 by running the
same guard against the parser from each of `origin/main` and the Q81 branch,
over 12 shapes crossing outer quoting, the apostrophe, and where the target
sits: **1 regression, 1 gain, 10 unchanged**. The regression needs all four of
a double-quoted `"$(…)"`, an apostrophe in the heredoc body, a `case` clause,
and the target inside a nested `$(…)` in that body:

    echo "$(case $x in a) cat <<EOF
    it's $(cat /etc/target)
    EOF
    ;; esac)"

Drop any one and it is unchanged -- a bare `$(…)` is unaffected throughout,
because the guard splits a subshell separately. A plain guarded command in a
clause beside an apostrophe heredoc defers both before and after, so it is not
part of this.

`plugins/workspace-guard/tests/test_workspace_guard.py` pins both in
`CaseClauseSubstEndToEndTests` -- the still-silent shape and the regressed one.
Fixing Q109 flips both assertions.

The fix lands in `lib/bouncer_parse.py` and reaches all five guards, so it
needs `make sync` and every suite re-run.
