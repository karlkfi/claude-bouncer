# `extra_watch_patterns` denies carry a principle, not a rewrite

Confirmed live 2026-08-24, and the deny is worse in two ways rather than one. A
repo registering a `flux ... --watch` regex under `poll.extra_watch_patterns`,
then running `flux get kustomizations --watch`, is told the command "runs in
watch/follow mode" — with the raw regex where a built-in prints a readable label
such as `gh run watch` — and then "Instead: (1) take one non-blocking snapshot
instead". The alternative degrades to the generic principle, this row's claim at
`plugins/foreground-guard/scripts/bash-foreground-guard.py:242:'take one non-blocking snapshot instead'`,
and the label degrades with it. One change fixes both: `watch_matchers` builds
an extra's tuple out of the pattern because the config gives it nowhere else to
read a label or an alternative from.

**Who is worse off.** The agent that has just been denied. This guard's whole
justification for denying rather than asking is that the reason carries the
rewrite the agent applies
(`plugins/foreground-guard/CLAUDE.md:5:Both classes **deny**, and the reason carries the rewrite the agent applies`).
A config row is therefore the one class of deny that costs a round trip and
teaches nothing — and it lands on the commands a repo cared enough to register.

**Which way it gets built,** settled by precedent in the same config file rather
than by preference: `slow.commands` already takes two shapes under one key. Let
`extra_watch_patterns` accept an object beside the string —
`{"pattern": …, "label": …, "alternative": …}` — with the string form unchanged
and today's generic text as the default for a missing `alternative`. A broken
regex already loses itself rather than the list; a malformed object drops the
same way. The README's config table and the covered-forms table both describe the
string form, so both move with it.

**If it is never built,** the deny contract holds for the eight built-ins and
fails for everything an operator adds, which is the half they chose deliberately.

`S` holds. Rank `ad` is too low: this is a defect in the deny contract, not a
tidy-up, so it belongs above Q82 rather than below it.
