# exit-status-guard does not register gh api writes as mutators

`mutators` names `gh pr merge` but no `gh api` form, so a gate sequenced with
`;` before an API write runs the write whatever the gate returned. Driven
against the registry Q312 left, on the guard's `decide`:
`make check; gh pr merge 1` denies, and
`make check; gh api -X PUT repos/o/r/pulls/1/merge` is silent. Both merge the
same pull request.

## Which way it gets built

Add the two `gh api` write patterns Q312 put in `gates` to `mutators` as well:
`-X`/`--method` naming anything but GET, and, with no method named, a field
flag or `--input`. A GraphQL call posts a query as readily as a mutation, so
`gh api graphql -f query=…` would deny after a `;` too; decide whether that
false positive is worth it, or narrow the mutator to non-graphql endpoints.

**Who it is for:** a session that publishes through the REST API — merging,
dispatching a workflow, writing a ref — after a check. **If never built:** a
failed check still publishes on that path, and nothing reports it. Frequency
unmeasured, so the rank at the tail is provisional.
