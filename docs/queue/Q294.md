# Gate a command-position reader placed below a token rewrite

**Event:** a third reader that decides what a word is from a token rebuilt
after lexing is found, counting from when the `glue_dollar_paren` fix (Q175)
ships.

`is_assignment`, `is_reserved_word` and `is_operator` read how a word was
written from a record the lexer attaches to each token, and a plain `str` has
no record, so they read it as written plain. Any reader handed a token that
`substitute_vars`, `expand_argv` or `MARK_RE.sub` rebuilt gets that answer,
and nothing reports it. The rule the scoping of Q175 settled is to decide what
a word is on the lexer's token and apply the answer to the rebuilt one by
index. That rule is written into a docstring, so it holds only while the next
author reads it.

A check could catch a reader placed below a rebuild: the three functions
could raise on a plain `str` when a test-only switch is set, and every
end-to-end suite would set it. Two costs stop it being built now, and neither
has been counted:

- workspace-guard reads post-substitution tokens on purpose in `poison_vars`
  and `clobbers_ifs`, so each such site needs an explicit opt-out.
- Unit tests pass hand-built plain strings throughout.

Raising at runtime is ruled out rather than unpriced. prod-guard turns an
exception into a silent exit, so a prod deny reached through a raising reader
came back as no verdict at all (measured on a scratch copy, recorded in the
Q175 pull request).

Revive it when the count makes the cost worth paying. Until then a reader
placed wrongly is found by a payload, as each one so far has been.
