# An inline-prefix ask in prod-guard advises a fix no pattern supplies

Since Q321, `CTX=<nonprod> kubectl --context $CTX <mutating>` with no earlier `CTX=` asks every time.
The ask is right: bash expands the command's words before it applies the prefix, so kubectl gets the shell's `CTX`, which is empty here, and that means the current context.
The guard judges that reading beside the prefix's at `plugins/prod-guard/scripts/bash-prod-guard.py:3513:        if reading is None and _expanded_by_parent(`.

The reason it gives cannot help.
It says the context `'$CTX'` matches no pattern and suggests adding a nonprod pattern, at `plugins/prod-guard/scripts/bash-prod-guard.py:2180:            'allowed. Confirm it is safe, or add a nonprod pattern to '`, but `$CTX` is not a name any pattern classifies.
An ask's reason never reaches the model, so a session that writes the inline form keeps writing it and the user keeps confirming it.
The command that does what the session meant is one rewrite away and defers.

Found by review-r2 on the Q321 pull request, comment 6940308323, and measured 2026-11-16 at `4bff7e2f` through the end-to-end hook with the fixture `$HOME`, whose current context is `gke_acme_prod-us`:

| command | prod-guard |
|---|---|
| `CTX=kind-dev kubectl --context $CTX delete pod x` | ask, reason as above |
| `CTX=kind-dev; kubectl --context $CTX delete pod x` | defer |
| `CTX=kind-dev kubectl --context=kind-dev delete pod x` | defer |

`docs/design.md` used to name the inline form as the largest single source of prompts, so how often sessions write it decides how much this costs.
That count is not measured.

## Which way it gets built

Where the only reading that fails to resolve is the shell's, and the prefix's reading is nonprod, deny with the rewrite in the reason: write `CTX=<ctx>;` with a semicolon, or the value literally.
A deny's reason reaches the model, which applies it and moves on, where an ask interrupts the user every time.
It is a policy change from ask to deny for that shape, so it needs the same sign-off any verdict change does.
A narrower alternative keeps the ask and replaces only its pattern advice with the rewrite, which fixes the wording but not the repetition.

## If it is never built

Each session that writes the inline form costs one confirmation per command, and the reason points it at a config change that will not stop the next one.
