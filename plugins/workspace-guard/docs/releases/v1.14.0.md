Minor release: in `auto` and `acceptEdits`, an `xargs` or a `kill` sharing a string with a guarded command now denies with the rewrite instead of asking, and four prompts stop firing: reads of a sibling session's scratch in another checkout of the same repository, of Claude Code's bundled skills and of the desktop app's side-session notes, and the commands after a session grant is re-approved past its 8-hour cap.

## Highlights

**[An `xargs` or a `kill` beside a guarded command denies instead of asking](https://github.com/karlkfi/claude-bouncer/blob/workspace-guard/v1.14.0/plugins/workspace-guard/README.md#suppression-escalation-in-pre-approving-modes).** In `auto` and `acceptEdits`, `git ls-files | xargs grep foo` and `cat in.txt; kill 12345` used to ask. Both reasons already held a fix the agent can apply itself: name the files on the command (`git grep`, `grep -r`), or run the `kill` as its own call. So the prompt was asking a person a question whose answer it already contained, and the deny hands that answer to the agent instead. `WORKSPACE_GUARD_OVERRIDE=<reason>` as a prefix turns either deny back into a prompt for one command. A `sh -c` body under a container or remote wrapper, and interpreter code, have no such rewrite and still ask.

**An escalation deny names only routes the agent can take.** Every escalation reason used to end with "or approve this one" and "Set WORKSPACE_GUARD_ESCALATE=off to restore the silence." Nobody approves a deny, and a variable set inside the session never reaches the hook. A deny now leaves out the approval, offers the override only where it can act, and says `WORKSPACE_GUARD_ESCALATE=off` is set by the operator, in the shell Claude Code starts from or a `settings.json` `env` block. An `ask` keeps both sentences, since its reason reaches the person at the prompt.

**[A dispatcher can read workers' scratch across worktrees](https://github.com/karlkfi/claude-bouncer/blob/workspace-guard/v1.14.0/plugins/workspace-guard/README.md#what-it-does).** Claude Code files each worktree's sessions under a scratch directory of its own, so a session in one worktree tailing a worker's task output in another was asked every time. A read now allows when that session ran in any checkout of the same repository. Where it ran comes from the `cwd` Claude Code recorded in its transcript, and which repository that is comes from git's own records, so a lookalike directory name cannot claim another repository. A different repository's scratch still asks, and writes into any other session's scratch are unchanged.

**[Bundled skills and side-session notes read without a prompt](https://github.com/karlkfi/claude-bouncer/blob/workspace-guard/v1.14.0/plugins/workspace-guard/README.md#allowed-read-prefixes).** Reads under `/tmp/claude-<uid>/bundled-skills/`, where Claude Code unpacks the skills it ships, and under `~/Library/Application Support/Claude/side-session-notes/`, the desktop app's notes folder, no longer ask. Writes there still do, and a root that is a symlink is not exempt. The Go standard library is not a default, since finding it would mean running whatever `go` is first on `PATH`. The README gives the `WORKSPACE_GUARD_READ_ALLOW_PREFIXES` value a Go user sets instead.

**[A session grant re-approved after it expires renews](https://github.com/karlkfi/claude-bouncer/blob/workspace-guard/v1.14.0/plugins/workspace-guard/README.md#session-grants-stop-re-answering-the-same-prompt).** With `WORKSPACE_GUARD_SESSION_GRANTS=1`, approving a prompt after a grant passed its 8-hour cap recorded nothing, so every later command in that session asked. The approval now starts a fresh 8-hour grant. A live grant still keeps its first timestamp, so the cap never slides.

## Decision surface

Measured by running the v1.13.0 hook and this one through their launchers over the same throwaway repository, where the session runs in a linked worktree holding `in.txt`, with no `WORKSPACE_GUARD_*` variable set unless the row says so. macOS. `defer` means the guard expressed no opinion and your own permission settings decided. *Sibling scratch* is task output under the temp root for a session whose transcript records the repository's main checkout as its `cwd`, and *foreign scratch* is the same for a session that ran in a different repository.

| command | mode | v1.13.0 | v1.14.0 |
|---|---|---|---|
| `git ls-files \| xargs grep foo` | `auto` | ask | **deny** |
| `git ls-files \| xargs grep foo` | `acceptEdits` | ask | **deny** |
| `cat in.txt; kill 12345` | `auto` | ask | **deny** |
| `tail <sibling scratch>/tasks/x.output` | `default` | ask | **allow** |
| `cat /tmp/claude-<uid>/bundled-skills/…/SKILL.md` | `default` | ask | **allow** |
| Read tool on `/tmp/claude-<uid>/bundled-skills/…/SKILL.md` | `default` | ask | **defer** |
| Read tool on `~/Library/Application Support/Claude/side-session-notes/n.md` | `default` | ask | **defer** |
| `cat /opt/q8-fake-target/c` *(grants on; an expired grant on that directory just re-approved)* | `default` | ask | **defer** |
| `WORKSPACE_GUARD_OVERRIDE=why git ls-files \| xargs grep foo` | `auto` | ask | ask |
| `git ls-files \| xargs grep foo` | `bypassPermissions` | deny | deny |
| `git ls-files \| xargs grep foo` | `default` | defer | defer |
| `kill 12345` | `auto` | defer | defer |
| `cat in.txt; docker exec c sh -c 'cat /opt/q8-fake-target'` | `auto` | ask | ask |
| `tail <foreign scratch>/tasks/x.output` | `default` | ask | ask |
| `echo x > <sibling scratch>/f` | `default` | ask | ask |
| `echo x > /tmp/claude-<uid>/bundled-skills/…/SKILL.md` | `default` | ask | ask |
| `cat in.txt` | `default` | allow | allow |

Three rows gain scrutiny and five lose it. The three trade a prompt for a deny that carries the rewrite, so a person stops being asked and the agent gets the fix. The five are reads of files a session did not write, or a prompt the grant had already answered. The `bypassPermissions` row keeps its verdict but its reason changes: it no longer offers an approval nobody can give.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update workspace-guard@claude-bouncer
```

A restart is needed. The hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** No variable is new or renamed. `WORKSPACE_GUARD_OVERRIDE` now also downgrades the `xargs` and `kill` escalation denies to a prompt, and `WORKSPACE_GUARD_ESCALATE=off` still turns escalation off altogether.

**If you work in `auto` or `acceptEdits`, expect denies where an `xargs` or a `kill` used to prompt.** The agent reads the rewrite and retries, so in most sessions the prompt simply goes away. Where you need the command as written, the agent can prefix it with `WORKSPACE_GUARD_OVERRIDE=<reason>` and you answer one prompt.
