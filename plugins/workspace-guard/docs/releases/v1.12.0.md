Minor release: two opt-in postures — one that escalates a withheld `allow` where the unattended modes would otherwise run the command unasked, one that turns the four deny classes into prompts — plus five parser fixes, three of which close a shape that used to pass in silence.

## Highlights

**[A withheld `allow` now escalates instead of evaporating](https://github.com/karlkfi/claude-bouncer/blob/workspace-guard/v1.12.0/plugins/workspace-guard/README.md#suppression-escalation-in-pre-approving-modes).** When a command mixes a guarded command with a shell `-c` body the hook cannot reach, or a kill it cannot scope, the guard withholds its `allow` and defers. Under `default` that is correct — your own permission settings still decide. Under `auto`, `acceptEdits` and `bypassPermissions` there is nothing behind the defer, so the command ran with nobody having looked at it. It now prompts in the first two and denies with the rewrite in the third. `WORKSPACE_GUARD_ESCALATE=off` restores the old behaviour; `=all` extends it to interpreter code.

**[`WORKSPACE_GUARD_POSTURE=supervise` turns the deny classes into prompts](https://github.com/karlkfi/claude-bouncer/blob/workspace-guard/v1.12.0/plugins/workspace-guard/README.md#supervising-posture).** Four classes deny outright — a host-wide temp write, a sibling-checkout write, a cross-session scratchpad write, and an unscoped kill. A deny is right when the model is the one being stopped and wrong when you are sitting there and meant it. `supervise` asks instead, and `WORKSPACE_GUARD_SIBLING_ACTION`, `WORKSPACE_GUARD_KILL_ACTION`, `WORKSPACE_GUARD_CROSSSESSION_ACTION` and the existing `WORKSPACE_GUARD_TMP_ACTION` override it per class. Defaults are unchanged, and `bypassPermissions` still denies whatever the posture says.

**[A prompt you approved this session can stop coming back](https://github.com/karlkfi/claude-bouncer/blob/workspace-guard/v1.12.0/plugins/workspace-guard/README.md#session-grants-stop-re-answering-the-same-prompt).** `WORKSPACE_GUARD_SESSION_GRANTS=1` records an approved decision shape against the session id and stops re-asking for it. Off by default, session-scoped, and the first grant's timestamp never slides, so a grant cannot be extended by repeating the command.

**Three shapes that used to pass in silence now reach you.** `python3 -m unittest` behind a clean guarded read returned `allow` for the whole string, so the module's code ran without the prompt your settings would have raised — `python3 -c` had deferred for two releases and `-m` had not. An `X+=1` command prefix made the guard stand aside entirely, because the append spelling was read as a command name rather than an assignment. And a quoted operator-only word — `cat ';' /etc/passwd` — split the command in the lexer but not in bash, so the guard judged a `cat` that had no outside path in it and allowed the read. A backtick or heredoc body after a `cd` out of the project root joins them: the substitution is now resolved where it was written rather than where the scan reached it.

**Two prompts stop firing, for the same reason the bypasses closed.** A quoted command prefix is a word bash runs as a program, not an assignment: `'X=1' cat /etc/passwd` looks for a program named `X=1` and never reaches `cat`, so there is no read to guard. The same goes for a quoted reserved word — `'time' cat …` — which the guard no longer peels to reach the command behind it. Written unquoted, both behave exactly as before. This cuts the other way too: `'WORKSPACE_GUARD_OVERRIDE=why' …` no longer arms the break-glass, because bash never set the variable.

**The override works where the denial says to put it.** `WORKSPACE_GUARD_OVERRIDE=<reason>` is now read off the command string as a prefix on a single Bash call, which is the form every cross-workspace denial has always named. `Edit`, `Write` and PowerShell denials have no command string to carry it, and they now name a route you can actually take. The sibling-checkout write denial names both of its ways out — the corrected in-session path, and the override — instead of leading with the path rewrite, which is the wrong repair for a worktree you created on purpose.

## Decision surface

Measured by running the v1.11.0 hook and this one over the same throwaway project and diffing the emitted `permissionDecision`. `defer` means the guard expressed no opinion and your own permission settings decided. Unmarked rows are `permission_mode: default` with no posture set.

| command | v1.11.0 | v1.12.0 |
|---|---|---|
| `cat README.md && python3 -m unittest` | allow | **defer** |
| `cat ';' /etc/passwd` | allow | **ask** |
| `X+=1 cat /etc/passwd` | defer | **ask** |
| ``cd /etc && echo `cat passwd` `` | defer | **ask** |
| `cat README.md && bash -c 'echo hi'` *(`auto`)* | defer | **ask** |
| `cat README.md && kill -9 -1` *(`auto`)* | defer | **ask** |
| `cat README.md && bash -c 'echo hi'` *(`bypassPermissions`)* | defer | **deny** |
| `cat README.md && python3 -c 'print(1)'` *(`auto`, `ESCALATE=all`)* | defer | **ask** |
| `echo x > /var/tmp/f` *(`POSTURE=supervise`)* | deny | **ask** |
| `'X=1' cat /etc/passwd` | ask | **defer** |
| `'time' cat /etc/passwd` | ask | **defer** |
| `cat README.md && bash -c 'echo hi'` *(`default`)* | defer | defer |
| `cat README.md && python3 -c 'print(1)'` *(`auto`)* | defer | defer |
| `echo x > /var/tmp/f` *(default posture)* | deny | deny |
| `cat /etc/passwd` | ask | ask |
| `cat ./docs/a.md` | allow | allow |
| `grep -r x .` | allow | allow |

Nine rows gain scrutiny and two lose a prompt. Both of the two are commands bash never runs the way the old lexer read them, so the prompt was about a read that was not going to happen.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update workspace-guard@claude-bouncer
```

A restart is needed — the hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** `WORKSPACE_GUARD_OVERRIDE`, `WORKSPACE_GUARD_READ_ALLOW_PREFIXES`, `WORKSPACE_GUARD_TMP_*` and `WORKSPACE_GUARD_SCRATCH_DIR` keep their names and their defaults. Six variables are new — `WORKSPACE_GUARD_ESCALATE`, `WORKSPACE_GUARD_POSTURE`, `WORKSPACE_GUARD_SESSION_GRANTS`, `WORKSPACE_GUARD_SIBLING_ACTION`, `WORKSPACE_GUARD_KILL_ACTION` and `WORKSPACE_GUARD_CROSSSESSION_ACTION` — and every one of them is off or neutral unless you set it.

**If you work in `auto` or `acceptEdits`, expect prompts where you were getting silence.** That is the release. A command that mixes a guarded command with a shell `-c` body was running unexamined; it now asks. If a shape is routine for you, `WORKSPACE_GUARD_ESCALATE=off` puts it back rather than turning the guard off.

**1559 tests green** on the release tree, alongside the 207 shared-parser tests that cover `lib/bouncer_parse.py` directly and the four sibling suites `make check` runs beside them. The count is from the release branch rather than quoted from an earlier run.

The decision surface above is the check a test suite cannot make: both hooks run as subprocesses over the same project, so a row records what a session would actually have seen rather than what a fixture asserts.

**What this does not assert.** No live Claude Code session runs in the suite — hook behaviour is asserted against synthetic payloads. The table was measured on macOS; the PowerShell paths are asserted by fixtures on every platform rather than by a Windows session. And the guard reads the command string Claude is about to run, so it governs Claude's own tools and nothing else. Anything that must hold unconditionally belongs in the filesystem's permissions.
