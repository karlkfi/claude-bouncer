Minor release: a blocking command hidden behind a wrapper flag, a prefix, a substitution or a comment now denies, and a command that bash backgrounds or never runs no longer does. One config key gained an object form, and the plain-string form still works.

## Highlights

**[A wrapper or a prefix no longer hides the command behind it](https://github.com/karlkfi/claude-bouncer/blob/foreground-guard/v0.8.0/plugins/foreground-guard/README.md#covered-forms).** The guard used to stop reading at a wrapper flag it did not expect, and the command it was there to catch ran unjudged. It now reads the flag that takes a separate value (`stdbuf -o L`, `exec -a name`, `/usr/bin/time -o f`), the bundled or abbreviated one (`sudo -nu root`, `env -iu FOO`, `sudo --us root`), the string `env -S` splits (`env -S 'sleep 300'`), an `env` or `sudo` operand that is not a shell identifier (`env 'a b=c'`), a `sudo` option written after an assignment (`sudo A=1 -u root`), and `sudo -h HOST`. A prefix that assigns an array element, `FOO[0]=x`, also no longer hides what follows it. Each of these denies a watch, a long `sleep`, or a registered slow command where it used to defer. bash's noexec option is read last-wins too, so `bash -n +n scripts/gate.sh` runs the script and denies.

**A substitution or a comment no longer hides a command.** A watch inside a double-quoted `"$(...)"` or a backtick substitution, or in an unquoted heredoc body, is now judged. So is a command on the line after a `#` comment, which used to be read as part of the comment, including a comment that holds a `$(`, a backtick or an apostrophe. Several quoting shapes the shared parser misread now reach the guard as well: an ANSI-C string like `$'\''`, a `#` straight after `<(true)`, a `#` inside `${x:- #}`, and a comment with an apostrophe inside a `$( )`. All of them hid the next command and passed it unjudged.

**A trailing `&` exempts what bash backgrounds, and nothing else.** `sleep 300 && ls & make build` backgrounds the whole and-or list, so it defers now where it used to deny. `sleep 300; ls &` backgrounds only `ls`, so it denies again. A `&` at the end of a line or inside `(sleep 300 &)` is read as backgrounding, a substitution in a backgrounded command (`echo $(gh run watch 1) & ls`) defers, and a registered slow command run as `scripts/gate.sh &` is no longer denied for its timeout.

**A command that never runs is not denied.** `nohup NAME=v cmd` makes `nohup` look for a program called `NAME=v`, so `cmd` never starts. The same holds after `command`, `stdbuf`, `exec`, `builtin`, `unbuffer` and `/usr/bin/time`. `time NAME=v cmd` with bash's `time` keyword does run `cmd` and still denies. `sudo -l`, `-v`, `-e`, `-K`, `-U` and `-V` run no command, `sudo -h <word>` takes the word as a host, and `sudo -- A=1 cmd` runs a program named `A=1`, so the guard no longer denies what is written after any of them.

**[An extra watch pattern can name itself and teach its own snapshot](https://github.com/karlkfi/claude-bouncer/blob/foreground-guard/v0.8.0/plugins/foreground-guard/README.md#configuration).** A `poll.extra_watch_patterns` entry may now be an object, `{"pattern": …, "label": …, "alternative": …}`. The deny then names the tool by its label and offers your snapshot command as the first fix, the way a built-in watch does. A plain string still works and is labelled with the regex itself. Its generic first fix now reads "take one non-blocking snapshot".

**[On Windows the hook runs where `python3` is only the Store stub](https://github.com/karlkfi/claude-bouncer/blob/foreground-guard/v0.8.0/plugins/foreground-guard/README.md#install).** The hook used to be launched as `python3`. On a Windows machine where that name is the Microsoft Store alias, the launch failed, Claude Code treated the failure as non-blocking, and every command went through. It now starts through `run-python-hook.cmd`, which tries `py -3`, `python` and `python3` by running each, and says so on stderr when none works.

**A deny names the writes it discarded.** A deny refuses the whole call, so a `> out.txt` redirect, `tee`, `sed -i`, `cp`/`mv` or a heredoc script in it never happened. The reason now ends by listing them, as every guard's does.

## Decision surface

Measured by running the v0.7.0 hook and this one over the same payloads and diffing the emitted `permissionDecision`. `defer` means the guard expressed no opinion and your own permission settings decided. The *registered* rows carry `{"slow": {"commands": {"scripts/gate\\.sh": 3600000}}}`, the *object* row carries `{"poll": {"extra_watch_patterns": [{"pattern": "mytool\\s+follow", "label": "mytool follow", "alternative": "mytool status"}]}}`, the *string* row carries the same pattern as a plain string, and the rest carry no config file.

| command | v0.7.0 | v0.8.0 |
|---|---|---|
| `stdbuf -o L gh run watch 1` | defer | **deny** |
| `sudo -nu root gh run watch 1` | defer | **deny** |
| `env 'a b=c' sleep 300` | defer | **deny** |
| `env -S 'sleep 300'` | defer | **deny** |
| `sudo A=1 -u root sleep 300` | defer | **deny** |
| `FOO[0]=x sleep 300` | defer | **deny** |
| `echo "$(gh run watch 1)"` | defer | **deny** |
| `sleep 300; ls &` | defer | **deny** |
| `bash -n +n scripts/gate.sh` *(registered)* | defer | **deny** |
| `mytool follow` *(object)* | defer | **deny** |
| `echo $(gh run watch 1) & ls` | deny | **defer** |
| `sleep 300 && ls & make build` | deny | **defer** |
| `(sleep 300 &)` | deny | **defer** |
| `nohup NAME=v sleep 300` | deny | **defer** |
| `sudo -l sleep 300` | deny | **defer** |
| `scripts/gate.sh &` *(registered)* | deny | **defer** |
| `mytool follow` *(string)* | deny | deny |
| `time NAME=v sleep 300` | deny | deny |
| `scripts/gate.sh` *(registered)* | deny | deny |
| `sleep 300` | deny | deny |
| `sleep 300 &` | defer | defer |
| `ls -la` | defer | defer |

Ten rows gain a denial and six lose one. A default install with no config file sees thirteen of those sixteen move: the `bash -n +n` and `scripts/gate.sh &` rows need a registered slow command, and the object row needs the object entry.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update foreground-guard@claude-bouncer
```

A restart is needed. The hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** The object form of `poll.extra_watch_patterns` is additive: a plain string entry denies exactly as it did. v0.7.0 skips an object entry without a word, though, so a project config that uses one guards nothing for a teammate still on v0.7.0. The environment-variable surface is identical to v0.7.0's.

The hook command in `hooks/hooks.json` changed from `python3 …` to the `run-python-hook.cmd` launcher. Off Windows it tries `python3`, then `python`, so any working Python 3 under either name is enough.

If you pasted the `reduce-foreground-guard-prompts` playbook into a `CLAUDE.md`, paste it again. It now says the guard denies by default rather than prompting.

**This plugin is pre-1.0 and its surface is unstable by design.** Nothing breaks in this release, but a break here would ride in a minor rather than waiting for a major, and it would be stated in these notes when it happens.

## Validation

**267 tests green**, up from 225 at v0.7.0, on the release tree, alongside the 304 tests at the repository root, 148 of them on the shared modules under `lib/`, and the four sibling suites `make check` runs beside them. The counts are from the release branch rather than quoted from an earlier run.

The **never-`allow`** invariant is asserted on every end-to-end call: the hook returns `ask`, `deny`, or nothing. An `allow` would bypass your permission settings and override the sibling guards evaluating the same command.

**What this does not assert.** No live Claude Code session runs in the suite. Hook behaviour is asserted against synthetic payloads, and the table above against real subprocess invocations rather than a real session. The Windows launcher path is not exercised on Windows here. Class B's registry is per-repo by design, so no test can tell you whether *your* slow commands are registered, only that a registered one behaves; the [friction report](https://github.com/karlkfi/claude-bouncer/blob/foreground-guard/v0.8.0/plugins/foreground-guard/README.md#friction-report) is the tool for that.

**This is a productivity guard, not a security boundary.** Parsing uncertainty defers, and infrastructure errors fail open to a silent defer, because a guard that breaks the session is worse than a missed prompt. Do not deploy it as a control that something must not run.
