Minor release: two shapes that let a blocking command past the guard now deny, and two false denials are withdrawn. No configuration changed, and a default install with no registry sees only the quoted-`&` fix.

## Highlights

**A quoted or escaped `&` is an argument, not a background operator.** `sleep 300 '&'` and `sleep 300 \&` read as backgrounded, so the guard stood down — and a command that parks the main thread for five minutes went through unjudged. Bash passes both to `sleep` as an argument and runs it in the foreground, which is exactly the case the guard exists for. A real trailing `&` is unchanged.

**[An interpreter option that takes its own argument no longer hides the script](https://github.com/karlkfi/claude-bouncer/blob/foreground-guard/v0.7.0/plugins/foreground-guard/README.md#covered-forms).** `bash -o errexit gate.sh`, `--rcfile`, `--init-file`, `-O`, and the `+o`/`+O`/`+x` forms each consume a separate word, and the Class B peel was reading that word as the script. A registered slow command invoked through any of them ran in the foreground unguarded. `bash -o noexec gate.sh` still defers, because it parses the script and runs nothing.

**A parse-only run executes nothing, so it cannot block.** `bash -n <registered-script>` and the other parse-only forms — `sh -n`, `zsh -n`, `-en`, `-n -c` — were denied as slow foreground runs. A `-n` written *after* the script name belongs to the script and is unaffected.

**A sleep between two different commands is one wait, not a poll.** The repeat-with-sleep rule fired on any `cmd; sleep N; cmd` shape regardless of whether the two commands matched, so `pkill x; sleep 3; pgrep x` and `echo armed; sleep 3; pgrep x` were denied as polling loops. They defer below the sleep floor now. The rule still fires when the same command sits on both sides.

**Two command prefixes are read the way bash reads them.** `X+=1 scripts/gate.sh` used to defer entirely — the append spelling was taken for a command name, so the guard never saw the script — and it now denies. In the other direction a quoted prefix is a program bash looks for and fails to find: `'X=1' scripts/gate.sh` never reaches the script, so there is nothing to guard and the denial is gone.

## Decision surface

Measured by running the v0.6.0 hook and this one over the same payloads and diffing the emitted `permissionDecision`. `defer` means the guard expressed no opinion and your own permission settings decided. The *registered* rows carry `{"slow": {"commands": {"scripts/gate\\.sh": 3600000}}}`; the rest carry no config file.

| command | v0.6.0 | v0.7.0 |
|---|---|---|
| `sleep 300 '&'` | defer | **deny** |
| `sleep 300 \&` | defer | **deny** |
| `bash -o errexit scripts/gate.sh` *(registered)* | defer | **deny** |
| `bash --rcfile /dev/null scripts/gate.sh` *(registered)* | defer | **deny** |
| `X+=1 scripts/gate.sh` *(registered)* | defer | **deny** |
| `bash -n scripts/gate.sh` *(registered)* | deny | **defer** |
| `pkill x; sleep 3; pgrep x` | deny | **defer** |
| `echo armed; sleep 3; pgrep x` | deny | **defer** |
| `'X=1' scripts/gate.sh` *(registered)* | deny | **defer** |
| `bash -o noexec scripts/gate.sh` *(registered)* | defer | defer |
| `sleep 300 &` | defer | defer |
| `sleep 300` | deny | deny |
| `pgrep x; sleep 3; pgrep x` | deny | deny |
| `scripts/gate.sh` *(registered)* | deny | deny |
| `gh run watch` | deny | deny |
| `ls -la` | defer | defer |

Five rows gain a denial and four lose one. The two `sleep 300` rows are the only ones a default install without a registry will see move, because everything under Class B needs a registered command to fire on at all.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update foreground-guard@claude-bouncer
```

A restart is needed — the hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** The config keys are the same keys with the same defaults, and the environment-variable surface is identical to v0.6.0's.

**This plugin is pre-1.0 and its surface is unstable by design.** Nothing breaks in this release, but a break here would ride in a minor rather than waiting for a major, and it would be stated in these notes when it happens.

## Validation

**225 tests green** on the release tree, alongside the 207 shared-parser tests and the four sibling suites `make check` runs beside them. The count is from the release branch rather than quoted from an earlier run.

The **never-`allow`** invariant is asserted on every end-to-end call: the hook returns `ask`, `deny`, or nothing. An `allow` would bypass your permission settings and override the sibling guards evaluating the same command.

**What this does not assert.** No live Claude Code session runs in the suite — hook behaviour is asserted against synthetic payloads, and the table above against real subprocess invocations rather than a real session. Class B's registry is per-repo by design, so no test can tell you whether *your* slow commands are registered, only that a registered one behaves; the [friction report](https://github.com/karlkfi/claude-bouncer/blob/foreground-guard/v0.7.0/plugins/foreground-guard/README.md#friction-report) is the tool for that.

**This is a productivity guard, not a security boundary.** Parsing uncertainty defers, and infrastructure errors fail open to a silent defer, because a guard that breaks the session is worse than a missed prompt. Do not deploy it as a control that something must not run.
