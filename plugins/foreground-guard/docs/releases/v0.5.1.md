Main-thread time guard for Claude Code Bash commands: catches foreground polling and watching, and slow commands about to be killed by an inadequate timeout.

> [!NOTE]
> **Your friction numbers will move after this upgrade, and the movement is the fix.** Three of the four changes here correct `friction-report.py`, all in the same direction: deny counts rise off a zero the old report could only ever produce, the friction percentage falls against a denominator that now exists, and hook crashes stop being counted as defers. The same window read by v0.5.0 and by v0.5.1 gives different numbers, so compare v0.5.1 output only against v0.5.1 output.

## Highlights

**[Class A reasons now name Monitor as the sanctioned wait](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/README.md#what-it-does), and never offer `run_in_background` as a fix.** Class A is the foreground polling and watching class — `gh run watch`, `tail -f`, `watch`, sleep-loops. v0.5.0 taught three fixes for it, and the middle one was to re-run the same call with `run_in_background: true`, which the guard itself does not accept: Class A prompts on a backgrounded call too. An agent that took the fix walked into a second prompt. The three fixes are now one non-blocking snapshot, a Monitor — a Claude Code tool — whose script exits when the condition flips, waking the session with a dated event and holding no Bash task slot, or an explicit `timeout N` bound. The [Exemptions](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/README.md#exemptions) section names backgrounding as a non-fix rather than offering it as one, and `run_in_background` is gone from every Class A reason, foreground and backgrounded alike (#22). On a surface that does not offer Monitor, the snapshot and the `timeout` bound still stand.

**Denies now reach the friction report.** It read hook decisions from the attachment stream — the records Claude Code writes into its session transcripts for each hook that speaks — and Claude Code writes one only for a call it goes on to run, so a `deny` left no record there and the report showed zero. That zero was worst exactly where it mattered: in an [unattended permission mode](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/README.md#unattended-permission-modes) every ask becomes a deny, so a guard doing nothing but blocking reported no friction whatsoever. Measured over 601 local transcripts: 48k allow/ask attachments and not one deny, while the denials sat in plain sight as tool results. Denies are now recovered from the error the blocked call handed back, whose text is verbatim the reason the hook printed (#25).

**The friction rate has a denominator.** It divided by the guard's own decision records, which cannot work here: a silent defer leaves no record, and this hook prints nothing when it defers and never prints `allow` — so its decision stream holds exactly its own prompts and the share reads 100% however the config is tuned. The rate now divides by Bash calls in the window. Those are recorded whatever a hook decided, so they mean the same thing for every guard, which makes a single-guard rate comparable with `--plugin all`. A second line counts sessions rather than calls: how often a session was interrupted at all. The denominator is every in-window Bash call, so a guard installed part-way through one reads low until the window catches up — the report prints that caveat in its own output, and [Friction report](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/README.md#friction-report) explains why (#27).

**A crashed hook is reported as an error, not a defer.** Claude Code writes an attachment for a hook that crashed or timed out as well as for one that spoke, and a crashed hook's stdout is empty — indistinguishable from a silent defer unless you read the record's `type`. The difference is the whole point: a defer means the guard looked and let the call through, an error means it was never consulted and the call ran unguarded. Measured over 782 local transcripts and 66,223 `PreToolUse:Bash` attachments, 5,472 were `hook_non_blocking_error`, all exit 126 — a sibling guard's hook script left non-executable for a day. Under `--plugin all`, every one of those had been counting as a defer. Failures are now listed above the prompt rankings with the exit code and the first line of stderr, which is why `--plugin all` is where you would notice a sibling has stopped running (#29).

## Upgrading

Install or update as usual. Nothing is required, no config file needs to change, and nothing you configured changes meaning.

**Nothing is deprecated or removed in this release.** No config key changed name, default, or meaning.

**If you script against `friction-report.py --json`, four keys were added and none removed.** `total` keeps counting decision records, and the rate's denominator is the new `bash_calls`. One existing key changes shape — see **Configuration surface**.

## Configuration surface

**No keys were added or removed** — the table in [Configuration](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/README.md#configuration) still holds the same eight keys as v0.3.0, and the hook's decision on any given command is unchanged: the `bash-foreground-guard.py` diff touches Class A reason text and the comments around it, and no matcher, policy, or config path. The prompt category taxonomy in the [friction report](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/README.md#friction-report) is unchanged too, so category-based tracking keeps working.

The report's own output did change. `--json` gains `bash_calls`, `sessions`, `sessions_prompted`, and `hook_errors`; `total` is untouched in name and meaning. `decisions` gains a new value, `error`, taken out of what it used to count as `defer` — so a tracked `defer` count drops against the same transcripts, and that drop is the fix rather than a change in the guard. The text report gains a "Hook failures" block above the prompt rankings, a "sessions with a prompt" line, a note that the denominator covers calls predating the install, and — under `--plugin all` only — a note that deny recovery keys on the `<name>-guard: ` opener, so a sibling wording its reason differently still under-reports.

## Validation

**189 tests, green across Python 3.10, 3.11, 3.12, and 3.13 on the tagged commit itself** — all four jobs named green in [run 32213363303](https://github.com/karlkfi/claude-foreground-guard/actions/runs/32213363303), against 152 at v0.5.0 measured by running that tree rather than by quoting its notes. 20 of the 37 new tests sit in three new friction-report classes: `DenyFromResultTests` (9, over what does and does not count as a recovered deny), `ScopeTallyTests` (6, over the Bash-call denominator), and `ErrorNoteTests` (5, over the failure line built from whichever fields a crash or a cancellation happens to carry). The other 17 grew `IterDecisionsTests` (7), `PrintTests` (4), the end-to-end pass over synthetic transcripts (4), `BuildReportTests` (1), and `ExemptionTests` (1). That last one is `test_class_a_fixes_name_monitor_and_never_backgrounding`, which asserts every Class A finding type both foreground and backgrounded — the assertion v0.5.0 had inverted, since it *required* `run_in_background` to appear in a foreground watch reason and only forbade it once the call was already backgrounded.

The **never-`allow`** invariant is asserted on every end-to-end call: the hook returns `ask`, `deny`, or nothing. An `allow` would bypass your permission settings and override the sibling guards evaluating the same command.

<details>
<summary><b>What the suite does not assert — deny recovery across guards, the denominator's install assumption, and three more</b></summary>

- **No live Claude Code session runs in CI.** Hook behaviour is asserted against synthetic payloads, and the friction report against synthetic transcript fixtures — never your own transcripts.
- **Deny recovery is complete for this guard and partial across guards.** It keys on the `foreground-guard: ` opener every reason here carries; a sibling guard wording its reason differently still under-counts its denies under `--plugin all`, and no test can tell you which siblings do. A low deny count there is not evidence that guard rarely blocks.
- **The friction rate's denominator assumes the guard ran for the whole window.** Bash calls predating your install sit in it, so a fresh install reads low until the window catches up. The report prints that caveat; nothing detects the condition for you.
- **Class B's registry is per-repo by design**, so no test can tell you whether *your* slow commands are registered — only that a registered one behaves. The [friction report](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/README.md#friction-report) is the tool for that.
- **`scripts/cut-release.sh` still has no end-to-end test** — its preflight runs the unit suite, which would recurse — so only the EXIT-trap regression from #20 is covered.

</details>

## Security

**No security advisory accompanies this release**, and no dependency changed — the hook remains a single stdlib-only Python script with no telemetry. The friction report re-reads your local session transcripts and sends nothing anywhere; the deny recovery added here reads a second kind of record out of those same local files and does not widen that. See [PRIVACY.md](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/PRIVACY.md).

**This is a productivity guard, not a security boundary.** Parsing uncertainty defers, and infrastructure errors fail open to a silent defer, because a guard that breaks the session is worse than a missed prompt. Do not deploy it as a control that something must not run.

## Installing this release

```
/plugin marketplace add karlkfi/claude-foreground-guard
/plugin install foreground-guard@foreground-guard
```

> [!NOTE]
> **An existing install does not pick this up on its own.** Claude Code auto-updates official Anthropic marketplaces only; a third-party GitHub marketplace stays pinned at the version you installed. Either set `autoUpdate` for the marketplace in `~/.claude/settings.json` once, or update by hand — both are in [Keeping it updated](https://github.com/karlkfi/claude-foreground-guard/blob/v0.5.1/README.md#keeping-it-updated).
>
> ```
> claude plugin marketplace update foreground-guard
> claude plugin update foreground-guard@foreground-guard
> ```
>
> Restart Claude Code (or `/reload-plugins`) to apply. Requires `python3` on your PATH.

The plugin pairs with the sibling guards — [workspace-guard](https://github.com/karlkfi/claude-workspace-guard), [branch-guard](https://github.com/karlkfi/claude-branch-guard), and [prod-guard](https://github.com/karlkfi/claude-prod-guard) — which is why this one never emits `allow`.
