Minor release: a blocking command written behind `sudo --login`, after a `#` that bash reads as text, or inside a quoted `$( )` the shared parser used to misread now denies. Nothing in this guard's own code changed. The fixes are in the shared parser it calls.

## Highlights

**`sudo --login` no longer hides the command behind it.** sudo reads `--login` whole, as `-i`, though it is also a prefix of the value-taking `--login-class`. The parser read it as the latter and took the next word as its value, so `sudo --login gh run watch 1` passed unjudged. It now denies, as `sudo -i gh run watch 1` already did.

**A `#` that bash reads as text no longer starts a comment.** Inside an extglob group (`@(a|#b)`), a `(( … ))`, or a `[[ … =~ … ]]` operand, and after an escaped blank (`a\ #b`), bash keeps `#` as part of a word. The parser read a comment there and dropped the rest of the line, along with any watch or long `sleep` on it. A `[[ … ]]` that holds a real comment with an apostrophe in it also hid a `$( )` written after it, because the apostrophe opened a quote that ran to the end of the string.

**A quoted `$( )` is read to its real end.** A `#` or `)` inside `${…}` or a backtick within a double-quoted `$( )`, or a nested quoted `$( )` inside one, used to end the substitution early. The command after that point was never judged.

## Decision surface

Measured by running the v0.8.0 hook and this one through their launchers over the same payloads, with no config file, and recording the emitted `permissionDecision`. `defer` means the guard expressed no opinion and your own permission settings decided.

| command | v0.8.0 | v0.9.0 |
|---|---|---|
| `sudo --login gh run watch 1` | defer | **deny** |
| `[[ $x == @(a\|#b) ]]; gh run watch 1` | defer | **deny** |
| `(( 1 #2 )); sleep 300` | defer | **deny** |
| `echo a\ #b ; sleep 300` | defer | **deny** |
| `echo "$(echo ${y:- #}; gh run watch 1)"` | defer | **deny** |
| `echo "$(echo "$(true ")" x)"; gh run watch 1)"` | defer | **deny** |
| `[[ -n x #it's` newline `]] && echo "$(gh run watch 1)"` | defer | **deny** |
| `sudo -i gh run watch 1` | deny | deny |
| `time -p sleep 300` | deny | deny |
| `sleep 300` | deny | deny |
| `ls -la` | defer | defer |

Seven rows gain a denial and none lose one. All seven are on a default install with no config file.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update foreground-guard@claude-bouncer
```

A restart is needed. The hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** The configuration keys and the environment-variable surface are identical to v0.8.0's.

**This plugin is pre-1.0 and its surface is unstable by design.** Nothing breaks in this release, but a break here would ride in a minor rather than waiting for a major, and it would be stated in these notes when it happens.

## Validation

**FG_COUNT** on the release tree, alongside the ROOT_COUNT tests at the repository root and the four sibling suites `make check` runs beside them. The counts are from the release branch rather than quoted from an earlier run.

The **never-`allow`** invariant is asserted on every end-to-end call: the hook returns `ask`, `deny`, or nothing. An `allow` would bypass your permission settings and override the sibling guards evaluating the same command.

**What this does not assert.** No live Claude Code session runs in the suite. Hook behaviour is asserted against synthetic payloads, and the table above against real subprocess invocations rather than a real session. Class B's registry is per-repo by design, so no test can tell you whether *your* slow commands are registered, only that a registered one behaves.

**This is a productivity guard, not a security boundary.** Parsing uncertainty defers, and infrastructure errors fail open to a silent defer, because a guard that breaks the session is worse than a missed prompt. Do not deploy it as a control that something must not run.
