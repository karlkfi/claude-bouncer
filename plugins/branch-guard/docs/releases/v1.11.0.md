Minor release: an opt-in grant that makes a worktree you just created yours to work in, three prompts withdrawn where the guard was judging the wrong tree or the wrong branch, and two parser fixes — one closing a prefix that stood the guard down in silence.

## Highlights

**[A worktree you create can be yours for the session](https://github.com/karlkfi/claude-bouncer/blob/branch-guard/v1.11.0/plugins/branch-guard/README.md#configuration).** `BRANCH_GUARD_WORKTREE_GRANTS=1` makes `git worktree add` ask once, and the new checkout is then a path prefix this session may read and write without re-asking. Off by default and session-scoped: the grant is keyed to the session id, the first grant's timestamp never slides, and every error fails toward more prompts rather than fewer.

**[A push is judged on the tree it runs in](https://github.com/karlkfi/claude-bouncer/blob/branch-guard/v1.11.0/plugins/branch-guard/README.md#push-guard).** The guard measured the session's worktree and then decided about a push that ran somewhere else. A `cd` or a `git -C` into another worktree of the same repository is now judged on that tree's own branch. This closed a gap in both directions — a rebase demanded for an overlap that was not there, and a `git -C` force-push waved through when there was one.

**A leased rewrite may send the branch it leased.** `git push --force-with-lease=other origin other` is auto-approved now rather than prompting: the lease names the destination and the push sends that same branch, so the check the lease performs is the check the prompt was asking for. A push sourced from some third branch still prompts, and a plain `--force-with-lease` on the worktree branch is unchanged.

**An overwrite gets the second chance a delete already had.** `git branch -f`, `-M` and `-C` stop prompting when the branch they overwrite holds only a merge git can reproduce — the same second chance `git branch -D` and `git reset --hard` already took. A tip that survives nowhere else, or that orphans anything but a reproducible merge, still asks.

**A leading `cd` no longer swallows the break-glass.** `cd . && BRANCH_GUARD_OVERRIDE=<reason> git reset --hard …` is lifted now, and a liftable denial behind a `cd` names the prefix again instead of leaving you to guess where it goes. A `cd` into a *different* worktree still keeps its prompt, which is the case the tracking exists for.

**A prefix that stood the guard down is closed, and one that never armed it is gone.** `X+=1 git reset --hard …` used to defer entirely, because the append spelling read as a command name rather than an assignment — that is a bypass, and it now asks. `BRANCH_GUARD_OVERRIDE+=<reason>` arms as you would expect. In the other direction, a quoted prefix is a program bash tries to run, so `'X=1' git reset --hard …` never reaches `git` and no longer prompts, and `'BRANCH_GUARD_OVERRIDE=why' …` no longer arms a break-glass bash never set.

## Decision surface

Measured by running the v1.10.0 hook and this one over the same throwaway repository and diffing the emitted `permissionDecision`. `defer` means the guard expressed no opinion and your own permission settings decided. The repository has a protected `main`, a branch `mergeonly` whose tip is a reproducible merge, a branch `orphan` holding unique work, and a second worktree checked out on `other`.

| command | v1.10.0 | v1.11.0 |
|---|---|---|
| `git branch -f mergeonly main` | ask | **allow** |
| `git push --force-with-lease=other origin other` | ask | **allow** |
| `git -C <worktree on other> push --force origin other` | ask | **allow** |
| `cd . && BRANCH_GUARD_OVERRIDE=why git clean -fd` | ask | **allow** |
| `cd . && BRANCH_GUARD_OVERRIDE=why git branch -f orphan main` | ask | **allow** |
| `X+=1 git reset --hard HEAD~1` | defer | **ask** |
| `BRANCH_GUARD_OVERRIDE+=why git reset --hard HEAD~1` | defer | **ask** |
| `'X=1' git reset --hard HEAD~1` | ask | **defer** |
| `'BRANCH_GUARD_OVERRIDE=why' git reset --hard HEAD~1` | ask | **defer** |
| `git branch -f orphan main` | ask | ask |
| `git push --force origin main` | ask | ask |
| `git push --force-with-lease origin main` | ask | ask |
| `git reset --hard HEAD~1` | ask | ask |
| `BRANCH_GUARD_OVERRIDE=why git clean -fd` | allow | allow |
| `git checkout -b newbranch` | allow | allow |
| `git status` | allow | allow |

Five prompts withdrawn, two added, two rows that were never about a `git` command at all. The two additions are the release's only new scrutiny, and both are a command prefix the guard used to read as a program name.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update branch-guard@claude-bouncer
```

A restart is needed — the hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** `BRANCH_GUARD_OVERRIDE` and the rest keep their names and their defaults. `BRANCH_GUARD_WORKTREE_GRANTS` is new and off unless you set it.

**If you scripted a break-glass as `'BRANCH_GUARD_OVERRIDE=…' git …`, it never worked.** Quoted, bash runs it as a program and the assignment never happens, so the guard now agrees with bash instead of honouring a variable nothing set. Write the prefix unquoted. Quoting the *value* — `BRANCH_GUARD_OVERRIDE="incident 42" git …` — is unaffected.

## Validation

**554 fixtures green** on the release tree, alongside the 207 shared-parser tests that cover `lib/bouncer_parse.py` directly and the four sibling suites `make check` runs beside them. The count is from the release branch rather than quoted from an earlier run. Every fixture goes through the launcher named in `hooks/hooks.json`, so the path under test is the path Claude Code executes.

The decision surface above is the check a fixture suite cannot make: both hooks run as subprocesses over the same repository, so a row records what a session would actually have seen.

**What this does not assert.** No live Claude Code session runs in the suite. The worktree rows rest on a fixture repository with two checkouts rather than on your layout, and the reproducible-merge test is a property of the commit graph — a branch whose tip is a merge git *cannot* reproduce still prompts, and the suite asserts both sides. The guard reads the command string Claude is about to run, so it governs Claude's own tools and nothing else; a branch that must not move belongs behind a server-side protection rule.
