Minor release: three routine operations stop asking under the default `strict` policy — pushing a branch this session created, a create-only queue-id claim, and `git worktree remove --force` on a worktree inside this session's own scratchpad.

## Highlights

**[A branch this session created can be pushed without a prompt](https://github.com/karlkfi/claude-bouncer/blob/branch-guard/v1.13.0/plugins/branch-guard/README.md#push-guard).** `strict` allows a push of the worktree's own branch and asks before any other, so a session that ran `git branch feat/new` and then pushed it from its worktree branch was asked, because the guard could not tell that branch from a peer's. Creation is the one moment that shows ownership, so the guard now records it. When `git branch`, `git switch -c`, `git checkout -b` or `git worktree add -b` creates a name that had no local branch and no remote-tracking ref, that branch is granted to the session for 8 hours, and a push of it allows like the worktree branch's. Deleting it, pushing it from a third branch, pushing it from another session, or a protected name all still ask, and a creation behind a `cd` records nothing.

**[A create-only queue-id claim allows](https://github.com/karlkfi/claude-bouncer/blob/branch-guard/v1.13.0/plugins/branch-guard/README.md#push-guard).** `git push --force-with-lease=refs/queue-ids/QN: origin <src>:refs/queue-ids/QN` used to ask as a push to a non-branch ref. The empty lease tells the remote the ref must not exist yet, so the push cannot overwrite someone else's claim. Every other spelling into that namespace still asks, including a `+` refspec, `--force`, `-f`, a lease expecting a commit, and a lease after an abbreviated long option such as `--force-w=`, which git reads as a lease the guard does not see. Tags still ask.

**[`git worktree remove --force` in this session's own scratchpad allows](https://github.com/karlkfi/claude-bouncer/blob/branch-guard/v1.13.0/plugins/branch-guard/README.md#git-branch-what-the-session-owns-not-how-the-verb-looks).** A worktree holding modified or untracked files asks before `--force` deletes it. One the session made under its own Claude Code scratchpad, `/tmp/claude-<uid>/<project>/<session-id>/`, is disposable by construction, so removing it by absolute path no longer asks. A relative path, another session's scratchpad, and any other location still ask.

## Decision surface

Measured by running the v1.12.0 hook and this one through their launchers over identical payloads, each against a fresh repository with a bare `origin`, the session checkout on `claude/x`, and the default `strict` policy. The scratchpad worktree is a linked worktree holding an untracked file, under a directory carrying the payload's session id. The other worktree holds one too, outside it. `defer` means the guard expressed no opinion and your own permission settings decided.

| command | v1.12.0 | v1.13.0 |
|---|---|---|
| `git branch feat/new`, then `git push -u origin feat/new` | ask | **allow** |
| `git push --force-with-lease=refs/queue-ids/Q42: origin HEAD:refs/queue-ids/Q42` | ask | **allow** |
| `git worktree remove --force <scratchpad>/pr1` *(absolute path)* | ask | **allow** |
| `git push -u origin feat/new` *(from another session)* | ask | ask |
| `git push origin --delete feat/new` | ask | ask |
| `git push origin peer/branch` *(not created by this session)* | ask | ask |
| `git push origin +HEAD:refs/queue-ids/Q42` | ask | ask |
| `git push --force-w=refs/queue-ids/Q42 --force-with-lease=refs/queue-ids/Q42: origin HEAD:refs/queue-ids/Q42` | ask | ask |
| `git push origin v1.3.0` | ask | ask |
| `git worktree remove --force <scratchpad>/pr1` *(relative path)* | ask | ask |
| `git worktree remove --force <scratchpad>/pr1` *(from another session)* | ask | ask |
| `git worktree remove --force ../wt2` *(outside the scratchpad)* | ask | ask |
| `git push` | allow | allow |

Three rows open and none harden. Each of the three is the narrow form the change targets, and the rows under it are the neighbours that keep their prompt: another session, a deletion, a branch this session did not create, a lease that does not protect the claim, and a worktree outside this session's scratchpad.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update branch-guard@claude-bouncer
```

A restart is needed. The hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** `BRANCH_GUARD_OVERRIDE` and the rest keep their names and their defaults. Grants for branches this session created live under `~/.claude/branch-guard/session-grants/`.

**The residual is a peer's branch this clone has not fetched.** Its name looks free, so creating and pushing a branch of the same name allows, and a force push of it would overwrite the peer's, as a force push of the worktree branch already could. Fetch before reusing a name you did not invent.

## Validation

**900 fixtures green** on the release tree, alongside the 319 tests at the repository root and the four sibling suites `make check` runs beside them. The counts are from the release branch rather than quoted from an earlier run. Every fixture goes through the launcher named in `hooks/hooks.json`, so the path under test is the path Claude Code executes.

The decision surface above is the check a fixture suite cannot make: both hooks run as subprocesses over the same repositories, and the created-branch row runs the `PreToolUse` and `PostToolUse` hooks around a real `git branch`, so a row records what a session would actually have seen.

**What this does not assert.** No live Claude Code session runs in the suite. The queue-id lease was driven against a real remote on git 2.55 when the change was written, not again for this release. The guard reads the command string Claude is about to run, so it governs Claude's own tools and nothing else; a branch that must not move belongs behind a server-side protection rule.
