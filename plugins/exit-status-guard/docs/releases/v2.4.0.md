Minor release: a gate inside a `$(…)` that another command consumes now denies, a `gh api` write counts as a state change, and a gate behind `timeout`, `nice`, a program-spelled `time` and four other wrappers is now seen.

## Highlights

**[A gate's `$(…)` used as an argument denies](https://github.com/karlkfi/claude-bouncer/blob/exit-status-guard/v2.4.0/plugins/exit-status-guard/README.md#5-a-command-substitution-as-an-argument).** In `echo "$(make check)"` the command around the substitution reports its own status, so a failing gate reads as 0. The same holds for `local out=$(go test ./...)` and `$(make check) && …`. Each now denies. The rewrite is to assign the substitution on its own, `out=$(make check); rc=$?`, where bash keeps the gate's status, and that form still passes.

**A `gh api` write sequenced after a gate denies.** `make check; gh pr merge 1` already denied, because a failed check would still merge. A `gh api` call that writes is the same kind of state change, so it now denies after `;` too: a method other than `GET`, a field flag or `--input` with no method named, or a GraphQL `mutation`. A GraphQL query, a plain `gh api` read and a `POST /markdown` render change nothing on the server and stay silent.

**A gate behind a wrapper program is seen.** `timeout`, `nice`, `ionice`, `chrt`, `taskset`, `doas`, `caffeinate` and a program-spelled `time` (`/usr/bin/time`, `command time -o log`) each run the gate and pass its status through. A gate behind any of them, piped into a filter, now denies, as it already did behind `sudo` or `env`.

**The shared parser reads more of what bash reads.** A gate behind the `time -p` or `time --` keyword, behind `sudo --login`, or after a `#` that bash treats as text (inside an extglob group, a `(( … ))`, a `[[ … =~ … ]]` operand, or after an escaped blank) used to pass unread, and is now judged.

## Decision surface

Measured by running the v2.3.0 hook and this one through their launchers over the same payloads and recording the emitted `permissionDecision`. `defer` means the guard expressed no opinion and your own permission settings decided. All rows are foreground calls.

| command | v2.3.0 | v2.4.0 |
|---|---|---|
| `echo "$(make check)"` | defer | **deny** |
| `local out=$(go test ./...)` | defer | **deny** |
| `$(make check) && echo ok` | defer | **deny** |
| `make check; gh api -X POST repos/o/r/issues -f title=x` | defer | **deny** |
| `make check; gh api repos/o/r/issues -f title=x` | defer | **deny** |
| `make check; gh api graphql -f query='mutation { x }'` | defer | **deny** |
| `timeout 600 make check \| tail -5` | defer | **deny** |
| `nice make check \| tail -5` | defer | **deny** |
| `/usr/bin/time make check \| tail -5` | defer | **deny** |
| `command time -o log make check \| tail -5` | defer | **deny** |
| `caffeinate make check \| tail -5` | defer | **deny** |
| `time -p make check \| tail -5` | defer | **deny** |
| `sudo --login make check \| tail -5` | defer | **deny** |
| `echo a\ #b ; make check \| tail -5` | defer | **deny** |
| `[[ $x == @(a\|#b) ]]; make check \| tail -5` | defer | **deny** |
| `out=$(make check); rc=$?` | defer | defer |
| `make check; gh api graphql -f query='{ viewer { login } }'` | defer | defer |
| `make check; gh api repos/o/r/pulls` | defer | defer |
| `make check; gh api -X POST /markdown -f text=x` | defer | defer |
| `make check; gh pr merge 1` | deny | deny |
| `sudo make check \| tail -5` | deny | deny |
| `make check \| tail -5` | deny | deny |
| `make check` | defer | defer |

Fifteen rows gain a denial and none lose one. Each of the fifteen loses a gate's status, or runs a state change after a gate that may have failed. The rows under them keep their verdict: the assignment that keeps the status, the `gh api` calls that change nothing, and the forms that already denied.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update exit-status-guard@claude-bouncer
```

A restart is needed. The hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** `EXIT_STATUS_GUARD_OVERRIDE`, `EXIT_STATUS_GUARD_REGISTRY` and `.claude/exit-status-guard.json` keep their names and defaults, as do the 1.x spellings. The bundled registry gains mutator entries for the `gh api` write forms. A registry of your own that sets `replace: true` keeps its own mutator list, so copy the new `gh api` entries from the bundled `exit-status-guard.json` if you want them.

## Validation

**ES_COUNT** on the release tree, alongside the ROOT_COUNT tests at the repository root and the four sibling suites `make check` runs beside them. The counts are from the release branch rather than quoted from an earlier run. Python 3.9 is this plugin's floor, and CI runs the shared parser against it.

The decision surface above is the check a test suite cannot make: both hooks run as subprocesses over the same payloads, so a row records what a session would actually have seen.

**What this does not assert.** No live Claude Code session runs in the suite. The `gh api` method rules rest on gh's own method selection as v2.3.0 measured it, not re-measured for this release. Wanting a pipeline's output rather than its status is legitimate and indistinguishable from the bug, which is why the override exists rather than a narrower rule.
