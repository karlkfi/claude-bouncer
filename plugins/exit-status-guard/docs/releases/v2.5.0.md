Minor release: a gate hidden behind arithmetic, a bash 5.3 funsub, deep `${…}` nesting or a quoted `=~` operand now denies, and three shapes that keep the status, or never had one to lose, stop being denied.

## Highlights

**A `$(( … ))` ends where bash ends it.** The guard masked an arithmetic expansion by counting every paren, so a quoted `(` inside it, as in `echo $(( $(echo "(" | wc -c) ))`, left the mask open to the end of the string and hid a gated pipeline written after it. A `$((` that bash closes with a single `)` is a command substitution around a subshell, and bash runs the commands in it, so `echo $((echo x) ; make check | tail)` is now judged too.

**An array fold closes on an unquoted paren only.** `arr=(")" $(make check))` is an array assignment, and bash keeps the gate's status in it. The guard read the quoted `)` as the array's end and denied. It now passes. The reverse case, `x= "(" $(make check) ")"`, is an empty assignment in front of a command named `(`. That command's status replaces the gate's, so it now denies.

**Two false denials are withdrawn.** git's completion helper, `git checkout --git-completion-helper-all | tr " " "\n"`, lists options and runs no gate, so it no longer denies when the helper is the subcommand's only argument. A captured status that exits on failure before a state change, `make check > log 2>&1; rc=$?; [ "$rc" -eq 0 ] || exit 1; git commit -m x`, now passes, because the commit runs only when the gate passed.

**The shared parser reads more of what bash reads.** A thousand nested `${…}` expansions, alone or alternating with `$( )`, used to crash the hook, so the command after them ran with no decision. Three more shapes used to pass unread: a gate inside bash 5.3's `${ …; }` substitution, one in a subscript after `time -- -p`, and one after a `[[ … =~ … ]]` operand that opens with a quote or an expansion when a comment holding an apostrophe follows. Each is now judged.

**A quoted override name no longer lifts the deny.** In `'EXIT_STATUS_GUARD_OVERRIDE='$(echo x) true`, bash runs the glued word as a command rather than assigning it, so no override is set. The guard used to read it as one and let the gate after it through. It now denies. The plain `EXIT_STATUS_GUARD_OVERRIDE=$(echo x)` prefix still lifts it.

## Decision surface

Measured by running the v2.4.0 hook and this one through their launchers over the same payloads, with the bundled registry and no config file, and recording the emitted `permissionDecision`. `defer` means the guard expressed no opinion and your own permission settings decided. All rows are foreground calls.

| command | v2.4.0 | v2.5.0 |
|---|---|---|
| `echo $(( $(echo "(" \| wc -c) )) ; make check \| tail` | defer | **deny** |
| `echo $(( $(( $(echo "(" \| wc -c) )) + 1 )) ; make check \| tail` | defer | **deny** |
| `echo $((echo x) ; make check \| tail)` | defer | **deny** |
| `x= "(" $(make check) ")"` | defer | **deny** |
| `echo ${a:-${a:-…}}` *(1000 deep)* `; make check \| tail -5` | exit 1 | **deny** |
| `echo ${a:-$(echo ${a:-…})}` *(1000 alternating)* `; make check \| tail -5` | exit 1 | **deny** |
| `echo ${ make check \| tail; }` | defer | **deny** |
| `[[ x =~ $'a' ]];#it's` newline `make check \| tail -5` | defer | **deny** |
| `[[ -n $( [[ x =~ "a" ]];#it's` newline `echo y) ]] && echo $(make check \| tail -5)` | defer | **deny** |
| `time -- -p FOO[a;make check \| tail;b]=x true` | defer | **deny** |
| `'EXIT_STATUS_GUARD_OVERRIDE='$(echo x) true; make check \| tail` | defer | **deny** |
| `arr=(")" $(make check))` | deny | **defer** |
| `git checkout --git-completion-helper-all \| tr " " "\n"` | deny | **defer** |
| `make check > log 2>&1; rc=$?; [ "$rc" -eq 0 ] \|\| exit 1; git commit -m x` | deny | **defer** |
| `'EXIT_STATUS_GUARD_OVERRIDE=x' true; make check \| tail` | deny | deny |
| `EXIT_STATUS_GUARD_OVERRIDE=$(echo x) true; make check \| tail` | defer | defer |
| `echo $(! true; case x in x) make check \| tail;; esac)` | deny | deny |
| `arr=(a $(make check))` | defer | defer |
| `out=$(make check); rc=$?` | defer | defer |
| `make check; git commit -m x` | deny | deny |
| `make check \| tail -5` | deny | deny |
| `make check` | defer | defer |

Eleven rows gain a denial and three lose one. `exit 1` is the v2.4.0 hook failing on the nesting, which Claude Code treats as no decision. The three that lose a deny keep the gate's status, or run no gate at all. The rows under them keep their verdict: the override that bash does assign, a `case` after `!` that already denied here, and the forms that keep or lose a status as before.

## Upgrading

```
claude plugin marketplace update claude-bouncer
claude plugin update exit-status-guard@claude-bouncer
```

A restart is needed. The hook is registered at startup, so a running session stays on the version it loaded.

**Nothing was removed and no configuration changed meaning.** `EXIT_STATUS_GUARD_OVERRIDE`, `EXIT_STATUS_GUARD_REGISTRY` and `.claude/exit-status-guard.json` keep their names and defaults, as do the 1.x spellings. The bundled registry is unchanged.

## Validation

**79 tests green**, up from 77 at v2.4.0, on the release tree, counted by running `python3 -m unittest discover tests` in `plugins/exit-status-guard`, alongside the 355 tests at the repository root and the four sibling suites `make check` runs beside them. Python 3.9 is this plugin's floor, and CI runs the shared parser against it.

The decision surface above is the check a test suite cannot make: both hooks run as subprocesses over the same payloads, so a row records what a session would actually have seen.

**What this does not assert.** No live Claude Code session runs in the suite. That bash 5.3 runs the glued override word as a command was measured on bash 5.3.15 when that change was written, not again for this release. Wanting a pipeline's output rather than its status is legitimate and indistinguishable from the bug, which is why the override exists rather than a narrower rule.
